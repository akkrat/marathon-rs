# Oracle tables and corpora

Generated by the Kotlin oracle (`tools/oracle`, WP 0.2a) on the reference JDK, from the Kotlin marathon at commit `e47352f2`.
Never edit these files by hand; regenerate them. `scripts/check.sh` only checks that they parse.

Every `.jsonl` file starts with a header object (`table`, `description`, `schema` with one entry per row field, `rows`, `jdk`,
`generator`), followed by one JSON object per row. Strings are UTF-8; unpaired surrogates and control characters are escaped.

## Regenerating

Build the oracle once (`tools/oracle/build.sh`, see `tools/oracle/README.md`), then:

| Output | Command |
|---|---|
| `jcompat/*.jsonl` | `tools/oracle/jcompat-tables fixtures/oracle/jcompat` |
| `yaml-corpus.jsonl` | `tools/oracle/yaml-corpus fixtures/oracle/yaml-corpus.jsonl` |
| `yaml-review-corpus.jsonl` | `tools/oracle/yaml-review-corpus fixtures/oracle/yaml-review-corpus.jsonl` |
| `regex-corpus.jsonl` | `tools/oracle/regex-corpus fixtures/oracle/regex-corpus.jsonl` |
| `config-dump/*.json` | `tools/oracle/config-dump-goldens.sh` |

All generators are deterministic (fixed seeds, fixed "now", no wall-clock values in the output, paths of the checkout and
of scratch directories replaced by placeholders), so regenerating on the same JDK gives byte-identical files from any
checkout path and working directory.

## YAML corpus ids and docs/research/yaml.md §5

| yaml.md row | Corpus rows | Family |
|---|---|---|
| C01–C52, C54–C57 | `Cnn` plus a letter per value (`C01a` = `yes`, …), each bound to the simple targets `String?`, `String`, `Int`, `Long`, `Double`, `Boolean`, `Enum?`, `List<String>?`, `List<String>`, `Map<String,String>?`, `Instant?`, `Duration?`, `File?`; `C52z` adds "key absent" | `spike` |
| C53 (unknown keys, the lenient hand-written deserializers) | `C53a`–`C53i`, each bound to the marathon type named in its `bind` (the simple targets ignore unknown keys) | `strategy` |

| C59 (`findValue` shadowing) | `C59-*` | `strategy` |
| C60 (P1 emission) | `C60a` (map), `C60b` (data class), `C60c` (`ConfigurationFactory.serialize` of M-base) | `emit` |
| none: file paths | `C61a`–`C61e`, added by the oracle | `spike` |
| PLAN.md §6.3 mutation families | `M-base` and `M-<key path>-<mutation>` | `mutation` |

The review corpus is generated by `YamlReviewCorpus.kt` through the same
`YamlCorpus.tokens` and simple binding targets. `tokens.error.marks` records
`context`, `problem` and Jackson `location` separately, obtained directly from
JVM exceptions, including explicit nulls. Byte rows carry `input_bytes` and
JDK-decoded `decoded`. Strings containing unpaired surrogates use
`{"$utf16": [code units...]}` in this corpus so serde_json can transport them
without replacing or rejecting units; valid Unicode strings keep the original
schema. The original corpus is unchanged.

## Regex corpus families and docs/research/regex.md §4.1

Families 1–11 keep the note's names (`ascii-classes`, `unicode-classes`, `flags`, `anchors`, `dot`, `quoting`, `advanced`,
`hardcoded`, `user-realistic`, `adversarial`, `invalid`). Two families are added: `flag-scope` (flag scopes with positive
and negative witnesses, see the `witness` field) and `split` (`split-003` and `split-004` pass a `limit`, WP 0.3c). The
`hardcoded` family includes NmTestParser's `nm` symbol filters over real `nm` output lines. The watchdog aborts the matcher in `adversarial-008` (`(.*a){12}`), whose expected
entries read `{"aborted": 20000000}`.

## config-dump goldens

`tools/oracle/config-dump-goldens.sh` dumps every `fixtures/configuration/**/sample_*.yaml`, plus the Marathonfiles in
`config-dump-inputs/` (added for the oracle; they use the `.ipa`/`.zip` bundles of the copied fixtures, which no copied sample
does, to show the extraction side effects). For each one:

- the directory `fixtures/configuration/fixture/config` is copied to a fresh sandbox (with `config-dump-inputs/` overlaid), so
  extraction never touches the fixtures;
- paths are normalised as docs/design/config-dump-format.md ("Path normalisation") specifies: the sandbox reads
  `<FIXTURE_CONFIG>`, and macOS's `/System/Volumes/Data/` prefix reads `/`;
- the extra top-level `golden` key records the input, environment, "now", host OS and the normalisations applied;
- the environment is exactly `ANDROID_HOME=/android-sdk`, as in the Kotlin `ConfigurationSerializationTest`;
- "now" is `1970-01-12T13:46:40Z`, the reference instant of the Kotlin `ConfigurationFactoryTest`.

`sample_7` and `android/sample_1` also run with an empty environment (`*.no-android-home.json`), the case their Kotlin tests
expect to fail.

`config-dump-inputs/oracle_map_keys.yaml` pins the canonical key order (UTF-16 code units, see the format doc) with a
non-BMP map key.

Round 3 adds `yaml-round3-corpus.jsonl` (28 rows), regenerated after
`tools/oracle/build.sh` with
`tools/oracle/yaml-round3-corpus fixtures/oracle/yaml-round3-corpus.jsonl`.

against the production binder. Target-specific `d9` annotations retain the JVM
result and assert the approved Rust policy; they never skip a row or token check.

`python3 tools/oracle/annotate-yaml-d9.py` to restore those annotations.
The annotation script contains policies only, not invented JVM expected values.

and readTree/treeToValue witnesses. Regenerate with `tools/oracle/build.sh reference`,
then `tools/oracle/oracle binding-corpus fixtures/oracle/yaml-binding-corpus.jsonl`.
See `docs/wp/2.1-findings.md` for production test commands.

## xcresult (WP 4.6)

`xcresult/corpus.jsonl` contains 157 AppleJsonMapper/generated-model probes;
`xcresult/models.json` records all 57 generated Kotlin constructor signatures
and default flags. Generated with `tools/oracle/xcresult/run.py` on the reference
JBR and Jackson 2.17.2; see `tools/oracle/xcresult/README.md`. Cases marked
`SCRIPTED-*` reuse WP 0.4b evidence and do not establish real bundle coverage.

run-results accumulators, CI factory and percent rounding (291 rows total).

WP 3.7: `queue/queue.jsonl` records the real Kotlin `QueueActor` message by message (19 scenarios after the
header row): replies, ordered events and queue state. Generator: `tools/oracle/queue-probes/run`; see
`fixtures/PROVENANCE.md`.

## Filters (WP 3.3)

`filters/{leaves,composition,annotation,files,allure}.jsonl` contain 144 JVM
probe rows from `tools/oracle/filter-probes/run`. They exercise the real pinned
Kotlin filters and allure-test-filter 2.29.0, including cache/call traces,
exceptions/logs and 14 DEX producer-to-filter cases. See the probe README for
regeneration, normalization and approved D6/P2 differences. Replayed by
`marathon-core/tests/{filter_edges,filters}.rs` and
`marathon-android/tests/filter_metadata.rs`.

## Run flow (WP 3.10)

`run-flow/scenarios.jsonl`: one row per core scenario input (outcome and its scheduler time, every event and device call
with time, batch and tests, raw.json text, parse output files, outputDir manifest), recorded with
`tools/oracle/run-flow-probes/capture_scenarios.py`. `run-flow/probes.jsonl`: Marathon.kt/ShutdownHook.kt/Modules.kt cases
(outputDir wipe, parse routing and logger levels, the `run` catch and exit mapping, onFinish slot failures, remote parse
retry/timeout, Koin construction failures, SIGINT/SIGTERM exit statuses); `run-flow/parse-command.jsonl`: the four
MarathonTestParseCommandTest files' exact bytes; both from `tools/oracle/run-flow-probes/run`. Regenerate into a scratch
directory and `cmp`; the scenario manifests and raw.json of `all-lost` carry host wall-clock values, normalized by the tests.
