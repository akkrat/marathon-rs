# WP 8.6b: Plain error wording instead of Java class names

Effort **M**. Branch `wp/8.6b-plain-error-wording`, based on `main` after WP 8.6a (commit `e70682a0`).

## Why

WP 8.6a gave every failure a typed kind (`marathon-error`, `docs/design/errors.md`) but kept the
rendered text byte-identical: each kind type still has a `legacy_class()` that prints the Java class name
(`java.io.IOException: …`, `com.malinskiy.marathon.exceptions.DeviceLostException: …`). PLAN.md §3.12 lets
Phase 8 drop such JVM artefacts from output. This WP replaces them with plain wording and deletes the
mappings.

## Scope

1. **Wording.** Each kind gets a short plain description through `Display` (for example `I/O error`,
   `file not found`, `timed out`, `device lost`, `ADB request rejected`, `SSH authentication failed`).
   - Rules: lower-case noun phrase, no Java/Kotlin package or class names, no `Exception`/`Error` suffix
     jargon. Kinds that rendered differently before stay distinguishable after (no two kinds share a
     description unless they mean the same thing to a user; say which if you merge any).
   - A failure renders as `<description>: <message>`, or `<description>` alone when the message is
     `None`, exactly the shape `to_java_string` had. `to_java_string` becomes `Display` for `Failure`;
     `stack_trace` keeps its structure (`Caused by: ` lines, frame text) with the new first lines.
   - `External(String)` keeps rendering its verbatim external class name.
   - Every `legacy_class()` is deleted. Afterwards Java class names exist in production code only where
     they are external text or a recorded-input format (below).
2. **Embedded debug text.** Messages that embed `{:?}` of a `Failure` or another error type in
   user-visible text (8.6a's reviewers saw one in the SSH clock-error fallback; grep for others) use the
   `Display` rendering instead.
3. **Recorded inputs stay as they are.** Replay tapes, scenario files and JVM oracle fixtures contain Java
   class names; they are copied fixtures. The recorded-input whitelist
   (`marathon-test-support/src/recorded_errors.rs`) keeps parsing those names into kinds; it becomes the
   one place that knows them. Its round-trip test becomes "every whitelisted name parses to a kind, every
   recordable kind has a name".
4. **Tests and oracles.** Tests that pin rendered text get the new text. Oracle suites that compare Rust
   output with JVM-recorded text must keep comparing meaning: parse the JVM class name through the
   whitelist and compare kinds (plus messages as today), rather than editing fixtures or weakening the
   assertion. Describe the approach in the design stop.
5. **`config-dump`.** The hidden `marathon config-dump` writes `"class"` in its error JSON
   (`crates/marathon-cli/src/config_dump.rs`, `docs/design/config-dump-format.md`), compared against the
   JVM oracle dumps and the native config corpus golden. Propose in the design stop how this field
   changes (for example a stable kind identifier with the oracle comparison going through the whitelist)
   and what that does to the corpus golden.

**Out of scope:** external text (instrumentation stack and `shortMsg`, runner output, logcat, XCTest and
xcresult text keep their class names), logger names, the pinned progress/summary log lines (they carry
no class names; confirm), exit codes, `KotlinValue`, YAML writing.

## Rules

- Never edit a copied fixture under `fixtures/`; add new files instead. Golden files under
  `fixtures/contract/` are re-blessed only through the documented tools, never by hand.
- List every changed test file in `docs/wp/8.6b-test-changes.md`, naming any test whose assertion changed
  beyond the new wording. Parity rows of deleted tests become `n/a` with reason `8.6b: D59`.
- Keep `//! Port of ...` headers and comment density; drop comments that only explained a class name.
- No `unwrap()`/`expect()` on I/O, process or network results.
