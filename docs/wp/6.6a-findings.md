## Decisions and boundary

- P1: constants and the cheap adam command-builder surface are implemented;
  no general on-device test-access client/server. Protobuf remains omitted under
  6.3's existing decision. `-f` serialization is retained.
- P2: approved cleanup is implemented as D15. Remote accumulators unregister on
  success, fallback, timeout, error and cancellation; owned instrumentation
  producers cancel/join even when an after hook throws. Kotlin witnesses show
  leaked registrations/connections before bounded harness teardown. Exception
  precedence is unchanged: a failing after hook wins over an earlier failure.
- P3: rejected. Invalid suffixes omit generated console/gRPC args; valid signed
  Ints and console+3000 wrapping remain. Prefix-only local-emulator detection
  ignores the adb endpoint host. Existing user keys retain their insertion slots.
- Q1: the injected executor owns listener construction and exception translation.
  The 6.5 Device wrapper only dispatches off core. Its public classification helper
  remains compatible; translation is applied once, including creation failures.
  The provider's identity lookup and stable bundle handles avoid core downcasts.
- Q2: an additive fallible compat adapter preserves existing infallible clients.
  Leaf conversion/transport failures remain typed errors, never empty successes.
  Transformer warnings are drained to the device logger, including on failure.
- Q3: all four shared-log rows remain Android integration tests using core's
  existing LogListener/AttachmentCollector. No second log writer was introduced.
- Q4: injected recorder, screen-capture, file-sync and profiling slots retain
  Kotlin callback order. Missing enabled services fail explicitly. A screen
  capture metric also fails explicitly until its slot is supplied. Disabled
  services allow the focused CLI evidence. No production factory uses the
  pending executor or remote-parser placeholder.
- Q5: effort H was already recorded. N1/N2/N3 stay under D5; N35, N38 and N39 are
  retained; the approved resource-only N36/N37 correction is D15.

## Consumer API for 6.6b

`AndroidRunnerExecutor { slots: ListenerSlots }` implements `AndroidBatchExecutor`.
`create_services_with_executor` remains the explicit injection seam. Each
`AndroidListenerFactory` creates a fresh `InstalledListener` and optionally an
attachment provider, registered before callbacks. Callback order is recorder →
log adapter → results → debug → screen capture → file sync → profiling. Provider
registration retains recorder → profiling → logcat → screen order.

`AndroidTestRunListener` uses the existing typed adam TestEvent enum plus separate
before/after hooks, rather than duplicating its payloads in twelve Rust methods.
Run-start events use the caller's fixed `AdamTestRun` name. Its `_in` callbacks
receive the explicit VendorContext; suspending listeners must observe that child
signal and finish their cleanup before returning. Composite forwards it without
racing/dropping a callback. Before/events run in the batch timeout's context;
after runs outside it. Core listener adapters retain their awaited file work.
The JVM and Rust suspended-hook probe pins cancellation → hook cleanup → failure
notification → after order.

`AndroidDevice::reference()` retains provider identity through execution results;
`listener_counts()` is an in-memory lifecycle diagnostic. The remote parser
uses the provider's existing identity registry. Installation, APK reading,
transport and callbacks run on vendor workers; blocking APK/file work uses the
existing blocking bridge. No new blocking core work was introduced.

Instrumentation owns one pull-based transport plus a joinable device-scoped
producer. The source has two channel producers. Rust closes the owned transport
and joins its producer under P2; it deliberately retains the source's separate
consumer-close versus producer-failure behavior (N38). Only stdout enters the
transformer; shell-v2 exit/stderr and CMD/ABB/sync features cannot change request
selection. The default request socket-idle timeout is signed Long.MAX_VALUE,
including N12's conversion. Normal close alone finalizes the transformer.
