**F5, the parity backlog gaps:**
- **Keep-alive semantics.** russh resets its miss counter and timer on incoming traffic, while sshj tracks unanswered request promises. So output that keeps flowing while probes go unanswered gives different worker-loss behaviour. Measure it, and record it as a parity item or a deviation candidate.
- **R3, known_hosts.** Several differing keys of the same algorithm, whitespace, host-name case, wildcards and negation. sshj accepts any matching key, while russh fails on a differing entry of the same algorithm even when another entry matches.
- **R6, streams.** UTF-8 and CRLF split across boundaries, asymmetric output resetting the shared idle clock, and backpressure from a stalled consumer. Kotlin decodes reads of up to 16 KiB from two independent readers, while the Rust spike decodes SSH packets.
- **Unmeasured cases:** cancelling the exit wait, the `isAlive` snapshot taken at construction (A11), exec-request rejection, explicit disconnect reasons, and a failed key exchange.
- **Logging rules:** ERROR unless `ssh.debug`, and the secrecy of `WriteFile`. Not yet observed.

**For WP 4.2:** Muse drafted an SSH parity checklist. After these fixes it goes into WP 4.2's brief.

**R2 deviation:** D7 is approved by the user: suppress the single stale TERM request after a non-TERM exit. The following close is a no-op.
