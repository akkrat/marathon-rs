# WP 8.10: `clap` instead of the Clikt emulation

Effort **M**. Branch `wp/8.10-clap`, based on `main` after WP 8.9 (commit `64f286ee`). WP 8.11 runs in
parallel; whichever merges second rebases.

## Why

`crates/marathon-cli/src/args.rs` is a hand-written parser that reproduces Clikt 5.0.0's observable
behaviour (token rules, Jaro-Winkler suggestions, grouped error reports, usage lines, 79-column help
layout). WP 2.5 chose that because every visible text was pinned. PLAN.md §3.12 point 2 now keeps only
**the CLI subcommands, flags, defaults and exit codes; help, usage and error wording may change.** So the
standard parser can do the job.

## Keep (contract)

- The surface of PLAN.md §3.1: root `marathon [-m|--marathonfile F] [--analyticsTracking B] [--bugsnag B]`
  runs when no subcommand is given; `run` with the same options; `parse [-m|--marathonfile F]
  [-o|--output NAME] [-f|--include-flaky-tests B]`; `version`. Same defaults (find them in `args.rs`,
  including the default Marathonfile name).
- Root options are **not** passed down to subcommands (`marathon -m x run` keeps rejecting or ignoring `-m`
  exactly as today: find out which and keep it).
- Boolean values keep Kotlin `String.toBoolean()` meaning: `true` in any case is true, **anything else is
  false, not an error** (a custom value parser).
- Exit codes for every case in the CLI matrix (`crates/marathon-cli/tests/cli_matrix.rs` and friends):
  success, help, `-h`, unknown/missing/repeated options, option placement, missing Marathonfile, config
  errors, parse with and without `-o`, `version`. Which stream (stdout/stderr) a message goes to stays
  as today for help (stdout, exit 0) and usage errors (stderr, non-zero).
- The run-outcome messages (`Marathon execution finished` and friends, PLAN.md §3.1 table) and the
  `version` output are not parser texts; they stay byte-identical.
- Repeated options: find what today's parser does (last wins or error) and keep the outcome.

## Change (allowed)

Help, usage and parse-error wording become clap's. No Jaro-Winkler emulation (clap's own suggestions are
fine). Delete the emulation and its tests that pin Clikt text; matrix tests keep asserting exit codes and
streams, and assert on stable fragments (the option name, "unexpected argument") rather than full Clikt
texts.

## Rules

- Add a **D61** row to PLAN.md §3.11: rc.1 prints Clikt's help, usage and error texts (79-column layout,

  meaning and exit codes are unchanged. Update PLAN.md §3.1's "The parser is hand-written to reproduce
  Clikt 5 behaviour…" bullet with a "superseded by D61" note (do not rewrite history). Remove the
  later-candidates bullet "`clap` instead of Clikt emulation."; add the §7 row
  `8.10 | clap instead of the Clikt emulation (docs/wp/8.10.md) | M | 8.9`. Keep

  `docs/wp/8.10-test-changes.md`. Parity rows of deleted tests become `n/a` with reason `8.10: D61`.
- Native goldens and the config corpus must pass unchanged (`git diff 64f286ee -- fixtures/` empty); if a
  golden pins CLI help or error text, stop and report.
- Keep `//! Port of ...` headers; delete comments that only explained Clikt behaviour.
- No `unwrap()`/`expect()` on I/O, process or network results.
