# WP 8.16: Plain image handling instead of the ImageIO/AWT emulation

Effort **M** (decided at the design stop). Branch `wp/8.16-image-emulation`, based on `main` after WP
8.15 (commit `f4244c70`). WP 8.17 (a design) runs in parallel.

## Why

Screenshots already use the `image`, `gif` and `png` crates, but the code still reproduces Java
ImageIO/AWT behaviour on top of them:

- `crates/marathon-adb/src/client/framebuffer.rs`: adam's framebuffer decoding converts through the
  JDK's bundled ICC profiles (`fixtures/adam/colorProfiles/sRGB.icc`, `DisplayP3.icc`), including
  `setRGB` quantization into the profile's 8-bit raster before `getRGB` converts back to sRGB.
- `crates/jcompat/src/report_text.rs` `awt_nearest_index`: AWT `ScaledBlit` nearest-neighbour sampling
  in 32-bit fixed point, used when scaling frames.
- `crates/marathon-core/src/screenshot.rs`: the `GifSequenceWriter` port (frame timing, loop and
  disposal metadata) and rotation; `crates/marathon-android/src/artifact_listeners/screenshot.rs` and
  `adam_capture.rs`; iOS image handling in `marathon-ios` (check `apple_simulator_device`).

PLAN.md §3.12 keeps result paths, names and data; images "compare as today" (bytes). So any change to
pixels, palette, metadata or encoding changes a result file and needs a D-row and a reviewed golden
update.

## Scope: decide at the design stop

1. **Inventory** every ImageIO/AWT/JDK behaviour still emulated (profile conversion, quantization,
   scaling arithmetic, GIF palette and metadata, PNG chunks, rotation), where it lives, and which tests
   and goldens pin it.
2. For each, propose: keep (and why), or replace with the plain crate behaviour (`image`'s resize filters
   or a plain nearest-neighbour, the `gif` crate's own quantizer and metadata, colour conversion without
   the JDK profiles or with a maintained colour crate), and what changes in the output bytes.
3. Recommend a set, with a D-row draft, and measure its golden impact with a prototype: which native
   views and files change, and whether the change is visible to a person looking at the screenshot or
   GIF (pixel difference statistics, file size, frame count and timing).

**Keep regardless:** result paths and names, the GIF's configured width, height, delay, loop and frame
order (PLAN.md §3 line about `GifSequenceWriter`), Allure/HTML references to the images.
