`buffered` is the only changed shared test helper. It still decodes twice,
checks dimensions, compares copied PNG pixels within the existing one-level
bound and verifies PNG roundtrip; it keeps old hashes for unaffected fixtures
and asserts direct source equality for explicit sRGB. New helper `packed_pixel`
builds local synthetic valid records; it reads no files and is used only by the
new layout/validation tests. Core adds SHA-256 as a dev-dependency for encoded
byte pins. No Android/iOS test body or test-support capture helper was changed.

## P1 review follow-up (U191)

No fixture, parity row or existing fixed-hash assertion is removed or changed.
`rgb565_colors_are_little_endian_for_both_adapters_d63` is the one modified test:
it now declares an actual RGB565 header instead of inheriting RGBA8888 fields
that the old 16-bit branch ignored. New helper `capture_sixteen_bit_header`
constructs version-1/2 and legacy-16 wire records, observes the acknowledgement,
and joins the fake socket session before returning the request result.

All four new tests are in `crates/marathon-adb/src/client/framebuffer/tests.rs`:

| Test | Coverage |
|---|---|
| `bgr565_header_decodes_blue_u191` | Reviewer's BGR565 `00 f8` probe: blue via `get_argb` and both adapters, for wire versions 1 and 2. |
| `impossible_sixteen_bit_channel_headers_are_rejected_u191` | Reviewer's impossible-bounds probe plus crossing channels, oversized offsets, invalid lengths and out-of-bounds alpha, using existing error kinds in both versions. |
| `sixteen_bit_layouts_keep_floor_scaling_alpha_and_png_bytes_u191` | Exact primary and midtone pixels plus fixed RGB565/BGR565 PNG hashes in both versions; declared ARGB4444 alpha. |
| `legacy_layoutless_images_remain_rgb565_u191` | Wire compatibility value 16 supplies fixed RGB565; a version-zero image with absent layout remains fixed RGB565; literal wire value zero remains unsupported. |

## Linux gate follow-up (U192)

No existing test, helper, deadline or assertion changes. New unit test
`crates/marathon-adb/src/client/framebuffer/tests.rs::rgba8888_copy_honors_all_channel_layout_fields_d63`
pins literal output pixels for canonical RGBA8888 and for individual changes to
each of its eight layout fields, plus absent alpha. It protects the exact-layout
copy from accidentally accepting other headers; existing fixed hashes and P3,
partial-alpha and malformed-input tests cover its other boundaries. Both failing
Android artifact tests are rerun unchanged, together with the entire test binary
and both full platform gates. The cause is excessive identity-decoding work
inside the existing capture deadline, rather than a concurrency race; there is
no timing-dependent regression assertion or widened timeout.
