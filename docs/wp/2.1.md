## Deliverables and boundary

In `crates/marathon-config` (today a 3-line stub on main; 0.6 replaces it with `binding.rs` + `schema.rs`):

1. **Production YAML front end.** Promote the spike's SnakeYAML 2.2 port (reader/scanner/parser, ~1,692 lines, Apache-2.0 attribution and `LICENSE` kept), `Node` tree, scalar resolution and token layer into the workspace crate. Keep the spike's invariants: `JavaString` (UTF-16) text, tags/anchors, duplicate entries, incomplete prefixes and `Cut`, iterative drop/walk, depth-1,001 stop, JDK `readText()` byte decoding at `load_bytes`. The corpus runners must exercise **this** code, not a second spike copy; state in findings what happens to `spikes/yaml-node` (delete, or rewire onto the crate). Do not reintroduce the saphyr baseline into production.
2. **Generic binder over `Node`.** The Jackson-databind + jackson-module-kotlin creator semantics as reusable primitives that 2.2/2.3a schema code calls field by field: constructor-parameter binding with Kotlin defaults, missing vs explicit-null vs default (`NullIsSameAsDefault=false`, `NullToEmptyCollection/Map=false`, `StrictNullChecks=false`, `SingletonSupport=true`), unknown-key rejection, duplicate keys, scalar coercion, collections/maps, enums, and polymorphic dispatch on the `type` property (`@JsonTypeInfo(Id.NAME, As.PROPERTY, property="type")`, 14 hierarchies under `C/`). No serde derives for config types (0.6 `schema.rs`: "missing/null/default rules belong to the profile binder, not Rust derives").
3. **Leaf deserializers** (the `SerializeModule.kt` + JavaTimeModule surface): `Duration` and `Instant` via `jcompat::jtime`/`jnum::Decimal`; `File` via `FileDeserializer.kt`; `Regex` via `JavaRegex` under D6 (Kotlin has only a `RegexSerializer.kt`; deserialization is the single-`String` creator). Plus the primitive/enum coercions the corpus pins.
4. **Custom-deserializer seam for 2.2.** The six lenient deserializers (2.2) call `p.codec.readTree`, recursive `findValue`, and `treeToValue` (see the three strategy deserializers under `C/serialization/yaml/`). Provide the equivalents over `Node` now — bind-subtree as another type, depth-first `find_value` in document order, ignore-unknown-keys mode — with tests, so 2.2 does not reopen the binder.
5. **P1 pipeline shape, split from post-processing.** Bytes → JDK decode → `StringSubstitutor` (WP 1.3; its `IllegalStateException` cycle stays **outside** the `ConfigurationException` wrapper, PLAN §3.2) → bind first document → wrap binding failures as `ConfigurationException("Error parsing config file <absolute path>", cause)` (`ConfigurationFactory.kt:200-202`). Error type follows 0.6 `binding.rs` `ConfigurationError` (stage, Jackson class name, `causes`, key path, span); wording is ours per §3.10, stage/path/cause are not.

**Not 2.1:** any concrete schema fields or defaults (top-level/strategies/filters/analytics → 2.2; vendor configs, derived defaults, SDK lookup → 2.3a); the six lenient deserializers themselves (2.2); Apple `bundle.validate()` extraction, devices/`knownHostsPath`/SSH-key re-resolution, `xcresult.pull` → `pullingPolicy`, tracking-flag merge (the post-binding half of `ConfigurationFactory.parse` → 2.3a/b and 2.4 behind 0.6 `VendorConfigurationHooks::post_process`); logical validation and `toMap()` (2.4); P2 Marathondevices schema and frame decoder (2.3b — but the binder must be **parameterised** so P2 can run without `File`/`Instant`/`Duration` deserializers); P3 YAML emission (1.5 writers; `Configuration.serialize` wiring lands with 2.5/3.9b); CLI (2.5); the full differential suite (2.6).

## Binding cases carried from 0.3b (required tests, not background)

`docs/wp/0.3b-findings.md` §"Round 3: carried to WP 2.1", witnesses in `fixtures/oracle/yaml-round3-corpus.jsonl` (28 JVM-generated rows × 13 targets; 27 currently `binding_expected_fail`). Acceptance: those 27 rows **pass** against the production binder and the marker is retired; the three corpora together stay at 2,852/2,852 tokens with no binding regression.

- **R3-sol-2** creator timing: duplicate-field assignment and exception precedence, e.g. `"k: null\nk: x"` → `MissingKotlinParameterException`, `"k: x\nk: null"` → `null`, and `"k: null\nz: ["` fails on the null before the later parse error. Null-for-non-null-parameter is raised when the creator runs, not deferred to bean completion (the spike's known divergence).
- **R3-sol-3 / R3-muse-3** enum ordinals from strings are ASCII-gated: `"+1"`, `"01"`, `"-0"`, `"١"`, `"１"` → `InvalidFormatException`, never an ordinal.
- **R3-sol-4 / R3-muse-1** decimal-token `Instant`/`Duration` precision and wrapping: `0.99999999999999999` keeps nanoseconds (`PT0.999999999S`), `1e309`/`1e1000` → epoch/`PT0S`, `9223372036854775808.0` wraps the `Duration` sign. (Simplification P2 proposes changing the overflow half; until approved these rows are binding.)
- **R3-sol-5 / R3-muse-2** quoted `Instant` recogniser: only unsigned plain decimals are epoch strings — `"-1"`, `"+1"`, `"1e1"`, `"-1.0"`, `"9223372036854775808"` → `InvalidFormatException`.
- **R3-sol-6** absolute `File` paths bypass canonicalisation: `"/a/../b"`, `"/."`, `"/../x"` are kept verbatim (relative paths canonicalise, R3-sol-6 vs `FileDeserializer.kt`).
- **R3-sol-7** `!!binary` `File` uses the original scalar text, validated as path text: a NUL fails (`JsonMappingException`), an embedded newline survives into the path.
- **R3-sol-8 / R3-muse-4** empty/blank scalar-root documents (`""`, `" "`) → `InvalidFormatException` for all 13 targets, not `MismatchedInputException`.

Also binding from earlier rounds, already in the corpora: Java-trim before empty/null/Boolean coercion (R2-S4), `File` validates NUL/lone surrogates only on the path branch (R2-S5), and every text-bearing scalar rendered from `JavaString` (R2-S6).

## Jackson/Kotlin behaviours to reproduce (with sources)

Mapper defaults are marathon's *unsets* in `ConfigurationFactory.kt:30-49`: `FAIL_ON_UNKNOWN_PROPERTIES=true`, `FAIL_ON_NULL_FOR_PRIMITIVES=false`, `FAIL_ON_NUMBERS_FOR_ENUMS=false`, `ALLOW_COERCION_OF_SCALARS=true`, `FAIL_ON_TRAILING_TOKENS=false` (`docs/research/yaml.md` §2, probe-verified). Concretely:

- **Coercion** (yaml.md §2 table): quoted number → number, any scalar → `String` keeping raw spelling (`017`, `0x1F`), float → int truncates, bool → int is rejected, number → boolean (`1` → true) while string → boolean accepts only `true/True/TRUE/false/False/FALSE`, `""` → `0`, scalar → collection is `MismatchedInputException`. `.inf`/`.nan`/sexagesimal tokenise as floats but fail to bind; `0o17`, `08`, `1:20` stay strings (then string-coercion rules apply).
- **Null rules** (PLAN §3.2): Kotlin primitive field ← `null` ⇒ zero value even with a default; non-null reference ← `null` ⇒ rejected; nullable/collection/map ← `null` ⇒ `null`, never empty. **Read the warning in yaml.md §2: these Kotlin deltas were inferred from module flags, not probed against a Kotlin data class.** Generate the missing oracle rows with `tools/oracle` before freezing the rules; do not port the spike's Java-bean assumptions blind.
- **Unknown keys** are `UnrecognizedPropertyException`, including `<<` (an ordinary key; no YAML merge on the Jackson path, yaml.md §1.4). The only lenient sites are the six 2.2 deserializers via the seam above (F3: `readOnly` dropped there).
- **Duplicates and documents:** last duplicate wins subject to R3-sol-2 timing; the binder consumes the first document only; a leading empty document makes `readValue` return `null`, which in Kotlin escapes the catch and crashes on `configuration.copy(...)` (`ConfigurationFactory.kt:57,192`) — reproduce the crash-vs-`ConfigurationException` staging, not just "an error". Empty/comment-only input is `MismatchedInputException` **inside** the wrapper.
- **Aliases** bind as their anchor-name strings, dangling aliases included, with no expansion and no error (yaml.md §1.4). Non-scalar mapping keys are a hard error in object context.
- **Enums:** case-sensitive names; integer and string ordinals accepted (subject to R3-sol-3). `@JsonCreator` exceptions exist downstream (`vendor/android/SerialStrategy.kt` uppercases with `Locale.ENGLISH`; the two `preferableRecorderType` enums) — the binder needs a per-enum creator hook, the enums themselves are 2.3a.
- **Polymorphism:** `type` may appear after other keys and still dispatches; an unknown `type` is an error at that node, and singleton subtypes (e.g. `StubVendorConfiguration`, `Configuration.kt:18` `@JsonDeserialize(builder=…)`) bind through `SingletonSupport` and the Builder pattern, not a primary constructor. 2.1 owns the mechanism incl. buffering a mapping until `type` is known; 2.2/2.3a own the subtype tables (`VendorConfiguration.kt:44-55`, incl. `watchOS/tvOS/visionOS` → iOS).
- **`Duration`/`Instant`** (JavaTimeModule, no marathon code): ISO-8601 strings, and bare numbers as epoch **seconds** with decimal nanoseconds (R3-sol-4/5). Reuse `jcompat::jtime`; any gap in `jtime` is fixed in `jcompat` with oracle rows, not patched around in the binder.
- **`File`** (`FileDeserializer.kt`): driven by `p.valueAsString`, so number/bool tokens coerce through their spelling first. Relative ⇒ `canonicalFile` against the Marathonfile dir — real filesystem semantics (`.`, `..`, symlinks of existing prefixes); `jcompat::file_manager::JavaPath` does **not** canonicalise today, so this needs new checked code and temp-dir tests, no `unwrap()` on I/O (CLAUDE.md).
- **`Regex` fields** are everywhere downstream (`Configuration.kt:39-40`, `FilteringConfiguration.kt`, `vendor/apple/TestParserConfiguration.kt:16`) and equality compares `pattern` strings. Under D6 compile with `JavaRegex::compile(pattern, field)`; a rejected pattern fails at load naming pattern and field. The Apple built-in default `"^((?!Abstract).)*Test[s]*$"` must stay distinguishable from an explicit user pattern (WP 1.4: retain `DEFAULT_TEST_CLASS_PATTERN`, compile only explicit values).
- **Substitution staging:** `StringSubstitutor.replace` runs on the whole text before binding and outside the try (`ConfigurationFactory.kt:55-57`); undefined ⇒ literal, cycle ⇒ unwrapped `IllegalStateException` (WP 1.3 keeps class and message).

## Proposed simplifications (pragmatic parity — for orchestrator approval, **not decided**)

Per the user's direction: few users, do not emulate quirks only exotic inputs reach; D6 (`regex` crate) and D8 (en-US) already apply. Until one is approved, the binding cases above stand and a divergence is a bug. Each approved item becomes a `docs/deviations.md` entry and its corpus rows are marked, not silently dropped.

- **P1, duplicate-key timing (R3-sol-2):** plain last-wins, then validate nullability, instead of creator-time precedence. Diverges only when a duplicated key carries `null` in a specific order, or masks a later syntax error.
- **P2, numeric overflow (R3-sol-4, R3-muse-1):** reject out-of-range epoch/duration numbers with a clear error instead of reproducing wrap-to-epoch/`PT0S`/sign-wrapping. Keep in-range nanosecond precision exact.
- **P3, absolute-path spelling (R3-sol-6):** canonicalise absolute `File` paths too. Diverges only in retained `/a/../b`-style spellings in logs, `toMap()` and output JSON.
- **P4, error-class fidelity (R3-sol-8, R3-muse-4):** one binder error kind with §3.10 wording instead of distinguishing `InvalidFormatException` vs `MismatchedInputException` for scalar-root/blank documents. Affects 2.6's class-name comparison, not accept/reject.
- **P5, non-ASCII digits in coercions:** ASCII-only digits when re-parsing quoted numbers/ordinals at bind time (Arabic/fullwidth digits already rejected for ordinals). The scanner/token layer keeps full Java digit behaviour.
- **P6, lone surrogates below the `Node` layer:** field names and map keys in schemas are ASCII; propose requiring valid UTF-8 when a scalar is used as a key, `File` path or regex (already the `File` rule), keeping lossless `JavaString` only for string values that flow to output.
- **P7, dead code:** do not port `MutableConfigurationFactory.kt` or `FileListProvider.kt` (no callers at `e47352f2`); set their inventory rows `n/a` with that reason (needs reviewer agreement per CLAUDE.md).
