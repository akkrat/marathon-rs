# WP 8.2: native strings

Models, configuration values, worker commands, reports, and borrowed APIs now use `String` and
`&str`. The former string wrapper and its encoding/construction methods are deleted. `JavaPath`
remains the path representation, with conversions at its boundary. D55 records the malformed-input
and supplementary/BMP ordering changes; C22 is fixed. C21's path truncation and C23's YAML style
quirks remain.

## Input boundaries

| Boundary | Handling |
| --- | --- |
| YAML quoted scalars, including keys | Accumulate escaped UTF-16 units for the complete scalar, then decode lossily. Adjacent valid surrogate escapes combine before replacement. |
| JSON and xcresult | `jackson::json_string` decodes a complete string. `normalize_json_strings` replaces lone escapes before native JSON readers, including keys, in xcresult, simctl, Allure plans, and analytics replies. Valid pairs and literal escaped backslashes remain unchanged; six-byte escape widths preserve diagnostic positions. |
| XML plists | UTF-16LE/BE input and numeric character-reference sequences decode lossily. Complete scalar reference sequences preserve valid pairs. Existing encoding declarations, XML controls, and other validation remain. |
| Binary plists | Normalize only UTF-16 string objects, including dictionary keys; preserve object lengths, offsets, valid pairs, and opaque data. Preflight the layout before mutation and leave malformed layouts to the existing parser. |
| DEX and process bytes | Retain the existing replacing UTF-8 decoders, returning native strings directly. DEX deliberately keeps Kotlin's existing wrong UTF-8 interpretation of MUTF-8: encoded NUL and supplementary MUTF-8 sequences already produce replacements. AXML's existing REPORT-mode rejection remains, since those malformed strings never entered the model. |
| DEX character metadata | A `Char(u16)` still models a Java character; projection into a string uses lossy decoding. Character arrays decode together, preserving pairs. |

## UTF-16 operations retained

- `file_manager`: `JavaPath`, path normalization/joins, `Utf16FileRequest`, filename/maxPath limits,
  and path diagnostics. `path_diagnostic` preserves `?` for a pair split by generated truncation.
- `jstring::take_utf16`: HTML and Android output-name limits and the instant-parser diagnostic
  abbreviation. Native Kotlin whitespace, trimming, letter predicates, and CR/LF line splitting
  remain in `jstring`; unused unit-based trim helpers are gone.
- YAML emitter columns/wrapping and explicit-key limits, Jackson's supplementary-character escapes,
  Logback abbreviation, instant parser indices, Java numeric/string hashing semantics, and CLI typo
  scoring still use units where their measured contract requires them.
- SnakeYAML reader offsets, Android length-framed annotation parsing and property error indices,
  ADB protocol length checks, and filesystem-snapshot path ordering retain their measured units.

Fragmentation uses `signed_md5` over the original UTF-8 test name; Allure hashes the class bytes
followed immediately by method bytes, without a separator. The removed `signed_md5_utf16` has no
production or test callers. Existing valid-Unicode hash oracles remain exact, supplemented by fixed
supplementary-character Allure digests.
