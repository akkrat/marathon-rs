## Behaviour to reproduce

- **Influx v1 setup** (`A/external/influx/InfluxDbProvider.kt:19–52`): 60 s **connect/read/write** timeouts, auth only when **both** user and password are nonempty, BASIC logging only for debug. Check database existence; **only if missing**, create DB then retention policy with configured name, duration, shard duration, replication and default flag. An existing DB with absent/wrong policy is not repaired. Set selected DB/policy and enable batching even for readOnly/history-only use. Probe the pinned library for exact check/create requests, quoting, batch thresholds/interval/buffer/failure retry and close-flush behaviour; Kotlin's `enableBatch()` does not specify those defaults.
- **Influx v2 setup** (`A/external/influx2/InfluxDb2Provider.kt:24–67`): same three 60 s timeouts, token auth and default org/bucket, BASIC/NONE debug setting. List organizations and select exact-name matches in returned order; none throws `Influxdb2Exception("No organization with name = $org found")`; several warn `Multiple organizations with name = $org found. Using first one, id = …`. Look up bucket by name; create only when absent with the selected org and both retention fields (`everySeconds`, `shardGroupDurationSeconds`), preserving the creation INFO line and Kotlin retention-policy text. Never update an existing bucket's policy. Setup occurs even readOnly. Record lookup pagination/parameters and bucket JSON from the actual library, not a generic REST sketch.
- **Influx v1 tracker** (`A/external/influx/InfluxDbTracker.kt:18–45`): readOnly returns; only FAILURE/PASSED write `tests`. Time is **event instant** in milliseconds; tags in source are testname/package/class/method/deviceSerial, using safe test name and safe serial. Fields ignored/success are doubles; duration is a Long. Preserve actual library line escaping/order and request precision, DB and retention policy. Close calls the client (draining the batch); write/close errors have no tracker catch.
- **Influx v2 tracker** (`A/external/influx2/InfluxDb2Tracker.kt:17–65`): lazily get blocking WriteApi only at first non-readOnly event; **all statuses write**, including INCOMPLETE despite the comment. Same tags, event time with `WritePrecision.MS`, ignored double, duration **double**. Failure success=0; passed/ignored/assumption-failure success=1; incomplete has **no success field**, but still has ignored and duration. Catch **InfluxException only**, log ERROR `Failed to write data point to InfluxDb2`, continue; other failures and close propagate. Neither tracker filters on `final` — retries/nonfinal events are written too. Characterize HTTP/parse/transport error classification with JVM probes so the catch does not swallow cancellation or unrelated errors.
- **Graphite writes** (`A/external/graphite/GraphiteTracker.kt:15–53`, `BasicGraphiteClient.kt:17–77`): readOnly and status gate match v1. One send per event, three lines ordered **ignored, success, duration**. No additional sanitation. Format `<path> <value> <timestampMillis / 1000>\n`, Java signed division truncating toward zero. Single metric and nonempty collection each invoke sender once; empty collection opens no socket. Each send opens/writes/closes its own connection; default carbon port 2003 belongs to `TrackerFactory.kt:86–88`. UnknownHostException becomes `GraphiteException("Unknown host: $host")`; IOException becomes `GraphiteException("Error while writing data to graphite: ${e.message}")`. **PrintWriter can suppress write errors**, and SocketSender sets **no 60 s timeout**: do not accidentally apply the HTTP timeout to carbon. - **Graphite reads** (`A/metrics/remote/graphite/QueryableGraphiteClient.kt:14–33`): query construction has no network effects; GET `http://host:port/render?target=<Java UTF-8 form encoded target>&format=raw&from=<HH:mm_yyyyMMdd UTC>`, using merged `format_graphite`. ## Proposed simplifications (orchestrator approval required; not decided)

The user's pragmatic-parity direction favours few-user inputs over exotic emulation. Until approved, source behaviour and PLAN gates stand; record approved differences and retained oracle witnesses in findings/deviation documentation.

- **P1 — no-container default gate:** use JVM-recorded exchanges + stateful fake HTTP/TCP peers for Linux/macOS gates and all matrix ports; keep real-service tests as an explicit qualification command. This proves lifecycle/wire/error behaviour without Docker but does not prove Influx aggregation/retention or Graphite ingestion. Orchestrator must decide whether real-service evidence is still required before merging 3.4b (PLAN §3.8/§6.3), or deferred with an explicit owner/gate; never mark an unrun container test as passed.
- **P2 — Java client implementation artefacts:** match functional headers/auth/encoding/payloads, configured deadlines, observable retries/batches and error catches; omit exact User-Agent/library-specific debug HTTP timing text, connection-pool reuse and malformed-response exception wording unless an actual caller/output relies on them. Logs are external under §3.5: this needs express approval, not an inference from D4. Keep setup's custom messages and v2 tracker ERROR exact.
- **P3 — pathological carbon faults:** propagate async socket write failures instead of recreating PrintWriter's suppressed errors; allow cancellation to interrupt a stuck send while keeping no production carbon timeout. Diverges only on broken/blocked peers; probe first, record the divergence and keep normal one-connection/ordered-line semantics. Do not silently bundle this into the HTTP rewrite.
- **P4 — exotic text/URL inputs:** extend 3.4a's approved Graphite host/prefix UTF-8 boundary to backend write tag/path/config text and support normal absolute HTTP(S) Influx URLs, rejecting lone surrogates/unusable URL forms clearly rather than emulating Java replacement/OkHttp permissiveness. Keep ordinary Unicode, punctuation escaping, query interpolation C40 and all committed URL observations. List exact rejected forms and error/fallback timing before approval; no new broad input restriction by default.
