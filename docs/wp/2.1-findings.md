## Delivered boundaries

- `crates/snakeyaml` contains the promoted SnakeYAML 2.2 reader/scanner/parser,
  its Apache-2.0 attribution and LICENSE, the Node tree, resolver and Jackson
  token walker. `spikes/yaml-node`, including its prototype binder and saphyr
  baseline, is deleted. Historical spike reports remain historical evidence.
- Node/Mark/Span are re-exported from `marathon-config::binding`; the old opaque
  location placeholders are aliases to the real types. Text uses the existing
  jcompat JavaString; production string and field tokens also use JavaString.
  Numeric tokens retain a parsing spelling alongside authoritative UTF-16 text.
  Depth limits, partial prefixes, duplicate entries, tags, anchors, iterative
  destruction/walking and JDK byte decoding are preserved.
- `binder::{Binder, Value, Object, Field}` provides synchronous primitives and
  handwritten schema composition. No serde config models, reflection registry,
  second clock, concrete Configuration defaults, or vendor processing is added.
  A schema function is also its deserializer registration: pass it to `bind`,
  `list`, `map`, `polymorphic` or the pipeline. The context selects profile leaf
  support; P2 has no JavaTimeModule or Marathonfile-relative File resolver.
- File binding resolves existing symlink prefixes for relative paths and retains
  absolute dot components (P3 rejected). Standard Unix File slash normalization
  uses jcompat; absolute paths are never canonicalized.
- `read_tree` materializes Jackson tree values (numeric spellings, duplicate
  replacement in insertion order), `get` selects a direct child, `find_value` prefers a direct hit then searches
  child containers in insertion order, and
  `Tree::bind`/`Value::bind` implement treeToValue/subtree binding. Tree building
  and lookup are iterative. Unknown fields can explicitly be ignored while
  still validating their token streams.
- `pipeline::bind_bytes` performs decode → substitution → first-document binding.
  Binding failures become ConfigurationException with the original class/cause
  chain, field/index path and span. Substitution cycles and null documents are
  distinct unwrapped outcomes. `ConfigurationLoader` and vendor hooks retain the
  0.6 signatures; a complete loader awaits 2.2/2.3 schemas and post-processing.
  Binding runs on a dedicated 32 MiB stack. The worker join and File
  canonicalization are blocking; this synchronous pipeline must still be
  called off the core executor as documented in the public API. The closure
  and result must be Send; they may borrow from the caller (scoped thread).

## API sketch

A schema loops through source-order fields and assigns typed creator slots.
The public constructors state Kotlin null policy; `Field::new` is private:

- `Field::primitive(&parent, default: T)` — missing keeps the schema default;
  explicit null becomes primitive zero (`T::default`), even if the schema
  default is nonzero. Finish with `required(name)`; a required primitive with
  no Kotlin default uses zero as its supplied default.
- `Field::reference(&parent, default: Option<T>)` — missing keeps the default;
  `None` means no default. Explicit null replaces any default and fails at
  `required(name)`. Required references are checked after assignment (D9).
- `Field::nullable(&parent, default: Option<T>)` — missing keeps the default;
  explicit null becomes `None`. Finish with `optional()`.

Strict primitive methods (`int`, `long`, `double`, `boolean`) already coerce
null to zero. Wrap them with `Value::nullable` for nullable primitive fields.
Unknown fields call `unknown(false)`; the six custom deserializers may use true.

```rust
use marathon_config::binder::{Field, Result, Value};
use jcompat::writers::JavaString;

struct Section { name: JavaString, count: i32, limit: Option<i64> }
fn bind_section(v: Value<'_>) -> Result<Option<Section>> {
    v.nullable(|v| {
        let mut name = Field::reference(&v, Some("default".into()));
        let mut count = Field::primitive(&v, 7);
        let mut limit = Field::nullable(&v, Some(10));
        let mut object = v.object()?;
        while let Some((key, value)) = object.next_field()? {
            match key.as_str() {
                "name" => {
                    let bound = value.string()?;
                    name.set(value, bound);
                }
                "count" => {
                    let bound = value.int()?;
                    count.set(value, Some(bound));
                }
                "limit" => {
                    let bound = value.nullable(|v| v.long())?;
                    limit.set(value, bound);
                }
                _ => value.unknown(false)?,
            }
        }
        Ok(Section {
            name: name.required("name")?,
            count: count.required("count")?,
            limit: limit.optional(),
        })
    })
}
```

`Value::nullable` is the canonical nullable-composite adapter. Keep object
schemas `Result<Option<T>>` as above; `object()` is the non-null object cursor
inside that adapter. Nested sections assign the returned Option directly to
`Field`, letting `required`/`optional` enforce the same policy as leaves.
`polymorphic` also returns `Result<Option<T>>`; its dispatch closure returns
`Option<Result<T>>` (`None` means unknown id). Only the occurrence of `type`
consumed for dispatch is hidden. Other occurrences reach subtype binding;
null/container occurrences before a usable id are buffered, not consumed.
Singleton schemas return their shared value; builders consume fields then build.

`list`/`map` preserve the element binder's result. Pass nullable schema functions
directly: `value.list(bind_section)` yields `Option<Vec<Option<Section>>>`.
This retains null elements under StrictNullChecks=false. The corrected example
in `tests/binding.rs` uses `Vec<Option<Filter>>` and a nullable `filtering` schema;
these remain test-only representations, not WP 2.2 schema implementations.

Custom deserializers use `let tree = value.read_tree()?` first. `tree.get(name)`
selects a direct child and `tree.find_value(name)` performs Jackson recursive
lookup (direct hits first, then child containers in insertion order).
Both return `Result<Option<Value>>` to retain key errors. `Value::as_text`,
`as_int`, `as_long`, `as_double`, and `as_boolean` are non-throwing JsonNode
accessors. In contrast, `int`/`long`/etc. remain strict field/treeToValue binders.
For example, `tree.find_value("size")?.map(|v| v.as_int())` handles true,
invalid text, decimal text and objects as 1, 0, truncated integer and 0.
`as_text` preserves UTF-16 text, renders null as "null" and containers as "";
`Tree::bind`/`Value::bind` remain the strict subtree-binding seam.

No disagreement with the requested fixes. Extra oracle probes resolved two
subtleties: `findValue` checks all direct fields before descending, and a null
or container discriminator before a usable discriminator is buffered and later
reaches the subtype as an unknown field. Thus `type: null` alone is
InvalidTypeIdException, while `type: null, type: local` is
UnrecognizedPropertyException. These are covered in both vendor and Android
parser hierarchies, alongside both duplicate orders for filtering. Five
additional JVM custom-deserializer witnesses pin discriminator visibility
through readTree, including a nested type field that must remain visible.
