## Implementation and consumer API

**Changed merged crate: marathon-apple only.** Its `lib.rs` exports five new
modules. Existing Apple command, tool and model implementations are unchanged.
No changes to marathon-core, marathon-config, jcompat, fake-worker, dependencies
or Cargo.lock.

- `apple_device::AppleDevice` is object-safe, extending Device, Screenshottable
  and LogProducer. Async operations use VendorFuture and a borrowed VendorContext.
  Setup implementations must return VendorError::DeviceSetup for setup failures.
  `execute_test_request` remains 4.8's addition, per decision 2.
- `apple_worker_id`, `apple_arch`, `SHARED_PATH` and `storage_path_for` are public.
  Concrete devices call the worker helper from their Device implementation.
  The default AppleDevice::arch reads the current ABI every time.
- `worker_commands::WorkerCommands` is the scripted/stub command seam.
  `ExecutorWorkerCommands` and the free `execute_worker_command` helper share
  safe_execute with shell/shellIdle, empty env, no workdir and host charset.
  Concrete devices delegate to the same helper; the manager holds no device.
- `remote_file_manager::RemoteFileManager::new(storage_path, udid, commands,
  logging)` captures the constant storage path. All asynchronous command methods
  take `&VendorContext` and return VendorResult; command wrappers absorb caught
  exceptions while exists/test propagate them. Optional directory and Boolean
  override arguments represent Kotlin defaults explicitly. `move_file` is the
  Rust spelling of Kotlin's `move`; `join_path` takes a slice of string args.
  Paths use strings, never Path normalization. Video and xcresult paths return
  JavaString to retain UTF-16 test names and batch IDs. Other path methods use
  String or borrowed str. The manager can be stubbed with WorkerCommands (both
  result and throwable are scriptable); no manager/device reference cycle exists.
- `apple_device_registry::AppleDeviceRegistry` is per vendor. `register` takes an
  Arc of an Apple device and returns its upcast DeviceRef; repeated registration
  is idempotent. `lookup` compares DeviceRef object identity; `remove` is
  idempotent and must be called on disposal by 5.x providers. A miss returns
  Kotlin's ConfigurationException and exact remote-parsing message. A short
  mutex protects a small vector: registry methods run off core, like parsers and
  providers. Serial numbers are never used as keys, and core's trait is unchanged.
- `apple_log_configurator::AppleLogConfigurator` takes compact_output and the
  vendor runtime. Its blocking-pool closure explicitly sets debug before calling
  the existing Apple registry configuration; no registry lock crosses await.
  The merged layouts, Jansi and six noise levels are reused.
