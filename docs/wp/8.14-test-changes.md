# WP 8.14 test changes

## 1. Unused timeout overloads

No tests changed or deleted. The workspace has no callers of the four removed
Duration overloads. Existing `runtime_oracle` and `runtime_races` cover the active
signed-millisecond scopes in `executor/clock.rs`. The Timeout.kt inventory row
still names its strategy/factory extensions; the active clock port also remains.
No Kotlin parity row refers to the removed overload module.

## 2. Bridge payload

Added in `executor/bridge.rs::tests`:
- `bridge_hides_new_cancellation_until_the_first_poll_returns`: manually gates
  dispatch, the first poll and task completion; a sent payload still waits for join.
- `bridge_exposes_cancellation_already_present_at_entry`.
- `bridge_rejects_successful_join_without_a_payload`.
- `bridge_preserves_failed_and_cancelled_joins_without_a_payload`.

All use explicit polling, with no real-time deadlines.

## 3. Dead coroutine surface

- Deleted `runtime_behavior::actor_safe_send_keeps_check_then_send_race` with
  the unused API it alone exercised.
- Updated `runtime_behavior::join_ignores_joined_failure_and_join_in_observes_caller`
  to cancel explicitly and then perform the same protected join.
- Removed `safe_send` implementations from the `support/device_actor.rs` and
  `support/queue.rs` fake actors; no scenario behavior changed.

Neither removed method has a Kotlin test row in the parity matrix, so no row
needs exemption. The Android runner's unrelated production method stays.

## 4. Completion diagnostics

Extended `runtime_review::exception_handler_only_records_unhandled_failure`
to check the single ERROR record, module target, message, failure and scheduler
time in the production output queue. Existing completion observers are now
compiled only for tests/test-support; all existing actor log checks remain.

Before the routing fix, the extended logging witness failed with
`assertion left == right failed; left: 0; right: 1` at the queue-length check.

## 5d. Timeout panic descendant coverage

Rewrote `runtime_races::timeout_panics_surface_as_failures_without_leaving_children_live`.
It now starts and observes a live timeout child before panicking, checks the child's
Parent cancellation, keeps the timeout result pending through protected cleanup
at virtual t=4, and verifies cleanup, child completion, original Runtime failure,
an unaffected supervisor and no remaining owned children at t=5.

The strengthened witness passed against the existing timeout implementation
before any timeout code change: `test result: ok. 1 passed; 0 failed`.
`RuntimeJob::finish_body` already cancels descendants and the scope joins their
cleanup. This was a test coverage defect, not an additional product defect; no
production timeout fix or new U-number is needed. All timing is virtual.

## Review P2. Future destruction hand-off (U189)

Added in `executor/tracking.rs::tests`:

- `pending_drop_hand_off_never_reads_as_idle` (woken pending future).
- `suspended_drop_hand_off_never_reads_as_idle` (no outstanding wake ticket).
- `unwinding_drop_hand_off_never_reads_as_idle` (poll panics before destruction).

Each inner future's destructor records `tracker.idle()` before waking a second
tracked future. The unwind witness also checks that the running unit stays
counted between the caught panic and destruction. All polling and ordering are
manual; no real-time wait or scheduler interleaving is assumed.

On the unfixed code at `443a3d7d`, all three failed with
`busy hit zero during pending-drop hand-off`:
`test result: FAILED. 0 passed; 3 failed; 0 ignored; 0 measured; 31 filtered out; finished in 0.00s`.

The fix explicitly destroys the inner future before releasing its retired ticket,
counts destruction even for suspended futures, and transfers the running unit to
a ticket on unwind until the future is destroyed. Existing tracking tests stay
unchanged. Guard comments document the non-panicking Tokio/replay waker assumption.
