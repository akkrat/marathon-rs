# WP 8.14 test changes

## 1. Unused timeout overloads

No tests changed or deleted. The workspace has no callers of the four removed
Duration overloads. Existing `runtime_oracle` and `runtime_races` cover the active
signed-millisecond scopes in `executor/clock.rs`. The Timeout.kt inventory row
still names its strategy/factory extensions; the active clock port also remains.
No Kotlin parity row refers to the removed overload module.

## 2. Bridge payload

Added in `executor/bridge.rs::tests`:
- `bridge_hides_new_cancellation_until_the_first_poll_returns`: manually gates
  dispatch, the first poll and task completion; a sent payload still waits for join.
- `bridge_exposes_cancellation_already_present_at_entry`.
- `bridge_rejects_successful_join_without_a_payload`.
- `bridge_preserves_failed_and_cancelled_joins_without_a_payload`.

All use explicit polling, with no real-time deadlines.

## 3. Dead coroutine surface

- Deleted `runtime_behavior::actor_safe_send_keeps_check_then_send_race` with
  the unused API it alone exercised.
- Updated `runtime_behavior::join_ignores_joined_failure_and_join_in_observes_caller`
  to cancel explicitly and then perform the same protected join.
- Removed `safe_send` implementations from the `support/device_actor.rs` and
  `support/queue.rs` fake actors; no scenario behavior changed.

Neither removed method has a Kotlin test row in the parity matrix, so no row
needs exemption. The Android runner's unrelated production method stays.

## 4. Completion diagnostics

Extended `runtime_review::exception_handler_only_records_unhandled_failure`
to check the single ERROR record, module target, message, failure and scheduler
time in the production output queue. Existing completion observers are now
compiled only for tests/test-support; all existing actor log checks remain.

Before the routing fix, the extended logging witness failed with
`assertion left == right failed; left: 0; right: 1` at the queue-length check.

## 5a. First-poll panic gate (U186)

- Added `executor/bridge.rs::tests::first_poll_panic_releases_a_retained_childs_cancellation_gate`.
  The actual retained Tokio child waits on the gated signal. Before the fix:
  `the retained child must observe cancellation after a first-poll panic: Err(Elapsed(()))`;
  `test result: FAILED. 0 passed; 1 failed` after 60.01 s. The failure path aborts
  and joins the child before asserting.
- Added `runtime_behavior::vendor_task_cancellation_takes_precedence_over_a_later_panic`
  and `runtime_behavior::vendor_task_panic_without_cancellation_is_a_failure` to pin
  IoRuntime's existing cancellation-over-panic precedence and uncancelled panic mapping.

## 5b. Tracked future retirement (U187)

Added in `executor/tracking.rs::tests` (all failed before the fix):
- `dropping_an_unpolled_tracked_future_releases_its_ticket`:
  `dropping an unpolled future leaked its runnable ticket`.
- `dropping_a_woken_tracked_future_releases_its_ticket_and_ignores_stale_wakes`:
  `dropping a woken future leaked its runnable ticket`.
- `dropping_a_suspended_tracked_future_ignores_stale_wakes`:
  `a stale wake reacquired a dropped future's ticket`.
- `panicking_tracked_poll_releases_running_and_runnable_work`:
  `a panicking poll leaked running or runnable work`.
- `aborting_a_tracked_task_releases_its_ticket`:
  `aborting a tracked task leaked its runnable ticket`.

Before: `test result: FAILED. 2 passed; 5 failed` (the two existing concurrency
witnesses passed unchanged). Explicit polling covers ticket states; actual Tokio
abort is joined under a 60 s hang guard.
