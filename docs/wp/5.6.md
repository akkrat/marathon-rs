## Deliverables and boundary

In `crates/marathon-macos`, with minimal CLI construction wiring:

1. **Provider and vendor factory.** Implement frozen `DeviceProvider::{initialize, borrow, subscribe, terminate}` and return `VendorServices` from explicit `VendorDependencies`. Wire the macOS `VendorFactories` slot in CLI; construction must not connect or initialize. The factory shares one `AppleTestBundleIdentifier` between provider, parser and core, selects the 4.8 XCTest parser only when configured (nm otherwise, with its default configuration on the source fallback), supplies the macOS installer to remote parsing, and uses 4.10a's `AppleLogConfigurator` (`M/MacosVendor.kt:25–70`). Reuse P2 binding; do not recreate Jackson/Gson registries or introduce core device downcasts.
2. **`MacosDevice`.** One stable allocation implementing frozen `Device`, shared `AppleDevice`, `LogProducer` and `Screenshottable`; fresh `DeviceInfo` snapshots preserve allocation identity separately. Setup, preparation, transfers, batch execution, listener construction and concurrent disposal follow the source below. The Apple runner/session request seam comes from 4.8. No macOS `ArtifactProcessor`, recovery loop, simulator boot state or media implementation.
3. **`MacosApplicationInstaller`.** Thin `AfterInstall` hook over the merged base installer, granting configured TCC permissions after test-root generation and before extra applications (`B/AppleApplicationInstaller.kt:64–76`). Reuse 4.5b's generated-runner copy and 4.10b's installation/check/retry logic. The hook's `FactoryResult` must retain `IncompatibleDevice`/`DeviceSetup` classification.
4. **Tests/evidence and handoff.** All eight rows below plus focused provider, permissions and factory integration coverage; `docs/wp/5.6-findings.md` records consumer APIs, evidence, decisions and incidental bugs. No production `todo!()`/panic for Kotlin's unimplemented methods: preserve their explicit failure through the existing error representation, subject to P2.

**Frozen lifecycle:** vendor operations run through `VendorRuntime`/the core vendor-call bridge, never blocking core. `Device::execute` returns independently from its `Deferred<TestBatchResults>`; completing one never implies the other. Use `VendorContext.cancellation`, `VendorClock` and retained task ownership for lazy batch start, protected joins and timeout cleanup. Disposal is async, idempotent, concurrent-joining; `Drop` is not a disposal substitute. No mutex across await, callback, command or logging. Keep device and batch pointer identity where Kotlin uses `===`.

**Not 5.6:** schema/post-processing/validation (2.x; F6 stays), tool argv/transport (4.1–4.4), plist/test-root generation (4.5), result parsing (4.6/4.7), runner/session/parsers (4.8), result-bundle delivery body (4.9), base installation (4.10b), iOS policy/listeners/provider (5.2–5.5b), full differential comparator (7.1), real host certification (7.2). Shared helpers may be reused from `marathon-apple`; no dependency on the concrete iOS crate is justified by this source.

## Behaviours to reproduce

- **Initialize before discovery** (`P:78–115,125–154`): DEBUG `Initializing AppleMacosProvider`, then INFO `Xcresulttool.describeTimeout`, even if devices input fails; provider logger name is the simple `AppleMacosProvider`, device logger is `com.malinskiy.marathon.apple.macos.MacosDevice`. Use configured devices file or `<process cwd>/Marathondevices`. File reading/substitution precedes the `JsonMappingException` catch; only mapping failures become `NoDevicesException("Invalid Marathondevices file <absolute path> format", cause)`. Empty workers produce `No workers found in the <absolute path>`. Syntax, I/O and substitution failures keep their different boundary. Reuse P2 with its process-relative SSH key (F4), not P1; provider config does not select a dynamic producer here.
- **Host filtering/connect** (`P:93–114,125–154`): insert workers into an ordered map keyed by the **whole Transport**, replacing an equal transport's device list, not merging it. Filter after replacement: warn once per non-Host target, initialize one device per retained transport having any Host. A nonempty file with no Hosts succeeds without devices. Launch transport initializations concurrently and await all; do not defer connecting to subscription or background discovery. A null executor means skip. Query provisioning UDID via system_profiler, fall back to ioreg only when blank, construct with MACOS, run tracked `setup`, then connect. Probe errors propagate; no new retry/reconnect policy beyond `ConnectionFactory`.
- **Identity/events/borrow/terminate** (`P:118–123,156–179,207–225`): serial-keyed devices; replacement stores the new allocation, logs ERROR `replaced existing device <old> with new <new>.`, disposes the old, then asynchronously emits Connected. No active caller emits Disconnected: commented recovery is not a feature. `subscribe` returns the same consuming unbounded queue. `borrow` polls every 200 ms while empty, then selects randomly via `macos.AppleMacosProvider.borrow`; no new empty-host error or lease/release protocol. Termination is NonCancellable: close channel (buffer drains), concurrently dispose each device then release its executor via the factory, swallow that pair's `Exception`, log `Disposed device <udid>`, await all, clear map, close dispatcher. Preserve catch/ordering; do not close a shared executor from the device itself. Setup failures before insertion and replaced-device leases need explicit ownership evidence (question 4).
- **Facts and setup** (`D:110–183,418–442`): serial `<udid>@<commandExecutor.host.id>`, storage `/tmp/marathon/<udid>`, initial OS/model/manufacturer/ABI `Unknown`, healthy always true and network CONNECTED, features empty, rotation zero. Setup order: `env`, Xcode version, validate HOME, ioreg model, ioreg manufacturer, sw_vers, `uname -m`, feature detection (no command). Failed env ⇒ `DeviceSetupException("macOS <udid>: unable to detect environment variables")`; blank HOME ⇒ `macOS <udid>: invalid value <home> for environment variable HOME`. Trim env lines, drop empty lines, split on first `=`, trim both halves, last duplicate wins; a line without `=` maps to itself twice. Successful uname uses trimmed combined stdout, otherwise `Unknown`. Preserve A45's shared architecture heuristic, rather than inferring arch from uname for macOS.
- **Prepare/transfers** (`D:215–257,283–305`): tracked preparation removes device storage, creates device and shared directories, runs installer, then constructs/stores `AppleTestBundle`; absent bundle throws `IllegalArgumentException("No test bundle provided")`. Preparation runs in the device scope: caller cancellation interrupts its await without an explicit cancel/join of that preparation job, and dispose tracks only the batch. Retain ownership of that continuing work; do not silently reparent it to the caller. Worker commands use shell/shellIdle, empty env, null workdir. File/folder transfers use the merged measurement wrappers; shared sends use `transport.id()` and the existing source/destination cache plus remote existence; changed bytes at the same source path still reuse the transfer while the destination exists (A37). `install` returns true without commands. No macOS `pushGeneratedFile` override: use the base transfer path, not iOS's WriteFile shortcut. Screenshot (both forms), video start/stop, shutdown and erase throw `NotImplementedError("An operation is not implemented: Not yet implemented")` (`D:259–280`), not successful no-ops.
- **Batch/session** (`D:308–372`): build lazy device-owned async job; create/register listeners and run `AppleDeviceTestRunner`, removing registered line listeners in finally. Under execution lock, disposal present ⇒ cancel lazy job and throw `DeviceLostException(IllegalStateException("Device <serial> has been disposed"))`; otherwise store executionJob. Completion clears it **only if it is still the same job**, then await. Catch cancellation before IllegalStateException: cancel/join the batch; caller still active ⇒ DeviceLost (e.g. disposal cancelled the batch), caller cancelled ⇒ propagate cancellation. ConnectionException/TransportException/OpenFailException/IllegalStateException ⇒ DeviceLost; DeviceFailureException(IncompatibleDevice) ⇒ IncompatibleDevice; **every other DeviceFailureException, including batch-level failure, ⇒ DeviceLost**. No three-strikes/progress policy or lost/retired flags. Other failures propagate through their existing taxonomy, preserving causes.
- **Cancelled wait/dispose** (`D:87–108,374–416`): session close default is 1 minute (4.8); cancelled batch default is that plus **10 seconds**, not two serial waits. Cancel then NonCancellable bounded join. Expiry only WARNs `Cancelled batch on <serial> has not finished within <Java Duration>, not waiting for it any longer`; it neither reports lost nor emits Disconnected. A later dispose gets its **own full wait** if the batch still runs. First disposer installs a shared completion cell and captures executionJob; concurrent calls await the same cell. Join boundedly, close dispatcher, complete the cell in finally. Public dispose catches Exception and DEBUG-logs `Error disposing <serial>`. Keep both timeout knobs injectable. Retain abandoned work without extending Kotlin's waits; tests release and drain it before exit.
- **Request/listener order** (`D:185–213,444–503`): check previous session closed, record new session, delegate to 4.8's shared body with MACOS and configured xcodebuild args. It sends parsed stdout events **before** line listeners (A20), drains stderr concurrently, skips blank trimmed stderr, logs nonblank stderr under `Xcodebuild` with `macOS <udid>`, and serializes listener callbacks. Do not duplicate that body. Composite order: TestResultsListener (including Xcode version and attachment providers), log adapter (`XCODEBUILDLOG`), DebugTestRunListener, diagnostic finder, session-results finder, no-op recorder, ResultBundleRunListener **with no processor**. Register only the diagnostic finder, session finder and debug printer as the extra line-listener set; the log listener uses its existing registration lifecycle. Result-bundle pull/rename/remoteClean runs synchronously in finalization and can delay execution return after result completion. Preserve 4.7 finalizer/error order and A20's possible log partitioning.
- **PlugIns** (`B/xctestrun/TestRootFactory.kt:100–117`, `T/MacosTestRootTest.kt:63–70`): generated MACOS runner copies `<shared>/marathon.xctest` into `<runner>/Contents/PlugIns` while TestBundlePath still names the shared xctest and TestHostPath the runner. Hosted XCTest's different root-level PlugIns path (A54), redundant push (A9), Frameworks path (A55), and missing-minimum-version failure (A28) remain unchanged.
- **SIP/TCC** (`M/MacosApplicationInstaller.kt:10–22`, `D:505–516`): empty grant map skips SIP entirely; otherwise query csrutil once and reject true with `IncompatibleDeviceException("Unable to add permissions: requires System Integrity Protection to be disabled")`.
