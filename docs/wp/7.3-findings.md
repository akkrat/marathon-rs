## Decisions and scope

The final 2026-10-25 user decisions override the earlier GitLab proposal:
GitHub Actions, native Apple arm64 and Linux x86_64 jobs, one
`marathon-<version>-<target>.zip` per target on the same GitHub Release, tags
only, GitHub latest release, and no silent replacement on reruns. P1/P2/P4
are implemented as approved. Version boundary: 1–128 ASCII characters,
alphanumeric first, then alphanumeric or `._+-`, no `..`. Direct CLI builds
are unchanged. No snapshot archive mode, cross-compilation or additional
formats/targets. Zero assigned source/test rows remain zero; the two buildSrc
n/a source rows are preserved with their existing Cargo/packaging rationale.
No parity CSV regeneration was necessary because ownership/status did not change.

**Changes to merged crates: none.** No Rust code, dependency, manifest,
lockfile, core/runtime seam, CLI log/version behavior or Java compatibility
layer changed. Cargo already invalidates `option_env!("GIT_TAG_NAME")` on
changes; evidence below requires no build.rs. `scripts/check.sh` now includes
the offline release helper suite. `.github/workflows/ci.yml` replaces the
previous dispatch-only workflow with the full native test/build and tag-only
publication path. Operator commands and setup are in `docs/releasing.md`.
