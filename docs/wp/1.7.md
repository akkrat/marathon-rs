## Goal

Byte-exact signed MD5 fragmentation, escaping, file/folder construction and truncation. Preserve C1/C2 and UTF-16 length semantics, including split surrogate pairs. Filesystem operations must return errors and run on an I/O executor when integrated by later WPs.

## Deliverables

- Independent jcompat modules for hashes and file naming, with pure path planning and explicit directory creation.
- Typed file/folder kinds, all optional filename components, absolute File serialization paths, and original truncation diagnostics.
- Oracle-driven tests and the seven named Kotlin tests; parity matrix updates; findings.

## API and integration

- `fragment_hash::{signed_md5, signed_md5_utf16, fragment_index, fragment_index_for_hash}`: signed i128 digest and Kotlin remainder correction. Zero divisor returns `None`; the filter integration must map that to Java ArithmeticException semantics. i64 fragment output also preserves invalid negative-count arithmetic.
- `file_manager::{escape, escape_utf16}`: Java regex code-point matching, including malformed units.
- `FileManager::{plan_file, plan_folder, plan_test_result_file}` and UTF-16 variants: pure naming and truncation. The file request accepts the original `Test.toTestName()` before escaping, so the eventual test-model WP owns package/class formatting.
- `FileType`, `FolderType`, `JavaPath`, `PathPlan`: original directory/suffix values, raw UTF-16 paths and exact diagnostics. `absolute_file_path` and its UTF-16 variant supply FileSerializer's value without canonicalizing dot components; the Gson writer owns JSON quoting.
- `PathPlan::materialize` performs blocking directory operations and emits ERROR messages through a callback in Kotlin order. Run it on an I/O executor. It creates no file. `create_directories` is the same operation without a logging callback. Use materialize in the final runner.
- Both native-path conversions reject malformed UTF-16 and NUL; the JavaPath itself retains them. No lossy conversion is used to construct output paths.

`StringExtensions.withPrefix` is an internal Graphite helper rather than hashing/naming behaviour; its two Graphite callers remain WP 3.4a/3.4b. Android APK MD5 checksums and worker md5 commands are distinct from the signed fragment hash and remain vendor work.
