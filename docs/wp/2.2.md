## Behaviours to reproduce (with sources)

**Top level via the Builder** (`Configuration.kt:18` `@JsonDeserialize(builder=…)`, `:148-212`). Only `name` and `outputDir` are required; everything else defaults on the `Builder`: `analyticsConfiguration = disabled`, pooling `omni`, sharding `parallel`, sorting `no-sorting`, batching `isolate`, flakiness `ignore`, retry `no-retry`, empty filtering, `ignoreFailures = false`, `isCodeCoverageEnabled = false`, `executionStrategy = ANY_SUCCESS/fast`, `uncompletedTestRetryQuota = Int.MAX_VALUE`, empty serial-regex lists, `testBatchTimeoutMillis = 1_800_000`, `testOutputTimeoutMillis = 300_000`, **`debug = true`**, `screenRecordingPolicy = ON_FAILURE`, `analyticsTracking = bugsnagReporting = true` (accepted and stored; D1 makes them inert downstream, the CLI AND-merge is the loader's, not this binder's), `deviceInitializationTimeoutMillis = 180_000`, `outputConfiguration = (0, 255)`, `vendorConfiguration = Empty`, `ciConfiguration = none`. The Builder's parameter order differs from `Configuration`'s constructor order (`outputConfiguration`/`vendorConfiguration`/`ciConfiguration` last, `:178-180`); bind by property name, build in `Configuration` order. Missing-vs-explicit-`null` per field follows the 2.1 `Field` policies: primitives (`ignoreFailures`, the `Long` timeouts, …) take zero on `null` even with a default, non-null references (`name`, `outputDir`, each strategy section) reject `null`, collections take `null` — what a `null` collection or a `null` element becomes in Rust is open question 3.

**Polymorphism everywhere is `type`-property `Id.NAME`** (`AnalyticsConfiguration.kt:7-17`, `CIConfiguration.kt:6-15`, each `strategy/*.kt`, `FilteringConfiguration.kt:14-34`), dispatched through 2.1's `polymorphic` (late `type`, unknown id, and the consumed-occurrence hiding from 2.1 R1 included). The subtype name tables are exactly the `@JsonSubTypes` lists in the sources above — e.g. pooling `device-model` (not `model`), filters `fully-qualified-class-name`/`annotationData` (camelCase, unlike its siblings). Singletons (`omni`, `parallel`, `no-retry`, `disabled`, CI's three, …) bind through the same path; which spellings Jackson accepts for a singleton (empty map, extra keys, scalar forms) must be oracle-pinned before freezing (fixtures below), not guessed. `combo` recurses (`PoolingStrategyConfiguration.kt:25`) and `composition` recurses through `List<TestFilterConfiguration>` (`FilteringConfiguration.kt:331`) — both ride the binder's existing depth handling; do not add a second depth limit.

**Per-field `timeLimit` (PLAN §3.2) — the three strategy deserializers only.** Each does `readTree` → `findValue("timeLimit")` → try `Instant`, and **only on `InvalidFormatException`** retry as `Duration` added to the injectable now (`instant.plus(duration)`; in Rust, `context.now`, and negative durations go backwards — `sample_10.yaml` expects `now − PT1H` / `now − P30D`). Any other failure from the `Instant` attempt propagates: corpus rows C58-sort-7/8/9 pin `[1]`, `{a: 1}` and `true` as `MismatchedInputException`, never reaching the `Duration` retry or the custom message. Rust has no `treeToValueOrNull` helper (2.1 findings); discriminate on the binder error's class (`binder::INVALID_FORMAT`) and prove with a unit test that a container `timeLimit` does **not** surface as `InvalidFormatException` from `Value::instant` — if it does, that is a binder gap for the open questions, not something to paper over. Then, per field:

- `execution-time` (`ExecutionTimeSorting…Deserializer.kt:22-34`): missing `percentile` → `ConfigurationException("Missing percentile value")`; missing `timeLimit` → `"Missing time limit value"`; present but neither `Instant` nor `Duration` (including explicit `null`, C58-sort-10/11) → `ConfigurationException("bbb")` — **F1, reproduce and confirm its known-bug row**.
- `probability` (`ProbabilityBased…Deserializer.kt:18-37`): checks in order `minSuccessRate` (`"Missing minimum success rate value"`), `maxCount` (`"Missing maximum count value"`), `timeLimit` presence (`"Missing time limit value"`), and on double failure throws `"Unable to deserialize $timeLimitValue into Instant"` where the interpolation is the Jackson `JsonNode.toString()` of the node — **not** `as_text` (a string node renders quoted). 2.1 has no such renderer; see open question 5.
- `fixed-size` (`FixedSizeBatching…Deserializer.kt:21-44`): `timeLimit` is optional and **any** double failure silently yields `null` — **F2**. `size` missing → `"Missing size value"`; `durationMillis`/`percentile` optional; `lastMileLength` defaults to 0.
- All three share the copy-pasted null-tree message `ConfigurationException("Invalid sorting strategy")` — yes, also in the batching (`:23`) and flakiness (`:20`) deserializers. Keep the wording (§3.10: custom messages are identical); add a known-bug row if one is not already implied by F1/F2.
- `success-rate` has **no** custom deserializer (`SortingStrategyConfiguration.kt:29-32`, not registered in `SerializeModule.kt`): strict creator binding, unknown keys rejected, `timeLimit` must be an absolute `Instant` (a `Duration` string fails as an ordinary binding error, C58-rate rows), `ascending = false`.

**`findValue` is recursive, the numeric reads are non-throwing (F9, confirmed in 2.1).** The three strategy deserializers look every field up with `node.findValue(...)` — direct children first, then child containers in insertion order (2.1 R1 precedence; corpus C59: a `size`/`timeLimit` nested under an unknown key is found, a direct one shadows it regardless of order). Values are read with `JsonNode.asInt/asLong/asDouble`, i.e. 2.1's `as_int`/`as_long`/`as_double`: a present `null` reads as 0 (so `percentile: null` binds 0.0, only a *missing* key throws), `size: true` binds 1, decimal text truncates, a container reads as 0. Never substitute the strict `int()`/`double()` binders here. Unknown keys anywhere in these three subtrees are ignored, but `read_tree` still validates their token streams (2.1 semantics).

**Analytics: two strictness regimes.** `influxdb` (v1), its retention policy and `graphite` are lenient (direct `get`, **not** `findValue`); **`influxdb2` and `disabled` have no custom deserializer** (`SerializeModule.kt:19-24` registers only v1, graphite and the v1 retention policy) and bind strictly through the normal creator path — unknown keys rejected (corpus C53c), and v2's `readOnly` is a real honoured field. In detail:

- `InfluxDbConfigurationDeserializer.kt:13-37`: reads `url`/`user`/`password`/`dbName` via `asText`, binds `retentionPolicyConfiguration` through its deserializer (absent → `RetentionPolicyConfiguration.default` = `rpMarathon/30d/30m/2/true`, `AnalyticsConfiguration.kt:37`) and `defaults` through the strict `Defaults` creator (absent → `Defaults()`), and only *then* null-checks in the order url, user, password, dbName with messages `"InfluxDbConfigurationDeserializer: <field> should be specified"`. So a malformed nested `defaults`/`retentionPolicyConfiguration` errors before a missing `url` is reported — keep that precedence unless S6 is approved. The constructor is called positionally without `readOnly`, so **`readOnly` is always `false`, whatever the file says — F3**. Because the reads are `asText`, only a *missing* key is `null`: an explicit `null` becomes the string `"null"` and passes, a number/bool becomes its spelling, a container becomes `""` (F3's second half; 2.1 `as_text` already does this).
- `RetentionPolicyConfigurationDeserializer.kt:17-37`: `name`/`duration`/`shardDuration` via `asText`, `replicationFactor` via `asInt`, `isDefault` via `asBoolean`; each missing key throws `"RetentionPolicyConfigurationDeserializer: <field> should be specified"` in declaration order. Present-but-wrong-typed values coerce silently through the non-throwing accessors (explicit `null` replication factor → 0, `isDefault: 1` → true per 2.1's `as_boolean`, float factors truncate).
- `GraphiteConfigurationDeserializer.kt:15-32`: `host`/`prefix` via `asText`; `port` via `asText` then Kotlin `String.toIntOrNull()` — missing port is fine (`null`), a present port that does not parse (including explicit `null`, which reads as `"null"`, and a float token, which reads as e.g. `"2003.5"`) throws `"GraphiteConfigurationDeserializer: port should be a number, e.g. 2003"`; checks run host → port → prefix, with `prefix = ""` throwing `"GraphiteConfigurationDeserializer: prefix cannot be empty"` while an explicit-`null` prefix passes as the literal string `"null"`. `readOnly` dropped as in v1 (F3); `defaults` as in v1.
- `Defaults` (`analytics/Defaults.kt:13-17`) is a plain creator everywhere it appears, including inside the lenient deserializers (`readTreeAsValue`): unknown keys inside `defaults` are rejected even under `influxdb`/`graphite`. `observedDurationMinTests < 1` is **not** a parse error — that check is `LogicalConfigurationValidator.kt:34-38`, i.e. 2.4.
- The secret-masking `toString`s (`AnalyticsConfiguration.kt:44-46` masks url/user/password, shows `dbName`, omits `defaults`/`readOnly`; `:67-69` likewise for v2) are output for 2.4's `toMap()`; 2.2 only needs to not lose the information. Whether Rust `Debug` should mirror the masking so secrets cannot leak into test failures/logs is open question 6.

**Filters.** `FilteringConfiguration(allowlist, blocklist)` both default to empty (`FilteringConfiguration.kt:9-12`). The seven regex/values/file variants share the shape `(regex?, values?, file?, enabled = true)` (package adds `subpackages = false`); `annotationData` takes required `nameRegex`/`valueRegex`; `fragmentation` takes required `index`/`count`; `composition` takes `filters` + `op: UNION|INTERSECTION|SUBTRACT`; `allure` takes only `enabled`. Binding is strict/creator-based (no leniency here); `regex` fields compile via `Value::regex` under D6 (rejected pattern fails at load naming pattern and field), `file` fields via `Value::file` (Marathonfile-relative, 2.1). `validate()` bodies to port verbatim: exactly one of `[regex,values,file]` (`"Only one of [regex,values,file] can be specified for <SimpleName>"` / `"At least one of … should be specified for <SimpleName>"`, with the **Kotlin** class simple name interpolated), fragmentation bounds (`:249-253`), composition recursing into children (`:335-337`), and the two no-ops (`annotationData`, `allure`). Note `validate()` is never invoked during binding in Kotlin.

**Equality quirks (F7 territory — record, don't emulate blindly).** `Configuration.equals` compares serial-regex *patterns* while `hashCode` hashes `Regex` identity (`Configuration.kt:103-104,134-135` — F7; the approved Rust replacement is consistent pattern-based `Eq`/`Hash`). The filter types repeat the pattern with extra twists the implementer must add to `docs/known-kotlin-bugs.md` when porting: `SimpleTestnameFilterConfiguration.equals` casts `other` to `SimpleClassnameFilterConfiguration` (`FilteringConfiguration.kt:98`), so comparing two of them throws `ClassCastException`; `enabled` is excluded from every hand-written `equals`/`hashCode` except `fragmentation`'s generated data-class one; `annotationData` equality concatenates the two patterns with no separator (`:201`, so `("ab","c") == ("a","bc")`) while its `hashCode` sums identity hashes (`:204`); `composition` equality is order-insensitive containment but its `hashCode` is the ordered list hash (`:345-355`); `allure` delegates to `super.equals`, i.e. reference identity (`:364-370`). Simplification S1 proposes replacing all of this with lawful full-field equality.

**Regexes and files in this layer.** `includeSerialRegexes`/`excludeSerialRegexes` (`Configuration.kt:39-40`) and every filter `regex` compile at bind time via `JavaRegex::compile(pattern, field)` (D6; the binder derives the field path). Keep the pattern spelling available (`JavaRegex::pattern()`) for 2.4's serializer. Under F10 (`StrictNullChecks=false`, confirmed in 2.1), Kotlin can also put `null` *inside* these lists and inside `allowlist`/`combo` lists — representation is open question 3.

## Proposed simplifications (pragmatic parity — for orchestrator approval, **not decided**)

Per the user's direction: few users; don't emulate quirks only exotic inputs reach. D6/D8/D9 already apply. Until a proposal is approved, the behaviours above stand and a divergence is a bug; an approved item is recorded with the deviations (PLAN §3.11 style) and its corpus rows are marked, not dropped.

- **S1, lawful equality instead of the Kotlin `equals` field subsets.** Derive/impl full-field `Eq`/`Hash` (including `enabled`, ordered `composition` filters, separated `annotationData` patterns, value-equal `allure`) with pattern-based regex equality per F7. Diverges only where Kotlin's equality is inconsistent, crashes (`:98`), or ignores a field; round-trip comparisons (2.4) are unaffected because both sides come from the same file.
- **S2, one `now` for the whole file.** Kotlin's `InstantTimeProviderImpl.referenceTime()` is `Instant.now()` *per `timeLimit` field*; use the single `BindingContext.now` snapshot for all of them. Diverges by sub-second amounts between fields of one file; also what makes the corpus deterministic.
- **S3, scalar-only node rendering in the `probability` message.** Render the failing `timeLimit` node exactly as Jackson `JsonNode.toString()` for scalars (the only realistic inputs); for containers use a compact JSON rendering of our own instead of a full Jackson tree writer.
- **S4, reject `null` collection elements at bind time** with a clear binding error instead of threading `Option` elements through filters/strategies/serial-regex lists into 3.2/3.3 (the F10 alternative to open question 3). Diverges only on files Kotlin accepts and then mishandles later (`[null]` in an allowlist NPEs downstream at `validate()`/filter construction).
- **S5, ASCII `toIntOrNull` for graphite `port`.** Rust `i32` parsing (optional sign + ASCII digits) instead of `Integer.parseInt`'s `Character.digit` acceptance of non-ASCII digits — D9-consistent.
- **S6, required-field checks before nested binds in the analytics deserializers.** Report a missing `url`/`host` before a malformed nested `defaults`. Diverges only on doubly-invalid analytics sections (accept/reject unchanged).
- **S7, overflow of `now + Duration` is a plain binding error** (no reproduced `DateTimeException` class chain) — D9-consistent.
