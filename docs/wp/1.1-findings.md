# WP 1.1 findings

## Implementation and validation

`JavaPriorityQueue<T, C>` uses a `Vec<T>` and a stateful `FnMut(&T, &T) -> Ordering` comparator. The implementation requires no element cloning or total-order trait. `remove` uses `PartialEq` independently of priority, searches the backing array from the front, then tries downward repair and, only if unmoved, upward repair. `remove_all(&[T])` removes all equal copies, stably compacts the survivors and heapifies bottom-up only when something was removed. `add_all` inserts in input order. Read-only iteration exposes backing-array order without comparator calls.

The full existing JVM oracle passes: **240 scenarios, 5,824 operations, 7,104 comparator calls**. The test checks every result, comparison argument/sign/order, backing array, size and emptiness. Each of random, equal-keys, few-keys and duplicates contributes 60 scenarios. The corpus reaches 30 queued elements, includes a successful upward repair after `remove(Object)`, and includes 175 bulk removals that make heapify comparisons. Duplicate equality groups have independent priority keys; this already covers comparators inconsistent with equals. No generator extension or fixture edits were needed.

Operation counts: offer 2,073; poll 1,144; peek 286; remove 594; removeAll 463; addAll 589; iterator 571; clear 104.

`scripts/check.sh` passed (exit 0): oracle parsing, formatting, clippy with warnings denied, all workspace tests, plan graph, source inventory (505 files), parity matrix (873 rows), and fixtures (141 files, zero problems). Final output: `==> all checks passed`.

No Kotlin tests or main-source rows are assigned to this WP; no inventory status changes are needed. Consumer call sites are listed in `docs/wp/1.1.md`; those modules and their Kotlin tests remain owned by their respective WPs.
