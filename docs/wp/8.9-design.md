# WP 8.9 milestone 1: YAML writer design

The following sections record the approved milestone-1 design stop. The final
implementation is described below; the excluded prototype has been retired.
The retired emitter adapter in `spikes/yaml-writer` borrowed the existing
`WriterValue` projections to isolate library behaviour. Milestone 2 replaced it
with serde structs and metadata adapters.

## Library decision (checked 2026-11-10)

Choose **serde-saphyr =2.1.1**, MIT OR Apache-2.0, released 2026-11-05.
Crates.io also records 2.0.0 on 2026-10-13 and 1.3.0 on 2026-09-16;
2.1.0 was yanked. This version uses safe-Rust `granit-parser` 2.1.0
(the successor to the earlier saphyr backend named in the brief).
Use only the `serialize` feature with defaults disabled: the Marathonfile reader
remains snakeyaml, and no replacement parser is pulled in. The spike pinned the
exact version and recorded its own lockfile.

The fallback **yaml_serde =0.10.7**, also MIT OR Apache-2.0, was released
2026-08-18 after 0.10.6 on 2026-08-12 and 0.10.5 on 2026-08-11.
It uses the libyaml-derived unsafe `libyaml-rs` 0.3.0. Both are active; saphyr's YAML 1.1 string
quoting and compatible finite-float spelling avoid extra adapters. The fallback's
quoting is evaluated alongside it in the spike. It leaves `yes`, `on`, `1_000`,
`1:20`, timestamps, `<<`, and y/n unquoted; using it would require a custom string
serializer. No archived serde_yaml/serde_yml.

Sources: [serde-saphyr metadata](https://crates.io/api/v1/crates/serde-saphyr),
[yaml_serde metadata](https://crates.io/api/v1/crates/yaml_serde), and each
version's downloaded serializer source.

## Output and quoting

Use `SerializerOptions { yaml_12: false, prefer_block_scalars: false, .. }`
through `ser_options!`. YAML 1.1 mode quotes ambiguous strings in both keys and
values: boolean words including y/n and mixed case; null/~; decimal, octal,
hex/binary, leading zeros, underscores and sexagesimal numbers; dotted special
floats; timestamps; merge `<<` and reserved `=`. Empty strings, whitespace,
syntax indicators, document markers and control characters also require quoting.
The library implements these checks, so no application hazard matcher or text
post-processing is needed. Explicitly disable automatic block scalars: double
quoted escapes preserve CR, LF, NEL, U+2028/U+2029 and trailing newlines across
YAML 1.1 readers. Ordinary strings may become plain or single-quoted.

Retain mapping/struct declaration order and vector-backed dynamic map order.
Omit null object entries (NON_NULL); retain null array elements. Empty sequences
and maps remain `[]` and `{}`. Metadata byte arrays remain tagged `!!binary`
base64 scalars, char arrays remain strings, malformed primitive arrays retain
the existing generic-array fallback, and decoded annotation wrappers keep their
current shape. Serialization errors return `Result` and propagate to callers.

Today's non-finite number spellings are undotted `NaN`, `Infinity`, `-Infinity`.
YAML 1.1 resolves these as **strings**, despite their numeric origin. Native serde
float serialization would emit `.nan`/`.inf`/`-.inf`, changing parse-result data.
Use a scalar serializer that writes strings for non-finite values on both paths;
our configuration binder converts those strings back to equal special floats.
Saphyr quotes NaN. Finite values serialize as numeric f32/f64, including negative
zero; integers use integer serializers. The spike parses old numeric spellings
only as a temporary bridge; no such parse is planned for production structs.

## Callers and implementation plan

`render::serialize` is re-exported by `marathon_config`. Its current callers are
`tests/serialization.rs` (`test_simple`, `timeout_round_trip`, and the NaN case)
and `tests/validation_corpus.rs` (recorded serialized text). There are no production
callers beyond the exported API. `examples/corpus.rs` does **not** call this
function: its `emit_case` directly invokes JacksonYamlWriter for writer-oracle
rows. Also migrate the direct writer use for Xcresult in serialization tests.

`projection::parse_results` is called by `execution::parse_command` and reporter
tests. Milestone 2 will return `Result` from both public functions and propagate
parse emission failures through the existing vendor failure channel. Use borrowed
Serialize structs for parse results/tests/properties and configuration sections;
use an ordered dynamic serde value for metadata, filtered maps and tagged
polymorphic configuration where needed. Preserve ISO duration/instant, path and
regex projections. Remove Java numeric formatting only from YAML projections;
KotlinValue and its numeric text remain in scope for their existing callers.

## Risks and design-stop boundary

The prototype exercises the emitter with today's projections. It does not prove
that milestone 2's new typed views preserve every field: rerun all these checks
once those views exist. Keep the non-finite string adapter on both paths;
serializing f64 directly changes YAML scalar type for NaN/infinity. Disabling
block scalars and pinning YAML 1.1 mode are deliberate compatibility settings.
The library is active but 2.1.1 is recent; retain the hazard regression tests and
review upgrades explicitly. Independent YAML 1.1 reader tests and full property
coverage of the final views remain milestone-2 work. No production API, writer,
parity row, test or golden has been changed at this design stop.

## Milestone 2 implementation

`marathon-config::yaml` is the single compatibility boundary. It pins
`yaml_12: false`, `prefer_block_scalars: false`, `empty_as_braces: true`, and
omission of null mapping entries while retaining null sequence elements. Each
setting has its reason beside it, and one regression test checks the options,
observable output and hazard quoting. The reader remains unchanged. Only saphyr's
`serialize` feature is enabled.

`marathon-core::report::yaml` derives `Serialize` for `ParseResults`, `TestYaml`,
properties and decoded value wrappers. Its metadata map/array adapters stream the
existing discovery models directly, retaining binary, char-array and malformed
primitive-array behaviour. `marathon-config::yaml_views::View<T>` implements the
configuration/section views. Each `view!` expression derives a statically typed
struct with declaration-order camelCase fields and explicit optional-field
omission; it does not build a generic value tree. Paths, regexes, ISO durations,
instants, discriminator aliases and the D6 default-pattern omission remain the
same. Both public output functions return Result; parse-command serialization
errors propagate through the existing vendor error channel.

Numeric edge capture found a further compatibility requirement: native float
formatting changes exact decimal data for subnormals (4.9E-324 becomes 5e-324;
f32 has the analogous 1.4E-45 case). As in WP 8.4's JSON number adapter, retain
these numeric values through the existing formatters. The shared Float/Float32
serde wrappers use an explicit core YAML float tag on finite decimal spellings,
so they remain floats, including -0.0, in both readers. Non-finite values remain
undotted strings. Integer fields use integer serializers through the i64 limits.
No YAML-only formatter or Java-number spelling tree remains in the parse projection;
its remaining numeric formatting serves Kotlin text rendering only.

The final-view/settings tests and every changed/deleted test are listed in
[8.9-test-changes.md](8.9-test-changes.md). The string properties each exercise
555 hazard/random inputs. They check our loader, the existing differential YAML
reader in a separate process, and equal ordered source data. That permitted reader
uses snakeyaml's YAML-tree helper independently of configuration binding; it
shares the underlying parser and adds no gate dependency. The config corpus test
now round-trips every parseable Marathonfile with a fixed context before checking
the unchanged golden. All 25 loadable configuration fixtures also round-trip.
The corpus example's emitter checks compare data and all its token/binding cases
remain enabled.

The old YAML writer, generic writer values, Java-number wrapper and writer-local
SnakeYAML licence are deleted. KotlinValue remains at its existing module path.
No Kotlin parity row points at a deleted writer-only test. Fixtures, result
comparators and golden files are unchanged. No D-row is needed.

## Review findings

Binary output remains the serde-saphyr scalar, without block wrapping. The native
comparator now decodes core binary-tagged scalars to byte lists, ignoring base64
whitespace. A 76-character-wrapped block and its unwrapped form compare equal,
while changed bytes and an untagged string remain distinct; invalid base64 is
rejected. No writer output or golden is changed by this comparator correction.

Two reader-visible improvements are accepted for WP 8.9:

- Explicit core float tags make PyYAML read unsigned-exponent spellings such as
  `1.0E10` as floats, whereas it read the old untagged spelling as a string. The
  numeric data and the intended float type are preserved; this strengthens
  "floats stay floats" for that reader. No further writer change is needed.
- The old writer emitted a key containing NEL (U+0085), `a\Nb`, in plain form.
  Both PyYAML and our reader folded it to `a b`. The new writer quotes/escapes the
  key and preserves `a\Nb`, fixing the old-writer bug recorded as U184 in
  `docs/found-bugs.md`. `nel_metadata_key_round_trips_without_folding` pins the
  final parse view against loader tokens and the differential reader, each
  compared to the source key.

The deprecated `empty_as_braces` pin is the most likely upgrade break. If
serde-saphyr documents a successor, select its explicit empty-collection mode
and retain the compatibility regression, rather than relying on a new default.
