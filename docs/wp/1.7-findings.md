# WP 1.7 findings

## Implementation and validation

The signed MD5 helper uses the complete signed big-endian 128-bit digest. Fragmentation preserves Kotlin's remainder plus one count correction, including negative-count arithmetic and the minimum signed value with divisor -1; zero returns None for the filter layer to raise its arithmetic error.

Escaping consumes Java regex code points: an emoji becomes one hyphen, not two. The raw UTF-16 entry points also preserve malformed input units. Only test names and serials are escaped; pool names, batch IDs, IDs and chunks keep their original path characters. File paths normalize repeated/trailing slashes while retaining dot components. Folder pool paths use Path.resolve (an absolute pool replaces its parent); file directories use Paths.get varargs (an absolute pool is appended).

Both limits count UTF-16 units. Filename trimming precedes absolute path trimming and can remove the extension, cut inside a directory or split a surrogate pair. Diagnostics preserve the exact Kotlin text, including the missing space after `conflict.` in the filename warning. File directory creation precedes these warnings; folder warnings precede creation of the trimmed folder. Initial NIO validation precedes either. The returned JavaPath may retain a split pair even though later native operations reject it. `createTestResultFile` ignores a failed File.mkdirs, but its initial Paths.get still validates the directory.
