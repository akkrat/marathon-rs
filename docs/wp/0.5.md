## Goal

A scripted ADB *server* that plays one or more fake Android devices. Both of these must be able to drive it:
- the Rust tests, in process;
- the Kotlin marathon through its `adbServers` setting, from a standalone binary.

It replaces adam's `server-stub` in our tests and is the Android side of the differential harness (§6.4).

## Part A: server, DSL, self-tests

1. **Server module** in `crates/marathon-adb` (module `server`, behind a cargo feature `server`, enabled for tests), plus a standalone binary `tools/fake-adb` (workspace member) that loads a device script file and listens on a TCP port. It must serve the subset marathon uses:
   - **host services:** `host:version`, `host:devices`, `host:devices-l`, `host:track-devices` (streaming; the script can add and remove devices over time), `host-serial:<s>:features`, `host:transport:<serial>` and `host:transport-any`, `host:kill`;
   - **shell v1** (`shell:<cmd>`) and **shell v2** (`shell,v2,raw:<cmd>`, the packet protocol with exit codes); **`exec:`**; **`abb_exec:`**;
   - **sync v1** (`sync:` with STAT/LIST/SEND/RECV/DATA/DONE/OKAY/FAIL/QUIT) and **sync v2** (STA2/LST2/SND2/RCV2), working on an in-memory device filesystem;
   - **`framebuffer:`** v1 and v2 headers plus pixel data from a file;
   - **`reverse:forward:`**, `reverse:killforward:` and `reverse:list-forward`;
   - **installs:** streaming (`exec:cmd package install -S`, `abb_exec:package install`), legacy (push, `pm install`) and split sessions (`install-create`, `install-write`, `install-commit`). They are scripted like any shell command, but the server must accept the streamed payloads correctly.
2. **Device-script DSL**, as YAML or JSON (`docs/design/fake-adb-script.md` documents it). A script defines:
   - devices: serial, state, features, `getprop` table;
   - shell expectations: matching (exact string, regex or prefix) → stdout chunks, exit code, delay, an optional "hang until killed", and an optional stream from a fixture file (instrumentation output, logcat). Unmatched commands give a configurable default plus a warning in the transcript;
   - files: the initial device filesystem;
   - events on a timeline: device connect and disconnect, `adb kill-server` behaviour.
3. **Transcript:** every request is recorded (service string, shell command, sync operations with paths and sizes) as JSONL, for the differential comparison.
4. **Self-tests:**
   - Rust unit tests for each protocol service.
   - An integration test that drives the server with the real `adb` client (`/opt/homebrew/bin/adb`, or `$ADB`) using `-P <port>`: `devices`, `shell echo` with v1 and v2, `shell` exit codes, `push`, `pull`, `ls`, `install` of a fixture APK (`fixtures/vendor-android/apk/*.apk`), `reverse`, `exec-out screencap`. The test is skipped with a message when `adb` is missing.
   - Port adam's own server-stub tests where they apply. Fill in and mark the `external` row for 0.5 in `docs/parity-matrix.csv`.

## Part B: validation against the Kotlin marathon (once 0.2a is merged)

5. Run the Kotlin reference build (`tools/oracle`) with an Android Marathonfile whose `adbServers` points at `tools/fake-adb`, using the fixture APKs and a script with two devices. Cover:
   - local DEX parsing;
   - install;
   - a batch with scripted instrumentation output: one pass, one failure, one ignored test;
   - screenshots or video disabled.

   Marathon must finish normally and write its reports. Commit the script and the resulting transcript under `fixtures/fake-adb/` as the first differential scenario. Iterate on the server until marathon runs cleanly; every protocol gap found here is a bug in the server.
