# WP 8.19: Scheduler pool index, plain job storage and sealed completion

Effort **M**. Branch `wp/8.19-scheduler-pool-index`, based on `main` after WP 8.18 (commit `207e5996`).

## Specification

`docs/design/coroutine-quirks.md` (WP 8.17, reviewed by two independent critiques; decisions A–D) is the
specification. This WP implements its §5 row 8.19 and the D-CQ2 draft, in two commits:

1. **Scheduler observes pools through its own pool index** (decision A): read pool `i` from Scheduler's
   retained map, release the borrow, join that pool's actor and supervisor with caller cancellation,
   advance, and stop when the index is absent. Admission contract: every pool admitted before Scheduler
   finds no next index is joined. Aggregate over the joined prefix as the design specifies. This commit
   may keep the old job internals and must be green on its own.
2. **Plain child storage, separate callback storage, count-based sealed completion** (decision B): delete
   the linked spine (`Node`, iterative drop, `append`, `remove_node`, cursor traversal,
   `join_observed_children` and callback marker nodes); parent continuation is count-based; once a
   body-finished parent's last child is removed the parent is **sealed** and rejects new children exactly
   as a completed parent does, with `completed = true` and the callback takeover in one borrow. Never ship
   an attach-during-completion interval.

## Required witnesses (decision D)

Marker connectivity (the intended new outcome); the tail-join late pool (now joined); late admission
around run completion in both orders of final pool completion versus a Connected event, and a Connected
event whose history prefetch finishes after traversal ends (explicit gates, not equal timestamps); a
callback attaching failing work does not change a sealed parent's `Success`; supervisor isolation;
attachment while the parent is Cancelling; reentrant cancellation with another child pending; an
already-cancelled spawned task never enters its body; the design's deep/wide chain tests.

## D-row

Add **D65** to PLAN.md §3.11 from the D-CQ2 draft. It must say: rc.1 can miss a pool admitted during the
final join (spurious "Expected to run … but no events received" failure, or a green run without that
pool's tests); 8.19 joins every pool admitted before the scheduler finds no next pool, so a run can end
later and report the correct outcome; callback and diagnostic ordering moves; completing parents are
sealed; exit-code **policy** is unchanged (a corrected outcome can select a different existing status).
D48 (late pool, 201,000 ms) and D52 (24,000 ms) hold. (D63 is reserved for WP 8.16, D64 is WP 8.18.)
