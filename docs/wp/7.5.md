## Queue discovery, classification and mapping

Use full immutable SHAs, not commit dates or a floating default branch. Read-only local discovery:

```sh
mrs_source=$MARATHON_KT
mrs_base=e47352f25cbc50333900d5d040a5544ff1224501
git -C "$mrs_source" rev-parse HEAD
git -C "$mrs_source" for-each-ref --format='%(objectname)' refs/heads refs/remotes
git -C "$mrs_source" rev-list --count --all "^$mrs_base"
git -C "$mrs_source" log --all --ancestry-path --reverse --topo-order --format='%H %P' "$mrs_base.."
```

The broad count is diagnostic only. The orchestrator names the authoritative release SHA and confirms freshness, refreshing the upstream refs in a disposable clone if needed. Record that clone's resolved SHA, without its sensitive ref names. Require `git merge-base --is-ancestor "$mrs_base" "$mrs_release"` before using a linear drain procedure. A non-descendant/rebased target needs an explicit reconciliation decision (Q1); do not silently substitute its merge base or port unrelated branches.

For the chosen descendant target, in the disposable clone:

```sh
git rev-list --count "$mrs_base..$mrs_release"
git log --reverse --topo-order --format='%H %P' "$mrs_base..$mrs_release"
git diff --name-status -M "$mrs_base" "$mrs_release"
```

For **every** commit in that range, inspect `git show --format=fuller --stat <sha>`, full patches and changed tests/resources/build dependencies. Use `git diff-tree --root -r -m --name-status -M <sha>` and parent-specific diffs for merges: first-parent-only review can miss side-branch changes or merge resolutions. Deduplicate by full SHA, retain reverts/empty merges, and reconcile the complete ledger with the final tree diff. Patch equivalence or an already-present Rust implementation is evidence for a disposition, never grounds to erase a row.
