# WP 4.4 findings

Implementation of `docs/wp/4.4.md` (orchestrator decisions of 2026-10-25), on `wp/4.4-apple-env`,
stacked on `wp/4.3-connection-factory` (decision 3). 38 Kotlin sources (the 37 of the brief plus
`test/TestRequest.kt`, decision 2) and 50 Kotlin test rows.

## Consumer API

All in `crates/marathon-apple`; every module starts with its `//! Port of` header.

- `bin::Tools { executor: Executor, timeouts: Arc<AppleTimeoutConfiguration>, runtime, logging: SshLogging }` is
  what every wrapper holds (Kotlin passes executor and timeouts to each constructor; the runtime is for
  off-core decoding, the logging handle is 4.3's registry + sink). `Executor` is 4.3's `Arc<dyn CommandExecutor>`,
  so local and SSH executors both work. Constructing anything runs nothing and neither acquires nor disposes of
  a connection.
- `bin::AppleBinaryEnvironment::new(executor, &Configuration, AppleTimeoutConfiguration, runtime, logging)` and
  `with_tools(tools, test_batch_timeout_millis, test_output_timeout_millis)`; fields in Kotlin order
  (`codesign`, `csrutil`, `sqlite3`, `getconf`, `lipo`, `nm`, `plist_buddy`, `xcodeselect`, `ioreg`,
  `system_profiler`, `swvers`, `chmod`, `xcrun { simctl, xcodebuild, xcresulttool }`), loggers looked up in that
  order under the Kotlin class names. `src/bin/` is a module, so the crate sets `autobins = false`.
- Every wrapper method is `async fn …(&self, …, context: &VendorContext) -> VendorResult<T>` and uses the merged
  `critical_execute`/`safe_execute`/`safe_execute_nohup` exactly where Kotlin does; the vararg overloads' 7-day idle
  timeout, empty env, no workdir and the host charset are in `Tools::request`. Safe calls return `Ok(None)` only for
  the two transport classes (merged helper); other errors and cancellation propagate.
- `simctl.device.list()/list_devices()` return 4.3's `ConnectionResult<T>`: command failures are
  `ConnectionError::Vendor`, ServicesUnavailable is `ConnectionError::Device(DeviceFailureException)`, so the reason
  stays typed; `into_vendor()` is the Failure projection (decision 3).
- `xcrun.xcodebuild.test_without_building(...)` returns the live `CommandSession` (consumption/close: 4.8).
  `bin::xcrun::xcodebuild::simulator_test_args(user, Option<XcodeVersion>)` is the simulator helper 5.2 calls;
  macOS passes user arguments directly. Ordered maps are `Vec<(String, String)>` with `LinkedHashMap.put`
  semantics (config's `xcodebuild_test_args` is `Vec<(String, JavaString)>`; the caller converts).
- `xcrun.xcresulttool.get::<T: LegacyDecode>(path, Option<XcodeVersion>, ResultBundleFormat, id, version, ctx)`
  decodes with 4.6's `decode_legacy` through `runtime.spawn_blocking`; `merge(output, paths)`;
  `bin::xcrun::xcresulttool::describe_timeout(&effective)` is the startup line (decision 5).
- `test::TestRequest` (moved from 4.7, decision 2) with `to_xcodebuild_test_filter()`; 4.7/4.8 reuse it.
- `model::{XcodeVersion, AppleOperatingSystemVersion, Sdk, Arch, Os, Platform, AppleTestBundle}`.
  `AppleTestBundle::new(app, runner, xctest, sdk, runtime, logging).await` reads the application's then the test
  bundle's Info.plist off core (Kotlin's `appId`/`testBundleId` initializers force both lazies at construction);
  `test_binary()`, `test_runner_binary()`, `application_binary()` are async, scan on first use, cache a success and
  retry after a failure (decision 4). It implements core `TestBundle::id()` with the `File.getAbsolutePath`
  spelling; paths are held `java.io.File`-normalized (repeated/trailing slashes collapsed, `.`/`..` kept).
  `BundleRef` identity is untouched.
- `bin::xcrun::simctl::model::decode_list_devices_output(&str)` is exposed for tests and consumers that already
  hold output.

## Decisions applied

1. **P1** (approved): version components and the `isRunning` runtime major parse as ASCII `i32`; Xcode versions
   compare lexicographically. Witnesses: oracle `XcodeVersion/１４.0` and `AppleOperatingSystemVersion/１７` parse in
   Kotlin, fail in Rust; `sim.running/１６.0/*` takes the `<16` branch in Rust; `XcodeVersion.compare` with
   `Int.MIN_VALUE` (Kotlin says greater) and `patch MAX` vs `-1` (Kotlin says less) are ordered numerically. Overflow
   itself (`2147483648`) fails/falls back identically.
2. **P2** (approved): fixture and real-tool shapes decode exactly as Gson (field names, A8, scalar-to-string,
   `Boolean.parseBoolean`, unknown/null/non-string states → Unknown, `ShuttingDown` accepted via `toString()`, JSON
   object order with a repeated key replacing in place, devices without state/name/udid dropped). Every other shape
   is one ServicesUnavailable `Error parsing simctl output on <host>: <stdout list>`. Measured Kotlin differences
   (all in `probes.jsonl`, replayed by `deviation()` in `apple_bin_oracle.rs`): missing `devicetypes`/`runtimes`
   and `null` lists (Kotlin returns nulls, later NPE), `null` list elements, `name: null`/`{}`
   (`UnsupportedOperationException`), lenient JSON (Kotlin accepts unquoted/single-quoted names), empty output and
   `null` (`NullPointerException: fromJson(...) must not be null`).
3. **P3** (approved): `SimctlListDevicesOutput.supportedDeviceTypeIds` not ported.
4. **Decision 2**: `scripts/source_inventory.py` rule moved `test/TestRequest.kt` to 4.4; inventory regenerated
   (commit b768e88).
5. **Decision 3**: `DeviceFailureException`/`DeviceFailureReason` and `ConnectionError` reused from 4.3; no new
   error enum. Other Kotlin exceptions are `Failure`s with the Kotlin class names (`DeviceSetupException`,
   `ConfigurationException`, `IncompatibleDeviceException`, `CommandException`, `NumberFormatException`, …).
6. **Decision 5**: 4.4 supplies `describe_timeout` and `simulator_test_args`; the INFO call belongs to
   **5.5a** (`ios/.../AppleSimulatorProvider.kt:157`) and **5.6** (`macos/.../AppleMacosProvider.kt:82`), once at
   provider startup; **5.2** owns the `simulatorTestArgs` invocation (`AppleSimulatorDevice.kt:683-684`). Parse
   warnings carry 4.6's structured failure as the cause.

Smaller choices (no decision needed, flagged for review):
- Env maps reach the executor as `BTreeMap` (sorted); Kotlin passes `LinkedHashMap` order. Local executors apply
  env as a set and SSH drops it (A2), so nothing observable changes; the oracle replay compares env sorted.
- `AppleTestBundle` errors: a missing Info.plist is `java.nio.file.NoSuchFileException` with the path (as
  measured); a wrong-typed key is `ClassCastException` with 4.5a's message (Kotlin's names JDK classes); an
  unopenable candidate binary is `FileNotFoundException "<path> (Permission denied)"` without Kotlin's NIO cause.
- `Nm`'s warning reproduces Kotlin's `trimIndent()` *after* interpolation (a multi-line stdout disables the
  dedent), via `bin::kt::trim_indent`; `bin::kt` holds the Kotlin `trim`/`isBlank`/`lines` used on command output.

## Review round 1

Reviewer: Sol (cross-family). Verdict: merge after fixes. Agreed with P1–P3, all 50 ported rows, the typed
`ConnectionResult`, the env `BTreeMap`, bundle staging and caching, the logging handoffs, `autobins = false` and the
self dev-dependency.

| Finding | Severity | Resolution |
|---|---|---|
| R1-sol-1: `AppleTestBundle::scan` resolved the macOS binary directory (`java_absolute`, which reads `current_dir()` for a relative path) on the caller's thread | Medium | Fixed. `binary_dir` is now a free function called inside the `blocking` closure, so the working-directory read runs on the blocking pool (lifecycle.md). No new test: the closure is the only place the read happens, and a runtime cannot observe which thread read `current_dir()` without instrumenting the standard library. The existing macOS bundle rows still cover the result. |
| R1-sol-2: the wire test accepted an unmatched merge command | Medium | Fixed. The test now compares the complete decoded exec strings with the scripted wires in order, requires one `route` event per exec with no `unmatched command` warning, and reads the env check from the event's `detail`. The old checks read top-level fields that the transcript nests under `detail`, so they passed vacuously. Prefixing the merge wire with `WRONG` now fails the test. |
| R1-sol-3: the fake worker's temporary directory outlived nothing explicit | Low | Fixed. The test drops the environment, closes the executor, awaits `worker.shutdown()` and only then drops the temporary directory. |
