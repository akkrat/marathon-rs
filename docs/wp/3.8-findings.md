## API for WP 3.10

`Scheduler::new(SchedulerParts)` followed by `execute(&self) -> VendorResult<bool>`.
The parts supply the concrete `Rc<CoreExecutor>`, provider, shared `Arc<Analytics>`,
configuration, prepared TestShard, tracker, timer, optional bundle identifier,
replay hooks/barriers, Ci, OutputDriver and the run's TaskContext.

Map `RunDependencies.provider`, `.analytics`, `.bundle_identifier` directly;
tracker, timer, hooks and barriers come from its vendor dependencies. Construct
OutputDriver with that vendor runtime and the run's console sink. Pass the same
concrete core executor that constructed RunDependencies; do not try to downcast
its `Rc<dyn CoreRuntime>`. Ci and the shard are Marathon's existing run inputs.
The context is the run's supervised child, not Scheduler's detached job.

The subscription is a child of that context. Every pool actor and its separate
supervisor are siblings under Scheduler's detached ordinary job. Queue/device
actors are children of the supervisor. `execute` does not terminate the provider,
close reports, perform the empty-test guard, or map NoDevices to an exit code;
those remain WP 3.10. A NoDevices timeout leaves the subscription running.

`DevicePoolActor::spawn(PoolParts) -> DevicePool` retains the actor, queue handle
and supervisor. Keep the long-lived pool actor handle: devices and queue refer to
it weakly. The test-only `spawn_observed` observes newly created device actors;
no production state inspector or mutation seam was added.

## Decisions and answers to WP 3.7

- **S1 / decision 2:** the three EstimateHook tests use BeforeExecute, preserving
  their injection point despite history prefetch occurring before device arrival.
- **S2:** pools and accumulators iterate in creation order (IndexMap), not Java
  ConcurrentHashMap bucket order. Broadcast log interleaving and which failing
  pool logs aggregate errors can differ, as explicitly approved.
- **S3:** safeSend is an ignored try_send on core. The cross-thread check/send
  race is not recreated.
- **S4:** prepare is awaited in the subscription loop after creating the
  accumulator and before inserting the pool. Failure ends that subscription;
  there is no retry or fallback. A slow metrics prefetch can therefore make the
  first-device wait expire where Kotlin would already have inserted its pool.
- **S5:** characterization asserts first wave, makespan and idle device time;
  request/wake counts are printed, not asserted.
- `execute` propagates `VendorError::NoDevices` with an empty message, and any
  accumulator error. Tracker.device_connected is awaited inside the subscription.
- **3.7 question 1:** pool termination waits for IsEmpty or queue completion
  before cancelling the supervisor and closing its own mailbox. Tests exercise
  both branches, closed-queue sends and discarded messages behind Terminate.
- **3.7 question 2:** Scheduler locks each SharedProgress before aggregate_result,
  and stops at the first false. Its child traversal uses join_observed_children_in,
  not a snapshot or a wait-for-all-future-pools loop.

**Reviewer-approved deviation from the full-trace acceptance:** the committed
ordered JVM pool/queue message and log transcripts are diagnostic evidence, not
an exact global Rust transcript comparison. Off-core vendor completion and the
queue's async tracker/output boundaries can order Terminated versus queue
completion differently. One observed example is the final removal test: Kotlin
shuts down through onQueueTerminated; Rust can process the device's Terminated
first and log the independently confirmed B4 error. Both handlers and both
shutdown paths are retained and tested. Reproducing one global dispatcher order
would require extra test-only scheduling controls across already merged actors
and output delivery. Under the pragmatic-parity direction, both round-1
reviewers agreed to the outcome/invariant projections here; this is **not** a claim
that full transcript parity passed. No production scheduling deviation is proposed.

The three actor-child failure scenarios use the approved WP 3.6 decision-6
vehicle: a test child fails the actual device actor's job, because VendorContext
has no coroutine Job. Each test explains that choice; both round-1 reviewers
agreed to this substitute, as required by the brief. Initial device arrivals that require a particular first
batch have explicit quiescence checkpoints, and a FIFO Gate models deferred
waiter order. No wall-clock sleeps or direct Tokio time calls are used.

**Repeated runs:** the 22 scheduling and 8 accounting tests passed **50** complete
iterations (1,500 scenario runs). The accounting shutdown case loops 50 times
inside each invocation (2,500 interleavings in that run). C27 and Scheduler's
mid-traversal pool case each additionally loop 50 times in the ordinary suite.

All four Sol findings and Claude's stale-SHA nit were addressed:

- **R1-sol-1:** every path to pool termination now passes the receiver's
  TaskContext. Cancellation escapes awaitQueue before supervisor cancellation
  or self-close. The blocked-queue regression asserts that the owner completes
  with the original reason while the queue and its supervisor remain active.
- **R1-sol-2:** Scheduler cancels the detached job, then uses join_in with the
  caller's job. An external Timeout cancellation retains its scope and exact
  failure instead of becoming NoDevices. The regression pins that error for
  WP 3.10 and also verifies detached-job cancellation. Existing own-timeout
  tests continue to require NoDevices with an empty message.
- **R1-sol-3:** provider receive first polls buffered/terminal state; only a
  suspended receive races caller cancellation. The same pending receive is
  retained. The regressions cover a buffered disconnect after cancellation,
  normal/exceptional close before cancellation, and prompt cancellation after
  suspension even if the channel closes before the receiver resumes.
- **R1-sol-4:** serial filtering uses checked as_utf8 and propagates an
  IllegalArgumentException identifying Scheduler's serial filter and unpaired
  UTF-16 surrogates. Connected and Disconnected regressions use a lone high
  surrogate with a replacement-character include regex, assert subscription
  failure, and ensure no pool or tracker connection is created. This follows
  D6/model-contract.md; it adds no Kotlin bug row.
- **R1-claude-1:** the rebased hook is `d6d4a9d` and the main base is `2539f75`.
