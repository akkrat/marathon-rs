# WP 8.12 test changes (D62)

The approved design is [8.12-design.md](8.12-design.md). D62 removes the reader
poll schedule, the 20 ms margin and wall-hook timing; line contents, failure
kind/message, A24 tail rejection, A25 channel lifetime and D19 terminal output
remain covered. No copied fixture, tape, evidence JSON or native golden changes.

## Shared helpers and unchanged regression coverage

- `marathon-apple/tests/reader.rs`: replace the non-waking stream, atomic liveness
  predicate and millisecond-by-millisecond poll stepping with a stream that
  registers/wakes its reader, explicit EOF, a watch end signal and direct
  paused-time advancement. Capacity-one channels and single-poll helpers gate
  ordering rather than assuming an interleaving. The stream also records its
  polling thread for the production runtime assertion.
- `marathon-apple/tests/support/mod.rs`,
  `marathon-test-support/tests/support/mod.rs`,
  `marathon-ios/tests/support/mod.rs`, and
  `marathon-macos/tests/support/runtime.rs`: add `VendorClock::now_millis`
  using the same elapsed paused-time source already used by `delay`.
- `marathon-apple/tests/support/ssh.rs::GatedTimeoutClock`: forward elapsed
  vendor time as well as delay. The existing scaled clock already does this.
  These helper changes do not change any other test expectations.
- `marathon-core/tests/contracts.rs::transport_contract`: the illustrative
  transport seam now reads vendor time instead of the retired reader wall
  hook; retain the separate simulator monotonic hook. This is a compile-time
  helper, not a renamed or deleted test.
- `marathon-apple/tests/local_executor.rs`: add fallible marker/file helpers
  for the two new process tests. Test commands wait on release files, with
  short sleeps only for external work and a 60 s hang watchdog. No real-time
  upper-bound assertion is added.

Existing `line_buffer`, `command_session_output`, local/SSH executor suites,
D32 command-prefix tests, D37 flow-control tests, D31/D43/U158 rsync tests and
U163 stalled-send witnesses keep their expectations. The production-runtime
suite checks existing command execution wiring. Long ignored U163 tests remain
ignored; a green default gate does not claim they ran.

Focused verification covers the Apple library, reader, local executor, SSH
session and production-runtime suites, plus core replay hooks/contracts.
The final report records the full foreground `scripts/check.sh` result,
including native vendor differentials, the configuration corpus and metadata
checks. `git diff 816e0000 -- fixtures/` must remain empty.

The initial full gates and an isolated differential reproduced the documented
A20/U116 event-before-line log-window race: a complete test line could move
between its test log and the batch log, or a start line could remain in a test
log. All transport lines and outcomes were present. No golden allowance,
normalization or copied evidence was changed.

## Differential-only event/line gates

Removing the reader's timer changed scheduling enough to expose A20 reliably.
The hermetic `marathon-cli/examples/differential_cli.rs` now explicitly enables
a `test-support` seam in `xcodebuild_session`: deliver the line, enqueue its
event, then await the event handler's acknowledgement before the next line.
This selects the valid A20 handler interleaving pinned by the existing native
goldens, with notifications instead of elapsed-time assumptions. The example
has a dev dependency on `marathon-apple`'s existing test-support feature; the
lockfile records that edge, with no new package or version. The differential
registry is explicitly regenerated: its only changes are the 16 input hashes
for the edited probe example. Scenario inputs, evidence inventories, factory
fingerprints, normalization and all native golden bytes are unchanged.

Production `send_line` still sends its event before delivering the line, and
does not await handler acknowledgement. The opt-in seam is never enabled by
the production CLI. `execute_test_request` delegates the event/line boundary
to this helper; `AppleDeviceTestRunner` and the XCTest discovery consumer acknowledge handled events only in
test-support builds (a no-op outside the opted-in probe). The existing A20
interleaving tests remain unchanged. This changes capture scheduling, not the
production contract, configuration, commands, result data or golden files.
