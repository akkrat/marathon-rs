## Frozen 0.6 traits

**No changes.** Production takes `Arc<dyn VendorRuntime>` and `VendorContext`;

## Scope and decisions

All 17 assigned main sources are covered. `ConfigurationExtensions.kt` was
already moved to 2.3a in the merged inventory rule; no inventory change was
necessary. Related value types share `cmd/mod.rs`, and local session operations
share the local executor module. `CommandSession`/`BaseCommand` are concrete;
`CommandExecutor` and `FileBridge` use static dispatch within Apple. There are
no Apple transport trait objects. The boxed callback functions in
`SessionControl` allow the concrete session to support 4.2's captured isAlive,
backend signals and asynchronous close without imposing local process rules.

- P1/P4/P6 are implemented and recorded as D10 in PLAN §3.11. Charset remains
  in the request/host API but decoding is UTF-8 with replacement, incrementally
  across chunks. Pending async reads do not block the idle check or change
  the poll schedule. Complete lines are sent immediately; tails are drained
  on canRead=false. Idle expiry closes before drain and loses the partial tail
  (A24); pipe EOF while canRead=true keeps polling until idle expiry (A25).
- P3 is implemented: unused `Reader.produceLines` is omitted. No test row is
  dropped for it; `produceLinesManually` and its six live rows are ported.
- P2 was rejected: total timeout completes the exit cell with None and leaves
  the child running. Explicit close is required, just as in Kotlin (A21).
- Conditional P5 is **not applied**. Converting cancellation to an ordinary
  failure would change DeviceActor control flow (lifecycle.md), so await keeps
  `VendorError::Cancelled(Requested(...))` with the original timeout cause,
  while consume_output preserves the original failure (A22). drain returns
  immediately and later failures stay inside its detached collectors (A26).

Command requests retain env, workdir, charset and signed durations. Helper
composition catches only the two named transport failure classes around both
execute and await, retains criticalExecute's unusual indentation, and builds
the unquoted nohup argv exactly. Logger names come from the per-run registry;
construction receives an ERROR-message sink for the run's output plumbing.
No process-wide logger registry or clock is introduced.

## Ownership and cancellation

Process spawn and recursive copying run through VendorRuntime.spawn_blocking;
process monitoring, readers, exit-code timeouts and detached collectors run
through VendorRuntime.spawn. There are no direct production tokio time calls.
Reader wall time uses `apple.Reader.currentTimeMillis`; scheduler delays and
total timeouts use the injected VendorClock. The reader uses 16 KiB chunks,
shared last-output time, 20 ms grace and the Kotlin PollBackoff sequence.

The bounded line queue distinguishes normal close, failure close and receiver
cancellation. Close preserves queued lines, cancellation discards them and
wakes blocked producers. consume_output's cancellation guard is its Kotlin
finally; it cancels receivers on every exit, including dropped futures. It
never closes the session or sends process signals.

Await/drain collectors belong to the detached session scope on the vendor
runtime. drain returns immediately after starting its collectors (A26).
Cancelling an awaiter leaves those collectors and the process alive.
Execute retains session ownership across delivery: if its caller drops during
spawn or before taking a queued session, the vendor task closes and joins it.
Explicit close is started as a retained vendor task: concurrent close callers
join it and dropping one close awaiter cannot abort cleanup. A failed close releases its
cached task, so a later explicit close can retry backend close/join (needed
for SSH A14); successful close remains joinable. Local close waits
for signal dispatch before cancelling/joining the session scope. The child
reaper remains independent, equivalent to JVM process reaping; total timeout
and scope cancellation do not destroy the process. No Drop implementation
performs process or session cleanup. TERM and KILL are synchronous signal
requests; their dispatch/reaping runs on the vendor runtime. Executor close
is a no-op and connected stays true.

The copy probe corrects the brief's suggested swallowed-errors assumption:
Kotlin's **default** copyRecursively error callback rethrows. Accordingly send
propagates missing-source and copy errors; receive alone has the explicit
missing-source false branch. Copying uses new file streams so source execute
bits are not preserved, matching the oracle rather than std::fs::copy.
A final launch probe also confirmed JDK parent-PATH lookup, unlike Rust's
child-environment PATH lookup. The executor resolves the program using the
inherited PATH when that environment entry is overridden, while passing the
requested PATH through unchanged to the child. A controlled-binary regression
checks both missing parent-PATH entries and successful inherited lookup.
The generic suite retains the original Kotlin total/idle timeout arguments,
including the 10-second buffering timeout and 10-minute interruption cases.

## Carried to WP 4.2 (review round 2, Muse Wonder Full)

These are minor items, not fixed in 4.1. WP 4.2 adapts the SSH streams to this executor.

- **R2-wonder-1:** `receive("…/file/", dir)`. Java's `File("file/").exists()` is true for a file, but Rust's `Path::exists()` is false, so the Rust bridge copies nothing. Exotic.
- **R2-wonder-2:** `spawn_blocking` bodies call `tokio::process::Command::spawn`, which needs a Tokio context. State this requirement on the `VendorRuntime` contract.
- **R2-wonder-3:** a `poll_read` error ends the reader normally. In Kotlin, a `read()` failure propagates as the channel cause. Matters for SSH streams.
- **R2-wonder-4:** the failed-close retry clears `close_task` before its joiners return, so a concurrent `close()` can overlap a second backend close.
- **Nits:** `LineChannel::cancel` overwrites an earlier close cause, where Kotlin keeps the first; `LineChannel::new(0)` panics, where Kotlin's `Channel(0)` is a rendezvous; `SessionScope::close` stops at the first join error; combined output hardcodes `"\n"`.
