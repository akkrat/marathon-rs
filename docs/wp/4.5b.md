## Proposed simplifications — orchestrator approval required

None is decided by this draft; keep ordinary file bytes/commands exact.

- **P1:** native secure temp allocation with the UDID prefix, literal suffix and owner-only access, without reproducing the JDK random-number/provider algorithm or collision retry sequence. PLAN §6.4 already compares these files through pushed bytes; retain full lifetime/cleanup tests.
- **P2:** reject lone-surrogate **xctestrun env values** with a field-specific error when crossing config's lossless `JavaString` into 4.5a's UTF-8 plist strings; do not add a UTF-16 plist writer solely for this input. D9 does not already approve this (string values reaching output stay lossless). Valid Unicode/XML-sensitive strings remain byte-exact.
- **P3:** assume local bundle trees are stable during one generation: preserve ordinary missing/unreadable/listing outcomes but do not emulate JDK-specific filesystem races while directories are concurrently replaced. Do not introduce canonicalisation or extra existence checks, nor change any worker-side failure handling.
