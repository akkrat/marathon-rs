## Implementation and consumer handoff

**Changed merged crate: marathon-apple only.** Added
`xctestrun::test_root_factory`, `distributed_derived_data::require_distributed`
and `generated_file::push_generated_file`, module exports and tests. Cargo.toml
adds normal `tempfile` (already locked) and dev-only `marathon-test-support`;
Cargo.lock adds the latter dependency edge. No existing model, plist writer,
binary wrapper, manager, device trait or core/config/jcompat implementation was
changed. Neither marathon-test-support nor fake-worker needed a source change.

`TestRootFactory::new(device, env, xcresult, skip_copying_derived_data, runtime)`
borrows the device and configurations; the explicit vendor runtime handles
blocking temp allocation, writing, removal, relative-path cwd lookup and local
runner directory listing. `generate(test_type, bundle, use_xctest_parser,
context).await` returns `FactoryResult<()>`. It consumes the concrete
AppleTestBundle and merged v2 constructors/writer. Async filesystem operations
handle the remaining local probes. Call it on the vendor runtime through the
existing bridge and await completion, including cancellation cleanup.

`FactoryError::DeviceFailure { reason, detail }` retains the platform mismatch's
IncompatibleDevice reason and original DeviceFailureException class, distinct
from `FactoryError::Vendor(VendorError::IncompatibleDevice)` for a macOS version
failure. DeviceSetup and Transfer use the corresponding frozen VendorError
variants; ConfigurationException, NotImplementedError and plist failures retain
their classes under Other. Cancellation stays Cancelled. `failure()` provides
the original Failure; `into_vendor()` is for crossing the core bridge **after**
vendor-local reason handling. 4.10b/5.2 must retain the adapter until then; the
core enum has not changed. Plist failures use 4.5a's approved P4 distinctions and
text, matching the existing bundle adapter (missing-key text stays exact).

4.10b reuses `require_distributed(device, local, remote_bundle, required,
error_constructor, context)`: its constructor receives a lossless JavaString.
The file's inventory row stays 4.10b with the approved split note, generated by
scripts/source_inventory.py; requireDistributedTestBundle remains 4.10b.

5.2's `AppleDevice::push_generated_file` override should delegate to
`generated_file::push_generated_file(device, src, dst, ssh_debug, shell_timeout,
logging, context)`. The helper calls merged WriteFile only for non-debug SSH
and a local file length at most 32 KiB. It returns cancellation without a file
bridge fallback. False, unsafe destination and oversized files fall back through
`device.push_file`, preserving its future transfer measurement. macOS retains
the AppleDevice default unless its source says otherwise.

## Decisions, scope and limitations

All final orchestrator decisions and approved P1/P2/P3 are applied. Temp naming
uses native secure allocation, preserving prefix/suffix/access/lifetime rather
than JVM random-provider details. Env values cross into the existing UTF-8 plist
model with field-specific surrogate rejection. Local bundle trees are assumed
stable during one generation. No additional behavioral deviation is proposed. The native allocator preserves
the JDK rejection of slash-containing prefixes (tempfile itself permits them).

Normal construction cannot reach the factory's absent-application guards (A27).
The oracle clears the already-constructed bundle's application field solely for
those defensive-branch witnesses; Rust uses its public vendor-owned field.
The script documents this and its JDK-21-only write-failure hook. The local
staging writer unit seam is private; no production test hooks or alternative
filesystem API were added.

No real signing/Xcode/worker integration was attempted. 4.10b owns initial
bundle distribution, installation and retries; 5.2/5.6 own concrete device
preparation. The orchestrator owns independent reviews and remote-check before
merge. There are no implementation-blocking open questions.

## Review round 1 (Claude, cross-family)

Verdict: merge. The reviewer regenerated the 183 JVM cases byte for byte, confirmed that the real-bundle smoke bytes match, and found the gate clean. They agreed with P1–P3, `require_distributed`, the generated-file helper, the error adapter and the reduced harness for the 4 rows. A9, A28 and the new rows are accurate.

- **R1-claude-1:** fixed. `tempfile` is pinned to `=3.27.0`, as in the other crates, because the prefix guard and the oracle depend on that version.
- **R1-claude-2:** deferred, as a follow-up for 5.2. `From<PlistError>` here duplicates `model/apple_test_bundle.rs` `plist_failure`, and the two differ on `Io`: this one uses `to_string()` and has no `NoSuchFileException` arm. The same plist I/O failure can therefore read differently depending on where it is raised. 5.2 unifies them into one `pub(crate)` adapter when it adds the third caller.
- **R1-claude-3:** consumer note. `FactoryError::DeviceFailure` (lossless JavaString) sits alongside 4.4's `DeviceFailureException` (String). Two catch sites must classify by reason before calling `into_vendor()`:
  - 5.2, at `AppleSimulatorDevice.kt:501`, where `failuresNotFixedBySetup` (`:115`) includes IncompatibleDevice;
  - 5.6, at `MacosDevice.kt:363–365`, which rethrows it as `IncompatibleDeviceException`.
- **R1-claude-4:** a comment now records that cleanup relies on cooperative cancellation.

On merge the orchestrator renumbered this WP's rows: A47 became A54 and A48 became A55. 4.7 had already taken A47–A49 on main, and A50–A53 are reserved for 5.4.
