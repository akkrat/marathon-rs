## Public API and WP 3.10 integration

`marathon_core::filter::TestFilter` is a closed enum with all eleven runtime
variants. `TestFilter::from_config(&TestFilterConfiguration, &FilterDependencies)`
recursively constructs children in declaration order without validation or I/O.
The three decisions already owned by config remain there: regex compilation,
logical validation, and lawful config equality/hash behavior.

`filter(Vec<Test>, &dyn VendorRuntime)` and `filter_not` return
`ServiceFuture<'_, Vec<Test>>` / `OperationResult<Vec<Test>>`. Every call runs
the complete ordered predicate loop through `VendorRuntime::spawn_blocking`,
owns its `VendorTask`, and awaits its protected join before receiving the result
from a Tokio oneshot. No blocking lock, filesystem call, environment read or
predicate scan occurs on core. A service failure preserves `Failure` class,
nullable message, causal chain and stacktrace; a service or task cancellation
remains `OperationError::Cancelled`. The lifecycle test stalls the reader on
a worker, releases it from core, and checks the result only after completion.
It separately checks typed cancellation and an intact causal chain.

**Caller contract:** await operations to completion; do not drop their future
to cancel synchronous Kotlin filtering. Kotlin's synchronous loops introduce
no suspending cancellation checkpoint. Dropping the future would detach its
blocking task, as with the merged vendor bridge. The operation does not infer
ambient caller cancellation. Calls on one filter can share synchronized lazy
state; clones are references to the same logical filter, not fresh caches.
Construct a fresh enum when Kotlin calls `toTestFilter()` again.

`FilterDependencies` contains:

- `Arc<dyn FilterValuesReader>`: synchronous, fallible, called only in the
  blocking task at the first actual leaf predicate. `FileValuesReader` supplies
  the real UTF-8/readLines/comment/missing-file behavior.
- `Arc<dyn AllurePlanSupplier>`: synchronous, fallible and lazy per Allure
  filter. `FileTestPlanSupplier` uses an injected `PlanEnvironment` and
  `FilterLogger`; `ProcessEnvironment` reads the real environment at supply,
  not construction, using the JDK-compatible UTF-8 replacement decoder.
- `Arc<AnnotationRenderer>`: projects frozen typed metadata through
  `KotlinValue`, Java numeric formatters and `DecodedWrapper::kotlin_value`.
  Its constructor takes the run's `ReplayHooks`, the run's DecodedNull singleton
  `ObjectIdentity`, and the run's shared token allocator. Share the renderer
  and allocator with metadata/report consumers. Array identities are tracked
  using weak references and allocated tokens; addresses never become output.
  Labels are `metadata.decoded_null.identity` and `metadata.array.identity`.

`FilterLogger::log(level, logger, JavaString, Option<Failure>)` is an off-core
sink. The output integration forwards these records to its run-owned logging
service, retaining the supplied logger name, level, message and cause. It must
not route callbacks directly to the core-only `Rc<LogQueue>` from a worker.
No environment, plan, reader or identity cache is global.

The compiling example `crates/marathon-core/examples/filtering.rs` demonstrates
exactly `Marathon.kt:252–256`: sequential allowlists, then sequential blocklists,
each constructed at its original call boundary. WP 3.10 calls this selection
before sharding on both run and parse paths (`Marathon.kt:163–171`), and owns
no-tests/exit policy. No run flow, CLI wiring, reporter or plan-DAG changes were
made here.

## Source and behavior accounting

All fourteen inventory-owned Kotlin sources are covered; the shared
`ConfigurationExtensions.kt:62–75` slice remains inventoried under 3.2.

| Kotlin source(s), under `execution/filter/` | Rust source |
|---|---|
| `TestFilter.kt`, shared factory slice | `filter/mod.rs` |
| `SingleValueTestFilter.kt`, `SimpleClassnameFilter.kt`, `SimpleTestnameFilter.kt`, `FullyQualifiedClassnameFilter.kt`, `FullyQualifiedTestnameFilter.kt`, `TestMethodFilter.kt`, `TestPackageFilter.kt`, `AnnotationFilter.kt` | `filter/single.rs` |
| `FilterValuesFileReader.kt` | `filter/values.rs` |
| `AnnotationDataFilter.kt` | `filter/annotation.rs` |
| `FragmentationFilter.kt`, `CompositionFilter.kt` | `filter/mod.rs` |
| `AllureTestFilter.kt`, pinned Allure dependency | `filter/allure.rs` |

Ordinary disabled filters return the input sequence for both operations. Empty
ordinary input never reads a values file. Explicit values, including an empty
list, win over files. A successful missing-file result and its single ERROR
are cached; read failures retry. Values preserve order, duplicates, BOM and
JDK malformed-byte replacement. The built-in comment regex uses ASCII whitespace
and Java end-anchor behavior, while trimming uses Kotlin whitespace.
Invalid legacy File paths (NUL) behave as missing, while Allure NIO paths WARN.

Composition membership uses hash sets only for lookup. UNION retains the first
representative in child/result order; INTERSECTION and SUBTRACT retain left
representatives. All children run at the source boundaries, including an empty
intersection; SUBTRACT's later children receive the original first result, and
zero/one child invokes nothing. Composition blocklists use an ordered set
complement, unlike ordinary leaf blocklists. Metadata is retained unchanged.
Fragmentation reuses signed MD5/Java remainder primitives, including zero-count
failure only on nonempty enabled input.

Annotation-name regex takes precedence over values for directly constructed
invalid configs. Annotation-data predicates match name and value on the same
entry, preserve scalar/list/map rendering, and apply the first `(value=` / `)`
substring rules to each object-array element. DEX wrapper identity/truncation
is retained end to end through the actual merged `to_meta_property` producer.
Checked regex conversion gives field/pattern context for malformed UTF-16;
literal values keep lossless JavaString equality.

Allure supplies even on empty enabled input; disabled calls do not supply.
Absence and Unknown plans are cached, while thrown supply retries. C7 remains:
disabled/absent/Unknown plans select all for allowlists and none for blocklists.
The first recognized AllureId annotation wins even when its value is unusable;
only a String is accepted. Plan id and selector values each match either the
candidate ID or `pkg.Class.method`, including empty strings. Paths remain
process-relative; the first nonempty environment variable wins before path
validation, without trimming or fallback after failure. Missing/nonregular
files are absent; read/JSON errors WARN under the supplier logger.

## Approved simplifications and probes

**P1:** runtime Eq/Hash/toString are omitted. A caller audit of Kotlin main
sources found factory construction and the two selection calls in Marathon;
no production runtime-filter comparisons, hashes or strings are consumed.
Config equality and Test equality are unchanged. Runtime defects are recorded
as source-confirmed C57–C59, not claimed reproduced.

**P2:** ordinary string/null test fields, unknown properties, version `"1.0"`,
valid empty plans and unknown/missing string version dispatch retain parity.
The actual pinned dependency probes establish these changed exotic cases:

| Input | Kotlin 2.29.0 | Rust P2 |
|---|---|---|
| V1 missing or null `tests` | supplies V1; selection throws NPE | WARN, absent |
| V1 `tests: [null]` | supplies V1; selection throws NPE | WARN, absent |
| numeric ID / boolean selector | coerces to strings, can select | WARN, absent |
| numeric `version: 1.0` | coerces to V1 | WARN, absent |
| root `null` | supplier throws NPE (not caught IOException) | WARN, absent |
| trailing tokens after the root object | supplies V1, can select | WARN, absent |
| lone-surrogate escape in an ID (`"\ud800x"`) | supplies V1; selector still selects | WARN, absent |
| duplicate `version` (`"1.0"` then `"2"`) | supplies V1 (first wins), can select | WARN, absent: duplicate keys at any depth are invalid, never a silent Unknown |

Malformed roots/collections and invalid JSON already WARN and become absent in
Kotlin; Rust keeps that boundary and the exact logger/message but represents
the parser cause with `java.io.IOException` and a Rust parser diagnostic rather
than shaded Jackson exception text. This falls under the approved malformed/
exotic-plan simplification. The table preserves the original JVM outcomes.
Unknown versions `"1"` and missing version produce Unknown, with no warning.

**P3:** the original custom `AnnotationValue` test uses a test-only element
renderer that projects its Object.toString text into a String at the typed
model boundary. The original no-match assertion and snake_case test name are
retained. No production Object kind or custom identity-string parser is added;
real typed producer coverage accompanies this adapted test.

**P4 (waived in review round 1):** an existing but unreadable plan file logs
`java.nio.file.AccessDeniedException` as the WARN cause in Kotlin, while Rust
logs `java.io.FileNotFoundException`. Logger, level and message are identical
and the plan is absent in both. Witness: a mode-000 `unreadable-plan.json` named
by `ALLURE_TESTPLAN_PATH`, read through `FileTestPlanSupplier.supply()` on the
JVM and through `FileTestPlanSupplier::supply` in Rust.

No unapproved behavior deviation or neighbour implementation change is known.

## Review round 1

Two independent R1 reviews (Sol and Claude) both **agreed** with the four D6
SimpleClassname `n/a` rows, approved simplifications P1–P3 as implemented, and
the new known-bug rows C48–C51 (C56–C59 since the rebase). Sol's single
finding was waived as P4. Claude's three findings were fixed:

- **R1-claude-1:** `decode_plan` rejects duplicate object keys at any depth, so
  a duplicate `version` WARNs and is absent instead of silently becoming
  Unknown. The three JVM-witnessed inputs are in the P2 table, and
  `p2_plans_jackson_accepts_warn_and_become_absent` asserts all of them.
- **R1-claude-2:** the array identity registry is a map keyed by `Arc` address,
  with a `Weak` guarding against address reuse and amortized pruning of dead
  entries; one downgrade per new identity. Regression:
  `array_identity_registry_scales_and_survives_address_reuse` (20k live arrays
  rendered twice, then 20k reused addresses getting fresh tokens).
- **R1-claude-3:** a missing values file no longer fails when the working
  directory cannot be read; the ERROR shows the path as given, since the JVM
  resolves against its cached `user.dir`.
