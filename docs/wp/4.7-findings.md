## API for 4.8, 4.9 and 5.x

- `test::TestEvent` has all seven variants and `to_kotlin_string(hooks)` for Kotlin data-class rendering. The two unused singleton events have symbolic names; they have no production rendering site. `marathon-core::model::Test::kotlin_value(hooks)` is an additive shared renderer, using the existing metadata projection and replay identity hooks.
- `logparser::parser::{DeviceFailureParser, TestRunProgressParser, ParseError}` and `logparser::XctestEventProducer` are synchronous, serial values. All three expose `Result<Option<Vec<TestEvent>>, ParseError>`; the failure parser's substring scan is infallible. `ParseError::to_failure()` supplies the Kotlin exception class/message to 4.8, including JDK's `multiple points` message for malformed Float text. Producers receive stdout only from their future device caller.
- `listener::AppleTestRunListener` is an object-safe Send/Sync trait with nine no-op `VendorFuture` callbacks. `CompositeTestRunListener::new(Vec<Arc<dyn AppleTestRunListener>>)` awaits them in registration order and propagates the first failure. Event delivery and lifecycle ownership stay in 4.8.
- `AccumulatingTestResultListener::new(expected_count, accumulator, logs)` wraps the merged accumulator in a short synchronous mutex. No guard crosses an await. Each callback drains `take_logs()` on success and failure. The sender must be from the device's shared output queue; records keep their original accumulator logger name, timestamps, level, message and cause as lifecycle.md requires. Kotlin's interleaving is preserved only if 5.2/5.6 point the listener's `SshLogging` sink at the same `LogSender` queue as the accumulator records. This is the device logging route, without resetting or rendering those records under another logger.
- `TestResultsListener::new(TestResultsListenerConfig)` returns `VendorResult`. Config holds the batch/device/deferred, Timer, wall source, device output sender, remote xcresult path, `Arc<Xcresulttool>`, worker Xcode version, `VendorContext`, per-run `SshLogging`, and attachment providers. Device construction computes the path through RemoteFileManager. There is no 4.10a type dependency. The wall source measures Kotlin's independent `measureTimeMillis` duration; it does not consume Timer reads. It completes the core `Deferred` only in `after_test_run`.
- Attachment delivery delegates to `AttachmentCollector`, including provider registration. `TestRunListenerAdapter` wraps an `Arc<dyn core::TestRunListener>`. `DebugTestRunListener` uses only core `DeviceRef` plus the logging registry and replay hooks.
- `ArtifactFinderListener` and its two finder newtypes implement both callback traits; callers must retain one Arc for both registrations. Finders are re-exported from `listener` and `logparser::parser`. `DebugLogPrinter` initializes its prefix logger only on the first visible line.
