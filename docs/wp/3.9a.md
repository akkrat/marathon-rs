## Deliverables and boundary

In `crates/marathon-core`, add the production pipeline, report snapshot/summary types and shared log/attachment/output implementations, with `docs/wp/3.9a-findings.md` documenting the handoff.

1. **One per-run pipeline.** Implement frozen `wiring::Tracker` with `Track`/`MappingTracker`, typed internal events, sequential internal delegation and an adapter with no-op handlers. Implement `wiring::ReportLifecycle` on the same internal pipeline. `RunDependencies.reports` and `VendorDependencies.tracker` must share it. Add an async reporter-generation seam over `ExecutionReport` for 3.9b/c (ownership question Q1); do not require concrete reporters to compile this WP.
2. **Report data.** `ExecutionReport`, all five event variants, `PoolSummary` and `Summary`, retaining event order, complete result/device/attachment/metadata fields, final flags and retry associations. These are report-domain types over the frozen models, not serializer value trees. Expose the sorted event lists and summary that 3.9b/c need; resolve result identity explicitly (Q3), never silently replace Kotlin `!==` with value inequality.
3. **Shared listeners and files.** Implement frozen `listener::{TestRunListener,LineListener,LogProducer,LogWriter,AttachmentListener,AttachmentProvider,AttachmentFiles}` as applicable: composite line listener, shared log listener/writer, attachment delegate/collector and empty check. LogProducer is an interface for vendor producers, not a mandate to invent a generic stream engine. Implement `output::OutputFiles` by adapting `FileTarget::request` to merged `FileManager::{plan_file_utf16,plan_folder_utf16,plan_test_result_file_utf16}` and `PathPlan::materialize` off core. File creation returns a path and creates directories; it does not open/touch the file.
4. **Transfer instrumentation.** Port `FileTransferExtensions` as shared wrappers around the caller's transfer operation, using the existing Device logger and labelled wall clock. Actual push/pull, remote path handling and vendor integration belong to 4.3/4.10a, 5.2/5.6 and 6.5. Keep the value/error of the wrapped operation and its source-specific finally behaviour.
5. **Factory handoff.** Port `TrackerFactory`'s composition policy through injected reporter/backend services; 3.4b supplies remote tracker implementations and constructors, 3.9b/c supply reporters, and 3.10 assembles the concrete run graph (Q2). Document exact registration/setup/close order now, and exercise it with recording/failing delegates. Backend creation is awaited before run, even on parse; history queries remain 3.4a's concern.

**Outside 3.9a:** concrete reporter bytes, JSON projections/Gson field selection, JUnit/XML, stdout summary, P3 parse output (3.9b); HTML/timeline assets, Allure, screen capture/GIF (3.9c); external backend protocol/lifecycle implementations (3.4b); scheduler/progress/retry decisions (3.5/3.7/3.8); `Marathon` construction, outputDir wipe, console drain and onFinish (3.10); vendor parsers/media/attachment production (4.x–6.x). D1 usage telemetry stays a no-op. Domain test-log buffering is distinct from 3.6's **core console `LogQueue`**: reuse that queue for core log records, never send test log lines through it or move its draining into this WP. No reimplementation of 1.7 path bugs or 1.5 writers.

All filesystem work, blocking logger/registry access, report generation, folder walking and network-capable callbacks run on the vendor/I/O runtime (blocking pool for synchronous libraries). Merely returning Send futures does not dispatch them. Await delegates in source order; hold no collection lock across await/callback invocation. `LogWriter`, `OutputFiles`, `ReportLifecycle` return frozen `ServiceFuture`/`OperationResult`; tracker/listener methods keep `VendorFuture`/`VendorResult`. Preserve failure class/message/cause and typed cancellation when adapting between them. Finish must await owned work; Drop must not generate reports. Keep 0.6 C25/C26 shutdown/parse decisions with 3.10.

## Behaviours to reproduce

References below expand against `K/`; do not infer behaviour from class names or comments.

- **Fan-out and clocks:** `analytics/internal/pub/Track.kt:11–35` uses CopyOnWriteArrayList: duplicates remain, iteration sees a registration snapshot, callbacks execute in order and a throw stops later callbacks. `:38–52` emits preparation timing only after a successful block (no finally; no finish read/event on error). `analytics/MappingTracker.kt:16–33` takes wall Instants for connected/disconnected/test; preparation events keep supplied start/finish and serial, with no pool field. Use existing labels `core.MappingTracker.{deviceConnected,deviceDisconnected,test}`, `core.Track.{trackDevicePreparing,trackProviderDevicePreparing}`; each wrapper's two reads share its label. No host-clock fallback on tape exhaustion.
- **Internal subscribers:** `analytics/internal/sub/DelegatingTrackerInternal.kt:3–6` delivers events and closes sequentially, no catch; `TrackerInternalAdapter.kt:4–24` dispatches all five variants with no-op defaults. `analytics/TrackerFactory.kt:45–63` puts report capture before the optional remote tracker and registers the MappingTracker in Track only after construction succeeds. Influx setup catches only the factory's Exception boundary, warns `Failed to reach InfluxDB at <url>` and omits that delegate (`:66–83`); Graphite uses configured port or 2003 (`:86–87`). Do not turn later tracking/close failures into setup fallback.
- **Capture and close:** `analytics/internal/sub/ExecutionReportGenerator.kt:7–29` appends to five separate lists, then stably sorts connected/disconnected/test by instant and preparation by start. Equal timestamps keep arrival order; no global cross-list sorting or deduplication. `:23–33` constructs one report shared by reporters; C11: first throwing reporter stops later ones. It neither clears lists nor marks itself closed: a second explicit close regenerates reports. The once-only run finish guard belongs to 3.10, not this generator.
- **Reporter order:** `analytics/TrackerFactory.kt:90–102`: **DeviceInfo → Billing → JUnit → Timeline → Raw → TestJson → Allure → HTML → Stdout**. Remote tracker close follows report generation because it is the second internal delegate. A reporter error therefore also prevents that later close. Keep this order despite 3.9b/c implementing alternating entries.
- **Pools/devices/final outcomes:** `analytics/internal/sub/ExecutionReport.kt:20–53` builds pools only from distinct connected-event pool IDs, in first occurrence order; test-only pools disappear from summary but remain in raw events. Devices use first connected snapshot per serial, not last state or a disconnect filter. `tests` retains **all** final non-INCOMPLETE results, in event order; it is not a last-result-per-test reducer. Passed/ignored/failed are separate insertion-ordered sets of `toTestName()` (`Test::to_test_name('.', '#')`); IGNORED and ASSUMPTION_FAILURE share ignored. Conflicting final statuses can put a name in multiple sets. `:89` hard-codes flaky to 0. Summary is lazy over the immutable report, not updated incrementally from incoming events.
- **Raw counts/durations:** `ExecutionReport.kt:55–76` takes raw lists from every attempt, preserving duplicates and INCOMPLETE; raw failure is FAILURE only, raw ignored includes assumption failure. Duration includes only results with both timestamps nonzero (`execution/TestResult.kt:15–28`), final-filtered for summary and all attempts for raw. Signed subtraction and summation wrap as Kotlin Long; negative elapsed values are not clamped. The five assigned tests use start=0/end=100 and thus do not test duration arithmetic.
- **Retries have two equalities:** `ExecutionReport.kt:78–80` selects same-Test attempts (metadata ignored) excluding the **same result object**, regardless of final flag, status or whether the event was earlier/later. `toMap()` keys use full TestResult structural equality; equal keys overwrite values without moving the first key's position. Preserve this distinction, with an ordered key/value representation if needed; do not deduplicate final tests or hash Debug text. Q3 must resolve identity transport before implementation.
- **Log lifecycle:** `execution/listener/LogListener.kt:22–50` appends LF to each supplied line, registers itself before run, clears all preamble on testStarted, and on testEnded snapshots then clears **before** awaiting save. Nonempty text is saved as one string and attached as LOG with default name `log` (configurable); empty text produces neither file nor attachment. On interruption testEnded may be absent (`TestRunListener.kt:11–14`). afterTestRun removes the same listener allocation first and saves a nonempty tail as a batch log, without attachment or buffer reset. It does not automatically flush on LineListener.close. Preserve newline/trailing-blank behaviour; save errors propagate after the reset and suppress attachment notification. A20 permits different tail partitions from different actual event/line interleavings, not arbitrary byte normalization.
- **Log bytes:** `report/logs/LogWriter.kt:11–25` overwrites with `logs.joinToString("\n")` (no additional terminator), while append adds exactly one LF and has no batch ID. Shared LogListener has already appended LF inside its one string. Use `JavaString::to_utf8_bytes()` for File.writeText/appendText encoding, including JVM `?` replacement of malformed UTF-16; no lossy U+FFFD conversion. Preserve per-test/batch naming and C1 through OutputFiles. Composite line/close calls stop at the first error (`execution/listener/CompositeLineListener.kt:3–9`); removal is by retained Arc identity, not display name.
- **Attachments:** `report/attachment/AttachmentProviderDelegate.kt:7–14` preserves listener registration order and duplicate registration; callback failure stops later listeners. `AttachmentCollector.kt:6–24` registers in provider order, keys by Test equality, appends without deduplication, returns absent for an unknown test, and never drains a list on lookup. `execution/Attachment.kt:5–7`: empty is `!exists || length == 0`; it is not “not a regular file.” Keep Java missing/unreadable-file stat behaviour and directory cases; stat is off core. Do not filter empty attachments inside the collector.
- **Paths and errors:** `io/FileManager.kt:22–80,83–162`: use 1.7 materialization unchanged, including raw pool names, UTF-16 filename-before-path limits, original directory creation before file truncation diagnostics, folder diagnostics before mkdir, C1 batch suffix, C2 jpg suffixes and C21 whole-absolute-path truncation. `createTestResultFile` ignores mkdirs' Boolean failure, unlike createDirectories exceptions. Report save/append errors still propagate; no “best effort” catch around the whole service.
- **Transfer logs:** `device/file/FileTransferExtensions.kt:7–29` reads wall millis around the operation and stats/logs in finally even on failure; `:32–64` measures/logs folders only on success. Folder traversal counts the root directory, all subdirectories and regular-file bytes; signed totals wrap. Require positive elapsed seconds and positive bytes. Speed uses **integer** `bytes / 1000` before Double division, formatted `%.2f`; seconds use `%.4f`, both via merged en-US formatting (D8). Preserve exact debug templates, suppression for missing/empty files and operation results/errors. Clock labels are `core.FileTransferExtensions.{measureFileTransfer,measureFolderTransfer}`; do not reuse SystemTimer's `core.di.Clock` label.

C1/C2/C21 are already confirmed by 1.7: verify their adapter witnesses without changing policy. Confirm C11 with a failing-reporter regression and update its row. ## Proposed simplifications (pending orchestrator decision)

None is approved by this brief. Until a decision is recorded, source behaviour above remains the target; preserve witnesses for any approved exception.

- **P1 — result aliasing:** treat each public `Tracker.test` notification as a distinct result occurrence, using internal handles for retry self-exclusion; do not retrofit an identity token through the frozen borrowed TestResult API merely to support submitting the identical object twice. Normal progress reporting copies back the original Test (`PoolProgressAccumulator.kt:325–330`). Audit all emitting paths and probe repeated-object input before approval. Structural retry-key replacement and equal-but-distinct attempts remain required; this proposal only drops cross-notification object aliasing.
- **P2 — mutation during notification:** for attachment registrations and other Kotlin mutable-list delegates, use a short-lock snapshot at dispatch rather than emulating fail-fast/concurrent-modification behaviour when a callback registers another callback. Preserve duplicates, order, stop-on-error and Track's already-required CopyOnWrite snapshot. Audit registrations; this would relax only reentrant/concurrent mutation of lists Kotlin does not make thread-safe, not A20's ordinary line/event interleaving.
- **P3 — unused model methods:** do not port auto-generated event/report/summary equality, hashCode or data-class toString unless a real caller or assigned test uses it. Preserve full fields, Test/TestResult equality needed by aggregation, ordered collections and explicit downstream serializers. Audit logging/call sites and record unreachable methods; no JVM hash emulation or duplicate serializer machinery for hypothetical callers.
