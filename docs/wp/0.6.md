# WP 0.6 — Interface freeze

Rebased base: `2fee7a8` (original `fa41eef`); Kotlin reference: `e47352f2`.
Implementation stays on
`wp/0.6-interface-freeze`. No push, merge, or edits to the reference checkout.

## Goal

Freeze the boundaries needed by the later ports without implementing their
runtime, scheduling, configuration binding, transports, or reporting engines.
Behaviour, including observable Kotlin defects, follows PLAN §3 and §5.

## Deliverables

- `docs/design/lifecycle.md`: source-addressed ownership, ordering, cancellation,
  timeout, shutdown and controlled-replay contracts, including the detached
  Scheduler job and the distinction between cancellation and completion.
- `marathon-core`: models, separate value and reference identity contracts,
  vendor/provider/parser/bundle traits, error taxonomy, clock/Timer seams,
  runtime contracts, listener/log/attachment contracts and explicit dependencies.
- `marathon-config`: schema and P1/P2/P3 binding boundaries. Config depends on
  jcompat, never on core or vendor implementations; vendor construction is in CLI.
- Reuse merged `jcompat` UTF-16/time, queue, regex, writer, logging and path
  APIs in downstream signatures; do not redeclare Phase 1 concepts.
- Compile-only integration examples covering every consumer family, plus the
  existing five WP 0.6 parity rows (DeviceFeatureTest and SystemTimerTest).
- A handoff with resolved design questions, implementation ownership and bugs.

Source scope is the 33 WP 0.6 rows in `docs/source-inventory.csv`, plus the
cross-cutting actor, Scheduler, DevicePoolActor, QueueActor, listener, attachment,
log, configuration and DI declarations referenced by the lifecycle document.
The source inventory and generator assign the two concrete JSON reporters to
3.9b and FileTransferExtensions to 3.9a; their algorithms remain outside this
freeze.

Only representation, constructors and the minimum pure/delegating operations
needed to honour the five mandated parity tests are in scope. There are no
placeholder successful runtime implementations or panic-based async stubs.
No new fixtures are required; no copied resource is changed.

## Acceptance

1. Every frozen interface is traced to Kotlin; model documentation distinguishes
   equality, reference identity and serialization, including C17/C19 and D3.
2. Compile-only clients demonstrate object safety, cross-executor Send boundaries,
   cancellation/result separation and construction without Koin or global lookup.
3. The five assigned Kotlin test rows are ported under snake_case names with Rust
   paths. Runtime/transport/serializer behaviour tests remain with their owning WPs.
4. Interface-affecting Kotlin bugs are recorded in `known-kotlin-bugs.md` without
   claiming behavioural confirmation from compile-only tests. Incidental defects
   use `found-bugs.md` columns in `0.6-findings.md`.
5. `scripts/check.sh` passes and its actual result is reported. Linux pre-merge
   checking and independent review remain the orchestrator's responsibility.

## Input availability

`docs/design/fake-worker.md` is the merged, frozen fake SSH worker contract.
Its routing, raw evidence, filesystem and awaited shutdown apply to vendor and
transport test adapters. The merged fake-adb script and replay tape formats
remain authoritative for their own boundaries.
