## Round 2 (rebased commit `f0bc0ab`): Sol (medium)

**Resolved:** F1, F2, F4, F5.

**Open:**
- **F3 (major).** The binary flushes while the server and the timeline are still running (`main.rs:118`). Shutdown is only requested when the handle drops, and `Transcript::close` is never called. On SIGTERM the final `server_stopped` record was missing in 20 of 20 runs.
  - Fix: stop the record-producing tasks and wait for them, *then* drain and close the transcript.
  - Add a signal-shutdown test that checks the final transcript.
- **F6 (major).** Strict mode checks `has_rule`, then waits for the upload before `take_rule` (`device.rs:244`). With one `times: 1` install expectation, two concurrent connections both get OKAY, and the second falls through to the default answer with exit 0.
  - Fix: reserve the expectation atomically before answering OKAY, and release the reservation if the upload is incomplete.
  - Add a concurrent-upload test.

## Round 3 (commit `01e8572`): Sol (medium)

The normal cases now hold: SIGTERM shutdown passed 20 of 20 runs, and the concurrent-upload reservation passed 10 of 10. Two edge cases are still open:
- **F3.** A SIGTERM during a restart wait leaves `server_stopped` out of the end of the transcript; it failed 5 of 5 runs. Scenario: the timeline kills the server at 20 ms with a 600000 ms restart delay, disconnects the device at 60 ms, then SIGTERM arrives. `mod.rs:240` records `server_stopped` before the wait, and the final shutdown adds no record.
  - Fix: the final shutdown always records `server_stopped` after every producer has stopped.
  - Add this scenario as a test.
- **F6 (major).** Reservations leak when an upload fails with a read error or is cancelled. A TCP reset after 50 of 100 bytes left C rejected in 5 of 5 runs, and so did a device disconnect and reconnect during A's upload (`device.rs:283` returns before releasing, and a dropped future never releases).
  - Fix: a guard that releases the reservation on error or drop until the upload completes.
  - Add both regression tests.

**Escalation (three rounds without closure, PLAN.md §8.2).** The orchestrator decided to allow one more targeted fix round. Reason: the findings narrow each round, they concern test tooling and not product behaviour, and each has a concrete reproduction. Sol confirms the fixes narrowly.
