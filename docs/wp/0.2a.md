## Ground rules

- **Never build inside `$MARATHON_KT` or modify it.** Build from a disposable clone: `git clone --no-hardlinks $MARATHON_KT tools/oracle/build/marathon-src`, then check out `e47352f2`. `tools/oracle/build/` is gitignored.
- **JDK:** Android Studio's, `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"` (OpenJDK 21.0.10). Record the exact `java -version` output in `tools/oracle/README.md`.
- **What gets committed:** only sources, scripts and generated tables. Build outputs are never committed.
- The clone's own files are not committed.

## Deliverables

1. **`tools/oracle/build.sh`.** Clones the source, checks out `e47352f2`, and builds `:cli:installDist` with the reference JDK. It is idempotent, so it reuses an existing clone at the right commit.
   - It produces the reference distribution: `tools/oracle/build/marathon-src/cli/build/install/marathon/bin/marathon`.
   - It also builds an `oracle` Gradle subproject in the clone, added by a patch from `tools/oracle/patches/0001-oracle-module.patch`. That subproject depends on `:cli`, `:core`, `:configuration` and the vendor modules, and hosts the JVM tools below.
   - Patches are applied with `git apply`. They only *add* files and settings entries, and never change marathon behaviour; the behaviour patches come in WP 0.2b.
   - Smoke test: `bin/marathon version` prints the version.
2. **`config-dump`** (JVM, in the oracle module). Usage: `tools/oracle/config-dump <Marathonfile> [--env-file F] [--now <ISO instant>]`.
   - It parses with `ConfigurationFactory` exactly as the CLI does: `marathonfileDir` = the file's canonical parent, analytics and bugsnag flags true.
   - It then runs `LogicalConfigurationValidator`, which is the run path's stage (b).
   - It prints one JSON document:

     ```json
     {"stage":"parse|logical|ok","error":{"class":"...","message":"...","causes":["class: message", ...]}|null,"config":<canonical>|null,"fsEffects":[...]}
     ```

   - The `canonical` config is a deterministic JSON rendering of the parsed `Configuration`, written to **`docs/design/config-dump-format.md`** (PLAN.md §6.3). It includes:
     - every field, with derived values (timeouts, resolved paths, and the bundle paths hidden by `@JsonIgnore`);
     - Durations as ISO strings, Instants as ISO strings;
     - Regex as the pattern string, Files as absolute paths;
     - polymorphic types with their `type`;
     - maps with sorted keys.
   - "now" is injectable through `--now` for relative `timeLimit`s: make `InstantTimeProviderImpl` replaceable from the oracle module without changing marathon code. If that is impossible without a behaviour patch, record it for 0.2b and use a system property read by a small added class.
   - `fsEffects` lists files and directories created or deleted under the Marathonfile's directory during parsing (bundle extraction): a before/after snapshot.
   - Environment variables come from `--env-file` (KEY=VALUE lines). The tool re-executes itself with exactly that environment, so the substitution truth table can be generated.
3. **jcompat tables** (JVM, oracle module; `tools/oracle/jcompat-tables`). Each table is written as JSONL under `fixtures/oracle/jcompat/`, covering the cases PLAN.md §4.3 lists:
   - `PriorityQueue`:
     - offer/poll/peek/remove/removeAll/addAll/iterator sequences over random and equal-key inputs with a recorded comparator call trace;
     - at least 200 generated scenarios from a fixed seed, with the operations and the expected state after each step.
   - `Double.toString` for a broad sample: edge cases, powers of ten, values around 1e-3 and 1e7, random doubles.
   - `String.format` for the patterns marathon uses (grep the Kotlin source).
   - `Instant.toString`/`parse`, `Duration.toString`/`parse`, including invalid inputs and their exceptions.
   - The `SimpleDateFormat` patterns marathon uses, in UTC and the default locale.
   - `DurationFormatUtils.formatDuration(ms, "H'H' mm'm' ss's'")`.
   - `StringSubstitutor` (marathon's configuration) over a truth table: `${V}`, `${V:-d}`, `$${V}`, undefined, empty, recursive, cycle, `${A_${B}}`.
   - The md5 → signed `BigInteger` → `mod n` fragmentation hash.
   - Gson output (marathon's configured instance) for representative report models.
   - Jackson YAML emitter output for parse-command models.

   Each table has a header line describing its schema. Add a `README.md` in `fixtures/oracle/` explaining how to regenerate.
4. **Spike corpora generators:**
   - **YAML (for 0.3b):** run each corpus row from `docs/research/yaml.md` §4, plus the mutation families of PLAN.md §6.3, through Jackson's YAML parser in two ways: as a token stream, and bound to marathon's types where a target type is given. Write `fixtures/oracle/yaml-corpus.jsonl` with input, tokens, binding result or error class.
   - **Regex (for 0.3c):** the generator from `docs/research/regex.md` §4 (patterns × inputs, families 1–11), with a watchdog for adversarial cases. Write `fixtures/oracle/regex-corpus.jsonl`.
5. **`tools/oracle/run-isolated.sh`.** Runs a marathon binary (Kotlin or Rust) on a Marathonfile in a fresh sandbox:
   - copies the input directory into `tools/oracle/runs/<id>/in`;
   - sets a controlled environment (`HOME`, `TMPDIR`, and an explicit allow-list of variables);
   - runs the binary with a timeout;
   - captures stdout, stderr and the exit code;
   - writes `manifest.json`: the output tree with sizes and sha256, plus the run metadata.

   Two runs never share files. Test it with the Kotlin `version` and `parse` commands on a Marathonfile from `fixtures/configuration/`.
6. **`tools/oracle/README.md`.** How to build, run each tool and regenerate each table.
7. **CI:** the oracle needs the Kotlin repo and a JDK, so it is **not** part of `scripts/check.sh` or CI. `check.sh` only checks that `fixtures/oracle/` tables parse (one JSON object per line).
