## Compatibility details

Root and subcommand option structs are separate and no option is global. clap's
`args_override_self` keeps repeated options last-wins. A custom infallible value parser
implements `String.toBoolean()`: only case-insensitive `true` is true; every other string
is false. The defaults remain `Marathonfile`, tracking/reporting enabled, no parse output
name, and flaky tests excluded.

A compatibility pass uses clap's generated option inventory to retain eager help's
exit/stream precedence (including invalid short groups), literal `=` in attached short
values, and subcommands following `--`. It does not generate help, usage, suggestions
or grouped diagnostics. clap formats those texts; its usage errors are routed through
the existing exit-1 stderr path. The hidden `config-dump` route stays first-token-only.

The new parse help names the actual `.yml` extension; C12 in the Kotlin bug ledger
records that wording correction under D61. File naming and contents are unchanged.

## Review follow-ups

Help assertions compare the full command target in the usage line, so root help cannot
stand in for subcommand help. The expected matrix target comes from the unchanged oracle;
the CLI contract test checks explicit targets in the `Invocation::Help` payloads.

The compatibility pass removes help tokens at their original position before emitting
one eager help token (or the invalid attached-value token) at the front of its scope.
clap's default features are disabled, retaining std, derive, help, usage, error context
and suggestions; the unused colour stack is omitted. The dependency pin reminds
upgraders to re-run the complete CLI matrix because the pass uses clap introspection.

The strengthened CLI matrix passes all 117 rows. A before/after binary comparison
also preserves exit code, stdout and stderr for every row after timestamp normalization.
