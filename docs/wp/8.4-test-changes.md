## Numeric and nullable output decisions

JSON object fields formerly omitted when null use `skip_serializing_if` or the
ordered metadata-map serializer. Null array entries stay null; decoded null stays
`{}`. Raw metadata remains strings (including empty strings for null), with
Kotlin rendering unchanged. Allure retains omitted optionals and empty links.

Only typed per-test metadata carries arbitrary numeric f32/f64 values. Its small
serializers reject non-finite values with the existing failure, then serialize a
validated serde `RawValue` containing the existing `jnum` decimal. This preserves
numeric data such as the smallest f32 (`1.4E-45`, not `1e-45`) and Java's distinct
decimal spellings at some f64 boundaries. It removes both JSON number wrapper
and writer-tree dependencies without changing the decimal data. `jnum` itself
is outside this WP. Timeline emits fixed finite `0.0` values and integer stats;
HTML retains its pre-serialization NaN checks and integer conversions. Device,
bill, Allure and analytics request schemas have no arbitrary floating fields.

## Hostile review

The complete baseline diff was reviewed for each output's numeric types, field
order, nullable fields, non-finite paths and escaping. Every embedded assignment
uses `HtmlSafeFormatter`; plain JSON uses the default formatter. No production
I/O, process or network result gained an `unwrap`/`expect`. The remaining added
unwraps operate on in-memory serialization or fixture JSON in tests.

The review uses the standard HTML parser to locate script contents, retaining byte equality
for JSON-like text elsewhere, and added its adversarial test. Standalone Allure
and HTML model assertions also compare ordered canonical JSON, avoiding
`Value` map equality's disregard for key order. Historical comparison and other
native content rules are unchanged. YAML, readers and contract fixtures remain
unchanged.
