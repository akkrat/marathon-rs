## Implementation

`SimulatorRecovery` completes every deferred 5.5a seam. Monitoring owns retained
recovery children; a separately supervised retry root owns pending workers.
Recovering membership uses Arc allocation identity, while losses, exhaustion,
removal and admission use Apple IDs. Pending entries use the full Transport key;
their target vectors retain duplicates and order. Replacement preserves the
factory's concrete allocation and DeviceRef. No core downcast or setup trait is
introduced.

The scan first excludes recovering, exhausted, retired and removed/disposed
allocations; it checks executor connectivity outside the provider lock. It then
classifies worker loss before connected-device loss before readdition. All
members are marked before direct Disconnected sends. Recoveries run outside the
16 ms monitoring loop; all worker disposals finish before the concurrent parsing
session waits. The session budget is 70 seconds. Connected losses retain their
persistent ID budget and pause 0/30/60 seconds after teardown; fourth loss is
teardown-only. Worker loss neither increments that count nor applies its pause.
Removal/readdition and registration retain the source's predecessor leases,
including the A90 exception below.

Retry attempts include the initial connection. The existing configuration's
`pause_after` supplies defaults: attempts at 0/10/30/90/150 seconds, periodic
60-second retries, a 600-second cutoff, and lateJoin=true. lateJoin=false still
allows attempts two and three. Only the existing ConnectionFailures classifier's
outer UnreachableHost and eligible cause chains retry. Two retry permits surround
acquisition only; the underlying factory still owns its eight handshake slots.
A successful planning reference is released in finally, including denied cutoff.
Pending additions drain on the same connection; only missing setups are offered
back. Removed explicit simulator targets are filtered before planning, and empty
filtered takes do not invoke shutdownUnused. Closed pending objects cannot
remove their successors.

The global cutoff uses strict wall elapsed > configured milliseconds and strict
monotonic idle >30 seconds. Zero disables only the wall limit. Approved P2 keeps
the first observed reason latched. Checks occur after delay, connection, setup,
and prepare. A replacement of an unadmitted simulator inherits its gate. Denied
setup drops its allocation and retires the predecessor; denied prepare retires the
new device and returns LeavePool(NotAdmitted), avoiding preparation retries and
the first batch. Admitted simulators continue ordinary recovery after cutoff.
Timing subtraction wraps and the late-worker Timings suffix uses its separate
Timer read. Provider log templates, levels and four-cause descriptions are kept.

`DetachedConnections` implements approved P1 at both acquisition call sites.
Each acquisition runs in retained vendor work under a protected inner context,
with an acknowledgement before lease transfer. Cancelled/dropped awaiters return
promptly; undelivered successes release once, even when readiness and cancellation
coincide. The task retains its release capability until its acquisition finishes.
Provider termination does not join blocked acquisitions or call the factory's
unbounded join_pending. Recovery/session disposal remains joined. Monitoring and
recoveries stop first, then retries, then the existing event/artifact/current/
predecessor cleanup sequence. These paths use VendorRuntime, explicit signals,
VendorClock and labelled wall/monotonic hooks; Rust Drop does no disposal.

Completed shared-provider source regions are `AppleSimulatorProvider.kt`
279–369, 452–501, 552–681, 845–866 and 898–923, plus detached call adapters at
133–145 and 630–635. Registration/update/termination integration reuses 5.5a's
408–422, 748–759, 776–813 and 867–886. Inventory ownership stays unchanged:
the two 5.5b files are Detached.kt and PendingWorker.kt; the shared provider file
remains assigned to 5.5a.

## Changes to merged crates and existing seams

`VendorResult<Option<String>>`; prepare propagates an injected clock/replay error
instead of disguising it as a cutoff reason. Its existing supplemental admission
test is adapted. No boot, setup, execute, disposal or core error type changes.

**marathon-ios, stacked 5.5a:** ProviderRecovery gets a provided weak-owner attach
callback; provider construction installs the detached connection adapter; setup
accepts optional late timing data. The production recovery implementation plugs
into the existing reconnect, registration/admission, offer, missing, connect
failure and termination seams. Existing healthy-path test adapters remain valid.
The provider support helper accepts trait objects for the new production policy.

**marathon-ios, production construction:** `ios_vendor::construct` supplies the
complete run-owned services. It installs 5.3's ProductionSimulatorListenerFactory,
shared identifier/log configurator, the configured XCTest parser or default nm
parser, shared transfers, and one artifact processor. The small ProviderConnections
adapter uses real create_or_throw for simulator acquisitions, preserving typed
authentication failures; the standalone 5.4 nullable connection API is unchanged.
Construction performs no provider initialization or connection acquisition.

**marathon-cli:** only the iOS factory slot is enabled; the macOS slot is retained
and the other slots keep their prior state. CLI test dependencies add the existing
fake-worker, Tokio and base64 packages; Cargo.lock records those dependency edges,
with no version changes. `tools/differential/registry.json` is explicitly regenerated
for the changed runner factory hash.

**marathon-apple / merged 4.3:** no implementation change. U84 is witnessed at its
existing acknowledgement seam and handled by the iOS adapter, as Q2 permits.
**marathon-core:** no implementation or frozen interface change. The integration
tests use its real Scheduler, DevicePoolActor, queue and DeviceActor, plus existing
3.8 test support by path.
