# WP 8.8 golden diff

Re-blessed through the documented tool only: the existing
`fixtures/contract/native-v1` generation was removed and
`tools/differential/run bless` captured all 18 adapters (`local`, `parse`, and
the 16 vendor cases). `tools/differential/registry.json` was refreshed with
`tools/differential/make_registry.py` first; its diff is only the new input
hashes of `crates/marathon-cli/examples/differential_cli.rs` and
`tools/differential/vendor_console.py`.

## What changed

`tools/differential/run diff-golden --against a830d106` prints exactly one
hunk: `fixtures/contract/native-v1/provenance.json`, where `native_sha` moves
from the old capturing commit to the WP 8.8 head. No `.json.gz` view changed;
the files are byte-identical to the `a830d106` generation in git.

An entry-by-entry comparison of the decompressed views (old generation saved
before the re-bless vs the new one) confirms it: all 18 views have identical
entry sets, and 0 of 1,141 entries changed. Per case, the `stdout` and
`stderr` entry contents hash equally on both sides.

## Why no view changed, and why that is the proof

The native contract view of stdout/stderr is `evidence.contract_console`: it
keeps only the per-test progress lines and the end-of-run summary block
(including `Marathon run finished:` and the `\tRaw: ...` lines), byte-exact,
and drops every diagnostic line. Those pinned bytes are therefore the whole
console content of every golden, and they are unchanged in all 18 cases.
Every other entry — report files and their data, worker files, transcripts,
host argv, final state — is also unchanged, so no result-file datum and no
worker command moved.

That the diagnostic lines really did change (and the identical views are not
vacuous) is visible in a fresh capture. The raw stdout of a new `ios-smoke`
capture begins:

```text
00:00:00.000 INFO marathon_cli::application: Starting marathon v0.10.1, CliConfiguration: ...
00:00:00.000 INFO marathon_cli::application: Checking .../Marathonfile config
00:00:00.000 INFO marathon_core::timing: Device provider initialized in 0 ms (+0 ms since start)
00% | [omni]-[...] sample_appUnitTests.SampleTests#testPassing passed
Marathon run finished:
	Raw: 1 passed, 1 failed, 1 ignored, 0 incomplete tests
```

Applying `contract_console` to that raw stdout reproduces the golden
`stdout` entry byte for byte. `tools/differential/run native-vendors` passes
all 16 vendor captures against the re-blessed goldens.

## Comparator change

`tools/differential/vendor_console.py` (the ordered full-console comparison)
gained one narrow rule: on a complete native diagnostic prefix
(`HH:mm:ss.SSS LEVEL marathon_<crate>::<module>: `) only the time token is
normalized. Level, target, message, fields and continuation lines stay exact;
compact (timeless) lines are untouched; the rule never applies to raw
progress or summary lines; historical JVM prefix handling is unchanged. The
declared reorder windows (artifact admission, provider timing/updates) accept
the same messages in the native target spelling. Adversarial self-tests in
`tools/differential/test_evidence.py`
(`test_native_console_rejects_changed_missing_duplicated_and_reordered_pinned_lines`,
`test_vendor_console_native_prefix_normalizes_only_the_time_token`) pin that
a changed, missing, duplicated or reordered pinned line fails, that a changed
level, target or message on a native line fails, and that an incomplete
prefix is not normalized at all.
