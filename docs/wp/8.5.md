# WP 8.5: Remove JVM identity strings from outputs

Effort **S–M**. Branch `wp/8.5-no-jvm-identities`, based on `main` after WP 8.4 (commit `871e8c46`).

## Why

PLAN.md §3.12 lets Phase 8 drop JVM artefacts that leak into output and replace them with real values.
The port still prints `Object.toString()` identity strings where Kotlin had no `toString` override, with a
made-up stable hash (F29):

- Allure `environment.xml` (from `marathon-config/src/render.rs`): every stateless strategy or config
  object, e.g. `com.malinskiy.marathon.config.AnalyticsConfiguration$DisabledAnalytics@…`,
  `…PoolingStrategyConfiguration$OmniPoolingStrategyConfiguration@…`, next to readable data-class values
  such as `FixedSizeBatchingStrategyConfiguration(size=10, …)`.
- Array-valued annotation metadata (`marathon-core/src/filter/annotation.rs`): `[Ljava.lang.String;@…`
  with an identity allocated from a replay tape (`metadata.array.identity`); `DecodedNull` gets a
  similar identity suffix (`metadata.decoded_null.identity`).
- Log text: `KotlinValue::object` in `marathon-macos` (`MacosDevice@…`, `Transport$Local@…`,
  `LazyDeferredCoroutine@…`) and the `version` command's `…@…` in `marathon-cli/src/args.rs`.

## Scope

1. **Stateless objects render as their simple class name**: the part after the last `.` and `$`
   (`DisabledAnalytics`, `OmniPoolingStrategyConfiguration`, `NoRetryStrategyConfiguration`), which reads
   like the data-class values next to it. Applies to `render.rs` (environment.xml and anything else that
   uses it) and to the log sites above. Delete `KotlinValue::object` and `render.rs`'s `object`.
2. **Array annotation values render as their elements**: `[a, b]`, each element rendered as the same
   value would be outside an array (Kotlin list style, matching `values=[…]` elsewhere). `DecodedNull`
   renders as `null`. Delete the array identity registry, `allocate_identity`, the two replay-tape keys and
   whatever else only served them (grep for their test hooks and replay fixtures; replay tapes that are
   copied fixtures stay untouched, the code just stops reading those keys).
   - This text is also what the `annotationData` filter matches its `valueRegex` against. After this WP a
     regex can match array contents; a regex that matched the identity string no longer matches. Record
     that in the D-row.
3. **Nothing else changes.** Data-class rendering, `KotlinValue` itself, Java exception class names in
   failure messages (a later WP) and every other output stay as they are.
