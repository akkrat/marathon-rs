# WP 7.3b: static Linux musl release target

**Implementer:** Claude Opus 5.5. **Reviewers:** cross-family reviewer plus fresh Sol. **Effort:** S. **Depends on:** 7.3. **Branch:** `wp/7.3b-musl-release`.

## Decision

User decision (2026-11-01): the Linux release build is static `x86_64-unknown-linux-musl`, so one archive runs on any x86_64 Linux. This WP adds the target to the native release tooling of 7.3; it keeps 7.3's contracts: one version flows into binary, archive name and root directory; the zip holds exactly `marathon-<version>/bin/marathon`, mode 0755; metadata records source SHA, toolchain and target. The gnu target is unchanged.

## Design

- Build with `cargo zigbuild` (cargo-zigbuild wrapping Zig as the C compiler and linker). `ring`, `aws-lc-sys` and `lcms2` compile C; zig supplies a musl-capable `cc`/`ar` without a system musl-gcc, root or apt. The Rust target stays native-arch, so this is not a cross-compilation: the host must be Linux x86_64 (gnu or musl), checked in `release.py`.
- `release.py` preflights `zig version` and `cargo-zigbuild --version` and records both in `x86_64-unknown-linux-musl.json` (`toolchain`).
- `package` fails unless `file` reports `statically linked`/`static-pie linked` without an interpreter, and `ldd` reports `not a dynamic executable` (or `statically linked`). The check runs before any output is created.
- `collect`/`publish` include the musl archive when its metadata is among the downloaded artifacts and still require the two original targets. `.github/workflows/ci.yml` is unchanged: whether the release job builds musl instead of gnu is the orchestrator's call.

## Deliverables

1. `scripts/release/release.py`: the target, the static check, toolchain metadata, optional collection.
2. `scripts/release/test_release.py`: offline tests with the toolchain stubbed.
3. `docs/wp/7.3b-findings.md`: exact commands, tool versions and checksums, smoke evidence, limitations. `docs/releasing.md`: a short musl section.
