## Deliverables and boundary

1. **Provider in `marathon-ios`**, implementing frozen `vendor::DeviceProvider::{initialize,borrow,subscribe,terminate}` with `VendorContext`/`VendorFuture`, `EventChannel<DeviceEvent>`, and the *same* `DeviceRef` allocation returned by 5.2/5.4. Provider state owns the live device map, removal markers, replaced-device references, input/monitoring tasks and event tasks. Use `VendorRuntime`, `VendorClock`, `CancellationSignal`, `Timer`/`ReplayHooks`, typed `VendorError`/`Failure`; Send alone does not dispatch off core. No core trait downcasts or new core setup method.
2. **Static loading, dynamic TCP input and serialized update processing.** Consume the existing P2 binder/decoder; own socket lifetime, failure classification, refused-connect retry, source handoff, monitoring cadence, delta application, first connection/setup and registration. A failed worker is isolated from healthy workers. Track all jobs and await source-defined cleanup; no blocking core work, I/O `unwrap`/`expect`, cleanup by Drop, or state lock held across await/callback/logging.
3. **Planning adapter**, passing fresh registry queries into merged `PlanCalculator::plan`, one `WorkerProvisioningContext` per transport/cycle, and concrete `ConstructedSimulator<Arc<AppleSimulatorDevice>>` through `SimulatorProvisioner`. Emit connect/plan/provision timing here; setup timing stays in 5.4, preparation timing in 5.2. Retain acquired connection references until their source-defined release.
4. **Explicit `IosVendor` construction** returning frozen `VendorServices`: provider, configured XCTest or nm parser (default nm), Apple log configurator, and one shared bundle identifier (`I/IosVendor.kt:26–71`). The simulator constructor receives the same artifact processor, transfers, track, timer and output services. P2 mapper and simctl decoding are reused. Construction performs no provider initialization. CLI activation/listener/recovery dependencies require Q2; no replacement service locator or successful stub.

## Behaviours to reproduce

- **Initialize** (`P:155–183`): DEBUG `Initializing AppleSimulatorProvider`, then INFO `Xcresulttool.describeTimeout`, even before empty-worker failure. Resolve configured devices file or `<process cwd>/Marathondevices`. Static configuration **or file existence** chooses static, even if dynamic was requested; existence is not `is_file`, readability, or successful parse. Read/substitute before the mapper catch. Wrap only `JsonMappingException`-family binding failures as `NoDevicesException("Invalid Marathondevices file <absolute path> format", cause)`; I/O, substitution cycles and parser/stream failures keep their separate boundaries. Empty static workers ⇒ `NoDevicesException("No workers found in the <absolute path>")`; null document fails outside that wrapper. Initialize launches monitoring and returns without waiting for devices. No second P1 post-processing pass.
- **Dynamic source** (`:185–264`): TCP client, ignored four-byte prefix, signed big-endian length, UTF-8/P2 substitution via `FrameDecoder`. Retain 2.3b's approved validation rather than Java buffer allocation mechanics. Mapping failures use `Invalid Marathondevices update format`; no static empty-worker check for updates. `ConnectException` logs WARN `Connection refused, retrying in 5 seconds...`, then delays **5000 ms**; cancellation rethrows; other errors log ERROR `Error occurred: <message>` and permanently stop the producer (**A1**), including EOF on a frame boundary. Do not restart on source-channel closure: the inner monitoring loop survives, tries at most one receive, processes the entire snapshot, calls the 5.5b reconnect slot, then delays **16 ms**. Static monitoring processes one initial snapshot, then reconnect/delay. Source `produce` uses rendezvous backpressure; distinguish it from the unbounded device-event channel. Do not silently make the decoder's returned frame vector an unbounded update backlog; verify frame handoff/error timing with loopback witnesses.
- **Snapshots/deltas** (`:371–440`): call merged `DeviceTracker.update` once, before worker I/O; full snapshots remove missing explicit devices/workers. Tracker mutation is not rolled back on failed setup. For each transport, split Connected/Disconnected; mark explicit simulator/physical IDs removed under the same registration lock that reads the current device. Host/profile disconnects warn with the exact source texts (`:384,389`); connected explicit targets clear their removal marker. Notify disconnect, then launch connected-executor disposal and added-target provisioning concurrently under supervision. Await all before the next snapshot. Ordinary exceptions log and isolate each worker/disposal; cancellation rethrows. Healthy siblings' running batches remain untouched. Dead-executor disposal belongs to recovery, not this loop. Registry entries are **not erased** on removal; the DEBUG `Providing <devices.size> devices` counts retained entries too.
- **First attempt/setup** (`:452–490,512–544`): measure start before connection; always release the planning reference in `finally`, including plan failure, independently of device references. One context covers inventory, plan and all setups for this worker/cycle. A planning error while still connected propagates to the worker's isolation catch; a lost connection returns the simulator/profile targets as missing. Map failed existing setup to the explicit target or `plan.reused`; created failure maps to its profile. Only unreachable failures, or failures on a lost planning connection, become missing; disposed devices added by planning but absent from targets are left to recovery. Preserve these results for 5.5b's retry handoff. `Timings` INFO at `:474–476,518–532`: `Worker ID: connected in C ms, planned N simulators in P ms, provisioned them in R ms`, with jcompat's separate suffix read ` (+T ms since start)`. N excludes physical targets. Use wall Timer reads/wrapping differences, not monotonic replacements.
- **Planning live state** (`:683–774`): reuse `PlanCalculator`; its `registered` callback runs after inventory, and `current` after shutdown awaits. Re-read device allocation/transport and classify disposed devices as eligible only if executor connected, not recovering/exhausted/retired/removed, and still `devices[id] === device` (`:753–759`). Everything else is kept and subtracted from planned UDIDs. Preserve inventory-first matching, profile multiplicity and shutdownUnused commands. No stale pre-await snapshot or blanket re-setup of all devices when one is added.
- **Register/replace** (`:678,845–895`): ID is `udid@transport.id()`, never bare UDID. Under the registration lock, reject a retired/exhausted predecessor or a removed ID using `:870,875` messages; removed rejection also records `skippedRemoved`. Otherwise clear that marker and replace the map entry. Outside the lock, dispose the previous device, retain its connection in `replaced` unless recovery owns that retention, then launch Connected with the new allocation. Preserve source ordering across disposal and event launch (Q1). Notifications are asynchronously launched sends, not broadcasts or inline actor callbacks; do not deduplicate stale disconnects (C27). Retain task handles and source failure behavior for a send racing channel close.
- **Borrow/subscribe** (`:126,150,445–450`): repeated subscribe returns the same unbounded consuming queue. Borrow waits **200 ms** while the map is empty, then randomly selects from its values, without consuming an event, leasing, or filtering disposed/removed/lost devices. Use `ios.AppleSimulatorProvider.borrow` stable-key selection through `ReplayHooks`; no host RNG fallback on exhausted tapes. Candidate A80 below pins the stale-device case.
- **Terminate** (`:776–813`): protected from caller cancellation; cancel/join monitoring (including its socket producer and update children), then 5.5b's retry root, **close** the event channel preserving buffered events, await **4.9's real `close_and_join`**, then concurrently dispose current devices and release each executor reference. Disposal and release share one catch: if disposal throws, release is skipped. Log `Disposed device <udid>` even on failure. Await all, clear devices, release replaced references sequentially (catch per release), then close the provider dispatcher/owned runtime resources. Do not close the shared run runtime. The artifact processor's returned undelivered list is not a new provider error; its own budgets/retained work apply. Do not extend its bounded shutdown into an unbounded join. Calls before initialize and repeated terminate are tested. Do not add automatic cleanup on successful parse (C26) or change core's short-circuit close behavior (C25).
- **Logs/formatting**: provider logger is the simple name **`AppleSimulatorProvider`** (`P:101`); 5.4's extracted planner uses its existing fully qualified handle. Preserve that distinction, exact warning typos, Kotlin transport/target rendering and exception chains, never Rust Debug. D12 permits omitted JVM frames, not rewritten custom messages.

## Proposed simplifications (for the orchestrator, not decided)

Until approved, source behavior stands.

- **P1 — provider map traversal:** extend 5.4's approved deterministic worker/removal bookkeeping to provider registry traversal, avoiding JVM concurrent-map bucket emulation. Preserve profile/target/inventory order, identity predicates, asynchronous notifications and draw-tape stable keys. Live borrow remains random over current map values (including stale values as Kotlin does); exact unhooked selection and independent disposal/log interleavings may differ. Do not impose a new total event order.
- **P2 — repeated initialization:** reject a second `initialize` explicitly instead of emulating overwritten monitoring handles/source channels and leaked old monitors. The run constructs/initializes once; this affects only unsupported direct reuse. Repeated `terminate`, initialize failure cleanup, and ordinary cancellation remain supported and tested. An uncalled outer producer-restart loop/source-publication mutex may then be omitted if the caller audit and oracle show identical one-initialize behavior; A1 remains mandatory.

No simplification is proposed for removal, artifact drain order, stale borrow, retry cadence, source backpressure, or connection-reference lifetime.
