# WP 0.2b: nondeterminism hooks and oracle patches

**Owner:** Opus, high effort. **Reviewers:** Sol (high) and Muse (xhigh). **Depends on:** 0.2a.

Read first:
- `CLAUDE.md`;
- PLAN.md §5 (determinism), §6.3 (hook inventory, `OracleHooks`, patch validation) and §6.5 (event script, quiescence);
- `tools/oracle/README.md`, plus `build.sh` and the oracle module from WP 0.2a.

## Goal

Make the Kotlin reference *replayable*, so that exact batch assignments and outputs can be compared with the Rust port under controlled inputs. Prove that the replay is faithful before any golden produced by it is trusted.

## Deliverables

1. **`docs/design/nondeterminism.md`: the hook inventory.** Every source of nondeterminism in the Kotlin main code at `e47352f2`, with `file:line`, a stable **call-site label** (e.g. `core.TestBatch.id`), its kind, and how the hook controls it.

   | Kind | Examples |
   |---|---|
   | Wall clock | the injected `Clock`, `Instant.now()`, `System.currentTimeMillis()`, `Date()`, `SimpleDateFormat` |
   | Monotonic time | `System.nanoTime()` |
   | Scheduler time | coroutine `delay`, `withTimeout`, `withTimeoutOrNull`, polling loops |
   | Randomness | Kotlin `Random`, `.random()`, `shuffled()`; in particular `RandomOrderSortingStrategy` and `devices.values.random()` in the providers |
   | IDs | `UUID.randomUUID()`: batch ids, Allure, simulator names |
   | Concurrency order | readiness launched asynchronously in `DeviceActor`, vendor completions, provider events, channel ordering |

   Grep thoroughly, and say how the search was done, so a reviewer can repeat it.
2. **The `OracleHooks` patch set** (`tools/oracle/patches/0002-…`), applied by `build.sh` to make a separate *patched* build. The unpatched reference build must stay available.
   - **Three virtual clocks:** wall, monotonic and scheduler. They advance only as an explicit time tape says. Scheduler time drives `delay` and timeouts through a controllable dispatcher.
   - **Draw tapes:** each random draw takes the next value recorded for its call-site label. Generators and draw order don't have to match between Kotlin and Rust.
   - **ID tapes:** per-site ID allocation.
   - **Quiescence probe:** the harness can deliver one external event at a time and wait until every core actor mailbox is empty and no core coroutine can run (PLAN §6.5). A test dispatcher drives the `runBlocking` loop.
   - **Activation:** the tapes are switched on by system properties, or a tape file path. Without them, the patched build behaves exactly like the unpatched one.
3. **Tape and event-script formats:** `docs/design/replay-tapes.md`. The JSON shapes for time tapes, draw tapes, ID tapes and event scripts are shared by the Kotlin patches and, later, the Rust seams (WP 3.1).
4. **Patch-validation suite** (`tools/oracle/validate-patches.sh`):
   - **(a)** With no tapes, the patched build passes the full Kotlin unit test suite of the clone. The Docker-dependent tests are excluded, with their names listed, exactly as the fork's CI excludes them.
   - **(b)** With tapes, the core scenario tests and one CLI end-to-end run reproduce their outputs **byte for byte over 10 repeated runs**. The core scenario tests are the StubDevice scenarios in `core/src/test/.../scenario`, driven through the oracle module. The end-to-end run is the Android scenario on `tools/fake-adb` from WP 0.5 part B; if that isn't merged yet, use the scenario tests only and record the end-to-end check as pending.
   - **(c)** The outputs of the patched build with tapes match the unpatched build's outputs, apart from the injected values. Every such difference is listed and justified.

## Acceptance

- The inventory is complete, and both reviewers can reproduce the search.
- Validation (a) and (b) pass, and (c) is documented. Replay goldens are **not** produced in this WP; WP 3.10 does that once this one is merged.
- `scripts/check.sh` passes. Branch `wp/0.2b-oracle-hooks`.
