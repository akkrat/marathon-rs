## Behaviours to reproduce (with sources)

### Bundle validation and extraction (`AppleTestBundleConfiguration.kt`, below `B/`)

- **Branch selection** (`B:34-83`): `application != null && testApplication != null` → explicit branch; else `derivedDataDir != null` → derived-data branch (a lone `application` is silently ignored when `derivedDataDir` is set); else `ConfigurationException("please specify your application and test application either with files or provide derived data folder")`. `validate()` runs at parse stage (a) only when `bundle:` is present, before any other Apple re-resolution (`ConfigurationFactory.kt:74-87`, duplicated for macOS `:135-148`); a null bundle is stage (b)'s problem (2.4). `extraApplications` and `testType` are bound and path-resolved by the factory but never touched by `validate()`.
- **Explicit branch, application first** (`B:36-47`) — its extraction side effect happens even if the test application then fails: a file with extension `ipa`/`zip` is extracted and searched for a `.app` (required); a directory with extension `app` is taken as-is; anything else (missing path, `.app` *file*, `.ipa` *directory*, uppercase extension — `File.extension` and `setOf("ipa","zip")` are case-sensitive) throws `"application should be .ipa/.zip archive or a .app folder"`.
- **Test application** (`B:48-73`): archive → extract, search `.app` *leniently* (`validate = false`); if found, `xctest` is searched **inside that `.app` only**, otherwise in the whole extraction; either search failing throws `"Unable to find xctest bundle"` — keep the two-step scoping exactly, it decides pass/fail for archives holding both. Directory `.app` → `xctest` inside it; directory `.xctest` → taken directly, leaving `testApp` null (what `testExplicitConfig` exercises); else `"test application should be .ipa/.zip archive or a .app/.xctest folder"`.
- **Derived-data branch** (`B:76-80`): `xctest` searched first, then `app` — with `validate = true` for both, so a derived-data dir without a `.app` throws even though `app` is nullable elsewhere. Both searches recurse the whole tree.
- **Directory search** (`findDirectoryInDirectory`, `B:86-114`): `walkTopDown` collecting every directory whose `extension` matches (root included). Zero + validate → `"Unable to find an $extension directory in ${directory.absolutePath}"` (absolute against the process dir for relative inputs — messages via `file_manager::absolute_file_path`, not canonicalisation). Exactly two → the Watch rule: if one is under the other's `Watch/` subdirectory return the outer, else ambiguous. More than two → ambiguous: `"Ambiguous $extension configuration in derived data folder [<abs paths>]. Please specify parameters explicitly"` — wording says "derived data folder" even for extracted archives (custom message, keep). Two Kotlin bugs here, each to confirm and give a `docs/known-kotlin-bugs.md` row: **(i)** the two-item ambiguous message joins `found` *after* both elements were `removeFirst()`-ed, so it always prints `[]` (`B:100-107`); **(ii)** the same `removeFirst` pair makes the size-2 non-Watch path the only return path — behaviour is right, the list in the message is not. Walk order is `listFiles` order, i.e. unspecified; don't invent a sort unless S4 is approved.
- **Extraction** (`extract`, `B:121-149`; `tempDirFor` default `B:21-23`): destination is `File(parent, nameWithoutExtension)` next to the archive, `deleteRecursively()` then `mkdirs()` — a pre-existing sibling directory of that name is destroyed at parse time, and if application and test archives share parent and stem, the second extraction wipes the first (record as a known-bug row; it is observable through the resolved `app` path vanishing). Entries are walked in `ZipFile.entries()` (central-directory) order; an entry named *exactly* `__MACOSX` or `.DS_Store` is skipped (`IGNORED`, `B:153`) — nested `__MACOSX/…` entries are **not** skipped (known-bug candidate, verify). Directory/file paths are rebuilt by splitting on `/` and dropping blank segments (`B:131-138`): leading `/` is relativised, but `..` segments survive and escape the destination — plain zip-slip, kept unless S1 is approved. Two more extraction quirks to verify with a JVM probe before freezing, then record: **(i)** a root-level file entry (`Info.plist`, no `/`) gets parent `substringBeforeLast("/")` = its own name, landing at `dst/Info.plist/Info.plist` (`B:136-139`); **(ii)** symlink entries and unix modes are ignored by `ZipFile`, so extracted files are always regular files with default permissions — do not restore modes or links from the `zip` crate's metadata (downstream `chmod` steps in 4.x exist partly because of this). Corrupt/non-zip archives fail in the `ZipFile` constructor and unreadable destinations in `FileOutputStream` — neither is a `ConfigurationException`; both escape `ConfigurationFactory`'s `JsonProcessingException` catch unwrapped (class mapping: open question 6).
- **Representation:** `app`/`testApp` are nullable resolved paths, `xctest` is Kotlin `lateinit` (reading it before `validate()` crashes). Rust: `Option<JavaPath>` ×3 filled by `validate()` is the faithful shape; "xctest always set after successful validate" is an invariant callers in 4.x rely on — do not model it as a separate resolved type unless open question 4 decides so. The Kotlin constructor also carries the `tempDirFor` lambda (part of data-class equality); in Rust it becomes a `validate()` parameter with the sibling-dir default provided by the caller — see S7. Path spelling throughout is `JavaPath` (model contract: stored spelling, not canonical); `is_file`/`is_directory`/`extension` follow `java.io.File` on that spelling (extension = after the last `.` of the *name*, `""` if none).

### P2 Marathondevices binding (`Marathondevices.kt`, `AppleTarget.kt`, `Transport.kt`; mapper in `IosVendor.kt:31-41`)

- **Schema:** `workers: [{transport, devices: […]}]` — all three of `workers`/`transport`/`devices` required. Polymorphism is `type`-property `Id.NAME` through 2.1's `polymorphic`: `Transport` = `local` (singleton) | `ssh` (`addr` required; `port = 22`, `authentication = null`, `checkReachability = true`); `AppleTarget` = `simulator`/`physical` (`udid` required) | `simulatorProfile` (`deviceType` required, `runtime = null`, `newNamePrefix = "marathon"`) | `host` (singleton `data object`); nested `SshAuthentication` = `password` (`username`, `password`) | `publicKey` (`username`, `key: File`) (`SshConfiguration.kt:47-63`). Unknown keys are rejected everywhere — P2 has none of P1's six lenient sites. Missing-vs-`null` per the 2.1 `Field` policies: primitives take zero on `null` even with a default (`port: null` → 0, not 22; `checkReachability: null` → false), non-null references reject `null`, `runtime: null` and a missing `runtime` are both null (indistinguishable in Kotlin too). Empty `workers: []` binds fine — `"No workers found…"` is the providers' stage-(c) check, not the binder's.
- **`File` is the standard Jackson deserializer (F4, seeded → confirm here):** no Marathonfile-relative resolution, no canonicalisation. 2.1 already implements it under `Profile::Marathondevices` (R1-sol-4: text trimmed, blank → null, spelling retained) — so a relative `key` stays relative in the bound value and resolves only when a consumer opens it, against the *process* working directory. Do not absolutise it at bind time; pin that with a test. What a blank/`null` `key` does to the non-null `publicKey` creator parameter is an oracle row (below), not a guess.
- **Id expansion** (`AppleTarget.kt:35-57`): lazy, computed from the raw ids — if the id does not `startsWith` the FQCN (`com.apple.CoreSimulator.SimDeviceType` / `…SimRuntime`, no dot-boundary check), every `' '` and `'.'` becomes `'-'` and `"$FQCN."` is prefixed; already-prefixed ids pass verbatim (so a runtime id in the `deviceType` field gets the device-type prefix in front of it). Equality/hash use the raw ids; the expansions are methods, consumed by `SimulatorProvisioner` and `DeviceTracker` keys (5.4).
- **Substitution and read staging at the call sites** (the behaviour this WP's entry point must make reproducible, the calls themselves are 5.5a/5.6): the whole text goes through commons-text substitution first (`AppleSimulatorProvider.kt:127,164`, `AppleMacosProvider.kt:85`), failures outside every wrapper (PLAN §3.2). The providers catch **only `JsonMappingException`** → `NoDevicesException("Invalid Marathondevices file ${file.absolutePath} format", e)`; a YAML *syntax* error (`JsonParseException`) is not a mapping exception and escapes unwrapped (verify with the oracle; `ConfigurationError`'s stream-vs-coercion cause must keep this distinction available to 5.5a — it decides crash-vs-no-devices, so D9's class-fidelity relaxation does not cover it). A leading empty document makes `readValue` return null and the `.workers` access NPEs — map to the P1 `NullDocument`-style outcome, not to an empty workers list.

### Dynamic frame decoder (`AppleSimulatorProvider.kt:188-264`, PLAN §3.3)

- **Wire format, per frame:** `readFully` 4 reserved bytes (discarded unread), `readInt()` — ktor, big-endian, signed — then exactly that many payload bytes, decoded with ktor `decodeString()` (UTF-8; malformed-input handling to confirm by probe), substituted, bound as P2, and sent as one full snapshot (`:253-262`). Frames are read back-to-back on one connection; split and coalesced TCP deliveries must not matter.
- **Length handling, exactly:** buffer starts at 4096 and the (possibly grown) buffer is reused across frames *and reconnects* (`ByteBufferWrapper` created once, `:188-190`). `clear()`, then if `length <= capacity`, `limit(length)` — a negative length takes this branch and `limit` throws `IllegalArgumentException`; zero yields an empty message that then fails P2 binding as an update. Otherwise `ceil(log2(length))` must be in `1..20`, the buffer is reallocated to that power of two and `limit(length)` set; anything else throws `RuntimeException("Device provider update too long: maximum is 2^20 bytes")` (`:234-246`). Net effect: max payload 2^20, growth by powers of two. The Rust decoder needs the same accept/reject boundary and the same custom message; whether it must also reproduce the negative-length exception class and the exact allocation steps is S5.
- **Failure taxonomy** (what the provider's `catch (e: Exception) { break }` at `:206-209` sees, i.e. A1's stop-for-good — 5.5a reproduces the *stop*, this WP must not merge the kinds): EOF inside the reserved bytes, the length, or the payload (`readFully`/`readInt` EOF); negative or oversized length; substitution cycle (unwrapped `IllegalStateException`, as in P1); payload binding — mapping errors wrapped by the call site as `NoDevicesException("Invalid Marathondevices update format", e)` (`:257-261`), syntax errors unwrapped, both fatal to the producer either way. Connection-refused/retry-5s and the static-file precedence (`:160-174`) are provider behaviour, out of scope.

## Proposed simplifications (pragmatic parity — for orchestrator approval, **not decided**)

Until one is approved, the behaviours above stand and a divergence is a bug. Approved items are recorded with the deviations (PLAN §3.11 style); corpus/oracle rows are marked, not dropped.

- **S1, zip-slip:** reject entries whose rebuilt path escapes the extraction dir (`..` segments) with a clear error instead of writing outside it. This is a safety fix, not just pragmatism: archives come from CI artifacts. Diverges only on hostile or broken archives.
- **S2, root-level zip entries** (if the probe confirms the `dst/<name>/<name>` landing): extract root-level files to the extraction root. Real `.ipa`/`.zip` payloads keep everything under a bundle dir, so nothing realistic moves.
- **S3, `__MACOSX`/`.DS_Store`:** skip any entry under a `__MACOSX/` prefix and any `.DS_Store` basename, matching the comment's intent (`B:152`), instead of the exact-name match. Affects only resource-fork junk that no bundle search can use.
- **S4, deterministic directory search:** sort the collected matches by path before the count/Watch logic. Kotlin's order is filesystem-unspecified, so no defined behaviour changes — but ambiguous-message path order and same-count outcomes become reproducible in tests on every host.
- **S5, frame length validation:** check `0 <= length <= 2^20` up front with the decoder's own typed errors (keeping the exact too-long message), instead of reproducing `limit(negative)`'s exception class and the `ceil(log2)` reallocation steps. Accept/reject is identical; only the negative-length class chain differs (D9-consistent).
- **S6, extraction-dir naming collisions:** keep the sibling-dir default (its path is observable via resolved bundles and `config-dump`), but do not emulate the archive-stem edge spellings: hidden-name archives (`.app.ipa`-style stems, empty `nameWithoutExtension` → destination = the parent dir itself, which `deleteRecursively()` would wipe). Propose a clear error for an empty stem instead.
- **S7, `tempDirFor` and equality:** the extraction-dir factory is a `validate()` parameter, not a stored field, and the bundle type gets lawful Eq over its five bound fields (2.2 S1 precedent). Kotlin's data-class equality includes lambda identity, which nothing can rely on.
- **S8, non-UTF-8 zip entry names:** require UTF-8 (D9-consistent, as for `File` paths) instead of emulating `java.util.zip`'s charset decoding/replacement of entry names. Bundle contents are ASCII-named in practice.
