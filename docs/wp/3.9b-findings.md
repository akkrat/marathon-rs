  DeviceInfoJsonReporter::new and TestJsonReporter::new take that value;
  RawJsonReporter::new also takes the run's ReplayHooks.

- JUnitReporter::new takes runtime, raw outputDir and cwd. StdoutReporter::new
  takes runtime, Timer and the shared ConsoleSink. Its sink future is awaited
  on a joined vendor task, without assuming Tokio context on blocking threads.

  slots. 3.10 combines 3.9c's Timeline/Allure/Html registrations through the
  existing TrackerFactory ordering: DeviceInfo → Billing → JUnit → Timeline →
  Raw → TestJson → Allure → Html → Stdout. C11 stops at the first failure,
  including preventing remote close. Stdout dispatches its async sink through one joined I/O-worker hop;
  file/XML writes use joined blocking tasks.
- Shared `report::projection` exports `device`, `pool`, `test`, `meta`,
  `attachment`, `test_result`, `object` and `status`. Each returns WriterValue;
  attachment/result helpers take cwd. `kotlin_meta` is the fallible raw-metadata
  projection with the RawJsonReporter identity label. Allure's Jackson model
  remains separate.
- `report::projection::parse_results(&[Test], &[Test]) -> JavaString` is pure.
  It emits tests first, omits empty flakyTests, retains duplicates and typed
  Jackson metadata, including byte[] binary and char[] strings. 3.10 owns
  ParseOutput, banner/log/file routing, four whole-command parity tests,
  selection/include-flaky policy and C12/C13/C26 integration. Config's existing
  Configuration serializer and 2.4 round-trip tests are unchanged.

OperationError/VendorError adapters preserve original failures/causes and typed
cancellation. Constructors do no filesystem I/O; generation preserves partial
writes. There are no unowned tasks, report-on-Drop or new blocking core calls.
