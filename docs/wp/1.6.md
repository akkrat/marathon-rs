## Goal

Byte-exact startup and vendor log formatting, with Kotlin logger names and mutable per-name levels. Preserve C18: changing debug does not reset existing loggers. C10 belongs to the shutdown lifecycle (WP 3.10); logging exposes debug state without installing hooks.

## Deliverables

- A `jcompat::logging` module for the three fixed logback layouts, target-length abbreviation, highlight colours and Jansi output modes.
- A two-phase logger registry: DEBUG startup root, netty/vertx ERROR, last-lookup-wins levels, vendor appender replacement and Apple noise filters.
- Timings INFO and Xcodebuild WARN helpers, preserving lazy message evaluation.
- Oracle-driven formatting, Jansi and logger-state tests; reproducible JVM probes and findings.

## Acceptance

- All 200 existing `logback.jsonl` rows match, including multiline messages and throwable placement.
- Real reference logger/appender probes cover repeated lookup, both debug settings, vendor layouts, and terminal/pipe/file output under default, force and strip Jansi modes.
- `scripts/check.sh` passes. No Kotlin test rows are assigned to 1.6 in the starting parity matrix; `StartupTimingsTest` remains owned by its core WP, with logging-specific behavior additionally exercised here.
- No writes to the Kotlin source or main checkout; no push or merge.

## Integration API

`jcompat::logging` supplies `MarathonLogging`, stable-name `Logger` handles,
`Level`, `Vendor`, three `Layout` patterns and `LogEvent`. The runtime owns one
registry, supplies the original Kotlin names from the inventory above, and
serializes level lookups/configuration with its logging events. `enabled` and
lazy `log` avoid evaluating suppressed messages. Root aliases are canonicalized
to `ROOT`; hierarchy separators are `.` and `$`. `timings`, `timing_message`,
`xcodebuild` and `xcodebuild_message` preserve singleton initialization and
subsequent same-name level changes. `KLoggerDebug` and `fallback_warning` expose
the non-logback forwarding behavior, including the missing-spread bug.

The output task keeps a `ConsoleOutput` with `JansiMode` and `OutputTarget`,
formats immutable `LogEvent` values, and writes the resulting bytes to stdout.
It queues `finish` bytes when stopping/replacing the appender. `JansiStripper`
retains escape state across byte writes. The stateless `Layout::format` and
`log` conveniences suit complete events; `ConsoleOutput` is the stream API.
No clocks, I/O, global subscriber installation, executor choices or locks are
hidden inside this compatibility module. CLI/runtime WPs wire its state and
output task into their tracing integration. Supply local epoch milliseconds
at `library.logback.wall` after the timezone conversion; worker traces are
already message text and internal throwable frames use PLAN §3.10.

Round-1 stream integration: vendor events must pass through one `ConsoleOutput`
per appender, preserving its parser and `JansiFailure` across events, including
force mode. `failure()` distinguishes persistent numeric overflow from a
recoverable invalid-option write; terminal teardown after overflow emits no
reset bytes. `timing_message` takes elapsed and message closures and evaluates
message first, then elapsed, only when enabled. Throwable rendering remains in
WPs 2.5/3.10; use the nested common-frame oracle row described in the findings.
