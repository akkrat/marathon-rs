# WP 8.2: Replace `JavaString` with `String`

Effort **M** (large but mechanical). Branch `wp/8.2-native-strings`, based on tag `0.12.0-rc.1`
(commit `21c4d67b`).

## Why

Phase 8 removes Java emulation from the code while keeping the external contract: input files and CLI
syntax, result files, commands sent to workers, and the progress and summary log lines (WP 8.1 writes
this down as PLAN.md §3.12; it runs alongside this WP). `JavaString` (`crates/jcompat/src/writers/mod.rs`,
a `Vec<u16>` of UTF-16 units) is the most widespread Java-ism: about 1,700 uses in about 245 files across
every crate. Every later Phase 8 WP gets simpler once strings are plain Rust strings.

## Scope

1. Replace `JavaString` with `String` (owned) and `&str` (borrowed) everywhere: models (`Test` in
   `marathon-core/src/model.rs`, the xcresult models, config types, `Failure`, ...), function signatures,
   tests. Delete `JavaString` and every `jstring.rs` helper that has no remaining caller.
2. **`JavaPath` stays** (a later WP). Convert at its boundary.
3. **Where lone surrogates can come in** (DEX MUTF-8 decoding, `\uD800`-style escapes in YAML and JSON
   inputs, xcresult JSON, plists, process output decoding), decode lossily to U+FFFD at the input
   boundary. Today such units reach output as `?` (the UTF-8 encoder's replacement); after this WP they
   reach it as U+FFFD. That is a contract change on exotic input: add row **D55** to PLAN.md §3.11
   describing it, and a "fixed in 8.2" note on any matching row in `docs/known-kotlin-bugs.md`.
4. **Keep Kotlin semantics where they reach the contract**, implemented on `&str`:
   - lengths, `take`, `substring` and truncation that decide output file names or paths
     (FileManager truncation, the `maxPath` limit) keep counting UTF-16 units (a small helper over
     `encode_utf16()`), so no output path changes;
   - the whitespace set used by Kotlin `trim()`/`isBlank()` and the line splitting of Kotlin `lines()`
     (keep the existing `jstring` predicates, ported to `char`);
   - the fragmentation hash and Allure history IDs hash exactly the same bytes as today;
   - anything else where the existing tests or differential suites show a difference.
5. Sort order: Rust `str` ordering differs from Java `compareTo` only between supplementary-plane
   characters and U+E000–U+FFFF. Accept that; mention it in D55.

## Rules

- No behaviour change except D55. The full existing gate is the proof: every existing test and every
  differential and oracle suite in `scripts/check.sh` passes unchanged, except tests that assert
  lone-surrogate or UTF-16-unit behaviour that D55 changes. Update those to the new behaviour, set their
  parity-matrix rows (`docs/parity-matrix.csv`) to `n/a` with reason `8.2: D55` only if the test is
  deleted, and list every touched test in the report.
- Never edit a copied fixture under `fixtures/`.
- Keep the `//! Port of ...` headers. Keep comments' density; delete comments that only explained
  UTF-16 handling that no longer exists.
- No `unwrap()`/`expect()` on I/O, process or network results.
- Commit in reviewable steps (for example jcompat + leaf crates, then core, then vendors, then CLI and
  cleanup); every commit should build. If you find mid-way that a part is too risky to finish safely,
  stop at a building commit and report what remains.

## Acceptance

- `grep -rn JavaString crates/` finds nothing (except, at most, a D55 comment).
- `scripts/check.sh` passes (export `MARATHON_KT` to the Kotlin checkout first; see CLAUDE.md).
- Report: commits, the input boundaries where lossy decoding now happens, the UTF-16 helpers kept and
  where, every test you changed and why, and anything you left out.
