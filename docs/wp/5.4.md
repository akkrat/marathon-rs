## Deliverables and boundary

In `crates/marathon-ios`, explicitly construct the five source modules below: a cycle-scoped `WorkerProvisioningContext`/`WorkerFacts`; a run-owned `SimulatorProvisioner` with worker permits and typed `FailedSetup`/`SetupDropped`; `SimulatorFactory`; ordered `ProvisioningPlan`; `DeviceTracker`/`WorkerTracker`/tracking updates. A context is made for **one transport and one planning/setup or reconnect cycle**, never cached process-wide by host. Its inventory and facts use separate asynchronous single-flight locks; refresh only holds a short publication lock. Retain original executor allocation identity in cache records.

**Frozen contracts consumed:** 0.6 `runtime::{VendorRuntime,VendorTask,VendorFuture,VendorClock,CancellationSignal}`, `vendor::{VendorContext,Device,DeviceRef}`, `error::{VendorError,Failure,Cancellation}`, `time::{Timer,ReplayHooks,MonotonicClock}` and `wiring::VendorDependencies`. Dispatch vendor work explicitly off core. Preserve typed cancellation, await protected cleanup/joins, and use `Arc` identity for executors/devices. No lock across network/close except the source's per-context async load locks; no blocking core work, abort-by-dropping-future cleanup or I/O `unwrap`/`expect`. This WP implements no new core trait: provisioning is vendor-local. Registration passes the same device allocation to the provider; it does not itself emit core `DeviceEvent`s.

**Neighbours and proposed construction seam (Q1):** 4.3 owns acquire/release, eight-handshake limit and connection classification; 4.4 owns simctl parsing/argv/timeouts; 5.1 owns both test backends. 5.2 owns concrete `AppleSimulatorDevice`, `setup(record, context)`, worker-fact probing and all prepare/boot/execute/dispose behaviour. 4.8/4.9/4.10b own bundle identification, artifact processing and installation. Keep those dependencies injected into the factory; share one `SharedTransfers` per factory, the same per-run Track/event services, Timer and output-file services. A narrow vendor-local constructor/setup/dispose callback permits factory/provisioner tests now; 5.2 supplies its concrete adapter. Do not create a successful placeholder device or add casts/setup to core `Device`. The 4.10a identity registry is a downstream adapter, not a replacement for `DeviceRef`.

**Planning/timing extraction (Q2):** PLAN assigns planning-related timing to 5.4, but executable planning is inside the provider (inventory `wp=5.5a`). Recommend extracting the plan calculation/shutdown helper here, accepting provider-owned current-device/eligibility queries, then wiring it in 5.5a. Re-read eligibility/identity at the source's final boundary; a snapshot taken before awaits changes recovery races. 5.5a retains initialize/update/events, static/dynamic input and registration; 5.5b retains retry, recovery, removal/admission checks, `Detached` and `PendingWorker`. Supply the connect/plan/provision timing contract here, without implementing either provider loop. No CLI/vendor registration in 5.4; 3.10's vendor slots remain for 5.5a to fill.

## Behaviours to reproduce

- **Cache clock and publication** (`WorkerProvisioningContext.kt:29–69,96–124`): default **10 s**, measured from request **start**, using monotonic nanoseconds. Reuse when `now - startedAt <= maxAge` (exactly 10 s is reusable); Java signed Long subtraction wraps. Fast lookup then double-check under `inventoryLoad`; failed loads leave any previous cache record intact. Explicit `refresh` bypasses that load mutex and may overlap other refreshes/readers. Assign request sequence before I/O, publish only if newer than the last **successful publication**, and return each caller's own output even if it loses publication. A later failed request does not prevent an earlier successful one publishing. A slow fresh request must not block cached lookups or another worker. This threshold is **not** a guarantee that a record is at most 10 s old when setup finishes.
- **Executor validity and facts** (`WorkerProvisioningContext.kt:75–114,132–139`): reuse if `loadedThrough === caller` **or** the old executor reports connected; do not substitute an unconditional connection check. A throwing old-connection getter means false; replacement callers then reload. Facts have no age TTL, are loaded under their own lock and published only if `shareable`; a thrown/partial/non-shareable load is returned or propagated as in source, not installed as a successful cache entry. Lookup finds the first UDID, rejects missing or `isAvailable == false`, but accepts null availability. Keep `InvalidSimulatorIdentifier` and exact messages `udid U is missing at ID` / `udid U is not available at ID`. Planning differs: it accepts only `isAvailable == true` (`AppleSimulatorProvider.kt:689–692`).
- **5.2 fact-loading contract** (`AppleSimulatorDevice.kt:222–290`): worker `env`, Xcode version, `uname -m`, display probe, optional configured transcoder `-version`; share env/version/arch/features/transcoding together. Null result/exit from arch, display or enabled transcoder makes facts unshareable; a **completed nonzero** probe can still be shared. Failures of mandatory env/Xcode do not publish facts. HOME/model/runtime remain per-simulator commands. Failed `simctl getenv U HOME` forces fresh inventory, even if the old record was young; if U still exists, setup uses fallback paths. 5.4 exposes the cache callback/data; 5.2 owns these commands and default values (`Unknown`, feature detection). Do not make worker HOME or model a per-worker substitute for simulator HOME/model.
- **Permit scope/results** (`SimulatorProvisioner.kt:31–113`): default **2**, positive constructor check `concurrency should be positive, got N`. One retained semaphore per `transport.id()`, across simultaneous calls, existing and new operations; credentials/reachability changes at one endpoint share this budget. Different workers progress independently. Permit spans the whole operation including validation/create/connect/setup/register/cleanup. Existing operations precede profiles in input order; profiles keep multiplicity. Await all under supervision, return failures in input order, isolate ordinary failures and propagate cancellation; permits are released even on failure/cancellation. `existing()` makes a new context per call and discards its failure list. Provider passes configured `provisioningConcurrency` and its own detached connector (`AppleSimulatorProvider.kt:133–135`); do not fold it into 4.3's handshake budget.
- **Setup/registration ownership** (`SimulatorProvisioner.kt:115–153,216–229`): transient connect failure/null executor → unreachable; permanent connect error → failed. Check cancellation after acquire and after factory creation, before register; register once as `U@transport.id()`. `SetupDropped` logs INFO and is **not** a failed setup. Other setup errors check connected **before** releasing the lease; disconnected → unreachable, connected → outer logged failure. Until registration succeeds, dispose any returned device then release its acquired reference in a finally, even if disposal fails. Factory failure cleans its partially built device; provisioner still releases the reference. Never directly close a shared executor. Success transfers ownership to the provider. Preserve source error logger names/text, including cleanup exceptions replacing earlier errors where Kotlin finally does so.
- **New profiles/cancellation** (`SimulatorProvisioner.kt:158–209`): require matching device-type ID and, when supplied, runtime ID from context inventory; unsupported profile logs and returns **no failure**. Create name `prefix-UUID` via hook `ios.SimulatorProvisioner.create`; do not invent an ID source. Protect side-effecting create from caller cancellation so its UDID is retained, but keep wrapper's configured create timeout (default 30 s). Then ensure active, reject only null UDID, refresh inventory and set up. On every unregistered exit, delete the created UDID in protected cleanup; false/error deletion logs WARN without replacing the main result. `DROPPED` creates no failure but still deletes a newly created simulator. A4's empty-string UDID is not null and flows through unchanged.
- **Factory** (`SimulatorFactory.kt:35–104`): validate inventory before constructing a device; strip device-type prefix, map iPhone/iPad → iPhone simulator, Apple-TV/Watch/Vision → their simulator SDKs, all other/missing types → iPhone simulator. Pass the same context and record to setup, bracket with Track's provider-device-preparing callback, then log setup timing and return. Any exception, including cancellation or a post-setup timing error, disposes the constructed device in protected cleanup; retain the original failure and attach cleanup failure as suppressed. Validation failure constructs/disposes no device and never closes the executor.
- **Plan and shutdown handoff** (`AppleSimulatorProvider.kt:683–774`): first available record per UDID; explicit available simulators reserve their IDs; registered same-transport devices are excluded from profile reuse. Reuse first matching unused type/optional-runtime record once per profile, preserving inventory/profile order; preserve physical UDIDs without validation, warn/skip Host. With `shutdownUnused`, shut down only remaining booted records, serially; false shutdown results are ignored, thrown failures propagate. Emit timing only for a nonempty shutdown set. Final existing set is `(explicit + eligible disposed + reused) - kept`, with live re-read and identity check at `:753–759`; lost/recovering/exhausted/retired/removed policy belongs to 5.5b. `ProvisioningPlan.kt:11–16` preserves ordered sets/map and repeated create profiles, including reused profile values for failure retry mapping (`provider :533–543`).
- **Tracking** (`DeviceTracker.kt:14–35,45–123`): worker key is endpoint ID, retains its **first transport** even if credentials change, and removed worker trackers remain stored. Target keys: `host`, bare physical/simulator UDID, expanded `deviceType-runtimeOrEmpty` for profiles (prefix is excluded). Remove absent ONLINE entries and emit disconnects before new stable targets, then profile additions; deduplicate stable keys. Profiles emit desired count initially and only increments above their retained high-water count thereafter. Shrinking/disappearing profiles warn `Deprovisioning simulators is not supported. Current = C, desired = D` and retain count/state. Reappearance below that count adds nothing. Do not implement deprovisioning or replace metadata on a no-op update. `OFFLINE` is never constructed by live code (S2).

**Kotlin bugs:** retain inherited A4 (create parser), A8 (runtime Gson fields), A16/A17 (transient classification), A35 (bridge auth alias) and A37 (same-path SharedTransfers reuse) at their already-ported seams; do not repair wrappers here. The sole literal `5.4` bug assignment, **A19**, is screen-recording temp-file retention and belongs to **5.3 / 4.9**, not provisioning (Q3). Newly encountered quirks to probe and register when reproduced: same-executor cache reuse despite disconnection (`context :104`); first-transport retention/endpoint coalescing and persistent profile high-water counts (`tracker :27–29,68–70,107–118`). Do not mark a new row confirmed from source inspection alone. Keep null-availability's lookup/plan asymmetry as written.
