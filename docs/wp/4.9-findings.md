## Implementation and changed merged crates

**Changed merged crate: marathon-apple only.** Core, config, jcompat, iOS and
macOS production APIs are unchanged. Cargo adds Apple's direct `indexmap`
dependency, using the version already in Cargo.lock. Existing Apple's exports
add the processor and listener. `RetainedTasks` gains cancellation-aware spawn
and snapshot methods; its existing spawn/take behavior is unchanged. The existing
TestRootFactory unit tests import the common test helper from the crate root
instead of declaring a second copy (avoids clippy's duplicate_mod).

`ArtifactProcessor::new` and `from_configuration` return a typed InvalidLimits
error. The processor owns its workers, fair transfer semaphore and cancellation
signal. All admission, pending-owner, running-work, source and diagnostic state
is protected by one short mutex; spawns, notifications, logging and user
callbacks occur after unlocking. Statistics clone their inputs under the lock
and sort outside it. The admission core is separate from the async
shell and is driven directly by the event simulator and JVM transition replay.
The immediate-admission clock read is made only after eligibility is established
under the queue lock, matching Kotlin; no work callback runs under that lock.
Simultaneous admissions dispatched by one completion share that transition's
clock sample in the shell. The pure core
also accepts individual timestamps for field-by-field JVM replay.

Admission counts queued and active work, skips over workers at their share,
and preserves each worker's FIFO. Cancellation removes only a still-waiting
admission; racing admitted work remains owned by the worker. The callback error
model is `Result<(), Failure>`; worker accounting completes even when reporting
fails, while shutdown uses report_safely. Panics in callbacks are not caught.

Close rejects waiters immediately, drains, cancels and joins with the vendor
clock's bounded waits, then reports stuck/residual work, waits a second time for
reporting already in progress, reports rejected admissions and sweeps registered
sources. Repeated close returns cumulative diagnostics. Abandoned bodies retain
their task handles; they are not joined beyond the cancellation deadline, and a
late return logs once without reporting or completing the work twice. No Drop
performs observable cleanup. The two real-thread tests use spawn_blocking, unblock their latches and
join before returning; waits have a 10-second watchdog and 200 ms bounds.

The listener imports 4.7's trait. It protects lazily resolved remote paths,
releases policy-discarded or successfully delivered sources, pulls and renames
without replacement, and runs cleanup only after delivery succeeds. An existing
FileManager logger level is reused rather than reset on every delivery. Java class
names are kept for common filesystem failures. Source diagnostics retain
JavaString data; the existing Apple logging sink accepts its String projection.
Queue callbacks hold weak processor references to avoid Arc cycles.

## Review round 1 (2026-10-26, Claude Sonnet 5.5, cross-family): merge

- **R1-sonnet-1 (low).** The `timer_ties` guard is run-wide, so it plausibly explains the 10 P2 report differences but doesn't prove them. Reordering ties moves the exact-match count to between 19 and 24, and the sizing differences are multiples of 1.1 s, consistent with tie reordering. Accepted under P2. Follow-up: narrow the guard, or reword the test comment so it claims no more than it checks.
- **R1-sonnet-2 (low).** `submit` samples the clock label twice per call; Kotlin samples a second time only on immediate admission. This is harmless, since record and replay are both Rust. Follow-up: take the second sample only on admission.
- **R1-sonnet-3 (nit).** A replay-clock error in `complete` leaves `outstanding` incremented. This is unreachable with the production clock, so no change.

The orchestrator merged at this point, because 4.9 is on the 5.2 critical path. R1-sonnet-1 and R1-sonnet-2 are carried as follow-ups for the 5.2 implementer, who touches this code next.
