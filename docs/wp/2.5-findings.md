# WP 2.5 findings: CLI argument and exit matrix, startup logging, `version`, hidden `config-dump`

> WP 8.5: F29 identity rendering is superseded by D58. References below describe the historical parity baseline.

Branch `wp/2.5-cli`, from main `95f15fe`, rebased onto `27c77b4` for review round 1. The brief's "Orchestrator decisions (2026-10-24)" are followed throughout.

## What was built

- **`crates/marathon-cli/src/args.rs`** (port of `CliCommands.kt`, `CliConfigurations.kt`): a hand-written parser
  (decision 1) ported from Clikt 5.0.0's `CommandParser` (`parsers/ParserInternals.kt`), finalization order
  (`internal/Finalization.kt`: eager help, then parse errors, then value counts) and `MultiUsageError` grouping
  (`core/exceptions.kt`), read from the Clikt 5.0.0 source tag. It reproduces the token rules (`--opt=v`, `-mv`, `-m=x`
  → `=x`, `+a=b` as a long option, `---x`, `-` as an argument, `--` then a subcommand, an option's first value taken
  whatever it looks like), Jaro-Winkler suggestions (`> 0.8`, most similar first, `-b` → `--bugsnag`), the usage-line
  rules (one error keeps its command's usage line; several are reported under the root's, without argument errors after
  an unknown option, which is why `version -m x` shows the root usage), `Did you mean` / `(Possible options: …)`, the
  three-argument truncation, `toBoolean()` booleans, last-value-wins, and root options dropped for subcommands. The four
  help texts are constants in the 79-column layout (D12).
- **`crates/marathon-cli/src/application.rs`** (port of `ApplicationView.kt`, `MarathonStartConfiguration.kt`):
  `execute` with the startup lines through `jcompat::logging` (`MarathonLogging` registry plus a `ConsoleOutput` stdout
  appender with `OutputTarget` detection and `JansiMode::Default`; thread `main`; no second formatter), `version`, the
  `isFile` check, the stage-(a) parse through `MarathonConfigurationLoader::parse_sync`, the D1 line, the Stub/Empty
  gate, the run seam, the final messages and exit codes, and the throwable renderers (uncaught and crash log, D12).
- **`crates/marathon-cli/src/config_dump.rs`** (port of the oracle's `ConfigDump.kt`): the hidden `config-dump`
  command and the `fsEffects` walker. **`crates/marathon-config/src/dump.rs`** (port of `Canonical.kt`/`Json.kt`): the
  canonical configuration renderer and `Json.pretty` (decision 4).
- **`crates/marathon-cli/src/main.rs`**: process arguments, working directory, environment, one clock reading (P6),
  local time of day (chrono) and the standard streams around `marathon_cli::run_cli`.

## Decisions taken

1. **Run seam (decision 2).** `CliRunner::construct(Arc<Configuration>, Arc<Mutex<MarathonLogging>>, Arc<Console>)
   -> Result<Box<dyn MarathonRun>, Failure>` stands for `marathonStartKoin` + `koin.get()`; its error is uncaught (raw
   trace, exit 1). `MarathonRun::run(self: Box<Self>, ExecutionCommand) -> Result<bool, Failure>` stands for
   `marathon.run(command)`; its error takes the crash path (ERROR `kotlin.Unit` plus the throwable through the shared
   registry, in whatever layout the run left, then `Marathon execution crashed`, exit 1). The command is passed to
   `run`, as in Kotlin. `ignoreFailures` is read before construction takes the configuration. The registry handed to
   `construct` is the one the startup lines used, so 3.10 can pass it on as `VendorDependencies.logging`; so is the
   `Console` (stdout sink plus Jansi state, review round 1), so 3.10's `configure` installs its appenders on the same
   console and the crash log writes through it (`docs/design/lifecycle.md`, "Run completion and construction").
2. **Until 3.10:** the binary uses `UnsupportedRunner`, whose construction fails with
   `java.lang.UnsupportedOperationException: Running tests is not supported by this build yet`. A valid
   Android/iOS/macOS configuration therefore exits 1 after the D1 line (accepted in decision 2).
3. **Threading.** Everything before the runner (file check, read, parse) runs synchronously on the `main` thread before
   any runtime exists, as Kotlin's `execute` does; there is no core executor yet, so `lifecycle.md`'s rule is not
   touched. 3.10 owns the runtime inside `MarathonRun::run`.
4. **D1 line** (decision 7): `Crash reporting and usage analytics are not supported by this build; --bugsnag,
   --analyticsTracking, bugsnagReporting and analyticsTracking are ignored`, INFO, logger
   `com.malinskiy.marathon.cli.ApplicationView`, after every successful parse (run and parse). Kotlin logs its reporter
   line only when the merged `bugsnagReporting` is false (`Noop exceptions reporter started`); with the default `true`
   the Bugsnag reporter logs nothing in a token-less build. The matrix marks the three rows where that differs.
5. **`config-dump` placement.** The renderer is in `marathon-config::dump` (decision 4). The command, its document
   assembly and the `fsEffects` walker are in `marathon-cli::config_dump` (the brief's recommendation), because `sha2`
   is only a dev-dependency of `marathon-config` (the brief said otherwise) and the walker is a CLI concern. 2.6 drives
   the binary anyway; if it wants the whole document in process, `config_dump::document` can be made public.
6. **`config-dump` details.** `--env-file` builds the environment from the file directly (no re-exec). An unparsable
   `--now` prints an uncaught `java.time.format.DateTimeParseException: Text '<v>' could not be parsed` (exit 1; the
   JVM's message adds `at index N`). Usage errors, `readEnvFile`'s `IllegalArgumentException` and the document are as
   in `ConfigDump.kt`. `config-dump` is recognised only as the first argument, as a subcommand would be; elsewhere it is
   Kotlin's `no such subcommand config-dump`. It is not in help (decision 5).
7. **Version** (decision 6): `option_env!("GIT_TAG_NAME")`, else `0.10.1`.
8. **Marathonfile path.** `-m` values go through `jcompat::file_manager::file_path` (`new File(String)`'s slash
   normalisation), so the startup lines print `File.toString()`; `absolutePath` is cwd-joined and not canonicalised;
   `marathonfile_dir` is the canonical parent.
9. **Write errors** on stdout/stderr are ignored, as the JVM's `PrintStream`s do.

## Deviations and simplifications

- **D1** (PLAN §3.11): one INFO line, see decision 4; Kotlin's `Noop exceptions reporter finished` has no counterpart.
- **D12** (P1–P5): 79-column help always; no SLF4J line; no stack frames (a `Failure.stacktrace`, which carries external
  text, is printed verbatim after its header line); no `@argfile` expansion or completion script (`@x` falls through to
  `no such subcommand @x`, `@a=b` to `no such option @a`, as Clikt's other rules give); identity hashes by F29's rule.
- **P6:** one `now` per process, taken in `main`.
- **P7:** a Marathonfile read error prints `java.io.FileNotFoundException: <path as given> (<OS error text>)` with
  Rust's OS error text, which matches the JVM's wording for the cases seen. A permission error keeps the JVM's
  `Caused by: java.nio.file.AccessDeniedException: <path as given>` (review round 1); P7 is the message wording only.
- **§3.10 messages:** Jackson-raised cause messages differ (`unknown property` for Jackson's `Unrecognized field
  "bogusKey" (class …), not marked as ignorable (26 known properties: …)`). Both binary tests compare a
  `com.fasterxml.jackson.*` cause by class only; outer messages, classes and cause order are compared exactly.
- **Supplementary characters in a short option** (R1-sol-3, accepted by the orchestrator): Clikt splits a short-option
  group by UTF-16 unit, so `-😀` reports `no such option -?` (a lone high surrogate); the Rust parser iterates Unicode
  scalars and echoes the emoji. Exotic input, error text only. Matrix row `error-unknown-short-supplementary` keeps the
  Kotlin output and the Rust expectation.
- **`Instant.parse` range error:** for an instant past `Instant.MIN`/`MAX` (`config-dump --now +1000000001-…`), the
  JDK message prints the `Parsed` field map in `HashMap` order, which follows the fields' identity hashes and changes
  between JVM runs; Rust prints one fixed order (the oracle test compares the fields as a set).

## Evidence

### CLI matrix: 117 rows, 117 pass

`tools/oracle/cli-matrix/generate.py` (new) runs the reference start script (`:cli:installDist` of `e47352f2`, JBR
21.0.10; this run used `MARATHON_CLI=/tmp/mrs25/kt/bin/marathon`, the build made for the brief) once per case, in a fresh
sandbox with stdin closed and only HOME/TMPDIR/PATH/JAVA_HOME plus the case's variables, and writes
`fixtures/oracle/cli-matrix.jsonl` (provenance entry added). Regenerating it gave byte-identical rows apart from the
intended edits.

Cases: help for all four commands, `-h`/`--help`, `COLUMNS` ignored, help winning over parse errors, help inside a
group (`-hm`) and dropped with a bad group (`-hx`), `--help=x` (`option --help does not take a value`), `-h=x`; every
usage-error form of the brief (unknown long/short/grouped/triple-dash/`+`-prefixed options, suggestions single and
multiple, missing values per command, unknown and near-miss subcommands, extra arguments 1/2/4, `--` forms, the
root-usage rules, `--version`/`-V`); value forms, repeated options, booleans, empty values, root options dropped for
`run`/`version`; `version`; missing, `./sub/../` relative, directory, dangling-link, symlinked and unreadable
Marathonfiles; binding error, empty file, no vendor, `type: empty`, null document, substitution cycle, default
`Marathonfile`; the Stub gate for `run` (flags on and off, subdirectory) and `parse`; `parse` errors. Review round 1
added a supplementary short option and 11 `config-dump` argument rows (`program: config-dump`, recorded with
`tools/oracle/config-dump`): invalid, truncated, unparsed-text, impossible-date and hour-24-offset `--now` values, a bad
`--now` before extra arguments, before `--env-file`, before a valid `--now`, and after `--env-file`; `--now` without a
value; a valid `--now` without a Marathonfile.

Normalisation (listed in the header and applied by `crates/marathon-cli/tests/cli_matrix.rs` on the Rust side):
the sandbox path in both spellings → `<SANDBOX>`; a leading `HH:mm:ss.SSS` → `<TIME>`; the `version` identity hash →
`<HASH>`; the version → `<VERSION>`; the reporter line → `<TIME> [main] INFO  <D1>`; on the Kotlin side only, the
SLF4J line, `\tat`/`... N more` frame lines and `Noop exceptions reporter finished` are removed. Five rows carry a
`rust` expectation: `argfile-not-expanded` (D12), `error-unknown-short-supplementary` (the simplification above) and
three Stub-gate rows (D1, decision 4).

```sh
cargo test -p marathon-cli --test cli_matrix -- --nocapture   # cli matrix: 117/117 rows pass
```

Not in the matrix: run-path rows (success, failures, `ignoreFailures`, crash, no devices). They need `Marathon.run`, so
`crates/marathon-cli/tests/run_outcome.rs` covers the mapping in process with stub runners (each table row, the crash
log in the startup layout and after `configure()` in the runtime layout, construction failure, `UnsupportedRunner`, the
Stub gate, `type: empty`, what `run`/`parse` hand the runner); the end-to-end rows remain with 3.10/7.1.
