## Resolved design questions

1. **Core versus I/O ownership.** Core jobs/actors use Rc and non-Send futures;
   vendor calls use Send futures plus an explicit VendorRuntime. Simply
   returning a Send future is not dispatch. Blocking work is a separate,
   joinable runtime operation. Device dispose, file creation, tracker callbacks
   and log configuration are awaitable adapters at the original call boundary.
2. **Job cancellation versus completion.** Separate states, ordinary/supervisor
   parents, detached roots, completion callbacks, cancel-and-join and explicit
   cancellation-safe cleanup. No cancellation-token-only replacement.
3. **Which children Scheduler joins.** Separate snapshot and lazy traversal
   APIs. The pinned coroutine bytecode confirms a single-child special case
   and linked-list traversal that reads the successor after each joined child.
   Scheduler uses that traversal, not a snapshot or an eventual fixed point.
4. **Batch result versus execution completion.** Device.execute returns unit
   and receives a writable shared Deferred<TestBatchResults>. First writer
   wins, even when a result precedes a later error. The actor seals/inspects it
   synchronously before enqueuing Terminated; readiness remains asynchronous.
5. **Mailbox close semantics.** Actor close cancels/discards; provider channel
   close drains. safe_send keeps Kotlin's check/send race; atomic try_send is
   a different operation. Provider subscribe is one shared consuming channel.
6. **Identity.** DeviceRef and BundleRef compare Arc identity. TestBatch keeps
   structural equality and a separate Arc identity. Serial, worker ID, bundle
   ID and batch UUID are never substitutes for identity checks. The stale
   serial-only RemoveDevice bug remains explicit (C27).
7. **Test metadata.** Test Eq/Hash excludes it, serializers retain it. Typed
   annotation values retain boxed types, signed-zero/NaN behaviour, ordered
   lists/maps and array/object identity. Map representation requires unique
   keys; only Node maps preserve duplicates. No eager stringification of arrays.
8. **Serialization.** No blanket serde or Debug formatting. Model-contract.md
   specifies the fields per type, C17/C19, D3, JavaPath paths, Kotlin names and
   time widths. Runtime resources are not serialization models.
9. **Clocks/replay.** Wall, monotonic and scheduler services remain separate;
   SystemTimer uses wall reads labelled core.di.Clock and wrapping subtraction.
   Draws/IDs/identity suffixes are per label. Runtime supplies quiescence,
   explicit timestamp advancement and live barriers using the existing tape
   formats. No driverless virtual clock or exhausted-tape random fallback.
10. **Queue comparators with metrics I/O.** Use the merged concrete
    JavaPriorityQueue with synchronous FnMut comparisons. The freeze's async
    comparator/queue traits were removed. 3.2/3.4 own the off-core adapter,
    exclusive operation ownership and query/log-order validation. The round-1
    decision approves first-touch bulk fetching with Kotlin failure absorption,
    a synchronous memoising comparator and fetch-shim warn-once/TimingLog;
    eager prefetch remains unapproved.
11. **Java strings and regex.** Model/Node storage uses the merged
    `writers::JavaString`; user regexes use the merged UTF-8 JavaRegex under the
    rewritten D6. `matches` returns bool; compilation rejects unsupported syntax
    with field/pattern context. Checked `as_utf8()` is the storage boundary;
    binding/filter callers own contextual conversion errors for malformed UTF-16.
    There is no lossless UTF-16 regex backend/full-match overload or budget.
12. **Config dependency cycle and scope.** Config depends only on jcompat, with
    the complete top-level fields and named private section slots. 2.x fills
    those representations/binders/defaults. Error/profile/context contracts
    are frozen; WP 2.1 owns Node/Mark/Span, replacing opaque source-location
    placeholders with the spike's definitions. Core owns vendor runtime
    traits; CLI owns vendor dispatch.
13. **Koin replacement and startup side effects.** Factories return Send futures
    and selection comes directly from parsed vendor configuration. Per-run
    services are passed explicitly. Influx setup during dependency resolution
    is retained, even for parse; history queries remain lazy. Tracker's Graphite
    writes are awaited, not reclassified as in-memory/fire-and-forget delivery.
14. **Shutdown and errors.** Preserve ordered short-circuit closes and the early
    cleanup guard (C25), successful parse bypass (C26), error-path noncancellable
    cleanup, debug-only hook, and separate NoDevices/no-tests/config/crash
    classification. LeavePool carries NotBooted/NotAdmitted cancellation, not
    retryable setup failure. SSH-specific errors/close semantics remain 4.2's
    spike checklist, with no extra deviation.
15. **Minimal behaviour versus required Kotlin tests.** This is an interface
    freeze, not an engine implementation. Value Eq/Hash, representation/adapter
    forwarding, DeviceFeature parsing and SystemTimer delegation are the only
    behaviour added. The latter two are needed to port the five mandated 0.6
    test rows; runtime/report/binder algorithms have no successful stub bodies.

No design decision above depends on an unapproved behavioural deviation.
Implementation validation remains with the owning WPs: no compile-only client
is represented as runtime, transport, serializer or oracle parity evidence.

### Candidate deviations — round-1 decisions

These decisions supersede the alignment's proposals and are binding on the
owning WPs. No runtime implementation or replay proof is claimed here.

1. **F7 config hashing: APPROVED.** All three reviewers approve pattern-based,
   mutually consistent Eq/Hash when WP 2.2 needs config equality. Keep pattern
   spelling/output; no emulated Regex identity or inconsistent Rust hash.
2. **Annotation edge equality: RETAINED.** Boxed distinctions, float identity,
   NaN/signed-zero and C19 array identity remain. Round 2 freezes a typed
   DecodedWrapper enum for every pinned DEX wrapper; none uses MetaValue::Object.
   The generic Object variant remains until WP 6.4 confirms it is unreachable
   across all producers, rather than being used as a DEX wrapper convention.
3. **Scheduler child-list race: RETAINED.** Preserve lazy observed-child
   traversal. WP 3.1 should structure the child list so a snapshot is a one-line
   switch; any change needs controlled-replay evidence and explicit approval.
4. **Metrics queue adapter direction: APPROVED in Kotlin-shaped form.** Bulk
   fetch per (percentile, limit) off core at the first-touch point, absorbing
   fetch failures as MetricsProviderImpl runCatching/defaults do; synchronous
   memoising comparator over JavaPriorityQueue; warn-once/TimingLog emitted by
   the fetch shim. No async/fallible comparator and no eager prefetch.
   WP 3.2/3.4 validate query/log order against the oracle and record any residual
   difference. The adapter implementation stays in those WPs.
   **Amended by WP 3.2 orchestrator decision 3 (2026-10-24), P2:** at
   pool queue construction, prefetch each declared history key once off core.
   Comparators then use memory only and queue operations stay on core. This
   supersedes D4's first-touch/no-eager-prefetch requirement for queue
   construction. History queries and TimingLog move earlier; a pool whose
   queue never compares gains a query and timing line Kotlin skips. Per-test
   warnings remain lazy in source lookup order. See `3.2-findings.md` and
   PLAN §3.11 D13. The async MetricsProvider interface stays frozen.
