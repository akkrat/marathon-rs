## Delivered and handoff

**Merged crate changed: `marathon-core` only.** No changes to jcompat,
marathon-config, any vendor crate, Cargo dependencies or the frozen model.
Existing `listener.rs` gains Kotlin's no-op before/after-run and line-close
defaults; `lib.rs` exports the implementation modules and `ServiceLog`. Existing
Tracker, ReportLifecycle, OutputFiles and listener method signatures remain.

- `report::{ExecutionReport, Event, DeviceConnectedEvent,
  DeviceDisconnectedEvent, DevicePreparingEvent, DeviceProviderPreparingEvent,
  TestEvent, PoolSummary, Summary, Reporter}` are the report-domain handoff for
  3.9b/c. Immutable report accessors expose all five event lists; `summary()`
  computes once from that snapshot. Fields retain frozen TestResult, DeviceInfo,
  metadata, attachments, times, pool IDs and final flags. No JSON value tree or
  serializer was added. `Reporter::generate` is async and fallible.
- `analytics::{Track, MappingTracker, TrackerInternal,
  TrackerInternalAdapter, DelegatingTrackerInternal,
  ExecutionReportGenerator, TrackerFactory, EventPipeline}` implement capture,
  fan-out, preparation timing, dispatch and lifecycle. The adapter has all five
  no-op handlers. Stable sorts are independent by event type and retain ties.
  Generator close preserves its captured lists and may regenerate explicitly;
  Drop has no reporting side effect.
- `artifacts::{FileManagerOutput, FileLogWriter, CompositeLineListener,
  LogListener, AttachmentProviderDelegate, AttachmentCollector,
  LocalAttachmentFiles}` implement the frozen service traits. The output adapter
  uses merged PathPlans and their materialization unchanged. It creates
  directories and returns a path without touching a file. Log bytes retain
  UTF-16 until JavaString's JVM-compatible UTF-8 encoding boundary; save joins
  strings with LF, append adds one LF, and batch naming retains C1.
- `transfer::TransferMeasurement` wraps a borrowed async transfer operation and
  preserves its typed value/error. File measurement runs its final clock/stat/log
  path on failure; folder measurement performs the second clock read and walk
  only after success. Root directories count; sub-KB speed uses integer division
  before en-US fixed decimal formatting. It performs no vendor transfer itself.

`EventPipeline::tracker()` and `reports()` expose the same per-run Track/internal
pipeline. 3.10 assigns these to VendorDependencies.tracker and
RunDependencies.reports. Constructors receive the actual VendorRuntime, wall
clock, existing Logger and run output sink. `ServiceLog` accepts that Logger,
Level, JavaString and optional original Failure; it does not implement another
console logger or registry. 3.10 wires it to the merged logging/output services;
test lines never enter the core console LogQueue. LogListener appends lines inline.
The pipeline implementation now lives in `analytics/event_pipeline.rs` alongside
main's existing metrics modules, with the same public `analytics` exports.

Track dispatch and EventPipeline close hop once through VendorRuntime; the inner
MappingTracker, internal delegates and generator execute inline on that I/O worker.
Preparation and transfer bodies execute inline in the caller's vendor future. File
materialization/writes, stats, folder walks and synchronous diagnostic/warning
sinks use its blocking pool; reporter/backend/listener callbacks run on its I/O
workers. Snapshot locks are short and are released before callbacks or await.
OperationError/VendorError adapters retain Failure class, nullable message,
cause/stacktrace and typed Cancellation. Native NIO versus FileOutputStream
failures keep their separate exception families; a real ENOTDIR witness also
checks the JVM parent-path message. Finish awaits the report/remote chain;
3.10 still owns the run's once-only finish guard, NonCancellable error cleanup,
provider termination, console drain and C25/C26 parse behavior.

## Factory ownership and order

All 105 TrackerFactory source lines remain inventoried to 3.9a as the owner of
composition policy. The approved split leaves concrete reporter construction
with 3.9b/c and the concrete run-graph assembly with 3.10; backend provider/client
construction and its exact Exception boundary belong to 3.4b. The small
Reporter interface already moved to 3.9a in base `03cb1d6`; regeneration confirms
that ownership, with no additional inventory or DAG edits.

3.10 injects ReporterRegistrations and, optionally, a BackendRegistration whose
factory captures the configured backend's host/database/prefix/read-only and
other client settings. BackendRequest distinguishes Influx's warning URL from
Graphite's optional signed port; default Graphite port is 2003. The injected
factory's inner failure represents only the source's caught createDb Exception;
its outer OperationError represents uncaught construction failures/cancellation.
In particular, subscriber-constructor failures must use the outer result.

Construction first creates the capture delegate, then awaits backend setup,
then appends the optional remote delegate, builds the internal composite and
registers MappingTracker in Track. A caught Influx setup Exception logs
`Failed to reach InfluxDB at <url>` with the original Failure and omits that
remote delegate. An uncaught failure prevents registration. Setup is awaited
when this factory is resolved, including before parse; it is not a history query.
3.10 must resolve it on the parse path too.

Reporter registrations are sorted into source order: DeviceInfo, Billing,
JUnit, Timeline, Raw, TestJson, Allure, HTML, Stdout. Generation supplies one
report reference to the ordered reporters. Internal close then reaches the
remote tracker. Any reporter failure stops later reporters and remote close;
a later tracking/close failure is never turned into backend-setup fallback.
Recording/failing services exercise setup, all nine slots, Influx omission,
Graphite's default port, registration failure and ordinary tracking failure.

## Approved simplifications and reachability audit

P1 is implemented: every public Tracker.test notification creates a distinct
Arc<TestResult> occurrence. Cloned internal events retain that occurrence's
identity. Direct report construction can represent shared result objects, and
both shared-object and equal-distinct retry witnesses are preserved. A public
boundary regression submits the same borrowed result twice and confirms two
occurrences. It also exhausts a clock tape and verifies no host-clock fallback.

Source search found the only production emitter at
`PoolProgressAccumulator.kt:313–330`. It selects the original Test and normally
copies the result before `track.test`; the null-original path can pass the
original result. This is precisely the cross-notification aliasing relaxed by
approved P1, rather than an inferred identity from borrowed addresses. Retry
selection still uses Test equality and reference exclusion, and retry-map keys
use full structural result equality with first-position/last-value semantics.

P2 is implemented as snapshot dispatch for mutable listener collections. The
production registration sites are AttachmentCollector construction, run-listener
setup and TrackerFactory's single Track registration, with Android media/
profiling and Apple video/screenshot providers forwarding registration. No
production callback was found that registers another listener during its own
notification. Reentrant registration tests prove the approved snapshot behavior.
Track already uses CopyOnWrite snapshots in Kotlin. Duplicates, sequential order
and stop-on-first-error remain; A20's ordinary line/event tail orders are both
scripted explicitly, without timing sleeps in Rust.

P3 omits Kotlin-generated event/report/summary equals/hashCode/toString. Source
reporters read fields and summaries; TimelineSummaryProvider constructs reports
per serial, and the five assigned tests compare result statuses/counts. No
production caller or assigned test uses those generated model methods. Rust
Debug is diagnostic only, never a report or log projection. The frozen Test and
TestResult equality needed by aggregation remains unchanged.

All three review findings are fixed in **`206332b`**:

- **R1-claude-1:** Track preparation and TransferMeasurement await
  `VendorFuture<'a, T>` bodies inline, accepting borrowed device state and borrowed
  return values. Only clock reads and preparation dispatch hop through `on_io`;
  transfer stat/walk/log work uses the blocking pool. Dropping either preparation
  wrapper or either transfer wrapper mid-body drops its borrowed guard, closes
  the release receiver, consumes no finish-clock read and emits no event/log.
  Transfer cancellation also asserts that no blocking stat task was submitted.
  The original body-thread checks now assert the caller's core test thread;
  production vendor callers keep their existing worker. Typed file failure still
  takes the final measurement path; folder failure still skips it.
- **R1-claude-2:** Both preparation helpers accept a serial closure and evaluate
  it after successful body completion and the finish clock read. The regression
  changes `adbSerial` to `realSerialNumber` inside the borrowed body and verifies
  both event kinds capture the new serial.
- **R1-claude-3:** Track and EventPipeline::close own the event runtime boundary;
  MappingTracker, DelegatingTrackerInternal, ExecutionReportGenerator and
  LogListener::on_line run inline. Inner constructors no longer take an I/O
  runtime. The counting-runtime regression checks exactly one spawn for each
  of the five event entry points and one for close, including the real generator
  and remote delegate; the log regression checks no spawn for on_line. Existing
  ordering, stop-on-error, repeated-close, typed cancellation and line/event
  partition assertions retain their meaning. Direct generator-close unit probes
  explicitly choose their I/O worker rather than relying on an inner hop.
