## Consumer API

`marathon_apple::xcresult::decode_legacy::<T>(&str)` is resource-free,
synchronous and returns `Result<Option<T>, XcresultDecodeError>`. `None` means
successful top-level JSON null. Blank/failed command output, trimming, warnings,
Xcode-version flags and timeout policy remain WP 4.4. Large decoding belongs on
the vendor runtime, never the core executor. There is no new core trait.

All 57 schema objects are public in `marathon_apple::xcresult`, including
`ActionsInvocationRecord`, `ActionTestPlanRunSummaries`, `Reference`, and
`TypeDefinition`. JSON field names map to Rust snake_case; constructor fields
are public, with each type's own fields followed by flattened superclass fields.
`_type`/`_supertype` do not cause runtime subtype dispatch. Binding the test
summary base class ignores subtype-only fields, as Kotlin does.

Strings use `jcompat::writers::JavaString`; consumers use its checked `as_utf8()`
boundary. Integers are i32, doubles f64, and `JavaDate(pub i64)` is epoch
**milliseconds**. A self-referential non-list edge is boxed (`TypeDefinition`'s
optional supertype). Lists are `Vec<Option<T>>`: the JVM actually retains null
entries even in a Kotlin `List<T>`. WP 4.7 must not silently discard nulls when
reproducing a downstream dereference failure. Optional properties are `Option`;
they do not manufacture empty nested objects.

Errors distinguish `JsonSyntax` and `Mapping`, carry field/index path segments
and a core `Failure`, and can convert into that Failure. P1 eliminates unchecked
adapter dereferences. Syntax failures use parse/EOF exception classes; mapping
failures identify constructor, shape, format or wrapper failures. Diagnostics
are structured decoder explanations rather than byte-for-byte Jackson parser
messages; original JVM exception messages/chains remain in the corpus. The
wrapper owns the warning line. Paths can contain list indices that Apple's
nested mapper calls omit from their Jackson exception path.

## Sources and generation

The eight assigned source responsibilities are covered: the Gradle entry point
and schema/property/type/version records become
`scripts/generate_xcresult.py`; object dependency resolution, flattening,
filtering, type mapping and defaults replace `XcresulttoolSourceCreator`; typed
runtime conversion replaces `AppleModule`/`AppleJsonDeserializer`/`AppleListJson`.
No inventory reassignment is needed.

```sh
export PATH=/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH
python3 -I scripts/generate_xcresult.py
python3 -I scripts/generate_xcresult.py --check
python3 -I scripts/test_generate_xcresult.py
```

The generator owns only `crates/marathon-apple/src/xcresult/generated.rs`, never
cleans another directory and never discovers a replacement schema through Xcode.
Its input is the unchanged schema 3.39, signature `PS0lrtUj8Aw=`, SHA-256
`c79f8f634da9472a244ddbb9c5650641e3fb7087563205f86089a7d3c79716db`.
The 63 definitions produce 57 objects; the five values and one array are
recognized without generating object classes. `Reference` is emitted. Internal
and SchemaSerializable properties are filtered; superclass fields follow own
fields. Unsupported kinds and unresolved dependencies fail generation.

Four offline generator tests verify all 57 classes against measured Kotlin
constructor field order/types/nullability/default flags, deterministic output,
self-reference, nullable arrays, inheritance, filtering, unknown kinds, missing
Reference and unresolved/mutual dependencies. The generator runs rustfmt only
for regeneration/checking. Ordinary cargo builds use the committed models;
no Python, JDK, reference checkout, Xcode, network or Gradle is needed at runtime.
The offline generator regressions and regeneration check are in `scripts/check.sh`.

## Measured mapper behavior

`tools/oracle/xcresult/run.py` compiles the **original** Kotlin generator and
Apple adapter in a disposable build, extracts the exact AppleJsonMapper setup,
and generates the original model classes. Dependencies are cached Kotlin
1.9.24, KotlinPoet 1.16.0, Gson 2.10.1, Jackson 2.17.2 and reference JBR 21.0.10.
It verifies reference HEAD `e47352f2` and byte identity of the schema. No writes
occur in the Kotlin checkout. Regeneration and projection are documented in
`tools/oracle/xcresult/README.md`.

`fixtures/oracle/xcresult/corpus.jsonl` contains 160 measured inputs and target
classes, projected model fields (Date as millis), and exception class/cause/path
and message on failure. `models.json` records the actual Kotlin constructors
using reflection. One synthetic Kotlin-generated class measures nullable arrays,
which the production schema does not contain. These are JVM measurements;
source readings are not substituted for oracle evidence.

The Rust differential test compares complete nested projections for successful
cases, including all five existing JSON fixtures and the two SCRIPTED objects.
It checks failure paths for rejected inputs, and explicitly checks the approved
narrowing witnesses. Additional regressions preserve lone UTF-16 surrogates,
structured nested error paths and the original two size assertions.

Measured details retained:

- Missing/null non-null primitive/string/list fields use generated defaults.
  Required object/date fields fail; optional scalars/objects remain null.
  Wrapped `_value: null` fails for String, while numeric/Boolean wrappers use
  boxed null or primitive defaults according to the constructor field.
- Missing/non-array `_values` and non-object wrappers return empty object/numeric
  lists. Entries retain order, duplicates and nulls; malformed entries fail.
- **String lists are different:** Apple's adapter predicate excludes Jackson's
  `StringCollectionDeserializer`. Wrapped arrays fail, while bare arrays of
  wrapped strings work. Missing/null string lists are empty. For nullable lists,
  missing/null object lists remain null but missing/null String lists become
  empty. This is pinned by the synthetic Kotlin constructor and corpus.
- Scalar unwrapping is type-directed. `_type` and unknown sibling fields are
  ignored, including in nested objects. Numeric-to-String uses Java spelling
  (`-0` becomes `0`, `1e7` becomes `1.0E7`); f64 NaN/infinities are retained.
- Date uses epoch millis, ISO offsets with/without colon, and truncates fractional
  seconds after milliseconds, including pre-epoch values. It does not use
  Instant's nanosecond representation as model storage.
- Top-level null succeeds. Invalid/truncated JSON fails. Duplicate fields use
  the last value and trailing JSON tokens are ignored, matching ObjectMapper's
  disabled trailing-token validation.
- Nesting depth 1000 succeeds and 1001 fails with Jackson 2.17's
  `StreamConstraintsException` (`depth-array-*`, `depth-supertype-1001`; the
  accepted 1000-level chain is a Rust regression test). Rust
  rejects it while scanning, as `JsonSyntax` with an empty path; Jackson's
  binding-time reference chain is not reproduced.

## Approved simplifications

P1/P2/P3 were explicitly approved by the orchestrator; D9 is not applied here.

- **P1:** malformed scalar wrappers become a structured mapping error. Witnesses
  include `int-shape-3/4`, `optional-4/5`, `double-list-8/9`, `string-list-bare`.
  The JVM's null dereference is already wrapped in JsonMappingException at a
  model field; the oracle does not establish an unchecked escape there. Rust
  has no panic or unchecked adapter category.
- **P2:** ASCII numeric/bool strings and in-range i32/f64 values are supported;
  full-width integer strings (`int-11`) and hexadecimal doubles (`double-10`)
  are rejected although Jackson accepts them. Numeric overflow is an error;
  normal fractional numeric-to-i32 truncation is retained (`int-5/6`).
- **P3:** support ISO timestamp offset forms and integer epoch milliseconds,
  including their string form. RFC-1123 (`date-9`), lenient February 30 rollover
  (`date-10`) and date-only strings (`date-13`) are rejected. The empty/`null`
  string and explicit-null boundaries still follow Jackson.

- **P4 (R1 fix round):** duplicate object keys keep only the last occurrence,
  and only that one is validated. Witness:
  `{"testsCount":{"_value":"oops"},"testsCount":{"_value":1}}` as
  `ResultMetrics` succeeds in Rust; Kotlin throws InvalidFormatException on the
  first occurrence. xcresulttool never emits duplicate keys.
- **P5 (R1 fix round):** object keys that are not valid UTF-8 after unescaping
  (lone surrogate escapes such as `{"\ud800":1}`) fail as `JsonSyntax`; Kotlin
  ignores them as unknown fields. xcresulttool keys are ASCII schema names.

## Robustness and performance

R1 replaced the per-level RawValue re-parse with one iterative scan of the
validated value: no recursion on input depth and linear work (the previous
re-parse was quadratic in depth). The Jackson depth limit bounds the generated
decoder's recursion. At the limit, recursive models such as `TypeDefinition`
decode on a default 2 MiB test thread in debug builds, with little headroom
(1.5 MiB overflows). Release builds need much less.
