## Decisions, deviations and remaining work

- CLOSE withholding uses narrow per-channel russh hooks for both automatic reply and child completion. It does not stall unrelated channels. R1 is retained; vendor adaptations and reproducible patches are documented beside the crate.
- Linux uses the installed Samba substitute because openrsync was absent from both executable lookup and the configured package catalog. Mac evidence separately certifies the required Apple dialect; Linux results make no such claim.
- OpenSSH's CLI cannot issue SSH channel signal requests. Its connection-reuse case sends virtual TERM via a second mapped command channel. sshj and russh test actual protocol signals.
- Receive's repeated `.links(true)` assignment is deduplicated by the actual rsync4j builder. Assertions preserve the measured single `--links` argv entry instead of inventing a duplicate.
- The real `pushGeneratedFile` method is called on a fixture allocated with `Unsafe.allocateInstance`, setting only its file-transfer fields. This invokes the original method while avoiding simulator provisioning, which belongs to 0.4b; no method logic is copied.
- U4 remains unresolved. The explicit fixture-only askpass path lets the Kotlin password transfer proceed without hiding baseline failures. The aggregate macOS runner stays red. Neither success on Linux nor the workaround establishes the cause or a production fix.
- The virtual root itself is reserved; children can be removed and snapshots reset. Real rsync is a trusted fixture executable with vetted flags and an exclusive filesystem lease, not an OS sandbox for a compromised binary.
- Readiness fingerprints, structured IDs/ports and run paths are normalized by field. Diagnostics and differing rsync streams are not certified equal across platforms; missing/failed/skipped outcomes never compare equal.

WP 0.4b still supplies Apple handlers, media/bundles and full simulator/macOS marathon validation. WP 0.6 and 4.2 own production lifecycle/client behavior. The orchestrator still owns Sol/Muse review and `scripts/remote-check.sh` before merge. No push or merge was performed. There is no blocking design question; U4's cause is the remaining investigation question.

### Deterministic reproduction and lock audit

`server::tests::term_drops_interrupted_output_before_finish_with_transcript_locked` pauses an append halfway through its JSONL row while the writer mutex is held, sends a real SSH TERM, and requires destruction of the suspended output future **before** releasing the write. It then asserts ExitSignal, EOF, CLOSE, session-slot reuse, bounded shutdown, an intact output record before the exit event, and contiguous sequence numbers through cleanup. Temporarily restoring the original output-future lifetime makes this regression fail deterministically with a two-second timeout (exit 101); restoring the fix passes. The mutant and fixed logs are retained under `tools/fake-worker/runs/round2-{regression-mutant,macos-contract}.log`.

Three transcript regressions separately prove that a cancelled half-written append completes losslessly, a still-pinned/unpolled append waiter cannot block a second event, and an error from a cancelled append fails both `flush` and later cleanup recording. The pause/failure hooks are per-transcript and compiled only for unit tests; production has no test controls.

The audit covered every `select!`, pinned future, mutex and filesystem lease in `tools/fake-worker/src`, plus russh's channel-window lock used by output:

- Output TERM now destroys `work` before finishing. Ignored-signal branches retain/resume `work`, but its transcript append progresses independently. The same independent ownership fixes background signal logging while a background-output append is suspended.
- `run_channel` explicitly drops the stdin reader on either selection branch before awaiting execution or writing `channel_end`; a completed/error execution future cannot leave its sibling holding a resource during cleanup.
- Rsync's stdout/stderr `try_join!`, stdin-error logging and cancellation/drain paths cannot retain the transcript mutex. Both pipe futures leave scope before `child_reaped`, snapshot and finish. The exclusive filesystem lease still covers child exit/reaping and pipe drain/drop and is released before snapshot.
- Slot and withheld-channel guards perform synchronous mutations only; no guard crosses an await after acquisition. The process map clones signal/completion handles and drops its guard before sending/waiting.
- Filesystem operations already move their owned lease into `spawn_blocking`; cancellation does not strand it in an unpolled async future. Initial/nested routing loses and drops its selected future on cancellation. A blocking filesystem operation already submitted may finish, and the final snapshot waits for its lease, as documented.
- Connection/transport abort can cancel transcript callbacks, now handled by the same append ownership and sticky errors. The russh window reservation drops its mutex before waiting for window credit; no additional retained lock was found there.
