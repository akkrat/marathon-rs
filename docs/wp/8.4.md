# WP 8.4: Write JSON with serde instead of the Gson emulation

Effort **M**. Branch `wp/8.4-serde-json`, based on `main` after WP 8.3 (commit `a5dac0b8`).

## Why

Phase 8 removes Java emulation while keeping the contract in PLAN.md §3.12. Every JSON result file and
JSON request body is still produced by `jcompat::writers::GsonWriter` (a port of Gson 2.11's `JsonWriter`)
from hand-built `WriterValue` trees whose numbers carry Java `Double.toString` spellings (`JavaNumber`).
The contract compares JSON results as parsed data (point 3), so serde can write them directly from typed
Rust structs.

## Scope

1. **JSON writers move to serde.** Every production use of `GsonWriter` goes, and the JSON-only uses of
   `WriterValue` and `JavaNumber` go with it. Known users: `marathon-core` `report/reporters.rs`,
   `reporters/mod.rs`, `reporters/html.rs`, `reporters/allure.rs`, `reporters/timeline.rs`, and
   `marathon-analytics` `http.rs` (grep for others).
   - Prefer `#[derive(Serialize)]` structs that mirror the written schema (field order = the current key
     order; `#[serde(rename = ...)]` / `rename_all` for the JSON names), written with `serde_json`.
     Use `serde_json::Value` only where the shape really is dynamic; then key order must still be the
     current order (enable `serde_json`'s `preserve_order` feature or use a derive).
   - **Same data.** Null versus missing key, integer versus floating-point type, string versus number,
     array order: all exactly as today. A Java `long`/`int` field is an integer type in Rust; a Java
     `double`/`float` field is `f64`/`f32` (serde writes `1234.0`, which the gate accepts for Java's
     `1234.0` and `1.0E10` vs `10000000000.0`). Find out what the current writer does with NaN and the
     infinities on each path that can carry them and keep that data; if serde cannot, use a small
     `serialize_with` for those fields and say so.
   - Compact output stays compact; pretty output stays pretty where it is today.
2. **JSON embedded in HTML** (`reporters/html.rs` `assignment`: `window.mainData = {...}`, `window.pool`,
   `window.test`, `window.logs`, and any timeline page that does the same): keep escaping `<`, `>`, `&`,
   `=`, `'`, U+2028 and U+2029 as `\uXXXX` inside JSON strings, so test names or logs containing
   `</script>` cannot break the page. Do it with a small `serde_json::ser::Formatter` (override
   `write_string_fragment` or `write_char_escape`), not by post-processing the text. Plain `.json`
   files use serde's default escaping.
3. **The gate learns to compare embedded JSON as data.** HTML report pages are compared as text today
   (`tools/differential/evidence.py`), so a serde switch would fail them on number spelling and escaping
   alone. Extend the native comparison for `reports/html/**/*.html` (and the timeline page if it embeds
   JSON): each `window.<name> = <json>` assignment is parsed and compared as JSON data (same rules as
   `.json` files); the rest of the page is compared as text exactly as today. Add adversarial self-tests
   next to the existing ones: a changed embedded value fails, a changed key order fails, a changed byte in
   the surrounding HTML fails, a re-spelled number (`1.0E10` vs `10000000000.0`) and a re-escaped string
   (`<` vs `<`) pass. Describe the rule in `tools/differential/README.md` and
   `docs/design/differential.md` next to the existing structured-comparison text.
4. **Delete what is left without callers**: `GsonWriter`, `GsonError`, and `JavaNumber` /
   `WriterValue` variants or helpers no remaining code uses. `WriterValue` itself stays while the YAML
   writer (`JacksonYamlWriter`, used by `report/projection.rs` and `marathon-config/src/render.rs`) needs it.

**Out of scope:** `JacksonYamlWriter` and the YAML outputs, `KotlinValue` (Kotlin `toString` rendering),
`jackson::normalize_json_strings` and every JSON *reader* (input side), `jnum`/`jtime`.

## Rules

- The gate is the proof: `scripts/check.sh` passes with the native goldens
  (`fixtures/contract/native-v1`) and the config corpus golden unchanged. **No golden file is re-blessed or
  edited.** The only gate change is item 3 (how HTML pages are compared), with its self-tests.
- If a golden fails for a reason other than number spelling or string escaping, the data changed: fix the
  code. If you believe a data change is a JVM artefact the contract lets us drop, stop and report it
  instead of changing it.
- Tests that pin Gson byte spelling (escapes, `1.0E10`-style numbers, `GsonWriter` unit tests) may be
  rewritten to assert the same data through `serde_json::Value`, or deleted when they test only the
  deleted writer; their parity-matrix rows become `n/a` with reason `8.4: serde JSON` only if deleted.
  List every changed test function in `docs/wp/8.4-test-changes.md` with a one-line reason.
- Never edit a copied fixture under `fixtures/`; add new files instead.
- Keep `//! Port of ...` headers and the comment density; delete comments that only explained Gson
  spelling.
- No `unwrap()`/`expect()` on I/O, process or network results; serialization errors propagate as the
  current `GsonError` paths do.
- Commit in building steps.
