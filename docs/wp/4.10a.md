## Deliverables and boundary

All in `crates/marathon-apple`:

1. **`AppleDevice` trait** (`B/AppleDevice.kt`): `AppleDevice: Device + Screenshottable + LogProducer`, object-safe, with async methods returning `VendorFuture` and taking a `VendorContext`.
   - Accessors: `udid`, `remote_file_manager`, `storage_path`, `transport`, `sdk`, `binary_environment`.
   - Async methods: `setup` (failures are `VendorError::DeviceSetup`), `execute_worker_command`, the push/pull/folder methods, `push_generated_file` (defaults to `push_file`, :65), `push_shared`, `install`, `get_screenshot(timeout, dst)`, `start_video_recording`, `stop_video_recording`, `shutdown` and `erase`.
   - `SHARED_PATH = "/tmp/marathon"` (:84).
   - Two free helpers that implementors call, because Rust cannot override the supertrait's `Device::worker_id` from a subtrait default:
     - `apple_worker_id(transport)` returns `Some(transport.id())` (:24–25).
     - `apple_arch(sdk, abi, udid)` (:27–39) is recomputed on every call. Never cache it: `abi` changes after simulator setup (`AppleSimulatorDevice.kt:264`).
   - `execute_test_request` is **not** declared here; see open question 2.
2. **`RemoteFileManager`** (`B/RemoteFileManager.kt`): the full path layer and command layer below, with the same logger name, messages and levels. It must not hold an `Arc` back to its device (open question 4).
3. **Shared worker-command helper.** Both devices implement `executeWorkerCommand` identically: `commandExecutor.safeExecute(command, timeoutConfiguration.shell, timeoutConfiguration.shellIdle, emptyMap(), null)` (`ios/AppleSimulatorDevice.kt:711–719`, `macos/MacosDevice.kt:215–223`). Provide it once here, so that 5.2 and 5.6 both delegate to it and `RemoteFileManager` can run without its device.
4. **`AppleLogConfigurator`**: `impl LogConfigurator`. It sets the registry's `debug`, then calls `configure(debug, Vendor::Apple { compact_output })` (`B/AppleLogConfigurator.kt:18–59`; `Marathon.kt:67–68` ordering per lifecycle.md). The registry lock is short, never held across an await, and taken off core. The layout, noise list and Jansi behaviour are already 1.6's (inventory `wp=1.6`); do not re-port them. The iOS and macOS factories (5.5a/5.6) construct it from `compactOutput` (`IosVendor.kt:67`, `MacosVendor.kt:66`).

## Behaviours to reproduce (exact sources)

Paths are plain `String`s joined with `"/"`, never `Path` (:10–11). Let `S` be the device's `storagePath`, read once (`by lazy`, :15).

**Path layer:**
- `remoteDirectory()` = `remoteTestRoot()` = `S` (:17, :144).
- `remoteSharedDirectory()` = `"/tmp/marathon/shared/"`, **with** the trailing slash (:18).
- `remoteSharedMediaDirectory()` = `"/tmp/marathon/shared/mediaFiles/"` (:19).
- Private `String.resolve(file)` (:218–223):
  - an absolute `file` (leading `/`) is returned unchanged;
  - otherwise the result is `this.removeSuffix("/") + "/" + file.removeSuffix("/")`, removing one slash at most.
  - Users of `resolve`:
    - `remoteXctestrunFile` = `S/marathon.xctestrun` (:57, :71);
    - `remoteXctestFile` = `…/shared/marathon.xctest` (:59, :73);
    - `remoteTestRunnerApplication` = `…/shared/xctestRunner.app` (:60, :77);
    - `remoteXctestParserFile` = `…/shared/libxctest-parser.dylib` (:61, :74);
    - `remoteApplication` = `…/shared/appUnderTest.app` (:62, :76);
    - `remoteExtraApplication(name)` (:63) and `remoteMediaFile(file)` (:64), both under `resolve` rules;
    - `remoteXcresultFile(batch)` = `S/<udid>.<batch.id>.xcresult` (:69, :79–80);
    - `remoteLog()` = `S/device.log` (:120–122).
- `remoteFileForTest(name)` = `S + "/" + name`, **without** `resolve` (:124–126):
  - `remoteVideoPidfile()` = `S/<udid>.pid` (:114, :143);
  - `remoteScreenshot(udid, type)` = `S/<udid>.<type.value>`, with value `png|tiff|bmp|jpeg` (:116–118, :128–130);
  - `remoteVideoForTest(test, batchId)` and `remoteTempVideoForTest(...)` (:106–112, :132–137): `escape(test.toClassName('-') + "-" + method) + "-" + batchId + ("-temp" if temporary) + ".mp4"`. Only the test part is escaped; `batchId` is not. Use `to_class_name('-')` (blank `pkg` is dropped, Java whitespace) and `jcompat::file_manager::escape_utf16` on the `JavaString`.
- Public `xctestrunFileName()`, `appUnderTestFileName()` and `testRunnerFileName()` (:71, :76–77).
- `parentOf(p)` = `substringBeforeLast("/")`: a string with no `/` is returned whole; `"/x"` gives `""` (:139–141).
- `joinPath(base, args…)` = `[base.removeSuffix("/"), args…].join("/")`; the args are not normalised (:146–151). It has 20 call sites, mostly 4.5b.

**Command layer.** Exact argv, in order:

| Method | Argv | Error message on exception |
|---|---|---|

| `test(p)` | `test -f <p>` | none: exceptions propagate; returns `result?.successful == true` (:196–202) |

The shared `executeCommand` (:92–104):
- A `null` result returns silently.
- Otherwise, if `combinedStderr.trim()` is not blank, it logs ERROR `cmd=<argv joined by " ">, stderr=<trimmed>`.
- **The exit code is ignored**, so a failure with empty stderr is silent and indistinguishable from success.
- Any exception logs ERROR `<errorMessage>` **with the throwable**, then returns null. That includes `CancellationException` (C36 pattern; see P1 and K2). Render the throwable through the merged `Failure` logging path; D12 covers `\tat` frames.
- The trimmed stdout it returns is discarded by every caller (all return `Unit`).
- Logger: `com.malinskiy.marathon.apple.RemoteFileManager` (`MarathonLogging.logger {}`, :14), abbreviated by `%logger{40}` or `{48}` per 1.6.

The executor's quoting of `!`, `{}` and `+` over SSH is 4.2/4.3's bug-compatible `shellCommand`; assert argv **before** quoting.

**`AppleDevice` defaults:**
- `workerId` = `transport.id()`, so `"local"` or `"addr:port"` (:24–25).
- `arch` (:27–39):
  - if `sdk == IPHONESIMULATOR`: `abi` `"x86_64"` gives `x86_64`; anything else, `"arm64"` included, gives `arm64`;
  - otherwise a `udid` containing `-` gives `arm64e`;
  - otherwise `arm64`.
- So tvOS and watchOS simulators, and macOS hosts (whose provisioning or ioreg UDIDs contain `-`, `AppleMacosProvider.kt:131–133`), are `arm64e`. That sends `TestRootFactory.matchArchitectures` (:446–452, 4.5b) into its `lipo` arm64e branch, which changes worker argv. Keep it (K3).

**Kotlin bugs to record** (new rows, status `seeded` until a Rust test confirms them; next free ids after A42):
- **K1:** `executeCommand` ignores the exit status (above).
- **K2:** `catch (e: Exception)` in `executeCommand`/`safeExecuteCommand` catches cancellation, logging an ERROR line and continuing to the next suspension point.
- **K3:** the `arch` rule for SDKs other than `IPHONESIMULATOR`.
- **K4:** `find -name` treats kept names as glob patterns, and a kept path ending in `/` yields `-name ""`, which deletes the bundle it meant to keep. Exotic, but free to reproduce.

## Proposed simplifications (pragmatic parity; for orchestrator approval, **not decided**)

Until one is approved, the behaviour above stands.

- **P1, cancellation in `executeCommand`:** propagate `VendorError::Cancelled` instead of logging `<errorMessage>` and returning `None`. Caveat: this is reachable in ordinary runs (dispose during a cancelled batch), not only on exotic input. It also matters only when cancellation arrives as `Err(Cancelled)` from the executor; if the future is dropped instead, neither language variant logs. The C36 precedent kept the Kotlin behaviour, so I lean towards **keeping it** and recording K2.
- **P2, dead code:** do not port the private `bashEscape` (:204). It has no callers.
- **P3, representation (not observable):**
  - `RemoteFileManager` stores `storage_path` at construction instead of reading it lazily; both implementations set it as a constant from `udid`.
  - The command helpers return `()` instead of the discarded trimmed stdout.

No simplification is proposed for any argv, path or log text. They cost nothing to keep exact.

## Open questions for the orchestrator

1. **Scope and size.** Two of the PLAN row's four items are done: the P2 types and transports (2.3b) and the Apple layout and noise filters (1.6). What remains is 309 Kotlin lines plus a roughly 20-line trait impl, with **0 parity rows**. 4.3's brief (:22) also gives 4.10a "runtime target integration" for `Transport`/`AppleTarget`. In base Kotlin that is only `AppleDevice.transport` and `workerId`; target handling lives in the 5.4/5.5a/5.6 providers. Recommendations:
   - rewrite the PLAN row as "Base `AppleDevice`; `RemoteFileManager`; shared worker-command helper; `AppleLogConfigurator` trait impl";
   - set the effort to S;
   - keep it a separate WP, because it unblocks 4.5b, 4.7 and 4.9 in parallel; the alternative is folding it into 4.10b.
2. **`executeTestRequest` dependency cycle.** `AppleDevice.kt:55` names `XcodebuildSession` (4.8) and `TestEvent` (4.7), and both of those WPs depend on 4.10a. Options:
   - (a) 4.10a omits the method and 4.8 adds it to the trait in the same crate (recommended);
   - (b) move `B/test/TestEvent.kt` (14 lines, `wp=4.7`, 0 rows) to 4.10a and declare an opaque session type that 4.8 fills in.

   Either way, no inventory change is needed for (a).
3. **Downcast seam.** `NmTestParser.kt:34` and `XCTestParser.kt:36–37` do `device as? AppleDevice ?: throw ConfigurationException("Unexpected device type for remote test parsing")`. Core's `DeviceRef(Arc<dyn Device>)` has no `Any`, and model-contract forbids core downcasts. Options:
   - (a) recommended: a vendor-owned `AppleDeviceRegistry`, shared by the Apple factory, providers and parsers, that maps `DeviceRef` identity (`Arc::as_ptr`) to `Arc<dyn AppleDevice>`. Providers register on connect and remove on dispose; a miss gives that exact `ConfigurationException`.
   - (b) add `as_any` to the frozen `Device`, which reopens 0.6.

   4.8 and 4.9 need the answer, so decide it now.
4. **Device ↔ manager ownership.** Kotlin's `RemoteFileManager(device)` is a reference cycle. Recommendation:
   - a `WorkerCommands` trait (`execute_worker_command(argv, &VendorContext) -> VendorFuture<Option<CommandResult>>`), implemented by the shared helper from deliverable 3;
   - `RemoteFileManager::new(storage_path, udid, Arc<dyn WorkerCommands>, logging)`;
   - `AppleDevice::execute_worker_command` delegating to the same helper.

   4.9 can then port `ResultBundleRunListenerTest`'s fake-device setup unchanged in spirit. The cost is that every command method takes a `&VendorContext`, which Kotlin does not have; confirm that this is acceptable.
5. **K1–K4:** confirm they are kept under D5 and added to `known-kotlin-bugs.md`, K3 in particular, since it changes worker argv on macOS and tvOS/watchOS simulators.
