The actor variants specify insertion offsets relative to the old non-sorting
events, rather than dropping runtime events from comparison. Every native key
and random draw is checked. The recording lookup itself does not emit metric
read events; sorting tests separately pin every read. Thirty-nine explicit
field replacements account for two snapshot reorderings plus the RandomOrder
and full D50 scenarios. Other non-sorting events and accounting are unchanged.

For RandomOrder, initial keys `[17, -4, 99, 3, 42]` belong to input tests
C0 through C4: order C1, C3, C0, C4, C2. The first failed status consequently
belongs to C1 instead of C0; their final attempt counts change to 2 and 1,
respectively. In the full D50 scenario, the first batch includes C3 after C1
and C2, and subsequent batches complete C0 and C3 instead of leaving their
states `Added` at the old truncated checkpoint. Retry-worker and progress
changes in those two cases follow these changed batches; none is ignored.
