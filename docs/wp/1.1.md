# WP 1.1: Java priority queue

**Depends on:** 0.2a. **Branch:** `wp/1.1-java-priority-queue`.

## Goal

Reproduce the reference JDK 21 comparator-based `java.util.PriorityQueue` as used by marathon, including comparator argument order, ties, equality-based removal, bulk removal and backing-array iteration. Comparator state may change on each comparison, so no extra comparisons are allowed.

## Deliverables

- `jcompat::JavaPriorityQueue<T, C>` with a stateful `FnMut` comparator returning `Ordering`;
- construction with a comparator, `offer`, `add_all`, `peek`, `poll`, `remove`, `remove_all`, `len`, `is_empty`, `iter` and `clear`;
- oracle-driven tests comparing every operation result, backing-array order and comparator call trace;
- findings and coverage recorded in `docs/wp/1.1-findings.md`.

## Kotlin call sites

All paths below are relative to `core/src/main/kotlin/com/malinskiy/marathon/`:

- `execution/queue/QueueActor.kt`: sole direct PriorityQueue construction (line 46); initial/rejected/retry insertion (67, 184, 246), backing-array traversal for retry filtering/counting (207, 226, 238, 273), bulk equality removal and reinsertion (211, 215, 282), size/emptiness checks throughout.
- `execution/strategy/impl/batching/ClassNameBatchingStrategy.kt`: peek, iteration/toList and removeAll.
- `execution/strategy/impl/batching/IsolateBatchingStrategy.kt`: poll.
- `execution/strategy/impl/batching/FixedSizeBatchingStrategy.kt`: size/emptiness, poll and addAll of deferred tests.
- `execution/strategy/impl/sorting/ExecutionTimeSortingStrategy.kt`, `SuccessRateSortingStrategy.kt`, `RandomOrderSortingStrategy.kt`, `NoSortingStrategy.kt`: comparator providers consumed by QueueActor. Lazy duration/random keys and the all-equal comparator require the exact call order.

No Kotlin test or source-inventory row is assigned to WP 1.1. The existing strategy and queue tests remain assigned to their consuming WPs.

## Oracle coverage and acceptance

Use `fixtures/oracle/jcompat/priority_queue.jsonl`, generated by `tools/oracle/module/src/main/kotlin/oracle/JcompatTables.kt`: 240 scenarios, 5,824 operations and 7,104 comparator calls, with 60 scenarios each of random keys, equal keys, few keys and duplicate equality groups. Keys and equality groups are independent, so the comparator is inconsistent with equals. All eight queue operations and empty/missing cases are present. This is sufficient existing coverage; no expected values are handwritten and no generator extension is needed.

Acceptance: every oracle result, trace and backing array agrees, and `scripts/check.sh` passes. No changes to copied fixtures or the Kotlin checkout; no intentional behaviour deviations.
