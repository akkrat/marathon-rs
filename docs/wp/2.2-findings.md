## Delivered boundaries

- `crates/marathon-config/src/schema.rs` holds the filled types: `Configuration`
  (field order and widths unchanged from 0.6), `AnalyticsConfiguration` with
  `InfluxDbConfiguration`/`RetentionPolicyConfiguration`,
  `InfluxDb2Configuration`/`InfluxDb2RetentionPolicyConfiguration` and
  `GraphiteConfiguration`, `analytics::Defaults` (re-exported as `Defaults`),
  the seven strategy hierarchies plus `ExecutionStrategyConfiguration`/
  `ExecutionMode`, and `FilteringConfiguration`/`TestFilterConfiguration`
  (11 variants). No serde derives, no `Default` impls carrying binding
  defaults. `AndroidConfiguration`/`IosConfiguration`/`MacosConfiguration`/
  `MarathonDevices` stay 2.3 slots.
- `crates/marathon-config/src/bind.rs` holds the hand-written `bind_*`
  functions, each `fn(Value) -> Result<Option<T>>` in the 2.1 style:
  `bind_configuration` (through the Kotlin Builder, vendor binder passed in
  as a parameter, decision 2), `bind_output_configuration`,
  `bind_screen_recording_policy`, `bind_ci_configuration`,
  `bind_execution_strategy`, `bind_defaults`, `bind_analytics_configuration`,
  `bind_retention_policy_configuration`,
  `bind_influxdb2_retention_policy_configuration`, all seven
  `bind_*_strategy` functions, `bind_filtering_configuration` and
  `bind_test_filter_configuration`. `bind_empty_vendor_configuration` is the
  seam stub handling only `empty`; WP 2.3a supplies the real dispatch through
  the same parameter. No loader, validator or vendor post-processing is
  implemented here, and no frozen trait is implemented.
- The six lenient deserializers are the schema functions inside `bind.rs`
  (`influx_db`, `graphite`, `retention_policy`, `bind_execution_time`,
  `bind_probability`, `bind_fixed_size`). They are the only binders that
  ignore unknown keys, via `read_tree` plus `get`/`find_value` and the
  non-throwing tree accessors; everywhere else unknown keys are
  `UnrecognizedPropertyException`. Per-field `timeLimit` tries `Instant`,
  retries as `Duration` only on `InvalidFormatException`, and adds it to the
  single `BindingContext.now` (S2). A container/boolean `timeLimit` surfaces
  as `MismatchedInputException` from `Value::instant`, never as
  `InvalidFormatException`, so it propagates exactly as in Kotlin; proven by
  `container_time_limit_is_mismatched_not_invalid_format` and the C58-7/8/9
  corpus rows. No binder gap was found there.
- `validate()` is defined on `TestFilterConfiguration` (each variant, Kotlin
  simple names and messages verbatim) and on `FilteringConfiguration`
  (allowlist then blocklist). Who calls it remains WP 2.4. It returns the new
  `schema::ConfigurationException { message }`; binding failures keep using
  `ConfigurationError` with that class name (`bind::CONFIGURATION_EXCEPTION`,
  cause `Custom` for lenient-deserializer messages).
- `Value::node_string` in `tree.rs` renders a tree node the way Jackson
  `JsonNode.toString()` does, for the `probability` failure message: scalars
  exactly (strings quoted/escaped), containers as compact JSON (S3; on the
  pinned witnesses this matches Jackson byte for byte). It is iterative.

## Approved simplifications, as implemented (S1-S7)

- **S1** Lawful full-field equality. `Configuration` and every section derive
  `PartialEq` over all fields (including `enabled`, ordered composition
  filters, separated `annotationData` patterns, value-equal `allure`), plus
  `Eq` wherever the fields allow it; types containing `f64` are `PartialEq`
  only, which is the one place "PartialEq/Eq" cannot both hold. `Hash` is
  derived nowhere in the schema (nothing needs it yet, decision 4).
- **S2** One `BindingContext.now` for every relative `timeLimit` in a file.
- **S3** Node rendering as above; pinned by the `NodeString-*` oracle rows.
- **S4 (D9)** A `null` collection element is rejected at bind
  (`list_non_null`, class `MismatchedInputException`, message
  `D9: null element in collection`); the frozen `Vec<T>` fields stay. A
  `null` *collection* keeps the 2.1 `Field` rules (a non-null Builder/creator
  collection rejects it, e.g. `includeSerialRegexes: ~`).
  **Narrowed in review round 1 (R1-claude-2):** a `null` element in a filter
  `values` list (`SingleValueTestFilter` / `AnnotationFilter`, where Kotlin
  only calls `contains`/`intersect` so a null element never matches) is
  **dropped** (`list_drop_nulls`) instead of rejected — matching is
  identical. Everywhere Kotlin later dereferences the element (allowlist/
  blocklist, composition `filters`, pooling `combo`, the serial regexes)
  the rejection stands. Note for WP 2.4: Kotlin's `toMap()`/config-dump
  would still show the dropped nulls; ours will not.
- **S5 (D9 P5)** Graphite `port` parses with Kotlin `toIntOrNull` semantics
  restricted to ASCII: optional sign, digits, no trimming (`" 2003"` fails
  exactly as `toIntOrNull` does; the JVM's non-ASCII digit acceptance is the
  one divergence, oracle row `AnalyticsConfiguration-graphite-port-arabic`).
- **S6** The analytics lenient deserializers run their required-field checks
  (`url/user/password/dbName`; graphite `host` → `port` → `prefix`) before
  binding nested `defaults`/`retentionPolicyConfiguration`; only the reported
  error changes on doubly-invalid input.
- **S7 (D9)** `now + Duration` overflow is a plain binding error
  (`JsonMappingException`, `D9: now + Duration overflows Instant`) when both
  values parse; a `Duration` spelling too large to parse at all takes the
  ordinary invalid-`timeLimit` path (`"bbb"` / `null` / the probability
  message). The JVM's `ArithmeticException: long overflow` chain is not
  reproduced.

Secrets are masked in hand-written `Debug` for influx v1/v2, mirroring the
Kotlin `toString` shapes (decision 6); graphite masks nothing in Kotlin and
keeps derived `Debug`. `toMap`/`config-dump` rendering stays WP 2.4.

### Carried to WP 2.4 from review round 2 (Claude)

- The "Kotlin only calls `contains`/`intersect` on filter `values`" wording in D9, F10 and `list_drop_nulls` has one exception. `TestPackageFilter` with `subpackages: true` (`core/.../filter/TestPackageFilter.kt:13-15`) uses `startsWith("$it.")`, so in Kotlin a `null` element becomes `"null."` and matches packages starting with `null.`. This is effectively unreachable, because `null` is a reserved word in Java and Kotlin. The behaviour stays; 2.4 should add this caveat to the three texts.
