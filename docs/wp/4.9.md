## Deliverables and boundary

In `crates/marathon-apple` (PLAN §4 places `ArtifactProcessor` here):

1. **`artifact_processor`**: a run-scoped, explicitly constructed `ArtifactProcessor`.
   - Two constructors: from `(capacity, max_concurrent, worker_capacity)`, and from `XcresultQueueConfiguration`. Both take a `VendorRuntime` handle and the monotonic hook.
   - API: `submit`, `await_owner`, `protect`, `release`, `report_undelivered`, `kept_sources`, `close_and_join(timeout, cancel_timeout)` and `admission_stats`.
   - All bookkeeping is under one short `std::sync::Mutex`. It is never held across an await, a spawn, a callback or a log call. This mirrors Kotlin, which starts workers and resumes waiters outside `synchronized`: `B/ArtifactProcessor.kt:233–236,444–447`.
   - **Recommended structure** (open question 3): a synchronous admission and accounting core (waiters, worker queues, `outstanding`, `pending`, sources, stats) as plain data with no async, plus a thin async shell (vendor tasks per worker, the transfer semaphore, timeouts). The fairness and sizing tests can then drive the core with a discrete-event simulator in exact virtual time, independent of the multi-threaded vendor runtime.
2. **`listener/result_bundle_run_listener`**: `ResultBundleRunListener` implementing `AppleTestRunListener`, taking an `Option` processor. `None` is the synchronous macOS path.
3. Public seams for 5.2, 5.5a and 5.6 above, each with a consumer-shaped test. **Not 4.9:**
   - device prepare/terminate wiring: 5.2 and 5.5a own it, along with their rows (`AppleSimulatorDeviceArtifactTest` 3 rows to 5.2, `AppleSimulatorProviderArtifactTest` 1 row to 5.5a);
   - rsync and the pull itself: 4.3 and 4.10a;
   - `TestResultsListener`, `CompositeTestRunListener` and `AppleTestRunListener`: 4.7;
   - `AppleDeviceTestRunner`: 4.8;
   - `XcresultQueueConfiguration` binding and validation: 2.3a and 2.4, merged.

**Frozen interfaces consumed:**
- Cancellation flows through `VendorContext.cancellation`. Each worker loop is a `spawn_cancellable` task that the processor owns (the Kotlin `SupervisorJob`, `:51–52`).
- Bounded waits use `VendorClock::with_timeout_or_null`, so own expiry is `None` and inner cancellation propagates unchanged.
- Work still running after the cancel deadline is **abandoned, not joined**, as in Kotlin (`:364–367`). Its handle stays in a `RetainedTasks` so nothing is detached silently (U55), and its late return is logged once (`:279–283`).
- No `unwrap` on I/O or process results. Callbacks never run under the lock.

## Behaviours to reproduce (`B/ArtifactProcessor.kt` unless stated)

- **Limits** (`:21–47,209`):
  - Admissible iff `outstanding < capacity` and the worker's `held < workerCapacity`. `held` counts queued and active work.
  - At most `maxConcurrent` transfers run (one fair semaphore, `:50,271`), and each worker runs one at a time in admission order.
  - The default worker capacity is `max(1, capacity / concurrency)` (`C/:52`).
  - The constructor checks `capacity≥1`, `maxConcurrent≥1`, and `workerCapacity ∈ 1..capacity` (`:43–46`). Config validation makes this unreachable (P4).
- **Admission** (`:137–186,212–231,243–256`):
  - When closed, the submit is rejected at once: `onUndelivered("artifact queue is closed")` is called directly, not through `reportSafely`, and `submit` returns false.
  - When admissible, the waiter is admitted (and starts the worker if no queue exists). Otherwise it is queued in arrival order with `blockedByRun = outstanding >= capacity`.
  - `dispatch` runs after every `complete`. It makes one arrival-order pass while `outstanding < capacity`, **skipping waiters whose worker is at its share**.
  - `admit` stamps `enqueuedAt = clock()`. Only waiters that suspended record `waitMillis = (enqueuedAt − arrivedAt)/1e6` (integer division) in `admissionWaits`, and only `blockedByRun` ones count in `waitedForRun`.
  - `pending[owner]` is a per-owner count with a barrier `done`. The run-wide `done` is replaced when `outstanding` goes 0→1.
- **Cancellation during admission** (`:189–207`): the side that moves the state away from WAITING reports. A cancelled WAITING waiter is removed, reports `"admission was cancelled"` and rethrows. A cancellation racing an ADMITTED waiter rethrows without reporting, and the work still runs. A REJECTED waiter returns false, and closing reports it.
- **Worker loop** (`:258–294`):
  - It takes the head under the lock into `running`. An empty queue removes the worker entry, and a missing entry returns.
  - `ensureActive`, then the permit, then a DEBUG queue-wait line, then the action. **`catch (Throwable)` also catches cancellation** (see K1).
  - If `running.remove` fails (shutdown already reported the work), it logs a WARN with the failure and returns.
  - On failure it logs a WARN with the throwable, then `onUndelivered("processing did not complete: $failure")`. `complete` always runs in `finally`.
- **`complete`** (`:432–448`): decrement the owner (removing it at 0 and completing its barrier), the worker's `held` (if the entry is present) and `outstanding`; then `dispatch`. Outside the lock: start new workers, complete the barriers, then resume admitted waiters, in that order.
- **Sources** (`:303–341`):
  - `protect` keeps the **first** callback (`getOrPut`). Once closed it reports immediately with `"artifact queue is closed"`.
  - `release` removes only REGISTERED entries; SWEEPING and REPORTED stay kept.
  - `reportUndelivered` creates a callback-less entry if absent, returns false if already REPORTED, and appends the diagnostic. A `null` source always appends.
  - `keptSources` is the owner's key set **in insertion order**. It becomes the `keep` argv of `removeRemoteDirectory`, so ordering is wire-visible.
  - All maps are Kotlin `LinkedHashMap`/`LinkedHashSet`: insertion order, and removal followed by reinsertion moves the key to the end (use `IndexMap::shift_remove` semantics).
- **`closeAndJoin`** (`:350–412`). Its order is pinned by three Fairness rows:
  1. close and snapshot `done`; mark the waiters REJECTED, clear them, resume them;
  2. bounded drain (`DRAIN_TIMEOUT_MILLIS = 300_000`). On timeout, WARN with `pending` rendered as `[owner: N bundles, …]`;
  3. cancel all workers and join them for at most `CANCEL_TIMEOUT_MILLIS = 60_000`;
  4. take `running` as stuck and the queued work as residual, and clear both. If anything is stuck, WARN with `[owner, batch id, …]`;
  5. report stuck work `"still running N ms after shutdown cancelled it"` and residual work `"not started before shutdown"`, each through `reportSafely`, then `complete`;
  6. a second bounded wait for `done`;
  7. report the rejected waiters `"artifact queue is closed"`;
  8. move REGISTERED sources to SWEEPING and report them `"never handed to the artifact queue"`;
  9. DEBUG finalization time; the INFO admission summary (only if admitted > 0); the ERROR undelivered block; return the list.

  A second call is legal and returns the cumulative list (`ArtifactProcessorTest.kt:310`). `reportSafely` catches `Exception` and logs ERROR `Reporting an undelivered artifact failed: <reason>` with the throwable.
- **Stats** (`:414–421`): nearest rank `(admitted*95+99)/100` over all admitted, where the ones not waited count as 0 ms. Max, p95 and total come from the sorted waits.
- **Log lines.** Logger names are `com.malinskiy.marathon.apple.ArtifactProcessor` and `…apple.listener.ResultBundleRunListener`. Exact text is at `:142,177–184,272,281,287,300,362,372–375,394,397–402,406–409,428` and at RBRL `:78,94,111–115`. Durations from `measureTimeMillis`/`nanoTime` go through the nondeterminism labels; `clock`-based durations go through `apple.ArtifactProcessor.clock`. Default `onUndelivered` (`:141–144`): ERROR `Artifact for <owner>, batch <id> was not processed: <reason>`, and diagnostic `<owner>, batch <id>: <reason>`.
- **`ResultBundleRunListener`** (`B/listener/ResultBundleRunListener.kt`):
  - `beforeTestRun` protects `remoteXcresultFile(batch)`, which is lazy (`:37–43`). `testFailed` and `testRunFailed` set `isBatchFailed`.
  - The policy is ALWAYS / NEVER / ON_FAILURE (`:118–124`).
  - `afterTestRun` (`:55–68`): if no pull, release first. If there is neither a pull nor `remoteClean`, return. With no processor, run inline. Otherwise submit with `(serialNumber, batch.id, transport.id())`, with a no-op `onUndelivered` when not pulling.
  - `processBundle` (`:70–80`): deliver, and release only on success; then `rm -rf` if `remoteClean`. A failed delivery skips cleanup.
  - `deliver` (`:86–108`): `createFolder(DEVICE_FILES, pool, deviceInfo)/xcresult`, created with `mkdirs`; `localCopy = <dir>/<remote basename>`; `pullFolder`, with its DEBUG time.
    - On success, `Files.move` to `<batchId>.xcresult` **without replace**. An existing destination, even an empty directory, fails.
    - If `pullFolder` returns false, the reason is `"pull failed"`.
    - Cancellation is rethrown; other exceptions become `e.toString()` (K2).
  - `undelivered` (`:110–116`) composes the diagnostic, with `local copy:` showing the path only if it exists. It logs an ERROR only if `reportUndelivered` did not return false.

## Proposed simplifications (for the orchestrator, not decided)

- **P1: JVM text in diagnostics** (K1/K2, under D12). Keep the `processing did not complete: <Class>: <message>` shape, using fully qualified Java class names from our error taxonomy for the common failures: IOException family, `FileAlreadyExistsException`, `NoSuchFileException` and `JobCancellationException: Job was cancelled`. Drop `; job=…@<hash>` and other identity hashes. WARN throwables follow D12: message, no `\tat` frames.
- **P2: tie-breaking at the same virtual instant.** The sizing and characterization rows pass on the Kotlin assertions and invariants, plus an exact match of the JVM report tables **where no two events share an instant**. Where kotlinx's dispatch order breaks a tie, a differing figure is recorded in the findings, not emulated.
- **P3: inline dispatcher row** (`Fairness:342`). Rust has no `Dispatchers.Unconfined`. Port its intent: an action or callback that runs synchronously on the submitting task and re-enters `submit`/`await`/`report_undelivered` does not deadlock, and admits the third submitter in order. Test it on a current-thread vendor runtime under the same name.
- **P4: constructor validation.** Return a typed error carrying Kotlin's `Invalid artifact queue limits: …` text, rather than emulating `IllegalArgumentException`. It is unreachable from a validated config.

Until a proposal is approved, the Kotlin behaviour above stands.
