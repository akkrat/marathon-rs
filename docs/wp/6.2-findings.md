## Delivery and handoff

`marathon-adb::client::sync` supplies v1/v2 stat/list/pull/push, independent compat dispatch,
compression flags (requests always use NONE), directory push and shell listing. Requests expose
adam names, with `StatFileRequest::v2`, `ListFileRequest::v2`, `PullFileRequest::v2` and
`PushFileRequest::with_v2` selecting v2 within shared implementations. Metadata is retained in
`FileEntry::{V1,V2}` with jcompat Instants. The compat wrappers expose inherent `execute` methods;
no generic MultiRequest hierarchy was added. Directory traversal is breadth-first and retains
platform directory enumeration order. It emits directories before files and stops on a final
progress other than 1.0.

`client::pkg` supplies remote/streamed/split install, uninstall and individual create/write/commit
requests. Split accumulates trailing newlines, does not abandon a failed create, and attempts
abandon after caught write/commit exceptions while preserving the original error. A non-Exception
Throwable still escapes. 6.5 retains installer choice, forced CMD split features, legacy md5 polling,
staging, retries and device-state translation.

`client::reverse` supplies the local/remote spec models/parsers, no-rebind mode, add and remove.
Serial transport selection is left to the client. The second status and optional integer reply
are consumed as adam does. Host forwarding and unused reverse list/remove-all were not added.

`client::framebuffer::ScreenCaptureRequest` returns `RawImage`, including all header fields and
profile metadata. `BufferedImageScreenCaptureAdapter::decode` produces an owned `FramebufferImage`
with dimensions, sRGB RGBA and source profile metadata. `RawImage::to_buffered_image` retains the
raw adapter's distinct component interpretation and profile roundtrip. `encode_png` exports sRGB
PNG. **Decoding and encoding are synchronous CPU work: call them through the vendor runtime's
owned `spawn_blocking` task and join it.** Network capture remains async. This splits capture from
conversion to preserve the frozen 6.1 traits without doing pixel work on core.

Conversion is pinned to `lcms2 = 6.1.1` with static Little CMS (`lcms2-sys 4.0.7`, LCMS 2.19 in
Cargo.lock); encoding/PNG tests use `png = 0.18.1`. The reference JBR standard sRGB profile is
exported by the probe and embedded as the output profile. The copied adam sRGB/P3 profiles stay
unchanged. `NO_OPTIMIZE` is necessary to reproduce the JDK's 16-bit ICC conversion rounding:
with default LCMS optimization, the sRGB full-image hash differed. Current JVM whole-image ARGB
hashes match exactly for all four fixtures, with repeated captures. The original sRGB PNG has
one-level channel differences from the current JDK, so the historical PNG comparison allows at
most one level; current JVM hashes remain exact. Synthetic raw/buffered P3 and protocol-16 pixels
also match. No AWT allocation/cache identity is emulated.

New AdbError variants retain the five requested Java exception classes and messages with null
causes, plus Runtime/UnsupportedOperation for the corresponding source exceptions. There is no
core/config dependency. No frozen trait, transport or stream change was made.

## File lifecycle and execution context

Run async request preparation/execution on the vendor/I/O runtime; a Send future does not schedule
it there by itself. `prepare` checks file metadata and opens valid inputs asynchronously, saving
metadata for synchronous validation. This approved P3 changes construction/failure timing: the
JVM missing-file constructor throws FileNotFoundException before validate; Rust preparation saves
a failing ValidationResponse for a missing/non-file input, while actual I/O failures return Io.
Preparation tasks themselves must be owned/joined by their caller, like other vendor I/O tasks.

Transfers use sequential Tokio file I/O, 65536-byte pull chunks and 65528-byte push chunks. Pull
opens/truncates only for positive size, writes/flushes before exposing progress, and awaits close
on DONE and on request cleanup. Push closes its reader before DONE and emits the extra 1.0 only
after acknowledgement. Unexpected local EOF and write failures propagate rather than reporting
success. No reader/writer coroutine, detached file task or blocking Drop cleanup was introduced.

Retain `request.completion()` before moving a prepared file request into the frozen client.
After dropping the **stream or execute future**, await that handle's `close()` in protected vendor
cleanup. It retains and finishes pending creation and drains outstanding Tokio file I/O before
releasing the file. A dropped `next()` future needs no cleanup: 6.1 retains the pull in the stream.
`PushRequest` and `InstallSplitPackageRequest` expose group completion handles for readers opened
as the sequence progresses. Successful exhaustion/read_element and error paths close files
explicitly. The caller still owns cleanup when it cancels/drops the whole request operation.
Tests use deterministic one-shot barriers and queued file writes, and await all stubs and tasks.

## Scope, parity and approved simplifications

There are zero marathon main-source inventory rows in this external-library WP. The original
baseline contains 62 adam file/portion assignments; source logic is consolidated into Rust modules,
with shared v1/v2 implementations and no generic request hierarchy. P1 omits seven unused request
files (recovery sideload, PmList, atomic parent create/add-session, reverse list/remove-all); its
33 test rows are n/a with exactly `marathon never calls this adam API at e47352f2`. The R1 reviewer agreed with all 33 n/a rows. The other **72 rows are ported** under
the Kotlin snake_case method names and class/package-specific Rust modules. The matrix generator
records the mappings and generates the CSV; the CSV is not edited by hand.

P2 is applied: negative/oversized/short sync or framebuffer records and inconsistent image geometry
return explicit typed protocol errors. Valid-wire packet limits, signed timestamps, UTF-16 versus
UTF-8 path limits, v2 N18 decoding, independent features, NONE compression, push DONE byte order,
progress and acknowledgement ordering are retained. A framebuffer is limited to 256 MiB before
allocation. The negative-DATA JVM witness is preserved as IllegalArgumentException; Rust's typed
UnsupportedSyncProtocol result is the approved difference.

P3 is applied as described above; two-slot coroutine/pool/open-start race identity is omitted.
P4 is applied only to AWT identity/cache reuse/poisoning, preserving pixel/profile fidelity. The
original tests capture twice through the same adapter value. No tests are moved to another WP.
No high-level recovery, atomic-install or pull orchestrator, installer wrapper, GIF or screenshot
listener was added. The only API-shape adaptation is explicit capture then off-core conversion.

  neither expectation calls the production decoder.

- N4: push samples modification time asynchronously at DONE, preserving N20's big-endian encoding.
  The witness changes mtime from `0x01020304` after preparation to `0x05060708` after DATA;

terminators that Kotlin skips. Witness: a filename such as `a\u2028b`. A filename that exotic does
not occur on Android test devices; the orchestrator explicitly approved recording this difference
without changing the implementation.
