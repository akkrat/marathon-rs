Implemented by Sol in `wp/0.4b-apple-world`, starting from main `5d9344d`, in
`.claude/worktrees/wp-0.4b` only. The original Kotlin tree at `e47352f2` was read

## Delivered scope

* A cloneable, SSH-independent `apple::World` behind the existing Handler seam;
  shared worker/device state, finite atomic expectation reservations, uploaded
  plist/product/dylib checks and discovery/batch session completion tracking.
* Valid pulled scripted xcresult trees, enrichment root/id JSON, recording,
  transcoding, PNG/GIF and device-log lifecycles. Real rsync and the existing
  filesystem/executor/process ownership are reused.
* A full Kotlin CLI scenario entry point, isolated archives/HOME/TMPDIR/keys,
  original host argv and lossless streams, declared evidence inventories,
  semantic comparison, report file hashes and completed cleanup checks.
* 110 command-form inventory records; 55 reached by these recordings (including
  nested background commands), 52 explicit deferred failures, and three unused
  pre-existing 0.4a file forms. Three additional host-side send/receive/version
  records retain portable argv templates; raw evidence keeps measured argv.
  Offline checks require version/send/receive shapes and catalogue-form counts.
  No currently unused Apple success response was added. Every form has a contract reference and every deferred example is
  tested for stderr/status 64. Malformed/unknown commands retain 0.4a failures.
* Real build-for-testing products, complete plists and Mach-O binaries in two
  lossless ZIPs, about 213 KB combined; source/build recipes, Unix modes,
  archive/tree hashes and a maintained macOS app/unit/UI sample with shared
  scheme. No caches, dSYMs or unrelated products are committed.

The schema/extension contract is in `docs/design/apple-world.md`; invocation,
comparison boundary and owning-WP backlog are in
`docs/design/fake-apple-scenarios.md`. The source/argv/timeout/stream/effect/test

## Evidence boundary and Kotlin quirks

The comparator requires normalized readiness, exact test status/failure/device role, JUnit totals,
command-form counts, per-test log/media attachments, report-family counts,
static JS/CSS and scripted xcresult content hashes, media hashes/metadata,
finished sessions, exact targeted TCC grants and final device/filesystem state.
The complete retained virtual tree compares modes, file sizes/hashes and
symlinks; only directory inode sizes and typed batch identities are normalized.
The original transcode temporary file is explicitly required (A19). Every output report retains its
path/size/content hash in the raw manifest. It rejects missing artifacts,
changed status, uncatalogued command forms, failed/interrupted recordings and
missing cleanup even on self-comparison. Catalogue patterns and host version /
send / receive shape checks do not validate every argv option. Host `--links` /
`--rsh` tampering and transcript `-destination-timeoutX` can pass offline replay
after updating evidence digests (R1-sol-3 / R1-wonder-2). Both witnesses are in
WP 7.1's backlog; this round does not add per-argv validation. It never decodes/re-encodes opaque streams or
globally rewrites UUIDs/text. Typed readiness fields are normalized; original
UUIDs stay distinct and references intact. Full report-byte/field and opaque
transcript comparison remains WP 7.1.

Two actual macOS runs exposed A20: the final xcodebuild line can be assigned to
the last per-test log or a separate batch log. The initial replay
`apple-macos-smoke-20261023T222538595168` correctly failed the overly strict
32-versus-31-file comparison. Both complete report manifests are retained under
`diagnostics/macos-log-partition/`. The defined comparison now excludes **only
one optional batch-tail log**, requires every per-test log attachment, and
rejects a second batch log. All raw hashes and this measured difference remain
visible; no sleep or behavior patch was added to hide Kotlin's log race.

Known Kotlin rows were updated/added:

* A9: the hosted XCTest is transferred again after the app already carried it;
  the world does not repair the `File == Path` comparison.
* A18: normal `csrutil` output saying SIP is disabled is rejected because Kotlin
  looks for an entire line equal to `disabled`. The initial full-line run showed
  the failure; the permission baseline explicitly supplies that one-line
  fixture response. Both TCC paths are virtual resources, never host databases.
* A19: the original recording remains at `-temp.mp4` after transcoding; final
  filesystem evidence preserves this leftover instead of cleaning it for Kotlin.
* A20: the log partition race above.

Existing A2/A3/A12 behavior, script-before-extension routing, ignored SSH
workdir/env, containment/symlink restrictions and real rsync remain intact.
No Phase 4/5 Kotlin tests were marked ported and no parity row ownership changed.

owning WP. The detailed backlog is in `fake-apple-scenarios.md`. In particular:

  preferences, app running/container/privacy/media-import models, broader media

  baseline UDID. That constant also gates xcodebuild destinations, PlistBuddy,
  recording pkill and the provisioning probe, so a different single initial
  UDID cannot finish a batch; WP 5.1 must address all of these gates.
  A general guards/effects/fault DSL would duplicate 0.4a and
  overbuild this baseline, so its transport fault rules remain the extension
  point instead.
* 7.1–7.2 owns complete byte/field comparisons (including the host `--links` /
  `--rsh` and transcript `-destination-timeoutX` witnesses) and real local/SSH/VM
  certification, with full host snapshot restoration and sequential same-Mac
  runs under PLAN §6.6–6.7. This WP does not certify real Xcode test execution,
  host TCC/SIP behavior or the remote Xcode 26.6 profile.
