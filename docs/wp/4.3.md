## Deliverables and boundary

In `crates/marathon-apple`, provide an explicitly constructed, run-owned `ConnectionFactory` with create/create-or-throw/connect-worker/dispose operations, executor-identity leases, per-transport single-flight sharing, an eight-handshake fair limit, address/reachability preparation, cached rsync bridges, `DeviceFailureReason`/`DeviceFailureException` and the transient classifier. Add `RsyncTarget`, a `RsyncFileBridge` implementing merged `cmd::FileBridge`, the `write_file` command helper and `SharedTransfers` with caller-supplied existence/transfer futures. Retain a connector/address-probe seam for deterministic tests; real constructors must use the production 4.1/4.2 executors and shared config.

**Frozen interfaces consumed:** 0.6's `runtime::{VendorRuntime,VendorTask,VendorClock,CancellationSignal}`, `vendor::VendorContext`, Send `VendorFuture`/`VendorResult` and `error::{Failure,VendorError,Cancellation}`. Dispatch I/O through the vendor runtime; await completion at the Kotlin boundary. Track and join blocking resolution/probes/process work even if an awaiter cancels. No lock across network, close, process wait or pending-attempt wait; no blocking on core and no observable cleanup in Drop. Lease bookkeeping is by executor allocation identity, not host id. Keep structured cancellation distinct from ordinary failure; retain sshj reason/class/cause until classification, before converting to core Failure (which has no disconnect-reason field). 0.6 freezes runtime/error boundaries, **not** a core ConnectionFactory or FileBridge trait: implement Apple's merged 4.1 trait, not a new core abstraction.

**Neighbours:** 4.1 owns local commands/copies; 4.2 owns SSH handshake/retries/authentication/known_hosts, keep-alive and channel/session cleanup. Import `Transport`/`SshConfiguration`/`RsyncConfiguration`/`SshAuthentication` from marathon-config (2.3), including transport Eq/Hash; 4.10a owns their runtime target integration, RemoteFileManager and logging configuration. 4.9 consumes transfers for artifacts; 4.10b owns installer/derived-data transfer decisions; 5.4 consumes worker connection failures for provisioning, while 5.5b owns retry/retirement policy. 4.7 reuses the failure reason/exception from this WP and owns parsing them from logs. Do not implement those consumers here.

The `ssh.debug` WriteFile guard is **at the iOS call site**, not inside `write_file` (`AppleSimulatorDevice.kt:738–745`): SSH, `!ssh.debug`, size ≤32 KiB, helper success; otherwise normal push/rsync. macOS has no equivalent override. Supply/test this contract now with a thin consumer harness; wire production iOS routing in 5.2. Likewise 5.4/5.6 share one SharedTransfers per factory/provider and call it with `transport.id()` and RemoteFileManager's nullable exists; this WP tests callbacks, not a second remote file manager. No per-device `--delete` re-push on reuse, and no alteration of rsync's own delete flag.

## Behaviours to reproduce (locations under B unless qualified)

- **Create/error staging** (`ConnectionFactory.kt:68–115,202–241`): positive max validation with exact custom text; local create registers a fresh executor/bridge, whereas direct `createLocal` does not register. SSH obtains its file bridge before acquire. `create` catches/logs only DeviceFailureException and returns `(null, bridge)`; createOrThrow/connectWorker propagate it. Resolve/check address and prepare auth/verifier **before** taking a fair permit; the permit covers the connector, including 4.2's retries/auth, and is released on every outcome. Only connector IOExceptions are wrapped as UnreachableHost with original cause. Missing auth (`no ssh auth provided for addr:port`) and known_hosts loading failures during preparation propagate unwrapped. Per-transport auth overrides global auth; accept-any unless knownHostsPath is supplied; pass ssh.debug and keep-alive config through unchanged.
- **Lease races** (`ConnectionFactory.kt:117–200`): increment a checking caller's reference under the short map lock, check connected outside it; a blocked check cannot block another worker/disposal or be closed by the former last user. A false check unpublishes only that executor, releases its checking reference and loops; old users still release the lost executor independently of its replacement. Thrown checks release the reference then propagate. Single-flight waiters share failure, unwrap CompletionException, and on success re-lookup/re-check rather than taking an unleased result. Remove pending state on every failure; last dispose removes lease/publication **before** closing outside the lock. Unknown/repeated dispose warns and does not close twice. Do not make new callers wait for an old close, even on the same worker. Preserve log names/text/levels at :79–81,126–131. Test barriers replace JVM thread-state/stack inspection, not the observable ordering.
- **Address handling** (`ConnectionFactory.kt:244–261`): DNS resolution still occurs with checkReachability=false; UnknownHostException becomes UnreachableHost with `Error resolving host $this` and cause. Reachability uses `InetAddress.isReachable(timeout.toMillis().toInt())`, independent of the SSH port. IO failure becomes `Error checking reachability of $this: $e` **without cause**, and false becomes `$this is not reachable within N ms` without cause; both classify transient. Preserve Kotlin Transport rendering in messages. Native ICMP/TCP-echo behaviour and numeric overflow need decisions below; an SSH-port probe is not equivalent.
- **Distinct cache keys** (`ConnectionFactory.kt:60–66,266–281`; `configuration/Transport.kt:20–33`): shared executor key is the whole SSH transport including optional auth/checkReachability; bridge key is only RsyncTarget(addr,port). Construct outside the bridge lock (debug construction runs rsync); first publication wins, including its auth. Competing constructors can each run the version probe. Do not merge these caches or key executor leases by transport.id(). `ConnectionCounter.kt:9–27` defaults to zero, increments/decrements signed Int and can go negative if retained (P1).
- **Failure taxonomy** (`ConnectionFailures.kt:12–40`): only DeviceFailureException(UnreachableHost) can be transient; no cause means true. Inspect at most **16 causes**, stopping an immediate self-link. Any TransportException with UNKNOWN, CONNECTION_LOST, TOO_MANY_CONNECTIONS, BY_APPLICATION, SERVICE_NOT_AVAILABLE or MAC_ERROR qualifies; SocketException/subclasses, SocketTimeoutException, UnknownHostException and concurrent TimeoutException qualify. Other nodes do not stop the search: a deeper qualifying cause can make the whole result transient. Generic IOException, UserAuthException, missing key and host-key failure alone are permanent. **A16 stays:** failed KEX measured as TransportException[UNKNOWN] is transient despite KDoc. A17's unwrapped IllegalStateException stays non-transient; A15's artificial password timeout remains waived by 4.2 P3. Use 4.2 `SshFailure::{is_instance,is_io}`/reason hierarchy (or its free helpers as exported), not a generic UNKNOWN wrapper that hides an explicit reason (U8).
- **Device failure model** (`DeviceFailureException.kt:3–18`): Unknown/FailedRunner are the only batch failures; all eight reason spellings matter. Message defaults to reason.toString(), the regex constructor uses pattern text, and reason/cause remain available for 4.7 and 5.5b. Keep the typed Apple reason alongside the frozen Failure adapter; no string-parsing classifier or new core VendorError category without review.
- **rsync** (`RsyncFileBridge.kt:32–108,110–159,166–177`): one per-bridge send mutex; **receives have no mutex**, despite the KDoc promising one send and one receive. Directory source (send) / existing directory destination (receive) gets exactly one trailing separator; remote operand is `addr:path`. Archive expansion includes recursive/links/perms/times/group/owner/devices/specials **and delete**; partial, `.rsync-partial`, delay-updates, configured remote path and configuration.debug verbose apply both ways. Receive calls links again (duplicated host option). Preserve rsync4j's exact argv order and `RSYNC4J_RSYNC` override, not Rust builder insertion order; T20 records it. Send has **no timeout (A3)**; receive's processoutput4j timeout is **30 seconds**. Probe timeout exit/process cleanup against the actual library; do not substitute a shell-command timeout or add retries. Nonzero exit returns false, logging nonempty stderr with `send error: ` only on send; process/start failures are not blanket-converted to false. configuration.debug alone runs/logs `rsync --version` at construction and keeps its first stdout line.
- **rsync SSH string** (`RsyncFileBridge.kt:110–154`): `ssh -o 'StrictHostKeyChecking no' -F /dev/null `, optional `-o ServerAliveInterval=<whole seconds> -o ServerAliveCountMax=<count> ` only when seconds>0, key `-i <key> ` when applicable, then `-l <username> -p <port> `, `-vvv` only when **both** debug flags are true. Keep the trailing space otherwise and Kotlin's unquoted key/user fields; password uses `sshpass -p <password>`. Null auth throws `ConfigurationException("rsync bridge needs ssh auth")` at send/receive, not factory construction. Rsync uses system OpenSSH's accept-new/write behaviour, independent of sshj known_hosts; tests isolate HOME/known_hosts and do not alter the command for convenience.
- **WriteFile** (`WriteFile.kt:12–40`): at most 32*1024 raw bytes; full match of `/[A-Za-z0-9_./@+-]+`, not a canonicalisation/containment check. Base64 standard padded encoding; exactly `sh -c` with `umask 077 && echo <encoded> | base64 --decode > <dst>.marathon-tmp && [ $(wc -c < <dst>.marathon-tmp) -eq <size> ] && mv -f <dst>.marathon-tmp <dst> || { rm -f <dst>.marathon-tmp; exit 1; }`. Caller total timeout, infinite idle, empty env, null workdir; success only exit 0. Rethrow cancellation, catch other Exceptions with DEBUG `Unable to write <dst>` and return false. Fixed neighbouring temp name, owner-only permissions, no mkdir; failures retain destination and remove a regular temp, not an existing temp directory. Run bytes/quoting/truncating-base64 tests locally as well as through SSH; fake-worker containment deliberately rejects some paths the helper accepts.
- **SharedTransfers** (`SharedTransfers.kt:18–61`): key is worker string + destination path, serialise exists/transfer under that destination's async mutex; unrelated destinations proceed independently. Source is absoluteFile **without canonicalisation or content hashing**. Existence is short-circuited unless the last successful source matches; true reuses, false re-pushes, null warns and trusts the previous transfer. Clear the remembered source before a new transfer, record only true, propagate thrown/cancelled callbacks and allow the next caller to retry. No cache eviction, no cross-process sharing; changed bytes at the same source path are still reused if destination exists. Preserve warning/debug text at :47,54. Do not replace this with unconditional rsync or an in-flight-only deduplicator.
