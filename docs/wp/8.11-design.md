# WP 8.11 design stop: rendering owned by its consumers

Milestone 1 only. Audit base: `81940a36`. No runtime code, tests, fixtures or
goldens change at this stop. Milestone 2 requires the next instruction.

## Recommendation

Keep group 1 byte-identical and keep **all group-2 data unchanged**. Replace
the generic recursive writer with small text formatters next to the input or
output that owns the format. Use ordinary Rust formatting for group 3. Delete
`jcompat::writers`, including its public export, after migrating its callers.
Effort: **M**. No D62 is proposed under this recommendation.

JSON would give nested configuration values and raw annotation metadata a more
standard spelling, but it would change strings stored in existing reports,
without simplifying the accepted input model. The configuration YAML view is
also not a replacement for `to_map`: it has different names, omissions and
credential handling. Removing the intermediate rendering tree captures most of
the implementation benefit while keeping report consumers working.

## Group 1: exact input text contract

The future `annotation_text` and `decoded_text` doc comments must state this
format as the `annotationData.valueRegex` input syntax, with references to D58
and §3.12.1. Place both functions beside the filter, not in `jcompat` or a
generic writer crate. `filter/mod.rs` re-exports both functions (the `annotation` module stays
private) so report projection and integration tests can exercise the contract
without returning an intermediate tree. `metadata_text` can share `annotation_text` because their
current renderings agree; the report's top-level null override remains outside.

Exact text to keep:

- Unboxed strings are emitted verbatim, unquoted and unescaped, including
  newlines, commas, equals signs, brackets and parentheses. There is no escaping
  pass and no whitespace normalization.
- Unboxed null renders `null`; booleans render `true`/`false`; signed integers
  use their current decimal text. Float and double use `jnum::float_to_string`
  and `jnum::double_to_string` (including `-0.0`, `NaN`, infinity and exponent
  spellings). A `Char(u16)` uses `String::from_utf16_lossy(&[unit])`, including
  U+FFFD for a surrogate under D55.
- Lists and arrays both render `[a, b]`, recursively, with `, ` between items,
  `[]` when empty and no extra padding. D58 array values contain elements, never
  JVM identities. Maps render `{key=value, next=value}` in `MetaMap::entries`
  order, with verbatim unquoted keys; empty maps render `{}`.
- Scalar decoded wrappers render exactly `DecodedByte(value=…)`,
  `DecodedShort(value=…)`, `DecodedInt(value=…)`, `DecodedLong(value=…)`,
  `DecodedFloat(value=…)`, `DecodedDouble(value=…)`, `DecodedChar(value=…)`,
  `DecodedBoolean(value=…)`, `DecodedString(value=…)`, `DecodedType(value=…)`
  and `DecodedEnum(value=…)`, using the same scalar rules above.
  `DecodedNull` renders `null`. `DecodedArrayValue` renders
  `DecodedArrayValue(values=[…])`, recursively with the same separators.
- Matching still checks only an annotation's `value` member after full-match
  name matching. An unboxed top-level null is skipped. An outer `MetaValue::Array`
  is eagerly rendered element by element; each element is then reduced to the
  text after the **first** `(value=` if present and before the **first** `)`
  in that tail. The value regex full-matches each reduced element. All other
  top-level kinds full-match their complete rendered string. Do not apply
  outer-array extraction recursively, or apply it to a List instead of Array.

Real examples from `model_contract.rs::decoded_array_elements_keep_pinned_wrapper_rendering`
and `filter_edges.rs` (before and proposed after are identical):

| Input | Before text | After text | Actual match target when used in an outer Array |
|---|---|---|---|
| `DecodedString("a)b")` | `DecodedString(value=a)b)` | `DecodedString(value=a)b)` | `a` |
| decoded nested integers 7, 8 | `DecodedArrayValue(values=[DecodedInt(value=7), DecodedInt(value=8)])` | `DecodedArrayValue(values=[DecodedInt(value=7), DecodedInt(value=8)])` | `7` |
| empty decoded array | `DecodedArrayValue(values=[])` | `DecodedArrayValue(values=[])` | `DecodedArrayValue(values=[]` |
| array of string `a`, null, list `[7]`, boolean array `[true]` | `[a, null, [7], [true]]` | `[a, null, [7], [true]]` | Each outer element is matched separately. |

Keep the existing group-1 expectations, including the apparently surprising
first-parenthesis behavior. Changing it would alter accepted filters' meaning.

## Group 2: actual persisted data and golden impact

### Allure configuration

`Configuration::to_map` is consumed by `AllureReporter` to write
`allure-results/environment.xml`. XML escaping belongs to the XML writer; the
parsed value is the complete configuration string. Keep entry order, field
order, constructor field names, omissions, `null`, collection order and the
D58 simple names. Keep the absolute `outputDir` rule and all existing numeric,
duration, instant, path and regex formatters. In particular preserve the Influx
masking/quoted fields, omission of its defaults/readOnly, SSH password omission,
and the Apple bundle's literal `(java.io.File) -> java.io.File` field text.

Examples read from the current native views, not reconstructed JVM identities:

| Source / value | Before | Proposed after |
|---|---|---|
| `android-smoke.json.gz`, environment `outputConfiguration` | `OutputConfiguration(maxPath=0, maxFilename=255)` | Same bytes. |
| `android-smoke.json.gz`, environment `pooling` | `OmniPoolingStrategyConfiguration` | Same bytes. |
| `ios-smoke.json.gz`, environment `batching` | `FixedSizeBatchingStrategyConfiguration(size=3, durationMillis=null, percentile=null, timeLimit=null, lastMileLength=0)` | Same bytes. |

The config oracle's `Duration-Instant-File` example also pins masking:
`InfluxDb2Configuration(url='*****', token='*****', organization='o', bucket='b', retentionPolicyConfiguration=RetentionPolicyConfiguration(everySeconds=2592000, shardGroupDurationSeconds=0))`.
Keep it byte-identical. A generic serde dump could expose credentials as well
as changing the representation.

### Raw annotation values

`RawJsonReporter` stores **strings** in
`test_result/raw.json` → `metaProperties[].values`. It does not store the
corresponding JSON arrays/maps there. The current `android-smoke.json.gz` has
`kotlin.Metadata` → `bv` equal to the string
`[DecodedInt(value=1), DecodedInt(value=0), DecodedInt(value=3)]`; proposed after:
the identical string. The `io.qameta.allure.kotlin.Epic` → `value` string is
`General`; proposed after: `General`, without adding JSON quote characters to
the string's contents. An unboxed null member is the empty string here,
whereas a decoded null is `null`. Preserve both rules.

`report/json.rs` and `report/yaml.rs` serialize typed metadata independently.
Their objects, binary encodings, omission rules and parse output do not use
`KotlinValue` and must not be rewritten by this WP.

### Runner messages that become failure data

The Android I/O branch sends its rendered message to
`AccumulatingResultTestRunListener` (`listeners.rs:270`); Apple cancellation
calls the corresponding accumulator through `listener/accumulating.rs`.
`TestRunResultsAccumulator::test_run_failed` stores it as `run_failure_message`.
`failure_of` / `create_uncompleted_test_results` use it as a missing test's
`TestResult.stacktrace`, which reaches per-test JSON, Allure status details,
JUnit failure text and the HTML test page. It is not necessarily attached to
every already-started test: existing temporal records have separate trace
rules. Preserve that distinction too.

For the real `UITests.SampleTests#testSample` batch in
`marathon-apple/tests/apple_device_test_runner.rs`, a cancellation renders:

```text
Tests [UITests.SampleTests#testSample] got stuck. You can increase the timeout in settings if it's too strict
```

For the real `com.example.MainActivityTest#testText` selector in the Android
native smoke case, the I/O-error branch renders:

```text
adb error while running tests [com.example.MainActivityTest#testText]
```

These examples apply the current error branch to repository test inputs; they
are not claims that those passing golden scenarios exercised the error. Both
before and proposed after are exactly the lines above. A Debug list would add
quotes and escape characters to result data, so use a direct unquoted join.

### Analytics boundary audit

No `KotlinValue` text is sent to an analytics backend today. In
`analytics/provider.rs:231–242` the request gets typed percentile/time-limit
arguments and returns typed rows. Only after the request returns, at
`274–290`, are those rows rendered for `context.log(DEBUG, ...)`. The map/cache
continues to store the original `(String, f64)` values, not that text.

The actual backend query/key data is independently built in
`analytics/remote/{influx,influx2,graphite}.rs` and
`marathon-analytics/src/{influx,influx2,graphite,points}.rs`. Examples already
used in the backend tests are the `testname` tag `pkg.Clazz.method` and returned
`5000.0` duration (`marathon-analytics/tests/history.rs:208–209`), and the Influx
query's `GROUP BY "testname"` / `PERCENTILE("duration",…)` clauses
(`marathon-core/tests/analytics_remote.rs:151`). These names, numeric data,
query text, tags, escaping and wire bytes stay unchanged. Backend payloads are
out of scope, even when a nearby log is rewritten.

### Golden decision

Recommend keeping group 2. **No group-2 prototype was made.** No D62, re-bless
or copied-fixture update is requested. Expected golden impact is **zero**;
this is a design projection, not a measurement of unimplemented replacements.
The milestone-1 gate checks the unchanged native goldens and config corpus.
The native comparison includes all 18 adapters / 16 bounded vendor cases.
The config corpus pins bound input/dump data; `validation_corpus` and
`config_differential` additionally check `to_map` strings, so corpus success
alone would not prove Allure text unchanged.

If a later decision instead chooses JSON for group 2, first approve D62,
prototype against both native goldens and the configuration corpus, and retain
the existing masking/omission policy. Then explicitly re-bless with the tools
in `tools/differential/README.md` and audit using
`tools/differential/run diff-golden --against 64f286ee` in
`docs/wp/8.11-golden-diff.md`. Compare against the actual implementation base
too so intervening WPs are not attributed to 8.11. Do not relax normalization
or edit copied fixtures to hide differences. This branch does none of that.

## Group 3: proposed log text

These are message bodies; the `tracing` level, module target, timestamp policy
and queue ordering from `docs/design/logging.md` remain as they are. Existing
`Component` / `LogSender` sites keep using that bridge; a formatter migration
does not justify bypassing the core executor's nonblocking log queue.

text. Keep parser oracle checks via local adapters in test support so removing
the production tree does not discard event-field coverage. The adapters can
join explicit fields, without introducing another recursive value enum.

## Milestone-2 boundaries, verification and risks

Suggested implementation order after approval: input renderer and unchanged
group-1 assertions; result projections and error-message joins; diagnostic
formatting and test adapters; remove the writer tree and export. Finish with
`rg -n KotlinValue crates` returning no matches. Add
`docs/wp/8.11-test-changes.md` identifying every moved, rewritten or removed
test, including synthetic generic-writer tests. Keep group-1 expectations and
report expectations. Retain Kotlin test names and ported parity rows when
their behavior coverage remains; any deleted parity row needs a reason
`8.11: §3.12.5` (or an approved D-row) and reviewer agreement.

Risks to test explicitly at implementation:

- Shared wrapper formatting must not drift between filter and raw report;
  top-level raw null remains an exception. Do not simplify delimiter extraction.
- Rust Debug quotes/escapes are allowed in group-3 diagnostics but must not
  leak into runner failure data or raw metadata strings.
- Keep configuration field ordering, secret overrides, nullable lists/maps,
  class names, the literal Apple lambda text, and nonfinite/negative-zero
  number spellings. The existing formatters remain the contract.
- `Test` Display must not change IDs, hashes, selectors or progress/summary
  text; use the current name helpers only at the migrated log sites.
- Test-only historical adapters must continue checking complete fields,
  traces and ordering; they must not merely normalize away meaningful data.
- The native vendor goldens do not cover every failure path. Add focused
  result-message coverage at implementation for both runner branches above.
- WP 8.10 is parallel work. This stop edits only this document and the 8.11
  plan entry; the second merged WP rebases and reruns its gate. Do not make
  numeric/time cleanup changes here.

Milestone 1 changes no tests or parity rows. It does not claim the milestone-2
acceptance condition (no remaining writer uses); those remain deliberately
until implementation is authorized.
