## Result and API

`jcompat::JavaRegex::compile(pattern, field)` returns a typed compile error carrying
both source strings and `regex::Error`; Display reports all three. The wrapper
exposes `pattern`, Display, `matches`, `contains`, `find`, `find_all`, `split` and
`replace`. `find`/`find_all` expose borrowed crate Captures with byte offsets.
`split` returns borrowed strings with Kotlin's limits and trailing empties.
`replace` expands Kotlin `$0`, numbered and `${name}` groups and backslash escapes,
returning an error for malformed expansion only when a match exists. Unmatched
groups expand to empty strings. Source serialization uses `pattern()`.

Regex syntax is Rust's `regex` crate; Java-only constructs are rejected at load.
No lookaround or backreferences; Unicode `\d\w\s` by default. `(?i)` performs
Unicode case folding, scoped flags use `(?i:...)` / `(?-i:...)`, and Rust `(?U)`
swaps greediness rather than enabling Java's Unicode character classes.
The crate accepts some Java-looking syntax differently: `a*+a` is nested
repetition, not possessive; we use the crate grammar directly without a validator. Empty
matches never fall inside a surrogate pair (explicit user decision during WP 1.4).
`regex = "=1.13.1"` is pinned; no budgets, aborts or runtime regex errors.
Searches use the crate's nonbacktracking engine. As with the crate's iterators,
repeated searches can cost O(m*n²) in pathological cases; no claim of linear
whole-iteration complexity is made.

Full matching uses absolute anchors and a separate compiled expression, so an
unanchored short alternative cannot hide a later full match. A final verbose-mode
comment gets a terminating newline when needed to avoid swallowing the added
closing group. Empty findAll matches advance a Unicode scalar and can immediately
follow a nonempty match, unlike captures_iter's empty-match suppression.

## Fixed patterns and source coverage

The brief lists main-code declarations, config fields, consumers, serializers,
equality/logging sites and shell patterns with file:line references. The source
inventory's module ownership stays unchanged; regex-pattern support here does not
complete the owning config/filter/parser WPs.

`regex_patterns` supplies every fixed JVM pattern, the three Nm shell predicates,
and tests for the assembled logcat header and its five pieces. Fixed patterns
spell Java's ASCII classes and dot exclusions explicitly. The two operations
whose Java final-anchor behavior needs code use `strip_filter_comment` and
`find_artifact`. Full matches retain strict whole-input semantics. Shell commands
are inventory entries only: downstream WPs must retain the original worker argv.

The default Apple negative lookahead is replaced by
`default_test_class_matches`: reject `Abstract`, line terminators and a missing
`Tests*` suffix. `DEFAULT_TEST_CLASS_PATTERN` retains the serialized Kotlin default.
The config WP must distinguish an omitted default from an explicitly supplied
pattern, which goes through ordinary D6 compilation. Known Kotlin A4 (empty UDID)
is reproduced; annotation extraction quirk N6 is recorded and reproduced.
