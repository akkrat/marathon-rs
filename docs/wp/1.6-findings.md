The JVM evidence refines the initial failure report: private erase does **not**
permanently break the appender. `ESC[?J`, `ESC[=J` and `ESC[?K` throw after
resetting Jansi's parser, so later events appear immediately after the partial
prefix. Numeric overflow leaves Jansi's numeric state broken; every later event
is lost. Terminal uninstall then throws (captured process exit 1), while
pipe/file shutdown exits 0. Rust exposes `JansiFailure` through stream `failure()`
and returns partial bytes without panic; `finish()` suppresses reset bytes after
overflow. Runtime integration can inspect that state when handling teardown.

**Throwable renderer handoff (WPs 2.5/3.10):** consume the `op: throwable` row in
`fixtures/oracle/logging/details.jsonl` when implementing throwable rendering.
It includes complete recursive frame inputs and the JVM's exact output,
including `\t... 1 common frames omitted` for both nested causes. WP 1.6 accepts
already rendered traces; its test adapter verifies this row but is not a runtime
throwable renderer. PLAN §3.10 permits differing JVM frames, not dropping the
common-frame representation when frames are shared.
