Implemented on `wp/3.4b-analytics-clients`, from `d56583f`, following the final

## Changes to merged crates

**`jcompat` changes; `marathon-core`, `marathon-config` and `marathon-cli` do not.**

- `jnum::influx_duration` implements the pinned Point classes' English
  NumberFormat for integral duration doubles (decimal notation, at least one
  fractional digit). JVM values include Long.MIN/MAX, which format as
  `-9223372036854776000.0` / `9223372036854776000.0` after conversion to double.
- `jtime::instant_to_epoch_milli` (merged from main during the round 1 rebase;
  it replaced this WP's identical `epoch_millis`) supplies checked
  Instant.toEpochMilli arithmetic; `influx_epoch_millis` implements v2's unbounded BigInteger division, including
  truncation toward zero for negative fractional milliseconds. The oracle
  retains Instant.MIN/MAX and the negative fractional boundary.
- `net::{form_encode, query_encode, basic_credentials}` retain Java UTF-8 form
  encoding, OkHttp query-component spaces (`%20`, unlike form `+`), and Basic
  authentication's ISO-8859-1 encoding with `?` replacement. Ordinary Unicode,
  punctuation and supplementary input are exercised against the real clients.

The new leaf crate is **`marathon-analytics`**. Its HTTP dependencies stay out of
core. Cargo.lock gains the leaf transport/CSV/URL dependencies; existing package
versions are retained. Round 1 adds `rustls-native-certs` 0.8.5 (with its
platform dependencies) and direct `rustls`/`webpki-roots` pins. Hyper/rustls with hyper-timeout is used instead of the
brief's suggested reqwest: it exposes independent connect/read/write idle
limits, with no 60-second total request deadline. Every connection driver is
polled inside the requesting future and has no detached pool task. Connection
pool reuse is omitted under P2.

**TLS trust.** HTTPS clients trust the bundled Mozilla roots (`webpki-roots`,
close to the JVM's cacerts) **plus the platform store** (`rustls-native-certs`:
the macOS keychain, the Linux CA bundle, Windows' system store), so
internally issued CAs installed on the host work without configuration. This is
broader than the JVM, which trusts only its own cacerts unless
`javax.net.ssl.trustStore` is set. The union is loaded once per process,
on the vendor side when the first client is constructed; unreadable platform
entries are skipped. An empty store still allows plain HTTP.

The parity generator gains only a 3.4b status/path mapping; its fourteen stable
row keys and inherited-test expansion policy are unchanged. Both CSVs were
regenerated; the source inventory remains byte-identical.

## Consumer API and executor ownership

`AnalyticsClients::new(MetricsContext, Arc<dyn VendorRuntime>)` implements the
merged `MetricsSetup`. `BackendClients { clients, config, debug }` implements
3.9a's injected `BackendFactory`. CLI dependency construction in 3.10 must run
these async constructors off core, await them before run/parse, and supply the
same per-run context and runtime. Calling the two factories separately creates
two independent Influx clients, including two v1 batch workers. No source
wiring trait changes, HTTP back-edge or new event timestamp is needed.

Each tracker implements the merged `TrackerInternalAdapter` over its existing
`TestEvent`. The event's single mapped `instant`, device, result and final flag
arrive unchanged; final is intentionally not a filter. Public `track_test` and
explicit async close operations are available through the concrete trackers /
client shutdown and subscriber adapter. V2's first non-read-only event starts
its first write; it has no eager writer acquisition side effect. Graphite close
is the inherited no-op. Invalid carbon ports retain Socket's write-time error
boundary, so readOnly/status-gated events still succeed without opening a socket.

Construction and all network/registry work run on the vendor side. Default tests
use the **production CoreExecutor → call_vendor → VendorRuntime bridge**, not
only a fully enabled test Tokio runtime. Registry guards never cross await.
Structured cancellation is distinct from failures. V2 catches only failures
classified as InfluxException descendants and preserves their causal chain;
source custom ERROR text and full Kotlin logger names are retained.

## Frozen lifecycle and protocol behavior

| Area | JVM observation and port |
|---|---|
| HTTP | Independent 60 s connect/read/write limits; zero total-call deadline. Default redirect following and retry-on-connection-failure enabled. Fresh EOF/reset/slow peers each receive one connection attempt, with no added transport retry. A 408 retries once without positive Retry-After; a 503 retries only with Retry-After: 0, once. 300/301/302/303 turn POST into GET without a body; 307/308 keep the method and body (JVM `v1-write-307`, `v2-write-307`, `v2-write-308`). Authorization survives same-origin hops only. |
| V1 setup | POST form `q=SHOW+DATABASES`; fresh DB gets CREATE DATABASE then CREATE RETENTION POLICY. Existing DB skips the policy entirely. Auth is Basic only when both credentials are nonempty. History/readOnly still set up and enable batching. Validation uses influxdb-java's Preconditions messages in its order: `Expecting a non-empty string for name` before CREATE DATABASE, then retentionPolicyName, database, retentionDuration, the duration formats (`Invalid InfluxDB duration: … for retentionDuration/shardDuration`), then `Expecting a positive number for replicationFactor`. Non-2xx error bodies keep InfluxDBException's message-selected subclasses (DatabaseNotFound, PointsBeyondRetentionPolicy, FieldTypeConflict, UnableToParse, HintedHandOffQueueNotEmpty, CacheMaxMemorySizeExceeded, AuthorizationFailed). |
| V1 batching | 1,000 actions, 1,000 ms fixed-delay interval, zero jitter, bounded 1,000-entry action queue with async backpressure, 10,000-point retry buffer, nanosecond batch precision and consistency `one`. Event milliseconds saturate when converted to nanoseconds. |
| V1 retries/close | Retryable batches retain order and merge up to 1,000 points; whole oldest batches are evicted over 10,000 points. Permanent field/parse/auth/database/retention errors are discarded as the default no-op exception consumer does. Every scheduled/explicit flush attempts buffered retries first. Close drains then makes a final retry pass, and joins the owned worker and socket. Repeated close is harmless. A second Java close re-sends any batches still retained after the first close's final pass; Rust's second close does nothing (the worker has gone). Only a failed final pass leaves retained batches, so the difference is a repeated delivery attempt after shutdown, not lost or added data on success. |
| V1 cancellation | The Java batch scheduler is independent of the run coroutine. The owned worker has its own cancellation scope so cancellation of the run does not prevent close from draining. History HTTP retains the caller's cancellation. No observable flush/close occurs in Drop. |
| V2 setup | One unfiltered `/api/v2/orgs` request, exact-name filtering in returned order, no pagination traversal; `/api/v2/buckets?name=...` is name-only. Every request sends `Authorization: Token <token>` trimmed as OkHttp does, so an empty token sends `Token` (JVM `v2-empty-token`). An empty bucket fails with `Expecting a non-empty string for Bucket Name` after the organization lookup. The first candidate organization supplies create orgID. JSON includes expire/everySeconds/shardGroupDurationSeconds; existing buckets are never updated. |
| V2 writes | All statuses write, including INCOMPLETE without success. Duration and ignored are doubles. Requests use org, bucket and `precision=ms`; no newline is appended. HTTP and I/O exceptions are caught/logged by the tracker, cancellation and unrelated errors propagate. No provider-level retry is added. |
| Points | Both pinned libraries sort tags and fields. V1 preserves raw control characters in tag values; v2 escapes CR/LF/tab. Space/comma/equals are escaped; backslashes are not additionally escaped. Safe test/serial names reuse merged helpers. |
| Graphite | One socket per nonempty send; ordered ignored/success/duration lines. Prefix behavior, dot replacement and signed millis/1000 are unchanged. No carbon timeout. GET render uses form-encoded target and Java UTC formatting; production setup's port is 80 (C39). An unparsable query host (`graphite host`, `::1`) fails each query with IllegalArgumentException, not construction, so 3.4a's retries and defaults apply as in Kotlin, where OkHttp parses the URL per call. Empty lines alone are dropped, CR/whitespace survive, and HTTP error bodies reach the raw parser. |
| Responses | V1 preserves top-level and statement errors, names/tags/columns/nulls/numeric/text cells in the merged DTOs. V2 parses annotation/header blocks, multiple tables, defaults, quoted CSV and null/numeric values into the existing records. An invalid long/double/unsignedLong cell raises InfluxException caused by NumberFormatException with Java's parse message (JVM `v2-csv-long`, `v2-csv-double`). Existing 3.4a queries, mapping, outer retries and cache remain in use. |

The default tests use explicit flush barriers, a manually released VendorClock,
request notifications and in-flight query barriers. They do not sleep to infer
that a worker or socket has closed. Awaited close proves the batch worker has
joined and its pending timer future has been dropped. A separate test with
shortened socket-idle settings verifies independent read and write deadlines.

## Approved boundaries and residual differences

- **P1:** all matrix ports use real Rust transports and JVM-recorded loopback
  exchanges. Scripted responses prove the client/DTO integration, not service
  aggregation, policy enforcement or persistence. No Docker test is ignored or
  represented as passed.
- **P2:** functional headers, auth, request bytes, retries and setup/custom logs
  are matched. Library User-Agent, debug timing text, pool reuse and native
  transport/parser exception wording are implementation artifacts. Error
  classes/cause classification remain tested. The JVM itself varied the v2
  slow-read message between `Read timed out` and `timeout` on repetition, with
  the same SocketTimeoutException cause; the recording retains the raw first
  observation.
- **P3:** the JVM suppressed a real carbon reset and an injected Writer failure.
  Rust propagates async socket write errors and permits typed cancellation to
  interrupt a blocked send, retaining one connection and no carbon timeout.
- **P4:** backend config/tag/path text must be valid UTF-8. Normal absolute
  HTTP(S) URLs, ordinary Unicode and punctuation work. Relative/schemeless URLs,
  non-HTTP schemes, backslashes, controls, leading/trailing whitespace, URL
  credentials, query and fragment are rejected clearly before Influx setup;
  Influx factories take their normal fallback boundary for these failures.
  Invalid Graphite write host/prefix text fails subscriber construction; invalid
  event text fails at that event. Read-side lone-surrogate host/prefix handling
  remains the merged 3.4a query-boundary behavior. Uppercase HTTP(S) schemes are
  accepted. The JVM URL acceptance witnesses remain recorded.
- **P4, v1 base URL without a trailing slash** (approved in review round 1):
  Retrofit rejects `http://host:8086/path` ("baseUrl must end in /"), so Kotlin
  omits the tracker and history falls back to no-op. Rust appends the slash and
  works. This is benign and more useful; a bare `http://host:8086` behaves the
  same on both.
- **P4, v2 duration text above 2^53 ms** (approved in review round 1, measured):
  the pinned Point classes format `(double) duration` through English
  NumberFormat, whose digit generation differs from Java's shortest repr above
  2^53. Measured against JBR 21.0.10 over 800,537 values (exhaustive ±100,000
  around 2^53, 400,000 random values in [−10^12, 10^12] and [−2^53, 2^53], every
  2^k±3 and 10^k±2, and 200,000 values above 2^53): **no mismatch with
  |duration| ≤ 2^53**; mismatches were sampled just above
  2^54 (e.g. 18,017,378,286,938,686 and …687 ms; R2 review: a sample, not an exact threshold), and Sol's sample of random longs
  differed in 7,580/10,000. 2^53 ms is about 285,000 years, so no real duration
  is affected. Oracle `duration-format` rows pin 1, 999, 9,999,999, 10^7,
  86,400,000, 123,456,789,012, 999,999,999,999, ±10^12, 2^53−1 and ±2^53.

C38/C40/C41 are exercised through unchanged sources and real transports; F3 is
verified by binding YAML readOnly=true and observing writes, while directly
constructed read_only=true still suppresses them. C25/C26 remain 3.10's ordered
cleanup/parse behavior; no Drop-based cleanup changes them.

New Kotlin rows are **C60** (existing-DB policy omission), **C61** (v2 INCOMPLETE
