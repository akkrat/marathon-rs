# WP 8.6a test changes

Existing rendered-output assertions keep their baseline strings. Constructor inputs now
use kinds, and assertions on known error classifications use the corresponding kinds.
No existing assertion changes its behavioural meaning; no fixtures, goldens or parity rows
change. Closed replay/injected markers retain their exact rendered names.

New coverage includes nullable/empty messages and opaque traces, I/O legacy mappings,
fatal catch membership without suffix guessing, deduplication independent of retry metadata,
all Influx v1 phrases and precedence/mixtures, generic bodies and typed transport sources.

## Milestone 3

Added exact catch-set regressions in:

- `crates/marathon-adb/src/client/error.rs`: refusal causes, connect timeouts and throwable/exception distinctions.
- `crates/marathon-dex/src/error.rs`: the five-member APK I/O catch, including its exclusions.
- `crates/marathon-android/src/support.rs`: only the two rejection kinds promote device loss; cause/message and cancellation stay intact.
- `crates/marathon-android/src/provider.rs`: the three-member connect retry set.
- `crates/marathon-android/src/runner.rs`: the explicit I/O retry set and cancellation exclusion.

Existing ADB/Android test helpers now use the neutral `AdbFailure` view and its typed constructor projection.

## Milestone 4

- `crates/marathon-error/src/ssh.rs`: new catch-graph tests pin channel, authentication, key decoding, socket timeout and deliberately unmodelled inheritance distinctions.
- `crates/marathon-test-support/src/recorded_errors.rs`: new tests pin short scenario tokens, unknown-input errors, device-loss causes and independent recorded Influx retry disposition.
- `crates/marathon-cli/tests/run_outcome.rs`, `crates/marathon-macos/src/device.rs`, and `crates/marathon-apple/src/xctestrun/test_root_factory.rs`: recorded-input helpers pass nullable messages at the parse boundary.

Existing runner output, instrumentation and XCTest/xcresult text remain opaque.
