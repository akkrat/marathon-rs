### Binding decisions and implementation

1. Capturing groups anywhere inside negative lookahead/behind are D6, with the entire
   original assertion spelling. Users can replace captures with `(?:…)`.
2. Validate Java `TreeInfo.maxValid` and determinism before applying fixed-length D6,
   including Ques/Branch, Curly/GroupCurly/Loop, zero counts, possessive groups and
   the unchecked overflow of greedy character loops. Java-invalid remains syntax.
3. Reject supplementary-capable lookbehind, with consuming full-match witnesses.
   BMP scalar content stays supported, including positive captures. Also reject sets
   containing surrogate code units: the added BMP-range witness can start its Java
   assertion on a low surrogate. This conservative scope application is called out
   below for the orchestrator; no UTF-16 model is introduced.
4. Preserve CRLF exclusion in negative dollar/\Z optimization; distinguish direct
   Ques, grouped optional Branch and counted GroupCurly linebreak choices, including
   lazy/possessive variants; recognize empty bodies recursively without erasing captures.
5. Resolve `\N{name}` through the committed table and ordinary literal/class/folding
   paths; surrogate-valued names follow the lone-surrogate policy. Remove named-character D6.
6. Record D6 while parsing, validate the complete Java syntax, then report rejection.
   Map fancy recursion exhaustion to the authorized compilation syntax error; test
   actual last-accepted/first-rejected depths (62 and 63 for nested captures).
7. General E1 replaces the three-row exception: **JavaRegex never places a match
   boundary inside a surrogate pair. Java can, after an empty match advances by one
   UTF-16 unit. This applies to every operation: find, findAll, split, replace and
   continuation.** Remove the bare-\B shortcut. Score E1 separately from passes and
   re-audit every Kotlin main use site.
8. The runtime D6 extension is **approved 2026-10-23**: exhaustion fails the run with
   an error naming the original pattern and config field. The already-approved PLAN
   change from main is copied identically into this branch; no new decision is inferred.
9. Document that 100M VM steps/backtracks is not a deadline. Keep the measured slow
   cases and add a WP 1.4 note for worst-case tests at realistic sizes such as 1 KiB.
   Do not add a deadline mechanism in this round.

## Round 3 (at 51de034): orchestrator closure under PLAN §8.2

- **Muse:** merge after fixes, with one minor finding (R3-muse-1). About 230 new JDK probes found no wrong answer for an accepted pattern. Muse independently redid the E1 use-site audit and confirmed it, and judged the D6 list publishable.
- **Fresh Sol:** rework. All 838 earlier divergences are resolved. New probes found seven more, all in exotic constructs:

| ID | Sev | Witness: JDK → spike |
|---|---|---|
| R3-sol-1 | major | `()*?\1Test` matches `Test`: false → true |
| R3-sol-2 | major | `(?:a())*\1a` matches `a`: true → false |
| R3-sol-3 | major | `(?:\R\|x){2}+` matches CRLF: false → true |
| R3-sol-4 / R3-muse-1 | minor | `(?:a{0}){2}a` matches `a`: true → backend compile error (a zero-count repeat nested in a repeat) |
| R3-sol-5 | minor | `(?=a)?a` and `(?<=\b*)a`: Java-valid → backend compile errors |
| R3-sol-6 | minor | `(?<=(?>a\|b)a*?)b`: Java syntax error → D6 |
| R3-sol-7 | minor, pre-existing | `(?<=a{1073741824})b`: Java compiles → undocumented compilation-size failure |

The full witnesses are in Sol's review (copied into the WP 1.4 brief when it is written).

**Decision.** Three rounds have not closed, and each fresh adversarial round finds new exotic constructs while clearing all earlier ones. The spike has answered its questions:
- the backend (fancy-regex `=0.19.2` behind our translator);
- the JDK 21 Unicode tables;
- E1, confirmed unobservable from marathon by two independent audits;
- the D6 families, and the runtime-exhaustion extension approved by the user;
- the API.

So the spike is closed and merged. R3-sol-1..7 and R3-muse-1 are carried to **WP 1.4** as required cases. WP 1.4 must also:
1. **Work from a whitelist.** Accept a defined, tested subset of the grammar, and reject everything outside it under D6. Patterns that are empty-matchable under a quantifier with captures or backreferences, quantified lookarounds, possessive or atomic quantifiers over `\R`, and nested zero-count repeats are rejected unless a probe proves them exact.
2. **Run a differential fuzzer** against JDK 21 as part of acceptance, over a grammar of the constructs that real marathon configs use, plus the accepted exotic ones. Every divergence is fixed, or its construct moves to D6.
3. **Publish the final D6 list.** The spike's list is the starting point, not the final list.
