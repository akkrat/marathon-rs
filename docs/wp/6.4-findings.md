## Decisions taken

The orchestrator decisions were implemented as written, with one forced
exception (P4, below). Review round 1 withdrew P1 and changed several
other points; see "Review round 1" at the end.

1. **Crate layout:** `marathon-dex` is a vendor-independent leaf
   (`spec`, `parser`, `axml`, `apk_parser`, `error`); the
   `LocalTestParser` adapter and `toMetaProperty` live in
   `crates/marathon-android/src/dex_test_parser.rs`.
2. **Parity rows:** `ApkParserTest` ported as assigned (1 row). The
   `AndroidTestParserTest` expectation is ported at the adapter level
   (`should_return_proper_list_of_test_methods`, meta-properties
   asserted explicitly because frozen `Test` equality excludes them)
   and the literal row moved to 6.5 (`scripts/source_inventory.py`
   rule + regenerated CSV). The external placeholder expanded to 23
   rows (21 `DexParserShould` + 2 `AbstractClassInSecondDex`), all
   `ported`: 24 rows total for 6.4, 0 `n/a`.
3. **"Production APKs":** none were available; the differential runs
   over the five `fixtures/vendor-android` APKs, the two upstream APKs
   and the generated probe/mutant APKs (below).
4. **`MetaValue::Object` removed** (P7) — audit under its own heading.
5. **Errors (P3):** one `DexError { jvm_class, message, cause }`.
   Forged texts are kept verbatim where marathon or the pinned parser
   forge them (DexException messages incl. the `DexMagic` data-class
   `toString`, `checkNotNull` messages, `RuntimeException("Unable to
   parse test app AndroidManifest.xml.")` with cause, the
   missing-manifest NPE `"entry"`, FileNotFoundException wording).
   JVM crash taxonomy collapses: StackOverflowError (superclass
   cycle), ArrayIndexOutOfBoundsException (NO_INDEX superclass),
   BufferUnderflow/shape failures all become `DexException` with our
   wording. The adapter maps `DexError` 1:1 into
   `VendorError::TestParsing(Failure)`.
6. **DEX 040 rejected**, pinned by test; known-bug row N10 records it
   as the first candidate future deviation.
7. Effort H was about right.

**Simplifications:**

- **P1 (MUTF-8): withdrawn in review round 1.** `kotlin.Metadata`'s
  packed `d1` strings are full of encoded NULs, so a proper MUTF-8
  decode changed every Kotlin class's Metadata (`C0 80` is two U+FFFD
  on the JVM). DEX strings, identifiers and values alike, now decode
  exactly as dex-test-parser's `String(bytes)` does with the reference
  JDK's default charset, UTF-8 (JDK 18+, JEP 400; `DexOracle` and
  `StringBytesProbe` refuse to run on another default). The existing
  `jcompat::utf8::decode_utf8` already implements the JDK rule (one
  U+FFFD per maximal invalid subpart; `ED A0..BF` starts a surrogate
  sequence that is ONE U+FFFD, complete or truncated) and agrees with
  the JVM on all 11420 sequences of `fixtures/oracle/dex/string-bytes.txt`,
  so jcompat is unchanged. The differential has no rendering map any
  more.
- **P2 (sign extension): rejected, as decided.** The JVM probe
  confirms zero-padding (`-1` → `255` for short/int/long in
  `fixtures/oracle/dex/probes.jsonl`); reproduced; row N9.
- **P3: applied** (above). A depth cap (256) replaces unbounded
  recursion on nested encoded values.
- **P4 (JUnit3 fixpoint): NOT applied — its premise is false.** The
  approval required the result set to be identical. It is not:
  `DecodedArrayValue` equality is backing-array identity (probed on
  the pinned JAR: `tools/oracle/dex/EqProbe.java` — fresh
  equal-content arrays are unequal while their hashCodes agree), so
  the original drop-last recursion's re-scans emit duplicates for any
  test with an array-valued annotation. The JVM dump of
  `abstract-class-in-second-dex.apk` contains 8 JUnit3 tests twice.
  The recursion is replicated unrolled (prefixes n…1); row N11.
- **P5 (AXML subset): applied.** Only what `ApkParser` drives; the
  resource-id chunk is still required and skipped in place, string
  pools in both encodings, no namespaces/resource mapping/styles.
  `StringBlock`'s `java.util.logging` warning on undecodable strings
  is not reproduced (library code writes no diagnostics); the value
  still reads as null.
- **P6: applied.** No Clikt CLI, no `findTestNames`.
- **P7: applied** (below).

## Further local decisions and deviations

- **Zip reading:** `zip` 2.6.1's streaming reader rejects *every*
  entry with a data descriptor ("The file length is not available in
  the local header"), deflated or stored. `ZipInputStream` reads
  deflated entries with a descriptor (the fixture APKs that use
  descriptors use deflated ones) and rejects stored ones with
  `ZipException("only DEFLATED entries can have EXT descriptor")`.
  `read_dex_files` streams first (archive order, `ZipInputStream`
  tolerance for bad tail signatures and too-short streams) and falls
  back to the central directory only on that failure; the fallback
  reads each entry's local header and raises the same `ZipException`
  for a stored entry with a descriptor. **Accepted simplification**
  (orchestrator, review round 1): the fallback visits entries in
  central-directory order, which is the local order for anything a
  build tool writes. A hand-reordered central directory, or an archive
  with a descriptor entry and no central directory, can give a
  different dex order or no dex files where the JVM streams them
  (Sol's witnesses: 29 JVM tests against 21 and 0).
- **Adapter shape:** `DexTestParser::new(bundles, runtime,
  create_bundle, register)`. `DexTestBundleFiles` (application?,
  test_application, extra_applications, split_apks) stands in for
  6.5's `testBundlesCompat()` output; `create_bundle:
  Fn(&DexTestBundleFiles) -> B` is the `AndroidTestBundle(...)`
  constructor, called once per configured bundle after its APK parsed
  (as upstream), and `register: Fn(&Test, &B)` is
  `AndroidTestBundleIdentifier.put`. So all tests of a bundle share one
  `B` and two identically configured bundles get two, which is what
  `BundleRef` identity needs. `LocalTestParser::extract` runs the
  extraction on `VendorRuntime::spawn_blocking` (the parser holds an
  `Arc<dyn VendorRuntime>`, since `VendorContext` does not carry one).
- **Conversion identity cache:** one `MetaConverter` per bundle, so a
  backing array shared by marathon-dex (class annotations are cloned
  per method around one `Arc`) becomes one `MetaArray` allocation,
  preserving JVM array identity for C19 raw reports and
  `MetaValue::Array` equality. Each cache entry holds its source
  `Arc<[DecodedValue]>`, so an address cannot be freed and reused for
  another array while the converter lives (review round 1 fixed a
  converter that outlived the first bundle's arrays and answered the
  second bundle's arrays at reused addresses with the wrong values).
- **Superclass walk:** `createAllTestMethods` is unrolled (walk up the
  chain, fold back down) and keeps no memo, matching upstream's
  never-filled `getOrPut` cache, so arrays are re-read per walk exactly
  as on the JVM (`probe-inheritance.apk`).
- **`TestAnnotation` values** keep insertion order with
  replace-in-place duplicates (Kotlin `mutableMapOf`), matching
  `MetaMap::insert` after conversion.
- `ApkParser`'s never-closed `ZipFile` (a JVM handle leak with no
  observable output) is not reproduced and gets no bug row, per the
  brief.
- **Hostile input (P3):** the AXML reader loops where
  `skipCheckChunkType` recurses (a header followed by zeros is
  `EOFException` here, `StackOverflowError` on the JVM once the run is
  long), does Java-`int` wrapping offset/length arithmetic followed by
  range checks (an `ff ff ff ff` UTF-16 length is `-2` and
  `IndexOutOfBoundsException`, as from `ByteBuffer.wrap`), and bounds
  preallocation by the bytes left. The superclass walk is iterative
  (a 200000-class synthetic chain completes). Truncated and garbled
  DEX bytes run through full discovery, and an extreme-int sweep runs
  over a real manifest, without panics.
