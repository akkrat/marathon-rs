# WP 8.19 test changes

D65 replaces representation-dependent traversal with domain admission. Copied
fixtures and native goldens remain unchanged. No mapped Kotlin test is retired.

## Commit 1

- `pool_scheduler::tail_join_observes_late_pool_with_or_without_completion_marker_d65`
  (new): manually holds execute after the final supervisor detaches; B publishes
  before traversal resumes and must run, with and without a completion callback.
- `pool_scheduler::publication_and_final_completion_have_an_explicit_admission_boundary_d65`
  (new): explicitly orders publication before final completion, and traversal's
  absent-index read before Connected; only the former joins B.
- `pool_scheduler::unpublished_prefetch_is_excluded_even_after_connected_d65`
  (new): gated prefetch acknowledges Connected/accumulator creation, then finishes
  after traversal; that accumulator is excluded. Covers successful publication
  and prefetch failure/cancellation without publication.
- Existing pool tests retain their assertions; their `Run` constructor now shares
  setup with the manual-polling harness. The test-only analytics adapter gates the
  real prefetch bridge without a replay label or time-based ordering.

## Commit 2

### Storage, sealing and admission witnesses

- `runtime_review::sealed_ancestors_reject_callback_failing_work_d65` (new):
  ordinary and supervisor parents; one and four body-finished ancestors; child
  callbacks registered before and after parent completion. Every ancestor is
  already Success during the callback; attempted failing TaskBody closures never
  enter, rejected tasks complete cancelled, joins finish and callbacks run once.
- `runtime_review::actor_receiver_seals_owner_and_supervisor_before_callbacks_d65`
  (new): the real RuntimeActor receiver/ordinary owner/supervisor graph seals
  before callback attachment, in both registration orders; no failing body enters.
- `runtime_review::admitted_failure_waits_for_cleanup_and_supervisors_isolate_it_d65`
  (new): a Completing parent with a real pending child admits work. Its failure
  fails an ordinary parent and cancels siblings, yet waits for explicit cleanup;
  a supervisor isolates it and succeeds only after the same gate. Later ordinary
  cancellation cannot override the failure.
- `runtime_review::cancelling_attachment_never_enters_or_removes_the_pending_child_d65`
  (new): an already-cancelled spawn under a parent awaiting real cleanup never
  enters; its detachment leaves exactly the genuine pending child. Repeated
  cancellation preserves the first reason and completion callback runs once.
- `runtime_review::reentrant_cancellation_waits_for_other_child_cleanup_d65`
  (new): child completion callback reenters parent.cancel twice while another
  task is gated; no borrow panic or early seal, original reason retained.
- `runtime_carried::wide_children_keep_order_and_release_after_completion_d65`
  (new): 10,000 strong child entries, stable removal and snapshots containing only
  children despite callback registrations; completion releases every child.
- `pool_scheduler::real_pool_supervisor_and_scheduler_seal_before_last_child_callback_d65`
  (new): real DevicePool actor/queue/device/supervisor graph, with the Scheduler
  parent Completing and the last supervisor child explicitly held. Its callback
  observes the supervisor sealed Cancelled and Scheduler sealed Success, and
  attempted failing work under either never enters or changes the outcome.
- `pool_scheduler::late_admitted_failure_is_aggregated_d65` (new): a failing B
  publishes after A detaches while execute is held; B runs and makes the result
  false, preventing an incomplete green outcome.
- `run_flow_witnesses::scheduler_cancellation_still_exits_at_24000_d52` (new):
  SIGTERM with a hung provider, with and without hung reports; exact virtual exit
  at 24,000 ms and existing status 143.

The existing `runtime_carried::deep_chain_cancellation_cascades_iteratively`,
`deep_chain_completion_cascades_upward_iteratively`,
`deep_chain_failure_propagates_iteratively` (100,000 levels) and
`many_completion_callbacks_on_one_job_are_released_iteratively` (100,000 FIFO

`a_pool_created_during_a_wait_is_joined_and_the_run_waits_for_both_d48` retains
its exact 201,000 ms end assertion. All existing handler-retention, timeout
cleanup, cancelled actor construction and DeviceActor accounting tests remain.

  retain the immutable historical early-child,parent,late-child value, assert
  native early-child,late-child,parent and parent Success during child callbacks.
- `runtime_carried::caller_cancellation_ends_observed_children_traversal` becomes
  `caller_cancellation_ends_join_without_cancelling_the_joined_job_d65`:

- `runtime_carried::cancellable_traversal_matches_jvm_traversal_rows` and its

  `list_traversal_reads_successor_after_each_join` are retired under D65.
  `snapshot_does_not_observe_attachment_during_list_join` is renamed

All retired tests are Rust synthetic probes, absent from the Kotlin parity
matrix; no parity row changes or unrelated comparison exclusions are needed.

## Implementation review follow-up

- `runtime_review::sealed_pending_registrations_preserve_fifo_in_both_orders_d65`
  (new): vary parent-first/child-first registration and registration of the
  second callback before/after parent.complete; the child's callback registers
  p-late on the sealed parent. All four combinations produce
  cbC,p-early,p-late,p-during, then a fully dispatched registration runs p-after
  immediately. p-during is registered by p-early during dispatch.
- `runtime_review::sibling_outcome_is_prepared_before_callbacks_d65` (new):
  parent cancellation prepares both children before A's callback calls
  B.complete; B is already Cancelled, complete returns false and parent remains
  Cancelled. D65 explicitly accepts this sibling outcome difference.
- `runtime_carried::dropping_root_only_incomplete_deep_chain_is_iterative_u193`
  (new): drop an active 100,000-deep tree with only the root retained; the weak
  leaf expires without stack overflow or a completion/cancellation cascade.
- `runtime_carried::dropping_parent_keeps_shared_child_tree_intact_u193` (new):
  dropping a parent does not steal an externally retained child's descendants.
- `executor::job::tests::failure_handler_panic_does_not_abandon_ready_packets_d65`
  (new): a failing child's handler panics; its callback and the parent's packet
  still dispatch, outcomes stay Failed and both pending queues are drained.
- `marathon-cli/tests/late_pool_admission.rs::admitted_late_pool_reports_files_progress_counts_and_cli_status_d65`
  (new): hold runAsync's final-join continuation while A detaches and B publishes.
  Standard reporters and the real CLI console/status mapping include B's raw JSON,
  JUnit suite, progress line and summary counts. B passing selects status 0;
  B failing selects the existing status 1.
- `marathon-cli/tests/late_pool_admission.rs::held_prefetch_is_excluded_from_files_progress_summary_and_cli_status_d65`
  (new): acknowledge Connected(B)/prefetch before A completes, hold that prefetch
  until runAsync and standard reporters finish, and exclude B from raw JSON,
  JUnit, progress and summary. Both passing/failing joined A prefixes select
  their existing statuses 0/1. Explicit scripted device gates and manual polling
  order the race; no timestamp tie or host-speed assumption is used.
- `MarathonFactory` gains an optional console sink for these CLI witnesses;
  existing factory users retain their recording console and all assertions.
  The test-only `Marathon::scheduler_job` accessor verifies that A's actor and
  supervisor detached before B publishes and the held traversal resumes.

All review additions are synthetic Rust witnesses. No Kotlin parity rows or
copied fixtures change. The CLI witness substitutes the scripted vendor through
CliRunner; it executes the production Marathon.run_async lifecycle, reporters,
RunConsoleSink and CLI exit mapping. Manual polling keeps the admission race
reviewable without a production scheduler hook or replay label.
