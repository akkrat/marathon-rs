## Delivered scope and decisions

The approved harness-first start and P1–P4 are implemented as a staged gate.
There are **28 active contracts and 14 explicitly planned scenario groups**.
The complete contract and command interface are in `docs/design/differential.md`;
`tools/differential/registry.json` records owners, transport, prerequisites,
comparison scope, inputs and native targets. Its generator has a read-only
`--check`; 78 legacy evidence files are pinned unchanged. Deleting a registered
case, losing an input/fixture, or changing the CLI factory registration/slots
makes the gate fail until the ledger is deliberately reviewed.

The new strict comparator captures every file/directory/link, modes, content
length and SHA-256 plus actual payload bytes. It rejects incomplete outcomes,
unconsumed tapes, unmatched commands, corrupt/extra payloads and collisions.
Typed JSON token and anchored-text replacements share bijective identity roles
across paths/references. Literal UUID-like messages stay exact. Scoped Allure
structure and causal stream aggregation are available; default bytes remain
exact. P4 compares one of a finite list of **complete** JVM variants; no
arbitrary missing-log tolerance or new A20 variant was added. Mismatch artifacts
preserve both raw records and normalized views (or the validation error).

Immutable JVM generations are validated before a same-filesystem rename. A
native, partial, failed or existing destination cannot replace a golden. Capture
and checks are separate commands. Every launched capture has a fresh sandbox,
HOME/TMPDIR, retained stdout/stderr and process exit/watchdog result. A failed
capture is not retried automatically. No public Stub CLI path was added.

`check.sh` validates the ledger/evidence and runs the 23 Python adversarial
checks. Its normal cargo workspace pass executes the registered native contracts,
including bounded loopback fake-worker/ADB tests. Manual/release-tag live CI is
in `.github/workflows/differential.yml`, with artifact retention and read-only
permissions. Full host profiles fail explicitly while vendor cases are planned;
manual `harness-first` is labelled as reduced. The workflow needs provisioned
macOS arm64/Linux x86_64 runners with the pinned Kotlin source and JBR.

## Round 1 review fixes (WP 7.1a)

* **R1-muse-1:** `pack` now derives terminal fields from the waited process and
  operation observation, plus JVM transcript completion/expectations and hook
  accounting. Validation independently checks those observations against the
  recorded outcome. Native in-process tests export after their operation has
  returned; they have no child harness process or watchdog. Both current strict
  cases are untaped (parse explicitly clears `JAVA_OPTS`); a null `hooksReport`
  therefore means no tape was installed, not a measured consumption result.
  Contracts using tapes must declare `uses_tapes: true`; absent accounting then
  fails. Hook `unused`/`failures` populate outcome `unused`/`unmatched`.
  Regression tests reuse the independent regen witness's null-report case,
  failed process/watchdog results, stamped-success forgery and hook failures.
* **R1-muse-2:** JVM records require nonempty jar/patch SHA-256 maps, a JDK
  identity and typed process argv/exit/watchdog provenance. A native record
  relabelled JVM with `{"probe": 1}` fails validation and publication. Golden
  `evidence.json` files and the verification manifest are now hash-pinned in
  the registry; tests mutate each pin and omit each required provenance field.
  These fields describe origin; they are not cryptographic attestation. Reviewed
  registry hashes protect the committed evidence against relabelling/editing.
* **R1-muse-3:** `command` accepts `expected_exit` and closes stdin with
  `DEVNULL`; a regression test reads EOF and exits 7. **7.1b:** replace fixed
  local/parse selections and `jvm-v1` generation paths with registered adapters
  and generation selection when whole vendor CLI cases become runnable.
* **R1-muse-4:** `opaque_json` accepts case-sensitive glob patterns over
  canonical paths. Product JSON/JSONL is parsed only where JSON structure or
  JSON-token normalization is selected. Dynamic names, duplicate-key JSON and
  empty JSONL otherwise remain byte exact. Tests cover those files and globs.
* **R1-muse-5 / R1-muse-8:** the available `allure-environment` structural
  comparison drops the XML declaration and comments; it preserves element
  order, attributes, text and tails. Both Allure modes currently require the
  `reports/allure-results/` prefix. **7.1b:** review that scope and root mapping
  before vendor activation. The registry's CLI entry/runner hashes are broad
  review tripwires, not semantic factory detectors: unrelated edits can trigger
  them. Narrowing those tripwires to factory registration/slot structure is
  deferred to 7.1b; the current fail-closed review behavior remains.
* **R1-muse-6:** removed the unused Rust `differential::compare` helper. Native
  tests retain their working `verify-local`/`verify-parse` driver paths; the
  structural, causal and finite-variant comparator test modes remain.
* **R1-muse-7:** missing comparison inputs retain the existing side and error
  artifact and raise `Invalid`, rather than masking it with `FileNotFoundError`.
