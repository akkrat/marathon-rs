# WP 8.12: async Apple command reads — design stop

Milestone 1 only. Production code, tests, parity rows and copied fixtures are
unchanged. The recommendations below need review before milestone 2 starts;
this document does not approve a contract change or allocate a D number.

## Current boundaries

`extensions/reader.rs` polls one `AsyncRead` every 1, 2, 4, 8, 16, then 20 ms.
Each command's stdout and stderr share an `AtomicI64` last-output timestamp.
Every positive read updates it through `apple.Reader.currentTimeMillis`, even
for an incomplete line. An empty read checks
`now - last - 20 > configured_idle`, then `can_read`. D19 adds a final
non-waiting byte drain when that predicate becomes false; that drain neither
updates last-output nor checks idle expiry. All reads use 16 KiB chunks.

The inputs are not yet usable as ordinary waiting async streams:

- Local `PollingPipe` calls the nonblocking descriptor directly and returns
  `Pending` without registering a waker. This also works around bytes already
  in the kernel before Tokio has delivered pipe readiness (U145).
- SSH `ChannelReader` consumes the pump's per-stream buffers but returns
  `Pending` without a waker or EOF on an empty buffer. `ExecChannel.changed`
  already publishes state changes; `wait_for` subscribes before inspecting
  state. Data after SSH EOF remains discarded by `receive`.
- `LineChannel` wakes blocked senders on close, but has no future that an idle
  reader can await for consumer closure.

`PollBackoff` also serves `sshj::executor::suspend_for`, with its own Kotlin
parity tests in `sshj_command_exit_status.rs`. Retain the type, module and its
two tests in this WP. The output reader will have no poll ticks; converting
the separate exit-status waiter is outside this proposal. The brief makes
deletion conditional on there being no other users.

D31/D43's rsync process/pipe readers live separately in
`cmd/remote/rsync/rsync_file_bridge.rs`; they do not call this reader. Preserve
`--timeout=300`, the progress monitor, signal/reap sequence and the five-second
post-exit reader bound (U158), and stalled-send retry suppression (U163).
D32's SSH exec prefix and all other worker command construction stay exact.

## Proposed state and wakeups

Replace `can_read: Fn() -> bool` with a latched, repeatedly observable end
signal, not a consumable notification. Each reader owns its stream and line
buffer. Both readers share a watch value containing the vendor-clock time of
the last positive read. Publish every read, including two reads in the same
millisecond; a watch version change wakes the sibling and invalidates its
pending idle wait. Subscribe before reading the current value.

Local end means either the detached reaper's actual exit completes or the
public `base.exit_code` completes (including total timeout or exit failure),
as the current `alive && !exit.is_completed()` predicate requires. Reuse
`ExitCode::wait`/watch subscriptions, without consuming or changing either
result. The reaper remains detached and explicit close retains its signal,
cancellation and join ownership. Awaiter cancellation still stops only that
awaiter, not the reader or process.

SSH end means `!is_open() || is_eof()`, including requested CLOSE, peer CLOSE
and transport failure. Add an async wait using `ExecChannel`'s versioned
state; do not substitute exit-status arrival, since it can precede the last
data. Both streams observe the same terminal predicate.

Use Tokio's ordinary child stdout/stderr `AsyncRead` while running, removing
the polling-only `PollingPipe`. Keep a narrow nonblocking final-drain operation
on the same exclusively owned descriptor: retry EINTR, read bytes already in
the kernel, stop on EOF/EAGAIN/error. It must bypass a stale Tokio readiness
cache. Simply polling `ChildStdout` once after exit can return `Pending` while
bytes exist, recreating U145; waiting for pipe EOF can hang on an inherited
write end. No timer or repeated empty read is part of this final drain.

Make SSH `ChannelReader` a real wakeable `AsyncRead`: atomically inspect the
buffer/terminal state and register a per-stream waker under the state lock.
Data or a terminal transition takes the relevant wakers and wakes them after
unlocking. Buffered bytes precede terminal EOF, including on transport loss;
retain `take`'s D37 window-credit calculation. Empty terminal reads return
zero; a zero-capacity `ReadBuf` returns immediately. Its final-drain operation
only consumes bytes already in the pump's buffer. No wait for later packets.
A register-then-recheck implementation is also acceptable; a check-then-register
implementation that can miss a wake is not.

Add `LineChannel::closed()` with the existing Notify register/enable/check
pattern. It completes for normal close, failed close or cancellation, but
never consumes queued lines or changes the first cause. Include it while
waiting for input and during line delivery, so a closed consumer stops an
otherwise silent reader immediately.

## Loop sketch and precedence

Use `Running`, `EofWhileAlive` and `Draining` states. Construct wait futures
before the select; keep the end signal latched and the current idle wait
pinned until output activity changes its deadline. A wake without activity
must not restart a full idle interval.

```text
subscribe to end, shared activity and output closure; initialize line buffer
loop:
    cancellation or closed output -> finish through existing epilogue
    Running:
        select, biased:
            cancellation -> cancel
            output closed -> stop
            next nonblocking async read:
                bytes -> append; publish vendor now; flush complete lines
                EOF   -> disable reads; enter EofWhileAlive
                error -> normal end, as today's reader; keep buffered tail
            shared activity changed -> recompute idle wait
            idle wait completed -> recheck shared activity/time; expire if due
            process/channel ended -> enter Draining
    EofWhileAlive:
        same waits except read (never re-poll EOF); SSH EOF is also end
    Draining:
        read immediately available bytes until EOF/Pending/error
        append and flush, checking cancellation/output closure per chunk
        do not refresh activity or check idle; then finish
finish:
    idle expiry closes output with the timeout before the tail drain (A24)
    drain LineBuffer unless cancelled; keep existing error/close mapping
    normal close preserves queued lines; cancellation discards them
```

Readable bytes win over an already-ready idle deadline, as the existing
late-output test requires. Cancellation and output closure win over reads.
Without readable bytes, a due idle deadline precedes an end signal, preserving
the current empty-read → idle-check → end-check order. Before committing a
timeout, reload the shared activity value and recompute the remaining wait;
a sibling's positive read must not be mistaken for silence. A concurrently
observed end transitions to final drain; reads in that drain do not refresh
activity. An already-latched end must still allow one non-waiting read before
choosing timeout versus drain, preserving this same precedence.

Flush/drain waits keep bounded-channel backpressure. While a send is blocked,
only cancellation/output closure interrupts it: do not introduce an idle or
end race inside delivery, which would discard already extracted lines. After
a flush, recompute the remaining interval from the shared timestamp, rather
than starting the idle allowance again. Ensure long immediately readable
bursts/final drains cooperate with other vendor tasks between bounded batches
of chunks; no periodic timer is needed for fairness.

Read errors currently break the loop and drain the tail rather than fail the
channel with an I/O error. Keep that behavior; SSH exit failure still travels
through the separate exit result. Keep timeout failure as
`FailureKind::Timeout` with `idle timeout {idle_timeout} reached`, including
the existing duration formatter. Keep the current `result.and(drain)` and
first-close semantics, including typed cancellation and A24's rejected tail.
All process, pipe, SSH and reader work stays on `VendorRuntime`; no blocking
wait, process cleanup in Drop, or new core-executor I/O is introduced.

## Decisions to review

### EOF while the local process is alive: keep the channel open

Recommendation: disable further reads after EOF, retain the partial tail,
and wait for the existing process/end signal, idle expiry, consumer closure
or cancellation. EOF itself does not refresh activity. This preserves A25's
observable behavior without polling: a live silent process can still fail
with idle timeout, whose first receive rejects its partial tail. If the
process ends first, drain the tail and close normally. No new D-row for EOF
is needed with this choice; the implementation-specific polling assertion
will become an EOF-wait assertion.

Alternative: drain and close normally at pipe EOF. A consumer would see its
partial tail/normal close immediately, even with the process still alive.
`consume_output` and `await_result` would still await the exit code, but could
now succeed for a process that previously failed its idle limit. The closed
stream would no longer enforce silence against the other stream. This fixes
A25 and needs a separate approved D-row, a ledger update, and changed EOF
witnesses. It is not the recommendation.

Neither option promises stdout/stderr order against each other or against
publication of the independently awaited exit code. With the recommendation,
local output does not close normally just because the descriptor reached EOF;
SSH still finishes its stream at protocol EOF, which already ends `can_read`.
Both command result helpers continue to await output and the exit result.

### Idle limit: use the configured value exactly on the vendor clock

Recommendation: expiry is `elapsed >= configured_idle`, with ready bytes
winning as above. Remove the 20 ms backoff allowance and tick quantization.
For a 200 ms limit with no output, the virtual deadline is 200 ms; today's
reader tests allow 221..240 ms. A 20 ms limit at live pipe EOF becomes 20 ms
instead of 41..60 ms. A live host can run the continuation later; this is a
deadline, not a promise about dispatch latency. Zero or negative limits expire
immediately when there are no ready bytes; conversion overflow keeps its
existing failure kind. Keep `i64::MAX` non-expiring and calculate remaining
intervals without addition/subtraction overflow, including a past timestamp.

Use `context.clock.now_millis()` and `context.clock.delay(remaining, signal)`
for both readers. The production SendClock already uses the same timeline
that ReplayDriver advances. Retire the reader's wall-hook calls entirely,
including initialization in both executors; do not replace them with host
Instant or Tokio sleeps. Vendor elapsed time no longer follows host wall-clock
jumps, frozen wall hooks or per-read step tapes. This clock change is part of
the proposed idle decision and must be stated in its approved D-row, along
with removal of the margin and the strict `>` boundary.

This is visible: output arriving during the old extra allowance can now be
too late, causing earlier command failure, with the same kind/message and
A24 tail handling. It needs an approved §3.11 D-row before implementation.
Assign the next available number then; do not reserve one at this design stop.
Configuration syntax/defaults, commands, result schemas and pinned console
text stay unchanged; native goldens/config corpus are expected unchanged.
Any result-file difference requires review under §3.12, not a broad allowance.

Alternative: retain the wall-clock semantics and `elapsed - 20 > limit`,
waking at its first eligible millisecond. This keeps the grace but still
removes polling quantization; arbitrary wall-clock jumps/per-read tapes do
not map naturally to one scheduler deadline. Keeping the extra 20 ms has no
read-latency justification after both streams register readiness and share
activity notifications.

## Replay and tape impact

The old count is not part of the new loop. Stop reading the retired
`apple.Reader.currentTimeMillis` key rather than fabricating reads at former
backoff ticks. No replacement replay label is introduced. Timeouts use the
existing vendor scheduler seam; wall/monotonic hooks at other sites keep their
independent cursors and semantics.

The tracked-input census at this design stop found:

- `tools/oracle/scenario-tape.json` has scheduler-derived wall/monotonic clocks
  and virtual scheduler time, with no explicit read arrays. The random-order
  tape has the same clock modes and only a `core.BillingReporter.defaultStart`
  read override. Neither pins reader read counts. Core scripted scenarios use
  stub devices, not local processes or SSH.
- `tools/differential/vendors.py` derives live vendor tapes from the scenario
  tape, replacing wall/monotonic with frozen modes and scheduler with real
  time. No reader read array is added. Native vendor readers must therefore
  still expire on the vendor scheduler even though report wall time is frozen.
- There are 61 historical evidence JSON files containing this label, all in
  `fixtures/differential/{vendors,vendor-verification,vendor-verification-c95b2128}`.
  They record hook call counts, not input arrays: ten Apple scenario families
  (`ios-ignore`, `ios-media`, `ios-parse`, `ios-pass`, `ios-screenshot`,
  `ios-smoke`, `macos-ignore`, `macos-parse`, `macos-pass`, `macos-smoke`). Counts
  already vary between JVM recordings. Leave all historical evidence exact;
  new native execution no longer produces these reader-hook calls.
- `reader.rs` pins poll counts (500..510 and reset >=5), call ordering in the
  D19 closure, and grace windows (221..240 and 41..60). Its `Stream` has no
  waker. These are the scripted tests that need adaptation: use a wakeable
  gated stream and latched end signal, preserving line/error expectations.
  Retain the Kotlin test names for surviving parity rows.
- Apple `tests/support/mod.rs::Clock` and the duplicated clock in
  `marathon-test-support/tests/support/mod.rs` recognize this label. Their
  VendorClock currently inherits `now_millis() == 0`; implement the same
  elapsed paused-clock source used by `delay`. Audit other clocks actually
  passed to these executors, including scaled wrappers, for matching units.
  `ssh::ScaledClock` already supplies scaled elapsed time. Do not keep an
  accidental constant-zero clock or mix wall timestamps with scheduler time.
- `crates/marathon-core/tests/contracts.rs::transport_contract` names the old
  reader hook; update that illustrative seam to vendor time, retaining the
  independent simulator nanoTime hook. The oracle hook patch and historical
  nondeterminism inventories remain witnesses, not production read sites.

For historical or external tapes with explicit `reads` at the retired reader
label, remove only that key from the in-memory Tape in `RuntimeHooks::taped`,
as D58 removed only its retired identity keys. Never edit the copied tape,
consume dummy values, skip all unused reads or suppress failures on active
labels. Add replay-hook tests proving the retired key needs no consumer while
unused/exhausted active read entries still fail. Document the single retired
read key and scheduler-clock decision in `docs/design/replay-tapes.md` and the
relevant lifecycle/nondeterminism guidance during milestone 2.

## Test plan and change accounting

Milestone 1 changes no tests. Milestone 2 must list every changed, added,
renamed or deleted test and helper impact in `docs/wp/8.12-test-changes.md`.
The polling-only `idle_reader_backs_off_to_the_maximum_poll_delay` should be
retired after approval, with its parity row `n/a`, reason `8.12: <approved
D-row>` and reviewer agreement; replace it with a native no-periodic-wakeups
test. Keep the mixed line-order/backoff test's Kotlin name and line assertions,
removing only the obsolete poll assertion. Keep both PollBackoff parity rows
and all SSH exit-status backoff tests `ported` because the type remains used.
Update any Rust test paths affected by signatures; do not mark kept behaviors
`n/a` merely because their harness changes.

1. With paused time and an instrumented VendorClock, drive slow producers,
   byte-split Unicode/CRLF, D32 small writes and bursts above 16 KiB/channel
   capacity. Assert exact lines/order/tail, bounded buffering, sibling
   activity, and no timer wakes during silence before the one idle deadline.
2. At limit minus 1 ms, exactly the limit and plus 1 ms, gate read readiness,
   end and cancellation separately. Assert readable-byte priority, no-data
   timeout priority, the exact configured expiry, refreshed sibling deadlines,
   no EOF spin, and no new idle limit while a flush is backpressured.
3. Gate a real local child after it closes stdout but before exit. Assert its
   output stays open while alive; test both exit-before-idle (tail/normal
   close) and idle-before-exit (timeout/discarded tail). Test stderr activity
   extending an EOF stdout's deadline. Do not use short scheduling sleeps to
   establish ordering.
4. Preserve the D19 gated race at pending-read → end, including bytes already
   in a child pipe before Tokio readiness. Have a descendant hold the write
   end open after the parent exits: available bytes/tail must be delivered
   without waiting for that descendant's EOF or inventing a new timeout.
5. Cancel mid-read, after EOF and during a full-channel send; close/cancel the
   consumer while input is pending. Join the reader and assert cause/queue
   state and no further reads. Independently cancelling an awaiter still
   leaves session collectors and the process alive until explicit close.
6. Gate SSH pump delivery at data-before-EOF, EOF-before-CLOSE, requested CLOSE
   and transport loss. Confirm all buffered data precedes stream termination,
   post-EOF data stays dropped, credit stays bounded, and other channels work.
7. Drive the reader with CoreExecutor's real virtual VendorClock: no time
   passes without ReplayDriver, due timers quiesce before an external event at
   the same timestamp, and frozen/step wall hooks do not control the deadline.
   Check retired-key accounting alongside active unused/exhausted-key errors.
8. Run focused Apple/core suites, then the full `scripts/check.sh` gate. It
   includes native vendor differentials, configuration validation, source and
   parity checks. Verify `git diff 816e0000 -- fixtures/` is empty; any golden
   delta is a review stop, not permission to regenerate copied inputs.

Use virtual/paused clocks for boundary assertions. Real process/socket tests
use explicit gates/notifications and awaited cleanup, with a 60 s positive
hang watchdog under `docs/testing.md`; only a timeout deliberately under test
gets a short configured value. Never assume independent task interleaving or
assert a narrow real-time latency. The long ignored U163 witnesses retain
their status; the workspace gate is not evidence that those ran.

## Risks and review boundary

- Lost wakeups at read/end/consumer-close registration can strand a command.
  Atomically register/recheck, including transitions before the first poll.
- Final local drain must retain U145 coverage without waiting for inherited
  descriptors or trusting stale reactor readiness. The dedicated post-exit
  operation is essential even though running reads are ordinary async reads.
- Shared activity must invalidate both deadlines. Biased selection must not
  spin on repeated EOF or lose terminal bytes; full output queues must retain
  existing cancellation and cause ordering.
- Vendor-clock migration exposes clocks with the default constant-zero
  `now_millis` and changes frozen/step wall-hook behavior. Scope the retirement
  to the one key; never weaken general replay verification.
- Exact idle expiry removes the old safety margin: writes near the limit can
  now time out, and live dispatch can still run late. This is the one
  recommended visible contract change and needs the D-row approval.
- Retaining EOF-while-alive behavior keeps A25's surprising timeout/discarded
  tail, deliberately. Retaining the exit waiter also leaves its independent
  PollBackoff use, which must not be mistaken for an unfinished reader port.

Stop here after milestone-1 gate and commit. Milestone 2, D-row allocation,
code/test changes and any golden review wait for the next instruction.
