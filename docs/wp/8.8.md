# WP 8.8: `tracing` instead of the logback emulation

Effort **H** (wide: about 160 files log). Branch `wp/8.8-tracing`, based on `main` after WP 8.6b (commit
`a830d106`). Runs alongside WP 8.7; whichever merges second rebases.

## Why

Phase 8 removes Java emulation while keeping the contract in PLAN.md §3.12. Logging is a port of
logback and kotlin-logging (`crates/jcompat/src/logging.rs`, about 700 lines): logback patterns and
layouts (`Startup`, `Runtime`, `Compact`), logger-name abbreviation, SLF4J `{}` message formatting, Jansi
ANSI handling, per-vendor log configurators, `TimingLog`, `KLoggerDebug`, and a wall-clock replay seam
(`library.logback.wall`). About 160 source files call it.

PLAN.md §3.12 point 5 keeps only **the per-test progress lines and the end-of-run summary block**
(including `Marathon run finished` and the `\tRaw: ...` lines) in their text format. **Every other log
line may change**: format, prefix, logger names, timestamps, wording.

## Scope

1. **Log through `tracing`.** Call sites use `tracing` macros (`error!`, `warn!`, `info!`, `debug!`,
   `trace!`) with Rust format arguments instead of `{}` placeholder strings and Kotlin logger names; the
   target is the Rust module path (no `com.malinskiy…` names). Structured fields where they help
   (`device`, `pool`, `batch`), not required everywhere.
2. **One subscriber**, set up in `marathon-cli` with `tracing-subscriber`:
   - Levels: today's `debug` setting and the vendor configurators decide what is shown (for example
     what ADB or Apple tooling logs at which level); keep those decisions, expressed as filter
     directives.
   - Format: a plain, readable line (time, level, target or a short component name, message). Colour
     when the output is a terminal, none otherwise (keep what Jansi handling achieved: no escape codes
     in redirected output). Keep Apple's compact-output option meaningful.
   - **No blocking on the core executor thread** (CLAUDE.md, `docs/design/lifecycle.md`): today lines go
     to an I/O task. Keep that property, for example with `tracing-appender`'s non-blocking writer, and
     make sure nothing is lost at exit (flush the guard before the process ends, including on error
     exits and cancellation).
3. **The pinned lines stay byte-identical.** Find exactly how progress lines and the summary block are
   produced and tested today. Keep their text, whether they keep going through the logger with a
   formatter that prints them unchanged or are written directly. The tests that pin them do not change
   their expectations.
4. **Logs that are files.** If any log text lands in result files or other output files (for example
   timing logs, xcodebuild stderr logs, device logs written by marathon), those files keep their data;
   find them and keep them out of the format change, or stop and report.
5. **Delete the emulation**: `jcompat::logging` and what only it used (Jansi stripping, abbreviation,
   `format_message`, the wall seam), once nothing uses them. Keep any helper that something else needs,
   moved where it belongs.

**Out of scope:** the progress/summary text, result files, CLI flags (no new logging flags), external
tool output that marathon passes through verbatim.

## Goldens and tests

- Native goldens that contain console output (`tools/differential`, `vendor_console.py`) will change.
  Re-bless through the documented tool, then `tools/differential/run diff-golden --against a830d106`,
  and summarize in `docs/wp/8.8-golden-diff.md`: which views and files changed, and a proof that **no
  pinned progress or summary line and no result-file datum changed** (only other log lines). If the
  console comparison needs a rule change to keep the pinned lines strict while letting other lines
  move, make it narrow, with adversarial self-tests (a changed pinned line fails; a changed other line
  passes only where the golden was re-blessed), and document it in `tools/differential/README.md`.
- Tests that pin non-contract log text get the new text or assert on structured events instead (a test
  subscriber that captures events is fine); list each changed test file in `docs/wp/8.8-test-changes.md`.
  Parity rows of deleted tests become `n/a` with reason `8.8: §3.12.5`.
- Replay tapes that contain the wall-clock seam stay as copied fixtures; the code stops reading that key
  (as 8.5 did for retired keys).

No D-row: §3.12 point 5 already allows the change. Record the new format in `docs/design/lifecycle.md`
(or a short `docs/design/logging.md`) and update the CLAUDE.md rule "use the jcompat formatters for
anything that reaches an output file or log" to say what holds now.

## Rules

- Keep `//! Port of ...` headers; drop comments that only explained logback behaviour.
- No `unwrap()`/`expect()` on I/O, process or network results.
