  `VendorClock::delay`. Cancellation is never retried. A pending body is dropped

  queue now accepts Send producers through one shared `SegQueue`. Core `log`,
  `records`, `take`, wall-clock replacement and rendering retain their APIs.

  Producers stamp their records before enqueueing, with no registry lock or I/O.

- **`jcompat/jnum.rs`: `parse_double_with_error`** adds the JVM exception message
  alongside the existing parser. The oracle caught `empty String` for blank
  values and trimmed text for malformed padded values; Graphite warning causes
  must retain those messages. The original `parse_double` API is unchanged.

No dependency or Cargo.lock changes. In particular, core has no HTTP dependency.

## Handoff contracts

`Analytics` owns the run-wide provider. Share one `Arc<Analytics>` across Marathon
and every pool. It implements the frozen async trait, plus
`prefetch(&[MetricsKey])` and `lookup() -> Arc<dyn MetricsLookup>`.
`Analytics::from_lookup` is available under `test-support` for the existing
strategy stub. The real provider implements both interfaces too.

Prefetch serializes all keys through one async mutex, checks the shared cache
under that mutex and publishes a complete immutable snapshot. Published snapshots
use the already-present crossbeam skip list: insert the new generation before
removing the old one. Readers retain an Arc and never acquire a blocking lock.
Only the current generation is retained by the provider; each in-flight reader
can retain its own older snapshot. Cache entries share immutable value maps.
Observations live independently of fetch snapshots: an insertion-order list of
shared per-test sample lists plus a name-to-index hash map. Private locks protect
only indexing/appending/copying; no lock crosses an await and sorting happens
after releasing the sample lock. Observing never waits for the fetch mutex and
never copies earlier observations. Own-test lookup is indexed, while global
averaging traverses the list in Kotlin insertion order. Observations become
visible before observe returns. Warn-once sets are shared across all views and
query keys.

A never-prefetched lookup asserts in debug builds and uses the normal fallback
and lazy warning in release. NoOp needs no prefetch. Ordinary async lookups retain
source first-touch timing. Empty coverage returns before any query. The source
order is warning on failure, Timings, then (only for successful execution-time
fetches) the Kotlin data-class list dump; the prose above the final decisions
incorrectly suggested the dump preceded Timings. Source and JVM evidence agree.

Construct `MetricsContext` off core with the run's VendorClock, labelled
MonotonicClock, cancellation signal, logging registry, `core.log_queue().sender()`
and a nonblocking `stamp` closure returning scheduler/wall millis. Replay must
supply its own stamp clocks. The existing two history hook labels are unchanged.
Construction requests class loggers before configureLogging. `Timings` is
registered once at provider construction through jcompat's fixed-INFO handle.
Prefetch never acquires the logging registry; registry guards never cross await.

The output task must retain the already-created analytics logger levels: obtain
its render handle with `MarathonLogging::slf4j_logger(name)` for registered names,
not a new `logger(name, None)` call after configureLogging, which resets levels.
All messages are queued with the original logger name and level; jcompat renders
and filters them off core. The JVM probe reproduces the Modules → configure order
without Koin/device startup, as permitted by the brief. All three analytics
loggers remain DEBUG in both debug configurations.

WP 3.4b implements `MetricsSetup::{influx,influx2,graphite}` and the narrow
`InfluxQuery`, `FluxQuery`, `GraphiteQuery` traits. Query DTOs carry errors, series
names/tags/columns/nulls or Flux records. Setup receives Influx configuration and
debug; Graphite setup receives only the UTF-8 host (no carbon port). A malformed
host string such as `not a host` must fail on query, as the Kotlin client does,
not necessarily on setup. Actual Graphite setup errors propagate without NoOp.
Influx setup errors warn and return NoOp(unavailable). Factory construction and
setup are awaited off core. Influx close errors propagate unchanged; Graphite
close is a no-op.

`QueryableGraphiteClient.kt` moved to 3.4b in the source rules. The committed
Graphite URL observations are useful to its future HTTP implementation; 3.4a
checks targets and line parsing, not a nonexistent HTTP transport.

3.7 owns pool prefetch and queue observation calls. 3.10 owns flakiness first
interaction, coverage invocation, startup ordering, the shared context's clocks
and output drain, and the C25 close slot. No strategies changed.

## Approved simplifications and residual differences

- **P1:** Influx numbers are f64; preserve errors, series filtering and null
  dropping without reflection/type-coercion emulation. Non-numeric measurements
  fail the query and participate in retries/defaults.
- **P2:** Graphite host/prefix require UTF-8. Lone surrogates become a query error
  (retried, logged and cached as empty), not JVM URLEncoder replacement text.
- **P3:** all Influx setup errors fall back to unavailable NoOp, including typed
  cancellation returned by setup. No JVM Error hierarchy is emulated.
- **P4:** cancellation interrupts a pending fetch, returns Cancelled and emits no
  query logs or cache entry. A subsequent caller can retry after a source-local
  cancellation. A cancelled run signal continues to cancel that run.
- **P5:** synchronous lookups read the latest published measurements and live
  observations while unrelated history fetches are in flight. Both lookup and
  observe never wait on the registry or fetch mutex.
- **D13:** per-pool key prefetch moves queries earlier. The residual extra query
  cases remain those in PLAN §3.11; per-test warnings stay lazy in lookup order.

Review-round-1 decision R1-claude-6 adds eager validation of
`defaults.duration.to_millis()` at factory time, before backend setup or the
Influx fallback. An unrepresentable duration is a clear configuration error,
so factory-produced synchronous comparator views cannot overflow on core.
Direct construction for the async interface retains the lazy ArithmeticException
only when fallback is needed; history and observed estimates still succeed.
Direct callers exposing a synchronous view must satisfy the same validation
precondition (documented on `MetricsProviderImpl::new`). No I/O result is
unwrapped or expected.
