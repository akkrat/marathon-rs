# WP 0.1: repository foundation

**Owner:** Opus, low effort. **Reviewers:** Sol and Muse. **Depends on:** nothing.
Read `CLAUDE.md` and PLAN.md §4.1, §6.1, §6.2 and §8.3 first.

## Deliverables

1. **Cargo workspace** at the repository root.
   - One crate for each entry of PLAN.md §4.1 under `crates/`: `jcompat`, `marathon-config`, `marathon-core`, `marathon-apple`, `marathon-ios`, `marathon-macos`, `marathon-adb`, `marathon-dex`, `marathon-android`, `marathon-test-support`, `marathon-cli`.
   - `tools/fake-worker` and `tools/oracle` are created later, by their own WPs.
   - Library crates are empty skeletons. Each has a crate-level doc comment saying what it will contain, with a pointer to PLAN.md.
   - `marathon-cli` builds a binary named `marathon` whose `main` returns exit code 0 and does nothing else yet.
   - Inter-crate dependencies follow §4.1. For example, vendors depend on `marathon-core`, and `marathon-core` depends on `marathon-config` and `jcompat`.
   - Edition 2024. Shared `[workspace.package]` metadata: `license = "GPL-2.0-only"`, `publish = false`.
   - `[workspace.lints]`: `unsafe_code = "deny"`, plus clippy `all` at warn level (`check.sh` turns warnings into errors).
   - Do **not** add third-party dependencies yet; the spikes choose them.
2. **Toolchain files.**
   - `rust-toolchain.toml` pins channel `1.99.0` with the `rustfmt` and `clippy` components and the targets `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`.
   - `rustfmt.toml` sets `max_width = 120`.
3. **`scripts/check.sh`** (bash, `set -euo pipefail`). It sets `PATH` as in `CLAUDE.md`, then runs:
   - `cargo fmt --all --check`;
   - `cargo clippy --workspace --all-targets -- -D warnings`;
   - `cargo test --workspace`;
   - `python3 -I scripts/check_plan_dag.py`;
   - the source inventory in check mode;
   - the parity-matrix check.

   Both inventory checks need the Kotlin repository. They use `$MARATHON_KT` (default `$MARATHON_KT`) and are skipped with a clear warning when it is absent, for example on CI.
4. **Source inventory check mode.** Add `--check` to `scripts/source_inventory.py`. In check mode it regenerates the CSV in memory, fails if the result differs from the committed `docs/source-inventory.csv` or if any file is unowned, and writes nothing. A reviewer noted that the script rewriting the file during a review was a side effect.
5. **Fixtures.**
   - Copy every Kotlin test-resources directory, unchanged, to `fixtures/<module path>/`. For example, `vendor/vendor-apple/base/src/test/resources` becomes `fixtures/vendor-apple-base/`. The source directories are:
     - `core/src/test/resources`
     - `configuration/src/test/resources`
     - `report/execution-timeline/src/test/resources`
     - `vendor/vendor-android/src/test/resources`
     - `vendor/vendor-apple/ios/src/test/resources`
     - `vendor/vendor-apple/base/src/test/resources`
   - The Android ones are about 19 MB; commit them as normal files.
   - Write `fixtures/PROVENANCE.md`: the source repo, the commit `e47352f2`, and the source → destination mapping.
   - Also write a small `scripts/sync_fixtures.py` that verifies (or, with `--write`, redoes) the copy, so the mapping is reproducible.
6. **Parity matrix generator, `scripts/parity_matrix.py`.** It reads the Kotlin repository and writes `docs/parity-matrix.csv`.
   - **Coverage.** It scans every test source set: `src/test` and `src/integrationTest` of every module.
   - **One row** per:
     - `@Test` method;
     - `@ParameterizedTest` method. Where the arguments are static, it expands them into one row per invocation:
       - `@ValueSource`, `@CsvSource` and `@EnumSource` with the enum's values when they can be resolved;
       - `@MethodSource` when the provider is a simple `listOf`/`Stream.of` literal in the same file;
       - otherwise a single row with `invocations = unknown`.
     - test that is disabled with `@Disabled`;
     - test inside a fully commented-out file (`kind = commented`).
   - **Columns:** `source_set, kotlin_file, test_class, test_name, kind (test|parameterized|disabled|commented|external), invocation, wp, status, rust_test, commit`.
   - **`wp`.** Take the main-source file the test covers (the test's path with `src/test` → `src/main` and the `Test` suffix dropped) and look its WP up with the rules in `source_inventory.py`. Import the `RULES` list; don't copy it. If no main file matches, use the rules on the test path itself. Leave `wp` empty only if nothing matches, and report those rows.
   - **External rows** (`kind = external`): placeholder rows for the test suites of the replaced libraries. They are expanded in WP 6.3 and 6.4:
     - adam 0.5.8's instrumentation response transformer tests and its stub-server tests (wp 6.3 / 0.5);
     - dex-test-parser 2.3.4's tests (wp 6.4).
   - **Status.** New rows are `pending`. On regeneration the script keeps the existing `status`, `rust_test` and `commit` of rows it finds again; it never resets ported rows.
   - **`--check`** fails if the committed CSV is out of date, or if a row is `n/a` without a reason in `rust_test`.
7. **CI.** `.github/workflows/ci.yml` runs `scripts/check.sh` on `ubuntu-latest` on pushes and pull requests. The Kotlin-dependent checks skip there, as described in item 3.
8. **`AGENTS.md`**: a symlink to `CLAUDE.md`, so Codex and Muse seats read the same conventions.

## Acceptance

- `scripts/check.sh` passes locally with the Kotlin repository present.
- `docs/parity-matrix.csv` exists. Report its row counts by `kind` and by `wp`, and every row whose `wp` is empty.
- No Kotlin file is modified. The fixtures are byte-identical to the sources (`scripts/sync_fixtures.py` verifies this).
- Work on branch `wp/0.1-foundation`; end with a summary of what was done and the `check.sh` output.
