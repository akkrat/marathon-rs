The final decisions in the brief govern the scope.

## Implementation and consumer boundary

All five owned Kotlin modules are ported under `marathon_ios::device`.
`WorkerProvisioningContext` is explicitly constructed for one transport/cycle,
uses separate asynchronous inventory/facts load locks, retains executor Arc
identity, and publishes refreshes by successful request generation. Production
mutex waiters observe caller cancellation; refreshes bypass the inventory load
mutex. Ages use request-start monotonic nanos, inclusive ten seconds, with JVM
wrapping subtraction. Lookup preserves null availability; planning requires true.
Facts retain the whole shareability decision supplied by 5.2, including env,
Xcode, architecture, features and transcoding; probing stays in that consumer.

The run-owned provisioner shares endpoint-keyed permits across concurrent calls,
existing simulators and repeated profiles, independently of connection handshakes.
It awaits every supervised operation, preserves failure input order, propagates
typed cancellation, protects create until its returned UDID is retained, and
awaits unregistered-device disposal, lease release and created-simulator deletion.
Cancellation never aborts cleanup by dropping its future. The command wrappers
retain their own configured timeouts, including the default 30-second create.

The factory takes a `BinaryFactory`, `SimulatorConstructor`, the factory's one
`SharedTransfers`, run-owned `Track` and `ProvisioningTiming`. The constructor
captures bundle/artifact/output/config services and returns
`ConstructedSimulator<H>` with the same `DeviceRef` allocation, its concrete 5.2
Arc as `H`, and a `SimulatorSetup` adapter; no setup method or downcast was added
to core Device, and no production placeholder device is supplied. Track brackets setup;
validation precedes construction, and errors after construction dispose once.

`ProvisioningError` retains original classification plus suppressed disposal
errors. `output_failure` renders suppressed relationships in the existing
Failure body, and `into_vendor` preserves cancellation scope/variant and other
vendor classifications at the core bridge. This is the proposed 5.2 adapter
contract to acknowledge when that WP is implemented/reviewed; core Failure is
unchanged. Provisioner finally errors replace prior errors as Kotlin does.

`PlanCalculator` extracts the shared provider calculation/shutdown boundary from
AppleSimulatorProvider.kt:683–774, not ownership of the entire provider source.
It preserves ordered explicit targets, repeated profiles and first inventory
matches; shutdown is serial. Its final `CurrentDevices` callback runs after all
shutdown awaits. 5.5a/5.5b must provide the fresh registered-device eligibility
and Arc identity checks there, and supply only same-transport registered IDs
from the separate callback invoked after inventory returns and target
classification completes. They retain update/events, retry/recovery/admission
policy and actual connection/cycle timing emission. No partial provider, CLI
registration, parser registry or core DeviceEvent emission was added.

Timing uses the supplied wall Timer, separate message/suffix reads and the
jcompat Timings handle at INFO with debug disabled. The provider's cycle helper
accepts already-computed connection/planning durations and its provisioning-start
wall timestamp. Local transport's singleton identity shares a reserved internal
object token across services and uses the existing `config.Configuration.identities`
hook; create and cache clocks use the specified provisioning hook labels.

## Review round 1

All six R1 findings are addressed; no finding is waived.

- R1-claude-1: `PlanCalculator::plan` accepts a registered-UDID callback and invokes
  it after the inventory await and target classification. A registration performed
  inside the inventory command is excluded from profile reuse. The final
  eligibility callback remains after all shutdown awaits.
- R1-claude-2: classify targets and emit Host warnings first, then validate explicit
  simulator targets in a second pass. `[Simulator(missing), Host]` asserts WARN
  followed by ERROR and compares the Rust levels with the frozen JVM planner.
- R1-claude-3: restored exact transport-qualified registration IDs, uniqueness,
  four creates, and deletion of the literal `new-1` by command value. The context
  matrix row now drives production `refresh`, `inventory` and `simulator`, including
  `simulator("new").udid == "new"`; unavailable lookup asserts its exact error.
  A narrow injected `SimulatorCommands::create` matches the source's mocked
  simctl service and returns `new-1` in unit tests. Production defaults to the
  existing wrapper with its UDID parser and timeout; create-cancellation and A4
  tests explicitly use that production path. Delete always uses the wrapper.
- R1-claude-4: Rust results now directly consume every supplemental cache/facts,
  refresh, request-start age, cleanup/failure, suppression and factory timing
  witness. S3 witnesses also drive Rust rejection and absence of partial mutation.
  The runner extracts `plan`, `reuseExistingSimulator`, and identity/eligibility
  helpers verbatim from frozen AppleSimulatorProvider.kt into a field-only JVM
  shell. New rows cover reuse order, WARN/ERROR order and serial start/end shutdown
  events. This tests the extracted production methods, not full provider lifecycle
  integration. Both cleanup probes use one permit to compare per-operation order

- R1-claude-5: factory/constructor/creating/provisioner/registration preserve generic
