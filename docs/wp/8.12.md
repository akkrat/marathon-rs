# WP 8.12: Plain async reads instead of the Apple polling reader

Effort **M**. Branch `wp/8.12-apple-async-reads`, based on `main` after WP 8.11 (commit `816e0000`).

## Why

Apple command output (local processes and SSH channels) is read by
`crates/marathon-apple/src/extensions/reader.rs` `produce_lines_manually`, a port of Kotlin's
`Reader.kt`: it polls the stream once per backoff tick (`extensions/poll_backoff.rs`), never blocks on a
read, checks an idle timeout by wall-clock arithmetic that includes the backoff maximum, and stops only
when `can_read()` (the process is alive) turns false, because Kotlin never reads at `available() == 0`,
not even at EOF. Callers: `cmd/local/kotlin_process_command_executor.rs`,
`cmd/remote/ssh/sshj/{channel,executor}.rs`. Tokio can wait on the read, the idle deadline and the end of
the process at once, without polling.

## Scope

Replace the polling loop with an async loop that `select!`s on: the next read, the idle deadline (reset on
each read; on the vendor clock, not a backoff tick), the process or channel ending (a future or watch
signal instead of the `can_read` closure), and cancellation. Delete `PollBackoff` if nothing else uses it.

Keep these behaviours (find the tests that pin each; they keep their expectations unless listed below):

- Lines are delivered in order, whole, with the same `LineBuffer` splitting and the tail drained at the
  end (A24: on an idle timeout the channel closes with the timeout before the tail drain, which the closed
  channel rejects).
- D19/U145: output that arrives together with the end of the process is still read.
- The idle timeout fails the command with the same error kind and message; cancellation cancels the
  channel; a closed output channel stops reading.
- No blocking on the core executor thread; replay and virtual-clock tests keep working (the reader reads
  time through the replay seam `apple.Reader.currentTimeMillis` today; the new deadline must be driven by
  the same vendor clock so scripted tests stay deterministic).

## Allowed changes (decide at the design stop, each needs a D-row if it is visible)

- **EOF while the process lives.** Today a stream that hits EOF while the process is still alive keeps
  being polled until the process ends; an async read returns EOF at once. Propose what to do (end reading
  at EOF, or keep the channel open until the process ends) and what is visible either way (when the
  command's output channel closes, ordering against the exit code).
- **Idle timeout arithmetic.** Today the timeout effectively adds the backoff maximum to the configured
  idle limit. Propose whether to keep that extra margin or use the configured value exactly.
- Fewer clock reads and no backoff ticks change replay tapes' call counts: say which tapes or scripted
  tests depend on the number or order of `currentTimeMillis` reads, and how they are kept (copied tapes
  stay unedited; the code stops reading retired keys, as 8.5 did).
