## Goal

Provide a small idiomatic wrapper over pinned `regex` 1.x. The abandoned Java
translator and spike are superseded by D6. Branch `wp/1.4-regex-crate` starts at
`ef8d755`; all work stays in `.claude/worktrees/wp-1.4b`.

User-facing note: regex syntax is Rust's `regex` crate; Java-only constructs are
rejected at load. There is no lookaround or backreference support (nor Java
quoting or atomic groups); possessive quantifier semantics are unavailable.
Some Java-looking syntax can parse with a different meaning: `a*+a` is nested
repetition in Rust, not a possessive quantifier. `\d`, `\w`, `\s` are Unicode
by default; use ASCII classes when required. `(?i)` enables Unicode case folding;
scoped flags use `(?i:...)` and `(?-i:...)`. Java's `(?U)` does not mean the same
thing in Rust (Rust uses it to swap greediness). Empty matches never fall inside a surrogate pair. See the crate syntax reference:
<https://docs.rs/regex/1.13.1/regex/#syntax>.

## Deliverables and acceptance

- `jcompat::JavaRegex` retains the source pattern for Display/serialization and
  reports compilation errors with field, pattern and crate diagnostic.
- Full `matches`, unanchored `contains`/`find`, Kotlin continuation in `find_all`,
  split with zero retaining trailing empties and positive limits, and Kotlin
  replacement expansion. No runtime budgets or abort machinery.
- Fixed marathon patterns as constants, preserving ASCII Java classes and line
  terminators; rewrite the default Apple negative lookahead as code.
- Unit tests and selected shared-syntax JVM rows for match operations; fixed
  patterns checked on representative inputs and existing Apple log fixtures.
- Review parity rows for Java-only syntax. No rows currently belong to WP 1.4;
  full filter/parser tests remain with their owning WPs. Java-dependent cases
  are marked n/a with D6 reason for reviewer agreement.
- Run `scripts/check.sh`; focused commits, no push or merge.
