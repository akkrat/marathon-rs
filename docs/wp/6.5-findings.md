# WP 6.5 findings

Implementation on `wp/6.5-android-provider`, based on `a039e70`. Kotlin reference is
`e47352f2`; no reference files, real adb servers, devices, emulators or remote hosts
were modified or used. All Android traffic went to loopback fake servers. The
start-server test uses a temporary executable under a temporary SDK.

## Delivered and consumer seams

`marathon-android` now supplies the multi-server provider, state tracker, device
setup/prepare/dispose, Android API, installer, bundles/identifier, recorder commands,
getprop/logcat adapters and vendor factory. `marathon-cli::runner::missing_vendors`
now fills the Android slot with that factory (the other slots retain their old
behavior). All logger calls use the shared run output queue and jcompat rendering.

6.6a implements `AndroidBatchExecutor` and supplies it through
`services::create_services_with_executor`. The pending executor returns
`java.lang.UnsupportedOperationException`. Rejections are translated to
`DeviceLost` only at the execution boundary, preserving causal chains. The remote
parser is an explicit unsupported slot until 6.6a. `AdamDeviceProvider::android_device`
resolves a core `DeviceRef` back to the typed Android API without downcasting or
changing the frozen core `Device` trait. `execute_test_request<R>` accepts an adam
channel request; the runner owns its batch/output clocks and stream consumption.

6.6b reads `device.runtime().file_sync`, uses the typed device's shell/transfer/
recording/screenshot methods and attaches the existing line/logcat listeners.
Transfer requests retain and close the merged ADB crate's file-completion handles
on success, error and cancellation. Core-facing device calls use the vendor bridge;
blocking APK/hash/file/process work stays off core. No new executor or adb protocol
implementation was introduced.

## Decisions P1–P7

- P1: Tokio vendor tasks replace Kotlin's configured thread pools. The
  `bootWaitingThreads` and `installThreads` values remain accepted/serialized but
  do not size pools or reject zero; recorded as D14.
- P2: keep the inverted API-21 check (N25). Plain application APKs below 21 fail;
  split APKs are not rejected by that check.
- P3: effective file-sync entries are computed once in `AndroidRuntime`, in
  insertion order with set deduplication. Allure and coverage augment this set,
  not the immutable configuration. Source reads are in `createExecutionListeners`
  and `AndroidDeviceTestRunner`, both after setup; both consumers must use the
  runtime set. This removes the unsynchronized configuration mutation (D14).
- P4: retain partial logcat lines across chunks, including split CRLF. UTF-8
  decoding remains the merged adb client's D11 behavior. D11 is extended; N28
  records the intentionally corrected Kotlin chunk splitting.
- P5a: failed reverse removal is logged rather than aborting the provider loop;
  dispose is joinable/idempotent. Keep disconnected map entries and adb-serial-only
  keys under D5, as recommended; N27 and tests pin those quirks. All created
  setups/logcat tasks remain owned for shutdown even after a map collision.
- P6: seven n/a rows have the exact approved reason `marathon never uses this option`:
  DiscoverAdbSocketInteractor's two rows; AsyncLogcatRequest's buffers, three since
  variants, and filterspec rows. Reviewer agreement is still required at review.
  Both used logcat rows and both getprop rows are ported.
- P7: omit dead AdbStartException, InvalidSerialConfiguration and isEmulator.
  Inventory entries remain; these have no callers. isLocalEmulator is implemented.

The four VideoConfigurationTest invocation rows move to 6.5. The generator records
listener construction and the remote-parser slot as 6.6a/6.6b portions of otherwise
6.5-owned files: the inventory format has one row per source file, not per method.

The installer uses an equivalent three-attempt loop rather than
`with_retry_send`: that helper races and drops its body on cancellation, which
would drop the transfer's explicit asynchronous file cleanup. Each attempt here
observes the same cancellation and scheduler delays and joins cleanup first.

## Kotlin-first evidence

`tools/oracle/android-provider-probes/run` compiles against the reference CLI's
read-only jars with Kotlin 1.9.24 and the Android Studio JDK. The committed
`fixtures/oracle/android-provider-probes.jsonl` pins AndroidVersion default, release,
preview and whitespace-codename behavior; IPv4, IPv6 and hostname address text;
per-chunk Kotlin lines; and the actual AdamDeviceProvider after track-devices EOF.
The probe keeps the fake listener available: the job completes cancelled after one
subscription and never reconnects. N16's earlier claim that the provider restarts
was incorrect and is corrected in the bug inventory.

`tools/oracle/android-provider-probes/scenarios` launches the strict fake-adb
executable, then the actual Kotlin AdamDeviceProvider/AdamAndroidDevice/installer:

- `fixtures/fake-adb/android-install-matrix`: two devices, one legacy and one CMD;
  installed-package uninstall, `-g`, `-custom`, legacy SEND mode 511, md5, install,
  removal and prepare wipe/mkdir/logcat clear. Kotlin pins streaming argument
  quoting/order, including `cmd package install '-g' '-custom' -r -S ...`.
- `fixtures/fake-adb/android-provider-multi-server`: two independent adbServers,
  two completed setups, then a disconnect on the first server. The Kotlin row
  confirms `healthy=false` while `networkState=CONNECTED` (N29).

Each scenario contains the server script, Kotlin log rows and raw wire transcript.
The Rust differential tests compare every request service in per-device order,
excluding independent logcat subscriptions and transport selection. Installation
mode/path is also checked. The existing `android-two-devices` Kotlin transcript is
compared through `logcat -c` preparation; instrumentation belongs to 6.6a. Strict
servers report zero warnings. No extension to fake-adb was necessary. The standalone
EOF probe uses a tiny Kotlin byte server so it can close only the tracking stream.

Reproduction:

```sh
export PATH=/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH
python3 tools/oracle/android-provider-probes/run > fixtures/oracle/android-provider-probes.jsonl
cargo build -p fake-adb
python3 tools/oracle/android-provider-probes/scenarios
cargo test -p marathon-android
scripts/check.sh > /tmp/mrs-6.5-check.log 2>&1; echo rc=$?
```

Existing APK/framebuffer resources are reused unchanged. New files are authored
scripts and generated observations; provenance is in `fixtures/PROVENANCE.md`.
