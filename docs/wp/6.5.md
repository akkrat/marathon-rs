## Behaviours to reproduce (with sources)

**Provider start** (`AdamDeviceProvider.kt`):
- Clients built in config order with `InetAddress.getByName(host)` (keep the name for Java's `name/ip` text, 6.1 R1-wonder-3) and filtered by `isConnectable` (`:71-107`): `host:version` (debug log `Android Debug Bridge <host>:<port>: version <n>`, `:194-197`); on `ConnectException` only, and only if `host.isLoopbackAddress`, run start-server then retry once; other errors propagate out of `initialize`. Unreachable → `logger.error "adb server <host>:<port> is unavailable"`; none left → `NoDevicesException("All adb servers are unavailable")` (`:109-111`).
- start-server (`AdbBinaryInteractor.kt:31-65`): binary = `androidSdk/platform-tools/adb`, else `$ANDROID_HOME`/`$ANDROID_SDK_ROOT`, else first line of `which adb`; not a file → false; argv `<abs adb> -P <port> start-server` with **inherited stdio** (adb's own "daemon started" text reaches marathon's stdout/stderr), polled every 16 ms, success iff exit 0. Off core (`spawn_blocking`/async process), no `unwrap` on process results.
- Device wait (`:113-117`): poll `host:devices` on every client every 500 ms (`DEFAULT_WAIT_FOR_DEVICES_SLEEP_TIME`, `:42`) until the union is non-empty — any state counts, not only `device` — under `waitForDevicesTimeoutMillis`; expiry → `NoDevicesException("No devices found")`.
- The loop (`:119-182`): one merged stream of `(client, devices)` from `host:track-devices` on every client; `MultiServerDeviceStateTracker.update` per item; CONNECTED → construct device, `trackProviderDevicePreparing` around **only the launch** of `setup()` + `DeviceConnected` (so the provider-init timing is ≈0 and carries the pre-boot serial `<ip>:<port>:<adbSerial>`), store `devices[serial]`; DISCONNECTED → cancel-and-join an active setup, send `DeviceDisconnected`, `dispose()`; debug log `Device <serial> changed state to <state>`. The `while (isActive)` restart "survives `adb kill-server`" only if a failed stream ends the `for` loop rather than the job — see open question 4.
- Tracker (`DeviceStateTracker.kt:24-74`): updates are emitted vanished-first, then in list order; a vanished serial is removed and reported only if its last state was `device`; non-`device` → `device` is CONNECTED, `device` → other is DISCONNECTED, a new non-`device` serial is NOTHING_TO_DO but remembered. Per-server trackers keyed `"$host:$port"` (`:18`).
- `borrow` (`:185-192`): poll every 200 ms for a device whose setup completed and was not cancelled/failed, then `random()` — a nondeterminism site (check `docs/design/nondeterminism-sites.csv`). `terminate` (`:199-211`): cancel setups and the loop, close the channel, cancel the merged stream, close logcat and the socket factory (N19 consequences for late requests).

**Device setup** (`BaseAndroidDevice.kt:83-135`, `AdamAndroidDevice.kt:113-122`), order pinned by the Kotlin transcript:
- `booted=false`; under `timeoutConfiguration.boot`, re-fetch all props (`getprop`) every 1 s until `sys.boot_completed` exists (any value) (`:220-226`); expiry → `DeviceSetupException("Unable to configure device <serial>: not booted")` with the pre-boot serial.
- abi, `AndroidVersion(sdk.toInt(), codename)` only if both props exist, else `AndroidVersion.DEFAULT` (`:94-98`; a non-numeric sdk throws `NumberFormatException` out of setup); `apiLevel`, `OperatingSystem(apiStringWithoutExtension)`, model/manufacturer default `"Unknown"`. `AndroidVersion` comes from `com.android.tools:sdklib` (version in `buildSrc/.../Versions.kt`); port only `apiLevel`, codename (`"REL"` → none), `featureLevel`, `isGreaterOrEqualThan`, `apiStringWithoutExtension`, `DEFAULT`, with JVM-probed rows.
- Rotation from `dumpsys input` (`:344-360`): first `SurfaceOrientation` up to `\n`, split on `:` into exactly 2, `toIntOrNull` → `Rotation.of`, else `ROTATION_0`.
- `echo $EXTERNAL_STORAGE` via the **safe** wrapper, trimmed of `\n`/`\r` only; null → `DeviceSetupException("Unable to configure device <serial>: externalStorageMount")` (`:103-110`).
- Features (`:179-191`): VIDEO iff API ≥ 19 and `ls /system/bin/screenrecord` exits 0; SCREENSHOT iff API ≥ 16 (`JELLY_BEAN`).
- Serial (`:158-177`, `AdamAndroidDevice.kt:105-111`): `<hostAddress>:<port>:<strategy value>`; AUTOMATIC = first non-empty of `marathon.serialno`, adb serial, `ro.boot.serialno`, `net.hostname`, random UUID (the adb serial is never empty, so the last three are unreachable); MARATHON_PROPERTY / BOOT_PROPERTY / HOSTNAME may yield `""` (`InvalidSerialConfiguration` is never thrown); DDMS = adb serial. `serialNumber` is the pre-boot form until `booted`.
- md5 binary (`:337-342`): `ls /system/bin/md5`, then `md5sum`; first exit-0 gives `md5`/`md5sum`, else `""`.
- Then `fetchProps()` again, `host-serial:<s>:features`, logcat subscription, and test access (`AdamAndroidDevice.kt:532-548`): if `testAccessConfiguration.adb` and the serial does not start with `emulator-`, reverse `tcp:<port>` → `tcp:<port>` under `timeoutConfiguration.portForward` (`withTimeout`, so expiry fails setup), remembered for dispose.
- File-sync mutation (`:116-134`): allure enabled → add `FileSyncEntry(relativeResultsDirectory, allure pathRoot, TEST_RUN)`; coverage → add `FileSyncEntry("coverage", APP_DATA, POOL)` to the **shared, mutable** config set (see P3).
- `networkState` is computed once at construction (always CONNECTED, `:453`); `healthy` reads the tracker live (`:455-459`).

**Shell wrappers** (`AdamAndroidDevice.kt:132-156`): `executeShellCommand` (no timeout; any `Exception` → logged `errorMessage`, null); `safeExecuteShellCommand` (`timeoutConfiguration.shell`; timeout → null, exception → logged, null); `criticalExecuteShellCommand` (timeout → `CommandRejectedException(errorMessage)`, exceptions propagate; a non-zero exit is **not** an error). All use shell v1 `shell:<cmd>;echo x$?` (6.1).

**Prepare** (`AdamAndroidDevice.kt:490-504`, inside `trackDevicePreparing` with the post-boot serial): installer → `rm -r <EXTERNAL_STORAGE>` (N4) → `mkdir <EXTERNAL_STORAGE>` (both critical) → `logcat -c` (safe). Core retries prepare 30× with 10 s delay (`lifecycle.md`), so installer failures multiply (3 × 30 attempts).

Params (`:120-129`): `-g` iff API ≥ 23 and `autoGrantPermission`, then `installOptions.split(" ")`. Appops (`:60-75`): `mockLocation` and API ≥ 23 → `appops set <p> android:mock_location allow` (critical), non-zero → `appops query-op …` and an error log; API < 23 → warn.
- Install branches (`AdamAndroidDevice.kt:306-381`): `ABB_EXEC` or `CMD` feature → streaming (blank params dropped; timeout → `InstallException("Timeout installing <path>")`; exit 0/1 from success); else legacy: push to `/data/local/tmp/<escape(name)>` with verify under `pushFile` timeout (N5's poll is bounded only by this), `pm install -r [params] <remote>` under `install` timeout, `rm <remote>` (safe), output trimmed. Split: forced `listOf(Feature.CMD)`, raw params (empty strings kept), timeout message literally `"Timeout transferring absolutePath"`.

**Transfers and the rest** (`AdamAndroidDevice.kt:158-298,383-451,506-530`), used by 6.6a/b and legacy install: stat-then-pull with the three `TransferException` texts and the `progress != 1.0` check; zero-size → create local file; push mode `0777` with md5 verify (`waitForRemoteFileSync`, `BaseAndroidDevice.kt:199-214`: poll `<md5cmd> <path>` every 10 ms until the output contains the hash; empty md5cmd → warn); breadth-first `pullFolder` with per-listing/per-pull timeouts that warn and continue (`split('\\')` quirk, `:266`); `pushFolder` timeout → warn; screenshot timeout → null, unsupported protocol → warn + null; screen recorder under `screenrecorder` timeout, API ≥ 34 lifts the 180 s cap (`ConfigurationExtensions.kt:9-49`); `getProperty(cached)`; logcat bridge line format `"<timestamp> <pid>-<tid>/<appName> <letter>/<tag>: <message>"` (`:520-524`); dispose = stop dispatcher, unsubscribe logcat, remove each reverse rule (a failure escapes dispose).

## Proposed simplifications (pragmatic parity — for orchestrator approval, **not decided**)

Until approved, the behaviours above are binding.

- **P1, thread pools:** do not emulate `bootWaitingThreads`, `installThreads`, the 2-thread per-device and 4-thread logcat dispatchers. Tokio tasks off core; behaviour is unobservable except in exotic contention (0 threads would throw in Kotlin at construction). Record the two fields like F5.
- **P2, the API-21 check:** fix the inversion (reject *split* installs below 21, allow plain installs) — or keep it. Only devices below Android 5 notice; recommend **keep** (it is the simpler port and no user has such devices), listed so the decision is explicit.
- **P3, file-sync mutation:** `Configuration` is an immutable `Arc`. Compute the effective pull set once (user entries, then allure, then coverage, deduplicated as a set) in a provider-owned Android runtime context that devices and 6.6b read, instead of mutating config per device setup. Diverges only if something reads the pull set before the first device finished setup (nothing does at `e47352f2`; verify) and removes Kotlin's unsynchronised `LinkedHashSet` mutation race. `BaseAndroidDeviceTest` then asserts the effective set.
- **P4, logcat line splitting:** keep a partial line across chunks instead of `lines()` per chunk (D11 already decodes UTF-8 across reads). Only long or fast logcat output split mid-line differs, and only in the device log text.
- **P5, dispose and disconnect robustness:** a failed reverse-forward removal during `dispose` is logged, not propagated (in Kotlin it can kill the provider loop when `testAccessConfiguration.adb` is on), and the provider forgets a disconnected device. Recommend P5a (dispose) only; the `devices` map bugs stay under D5 unless a scenario shows harm.
- **P6, unused adam APIs:** `DiscoverAdbSocketInteractor` is never called by marathon (ports always come from `adbServers`); set its 2 rows `n/a`. Port only the logcat options marathon uses (`-v long`) and set 5 of the 7 `AsyncLogcatRequestTest` rows (`testBuffers`, three `since` variants, `testFilterspec`) `n/a`, or port the whole builder if the implementer finds it cheaper — it is ~20 lines.
- **P7, dead code:** do not port `AdbStartException`, `InvalidSerialConfiguration`, `BaseAndroidDevice.isEmulator` (`:230-234`) — no callers. Inventory rows stay (they share files), noted in findings.

## Open questions for the orchestrator

1. **Start point:** 6.5 needs 3.10's `VendorFactories`. Start after 3.10 merges (recommended), or start the provider/device/installer now and wire the factory in a last commit after rebasing?
2. **The `execute` seam with 6.6a:** 6.6a depends on 6.5, yet `Device::execute` and `createExecutionListeners` live in this WP's files. The 7 adam `AsyncLogcatRequestTest`/`GetPropRequestTest`/interactor rows stay here. No other row looks misassigned.
4. **Does "survive kill-server" work in Kotlin?** With N16, the merged `produce` fails and the `for` loop should rethrow, ending `providerJob` (logged by its handler) rather than restarting; if it does restart, a down server gives a hot reconnect loop with no delay. 5. **`identify` failure shape:** Kotlin throws `ConfigurationException("Invalid test <name>: can't locate test bundle")`; the frozen trait returns `VendorResult<Option<BundleRef>>`. Return `Err` with that class and message (recommended, matches 3.x callers) or `Ok(None)`?
