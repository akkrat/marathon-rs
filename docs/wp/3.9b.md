## Deliverables and boundary

In `crates/marathon-core`, implement six `report::Reporter`s: DeviceInfo, Billing, JUnit, Raw, TestJson and Stdout. `Reporter::generate(&ExecutionReport) -> ServiceFuture<'_, ()>` is 3.9a's async/fallible interface; consume its immutable event accessors and `summary()`, `PoolSummary.tests/retries` and ordered counts. Do not recompute aggregation, deduplicate finals or replace identity-aware retry associations with Test-keyed maps.

1. **Explicit projections and writers.** Share projections for frozen Test/MetaProperty/MetaValue/DecodedWrapper, DeviceInfo/OperatingSystem/DevicePoolId, Attachment and TestResult. Gson uses `WriterValue` + compact `GsonWriter`; raw metadata uses Kotlin rendering, not that JSON projection. Keep Java UTF-16 until `JavaString::to_utf8_bytes()`. No serde/Debug external serialization or second value tree. Expose reusable projection helpers to 3.9c where appropriate; Allure's Jackson model remains separate.
2. **JUnit.** Port its model/serializer surface and reporter selection, with exact StAX bytes rather than a pretty XML approximation. Reuse `jnum::double_to_string`, `formatting::format_date(_, DatePattern::Junit)` and Test's class-name formatter. Optional/dead serializer branches are subject to P1/P2 below, not silently discarded.
3. **P3 parse-results emission.** Supply a pure projection/emission entry point over `&[Test]` and `&[Test]`, returning `JavaString` through `JacksonYamlWriter`. The proposed split leaves concrete `wiring::ParseOutput` implementation, log/file routing and command execution to 3.10 (Q1). Config remains dependent only on jcompat; no core-model dependency may be added there. Do not replace `render::serialize(Configuration)` or its existing 2.4 round-trip tests.
4. **Construction handoff.** Provide constructors taking the run's output directory/files, runtime, timer, labelled wall/identity hooks and existing logger/output services as needed, and document registration in `3.9b-findings.md`. Supply `ReporterRegistration`s for slots **DeviceInfo, Billing, JUnit, Raw, TestJson, Stdout**; 3.9c fills Timeline, Allure, Html. 3.10 builds the concrete graph. Preserve full order **DeviceInfo → Billing → JUnit → Timeline → Raw → TestJson → Allure → Html → Stdout** and C11's first-error stop, including prevented remote close.

Consume frozen `OutputFiles`/`FileTarget` via 3.9a's `FileManagerOutput` for ordinary JSON paths. JUnit deliberately bypasses FileManager: it uses the raw pool path and fixed report filename. Consume `Timer` for total stdout time; use `WallClock`/`ReplayHooks` for billing/identity, not a new clock. Stdout goes through the shared `ConsoleSink`/raw output path; logger messages retain source logger names and registry levels. 3.9a already dispatches report generation once to the I/O runtime: avoid redundant per-reporter hops. Synchronous file/XML work and blocking sinks use the runtime's joined blocking pool; never block core. Keep `OperationError` versus `VendorError` adapters and typed cancellation, and preserve partial side effects on error. No I/O unwrap/expect, unowned tasks or report-on-Drop.

**Outside this WP:** event capture/summary/retry algorithms, factory policy, FileManager escaping/truncation (3.9a/1.7); HTML/timeline/Allure/media (3.9c); run finish guard, output wipe, CLI exits, parse selection/include-flaky policy, parse log/file routing and successful-parse cleanup bug (3.10/2.5); annotation discovery (6.4) and backend protocols (3.4b). D1 makes Billing's usage-tracker calls no-ops; do not recreate telemetry or an unused usage event hierarchy.

## Behaviours to reproduce

References expand against `K/`; these are source requirements pending JVM confirmation, not inferred golden bytes.

- **Device JSON:** `report/device/DeviceInfoJsonReporter.kt:13–18` writes every connected event in supplied order, including repeat connections; later writes overwrite the same path. It does not use summary.devices or disconnects. FileType.DEVICE_INFO yields `devices/<pool>/<safeSerial>.json` through existing rules. Device fields are the seven constructor fields in `device/DeviceInfo.kt:5–14`, with nested OS `{version}`; omit `safeSerialNumber$delegate` everywhere (D3), not `healthy` or features.
- **Billing:** `report/bill/BillingReporter.kt:21,24–56` captures `defaultStart` at construction, independently of Timer. Serial-only maps take the **last connected** device and pool, even across pools, keeping first key position. Start is the earliest **finish** of device preparation; provider preparation/disconnection are ignored. End is the largest test-event **instant**, including non-final/ignored/incomplete events, not TestResult.endTime. Iterate ordered union of starts/ends; no end means no bill. A missing start uses defaultStart; missing connected info/pool warns exactly `Failure to process device bill: missing timeline event` and omits that bill.
