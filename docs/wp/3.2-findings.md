## Implementation and seams

All six strategy families are enums constructed through `from_config`.
`strategy/mod.rs` defines synchronous, infallible `MetricsLookup` and the
`MetricsKey` declarations consumed by the later prefetch adapter. Key equality
uses Java Double semantics for NaNs and signed zero, matching Kotlin
MetricsProviderImpl.MeasurementKey for prefetch deduplication.
`RetryProgress::retry_test` returns `Option<TestAction>`; `None` does not mean
complete. `TestAction::Complete` and the Test name helpers landed in the
existing model commit. Java `Double.compare` lives in jcompat, with signed-zero,
infinity and canonical-NaN tests; comparator fixtures also cover those values.

Sorting returns a Send `FnMut` comparator for the concrete JavaPriorityQueue.
ExecutionTime memoisation is fresh per process call and survives re-queue;
reversed comparators extract the second argument's key first. SuccessRate
performs every Kotlin lookup. RandomOrder shares one key cache across the
strategy's comparators, draws the first argument first, and uses key 0 after
a hook failure; the hooks retain that failure for `verify_consumed`. Its
`try_lock` enforces serial access without blocking the core executor. Queue
ownership is serial as in the lifecycle contract; concurrently invoking two
comparators from one strategy violates that invariant.

Batching retains heap-array iteration, JDK bulk removal, insertion-order set
membership, last-mile polling, and every unbatchable poll's slot and duration.
A null bundle leaves the batch unlocked. Bundle identification and id-hook
errors propagate. Empty queues return `BatchingError::EmptyQueue`, an approved
unreachable-path choice: QueueActor checks emptiness before batching. Batch
ids are allocated only after the final queue operation.

Flakiness replaces the shard's flaky list in shard order. Retry preserves the
record / count-plus-flaky / retryPossible / AddRetry / requestRetry sequence,
short circuiting, per-instance watchdog state and Java wrapping Int arithmetic.
No production metrics provider, progress FSM or actor was introduced here.

## Approved decisions and differences

The final Orchestrator decisions in `3.2.md` override the earlier proposals.

- **P1:** omit strategy equals/hashCode/toString. Rechecked every strategy
  instance use at the frozen source: Scheduler only calls pooling associate;
  Marathon only creates shards/processes flakiness; QueueActor only builds
  comparators and calls batching/retry. RetryWatchdog comparison/hash/printing
  is reachable only from FixedQuota's own omitted object methods. No production
  code observes these methods. C31/C32 record the unreachable source bugs.
- **P2:** declare each strategy's history keys; fetch once per declared key
  per pool at queue construction, off core. WP 3.4a supplies both the frozen
  async MetricsProvider and in-memory synchronous view; WP 3.7 awaits prefetch
  before constructing/populating its queue. Queue operations then stay on
  core. This supersedes 0.6 D4 for queue construction and is recorded in its
  findings, lifecycle/model contracts, and PLAN §3.11 D13. Query/TimingLog
  moves earlier; a queue that never compares gains the history query and timing
  line Kotlin skips. Per-test warn-once lookup order remains lazy. Outside
  queue construction the source first-touch boundary remains. Actual provider
  query/log integration and verification belong to 3.4a/3.7.
- **P3:** batching takes JavaPriorityQueue only. The six LinkedList Kotlin
  tests retain their assertions over a NoSorting heap. This is not a FIFO
  promise: the separate heap-order test pins the non-FIFO poll sequence.
- **Replay exhaustion:** key 0, no random fallback, with a failing end-of-run
  replay check. A rule test pins this approved choice.
- **Parity ownership:** four “without history” tests moved to 3.4a and the
  terminal-state retry test to 3.7. Five other retry rows use a fresh-Added
  accumulator stand-in returning None. The real FSM also increments totals;
  that side effect does not change those five tests' returned retry lists.
- ConfigurationExtensions belongs to 3.2, with toTestFilter reserved for 3.3;
  TestAction belongs to 3.2. Generated inventory notes Test.kt's name helpers.

No additional external-interface differences were taken. P1 is an omission
of unobservable methods; P3 changes only the Kotlin test container.

## Known Kotlin bugs

- **C5:** confirmed and reproduced call sequence; at quota zero AddRetry runs,
  then requestRetry refuses. The real total+1 is in JVM evidence; its full Rust
  FSM assertion remains 3.5/3.7's responsibility.
- **C8:** confirmed and reproduced with a zero-rate stub; real NoOp integration
  remains 3.4a's responsibility.
- **C29:** confirmed and reproduced squared running fail rate. The divergent
  0.1/0.8 case adds four copies instead of fifteen under base multiplication.
- **C30:** confirmed and reproduced separate per-pool watchdog quotas; two
  independently built strategies each spend the configured total.
- **C31/C32:** source-confirmed CountSharding self-comparison and RetryWatchdog
  identity hash, omitted under approved P1 because production cannot observe
  them. These rows explicitly say they are not reproduced.

FixedSize's slot/duration accounting for rejected polls and null-bundle
non-locking are reproduced with rule tests and JVM rows. Review round 1
classified them:

- **Rejected polls** (a duplicate flaky or sharding copy, or a test from another
  bundle) use up a `size` slot and add their expected duration: a Kotlin bug,
  reachable in production, kept as **C33** (e.g. queue A₁ A₂ B C with size 3
  gives batch [A, B]; durations A=3000, B=1000 with limit 6000 give [A]).
- **Polls consuming size slots** in general: design ("dequeued for at most size
  tests").
- **A null bundle not locking the batch:** design, and unobservable: every
  production `TestBundleIdentifier` throws `ConfigurationException` instead of
  returning null.
