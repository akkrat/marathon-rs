## Behaviour to reproduce (Kotlin source addresses)

- **Generation:** `G/Xcresulttool.kt:35–47,66–72` finds the named schema and regenerates output; do not reproduce destructive cleanup outside a generator-owned output location. `G/XcresulttoolSourceCreator.kt:39–45` recognises object/value/array kinds and rejects unknown kinds; only objects become classes (`:50–86`). `:99–126` resolves superclass and unwrapped property dependencies, recognising WKT, artificial `Reference` and self-loops; unresolved dependencies fail after the iteration (`:88–96`). Do not silently omit a type. `Reference` actually has an object definition in the pinned schema and must be emitted.
- **Fields/inheritance:** `G/XcresulttoolSourceCreator.kt:25–26,55–75` removes `SchemaSerializable`-typed and internal properties, then appends superclass fields after a type's own fields. `:64–68` preserves original JSON property names. Flatten inheritance; `_type`/`_supertype` metadata does **not** create runtime subtype dispatch (mapper ignores unknown keys). Binding as a base type must not require subtype-only fields.
- **Type mapping:** `G/xcresulttool/Property.kt:18–41,45–54` unwraps optional types and arrays via `wrappedType`; arrays become lists, optional properties become nullable. WKT are `Date`, `Double`, `Int`, `String`, `Bool`: retain i32 integer width, f64 and Date's millisecond semantics. Do not substitute numeric epoch seconds for Date or convert a missing value into an empty nested object.
- **Constructor defaults:** `G/XcresulttoolSourceCreator.kt:131–165` gives non-null lists `emptyList()`, non-null Int/Double/Bool/String `0`/`0.0`/`false`/`""`; other non-null objects and Dates have no default. Nullable properties have no generated constructor default; Jackson/Kotlin supplies their missing/null behaviour. Preserve missing vs null vs empty wrapper, and probe nullable-list precedence rather than inferring it from Rust `Option<Vec<_>>`.
- **Apple mapper differs from config:** `B/bin/xcrun/xcresulttool/Xcresulttool.kt:33–46` enables `NullToEmptyCollection`, `NullIsSameAsDefault`, `SingletonSupport`; disables `NullToEmptyMap`, `StrictNullChecks`, `FAIL_ON_UNKNOWN_PROPERTIES`. It registers `AppleModule`, **not JavaTimeModule**. Unknown fields, including `_type`, are ignored recursively. Check missing/explicit-null defaults on generated classes and collection elements against this exact mapper; P1's null rules and D9 are not interchangeable with it.
- **Scalars:** `B/bin/xcrun/xcresulttool/AppleJsonTypeAdapterFactory.kt:31–53,75–84` wraps String, Date, primitive/boxed Double, Int and Boolean. A non-null scalar consumes the object's `_value`, then invokes its ordinary Jackson deserializer; `_type` is not validated. This is type-directed unwrapping, not global recursive JSON rewriting: arbitrary objects with `_value` are not all scalars. A bare scalar or missing `_value` hits `value!!`; explicit JSON null may bypass this adapter. Pin the error/cause and null/default boundary with the oracle before representing it.
- **Lists:** same file `:57–70,87–96` installs the adapter for applicable List deserializers. Absent `_values`, a non-array `_values`, or a non-object list wrapper returns an empty list. An actual `_values` array preserves order/duplicates and decodes each entry as its declared element class. Null property/list-element handling and the element parser's initial-token behaviour need oracle cases. Do not silently filter malformed entries.
- **Dates and coercions:** scalar conversion delegates to Jackson (`AppleJsonTypeAdapterFactory.kt:81–83`); Date uses its ordinary mapper parser, including offsets/numeric milliseconds, rather than P1 `Instant` rules. Measure accepted fixture date forms, precision and failure behaviour; reuse/extend `jcompat` for the necessary Java semantics. Ordinary numeric/string/bool coercions need small table probes, not assumptions that serde defaults agree.
- **Caller control flow:** `B/bin/xcrun/xcresulttool/Xcresulttool.kt:90–97` trims output, skips blank, catches only `JsonProcessingException` and returns null after warning. The decoder must let 4.4 distinguish successful JSON null, malformed/truncated JSON, mapping failure and any unchecked adapter failure. The command wrapper owns those warnings. Keep external failure messages/URLs verbatim for `TestResultsListener.kt:119–148`; no name repair or trace normalisation here.

## Proposed simplifications (orchestrator approval, not decided)

Few users; avoid emulating quirks only exotic inputs reach. Until approved, the baseline above stands. Record any approval and affected oracle cases explicitly; do not silently apply D9 here.

- **P1 — malformed scalar wrappers:** return one structured JSON decode error for bare/missing-`_value` inputs instead of preserving an unchecked null-dereference category. This can make 4.4 warn/return null where Kotlin escapes its JSON catch; requires an observed witness and explicit approval. Keep valid wrappers and list fallback behaviour unchanged.
- **P2 — narrow scalar coercions:** support types/spellings emitted by the five real JSON fixtures and scripted world, plus normal numeric/bool strings; reject exotic Jackson coercions (non-ASCII numeric strings, overflowing conversions) with a clear decode error. Preserve i32/f64 widths and in-range values. Measure concrete differences before approval; no blanket serde substitution.
- **P3 — Date grammar:** support the ISO-8601 offset forms used by xcresult and integer epoch milliseconds; reject other Jackson Date grammars (e.g. RFC-1123), rather than porting an unused general Date parser. Preserve measured millisecond precision, offsets and normal errors. This narrows accepted input and needs approval even if current fixtures never reach it.
