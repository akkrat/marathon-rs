## Goal

A reusable SSH transport and filesystem harness for differential Apple tests: the Kotlin marathon (sshj), Rust (russh), and stock OpenSSH can drive the same fake worker. This WP is on the critical path to 0.4b. It supplies transport, routing, files, faults and transcripts; 0.4b supplies the simulator/macOS world, fixture output, media generation and whole-marathon validation. Fake tests do not replace §6.6 real end-to-end or §6.7 isolated shadow runs.

## Deliverables

1. **`tools/fake-worker/`**, a workspace package with a reusable library and standalone binary. Pin russh `=0.64.1`; document any vendoring/patches and preserve U1's client regression coverage if sharing that patch. Do not promote the spike executor into production.
   - Configurable loopback listener (including port 0), per-run disk root, script, transcript destination, host key, auth policy and concurrent-session limit; machine-readable readiness reports the bound endpoint and host-key fingerprint.
   - Password and public-key acceptance/rejection, unknown users, and keyboard-interactive `Password:` challenges (OpenSSH tries these before password in the spike). Use disposable fixture credentials and an explicit authorized-key set.
   - Count live session channels per connection; reject N+1 with a documented open-failure reason, reclaim slots on completion/close/disconnect, and keep accepted sessions usable.
   - Concurrent stdin/stdout/stderr with SSH flow control, client EOF, exit-status or exit-signal, server EOF/CLOSE, and TERM/KILL/custom signal requests. Answer env, PTY, shell, subsystem and forwarding requests explicitly; unsupported requests fail rather than hang.
   - Own and reap child processes/tasks on shutdown and connection loss, including fault modes; use async I/O and bounded queues. Keep the harness independent of unfinished 0.6 production interfaces, then document its lifecycle contract for that WP.

2. **Exec routing and a stable extension interface**, documented in `docs/design/fake-worker.md` with runnable scripts.
   - Preserve the raw exec bytes/string before parsing. Accept sshj's `shellCommand` quoting, including A12's malformed-quote failures; do not silently repair it. SSH env/workdir are absent in Kotlin; do not invent them.
   - Route exact/prefix/pattern expectations to delayed stdout/stderr chunks or fixture streams, exit status/signal, hang-until-signalled/ignored-TERM, or a filesystem operation. Unmatched commands produce a transcript warning and a configurable explicit failure.
   - Accept `sh -c` wrappers: the exact `WriteFile` script and `safeExecuteNohup`'s redirected background command plus PID-file write. Document nested-command/PID handling for 0.4b; never pass an unmapped command to a host shell.
   - Implement the file operations in `RemoteFileManager`: `mkdir -p`, `rm -rf`/`rm -R`, its `find … -mindepth 1 -maxdepth 1 … ! -name … -exec rm -rf {} +`, `cp -R`, `mv -f`, `ln -s`, `test -e`/`test -f`.
   - Let 0.4b register handlers for every §6.4 tool, including absolute executable names, without changing SSH code. Do not implement the Apple command world here.

3. **One virtual filesystem and resolver.** Map remote `/tmp/marathon` (including shared paths) into a fresh private directory per run; multiple connections in that run see the same files. Never use the host's real `/tmp/marathon`.
   - The same resolver serves argv path operands, nested shell paths/redirections, WriteFile destinations/temporary files, rsync operands, and path fields in xctestrun content consumed by 0.4b. Preserve virtual paths in transcripts and on the wire; do not blanket-replace opaque payload bytes.
   - Expose virtual read/write/stat/list/copy/rename/remove/symlink plus snapshot/reset and xctestrun path resolution to 0.4b. Define traversal/symlink handling so real child processes cannot escape the backing root; script other absolute worker paths rather than touching host state.
   - Recognize WriteFile's exact base64/size-check/rename/cleanup sequence (`WriteFile.kt:28–45`): byte-identical content, mode 0600, replacement, failed-write preservation and temporary-file cleanup. Retain the 32 KiB/plain-path client guard and debug-forced rsync fallback in real-client validation.

4. **Real rsync server processes and host argv shims.** Use real piped stdin/stdout/stderr for `rsync --server` and `--server --sender`; map the configured remote executable (normally `/usr/bin/rsync`) to an explicitly selected real binary and map only its remote filesystem operands.
   - Accept exactly the `RsyncFileBridge` contract: archive flags expanded to recursive/links/perms/times/group/owner/devices/specials plus `--delete`, `--partial`, `--partial-dir=.rsync-partial`, `--delay-updates`, `--rsync-path`, optional verbose, directory trailing slashes and receive's repeated links flag. T20 records openrsync's generated server argv (`--delete-before`, `--dirs`, etc.); test it rather than hard-coding Samba argv.
   - Preserve the exact `--rsh` string from `RsyncFileBridge.kt:110–154`: quoting, trailing space, `-F /dev/null`, StrictHostKeyChecking, truncated/disabled keep-alive options, key versus password, user/port and conditional `-vvv`.
   - Shims for `rsync`, `ssh`, `sshpass` record argv as unambiguous JSON arrays before execing configured, pinned real binaries; preserve binary streams, status and signals. Wire `RSYNC4J_RSYNC`, `RSYNC4J_SSHPASS` and controlled PATH; avoid recursive shim lookup and Mac-only binary paths.
   - After recording original argv, the ssh shim supplies isolated `UserKnownHostsFile`/`GlobalKnownHostsFile` and disables host-key updates. Every direct test invocation uses the same isolation: the fake key must never enter real known_hosts. Preserve original argv separately from harness-added options; normalize only documented fields such as debug `rsync --version`.
   - macOS uses Apple's `/usr/bin/rsync` (openrsync), matching real workers. On Linux build/use openrsync if practical; otherwise document the substitute/version, protocol and argv differences, and limitations. Samba-only evidence cannot certify macOS parity.

5. **Scriptable protocol faults**, using per-server/connection/channel controls where applicable, with observable triggers:
   - Withhold CLOSE for T15/T15h, including the child's CLOSE after TERM/exit (U6). russh auto-replies before `channel_close`; implement a narrow server hook/patch, or document a connection-stalling mode on a dedicated connection. In either design shutdown remains bounded and other connections progress.
   - Control keep-alive replies independently of channel traffic (answer/delay/withhold), including T25/R7 output flowing while probes go unanswered; the spike patch shows the automatic global-request reply path that must be controlled.
   - Reject exec (T23); send explicit disconnect reason/message before KEX, after auth and during exec (T24/T26); force no-common-algorithm KEX failure (T26). Cover reasons 12/2/11 and preserve the wire reason for U8's classifier tests.
   - Script unusual extended-data types, split/partial/late output, EOF/CLOSE ordering, abrupt transport loss and ignored signals, enabling the remaining WP 4.2 stream/cancellation/error tests. Distinguish request rejection from a command exiting nonzero.

6. **JSONL transcripts** with a documented schema: run/connection/channel IDs, ordered events, original exec and host argv, selected handler, auth method/result, session rejection, stdin/output bytes (or lossless artifact references), exit/signal, EOF/CLOSE, keep-alive and disconnect reason, virtual file paths/sizes/content hashes and final cleanup snapshot.
   - Retain raw evidence; normalize copies per field, preserving path/ID relationships (§6.4). Record completion/failure/timeout explicitly: skipped, missing or failed runs cannot compare equal (U7). Record partial output through close (U10).
   - Do not record real passwords/private keys; argv goldens use clearly labelled fixture credentials. Keep WriteFile payloads in controlled test artifacts, out of ordinary logs.

7. **Tests, validation runner and `docs/wp/0.4a-findings.md`.** State exact commands, versions, platform results, raw/normalized artifact locations and remaining limits. Include an **Incidental bugs** section per `docs/found-bugs.md` (where/version, behaviour, reproduction, handling, status/upstream report), even if none are new. Keep copied fixtures unchanged and record provenance for additions.
   - This is new harness code; Kotlin client/file-transfer ports remain in 4.1–4.3. Check the inventories and record the tests exercised here without claiming those later parity rows are ported.

## Acceptance

- An automated real-client matrix connects/authenticates with the Kotlin marathon's actual sshj executor/factory, stock OpenSSH and an R1-patched russh client; each runs exec, separates stdout/stderr, returns status, delivers TERM, reuses the connection, and produces asserted transcripts. Key/password rejection and keyboard-interactive are exercised explicitly.
- At limit N, N held sessions work, N+1 fails, then a released slot works on the same connection. Fault tests assert exec rejection, wire disconnect reasons/stages, failed KEX, non-1 extended data, ignored TERM and keep-alive suppression despite output; reuse T15/T15h and T23–T26 harness cases where practical. Hang tests use external deadlines, distinguish the first ~30 s close failure from the later join, and clean up without leaks.
- **Validation with real Kotlin code**, analogous to 0.5 part B at the transport boundary: a committed runner drives actual `SshjCommandExecutor`, `writeFile` and `RsyncFileBridge` from a disposable reference build/harness, not a reimplementation. It creates a virtual directory, writes/replaces an xctestrun, verifies its resolved path references, forces rsync fallback (oversize and `ssh.debug`), sends and receives through all three shims, then cleans up. Fix every uncovered harness gap; retain the scenario and transcript under `fixtures/fake-worker/`. Full simulator/macOS marathon runs remain 0.4b's gate.
- Real rsync roundtrips cover file/directory operands, nested binary files, symlinks, trailing slashes and deletion; assert byte/mode preservation as applicable and no effects outside the run root. On macOS both ends use openrsync; on the Linux box use openrsync or the documented substitute. Shims prove exact original argv/`--rsh`; known_hosts remains unchanged after success and failure.
- Build and run the server, deterministic self-tests and real-client/transfer smoke suite on this Mac and the Linux box; record results separately from the workspace gate. U4 remains unresolved: run/report sshpass attempts explicitly, preserve failures, and allow no silent retry-to-green. Document any proposed feeder/retry workaround and test its limits; do not claim U4 is solved by a successful login.
- `scripts/check.sh` passes; the orchestrator runs `scripts/remote-check.sh` before merge. Tests with missing external prerequisites report that fact; skipped interop/platform checks do not satisfy the acceptance above.
- `docs/design/fake-worker.md` freezes the CLI/readiness, script/router API, virtual-path/xctestrun resolver, transcript schema and lifecycle/fault controls that 0.4b builds on. 0.4b adds Apple handlers, media and bundle fixtures without rewriting transport or introducing another path map.
