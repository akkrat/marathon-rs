# WP 4.2 findings

SSH executor on the vendored russh client, in `crates/marathon-apple/src/cmd/remote/ssh/sshj/` (modules follow the
Kotlin files: `executor`, `factory`, `session`, `host`, `auth`, `config`; plus `client`, `channel`, `known_hosts`,
`keep_alive` and `error`, which port the sshj 0.39.0 behaviour those files rely on). The brief is `docs/wp/4.2.md`;
its orchestrator decisions (2026-10-24) and the real-host addendum were applied as written.

## Scope and decisions

- **Flow control (decision 1, option a).** Patch 3 of `vendor/russh` (`crates/marathon-apple/russh-manual-window.patch`,
  recorded in `vendor/russh/README.marathon.md`) adds `Config::manual_window_adjust` (default off, upstream wire
  behaviour unchanged) and `Handle::adjust_window`. The executor's per-channel pump drains russh's channel queue at
  once into per-stream byte buffers, so the session loop never waits on a consumer; the buffers are bounded by the
  receive window, which grows only as the readers consume, with sshj's `Window.Local` threshold
  (`min(maxPacketSize × 20, initialWinSize / 4)`). A stalled consumer therefore stops its own channel only.
  Tests: `ssh_session.rs::stalled_consumer_blocks_only_its_own_channel` (16 MiB unread on one channel while a second
  channel and keep-alive replies progress) and the vendored client tests `test_manual_window_grows_only_on_request`,
  `test_automatic_window_is_the_default`.
- **Errors (decision 2).** `error::SshFailure` carries the Java class, the sshj `DisconnectReason` (SSHException family
  only), the message, the cause chain and suppressed failures, plus `is_instance` over the measured class hierarchy
  and `is_io`. Connect failures stay `SshFailure` for 4.3; execute failures cross the 4.1/0.6 boundary as `Failure`
  (class, `getMessage()`, causes). 4.1's `safe_execute` now catches subclasses (`OpenFailException`).
- **Taxonomy (decision 3).** The classifier stays in 4.3; the measured table is below.
- **Suite (decision 5).** `ssh_executor.rs` runs 4.1's ten generic cases against the fake worker in the gate, with the
  commands scripted as fake rules (`support/ssh.rs::suite_script`); `ssh_real_sshd.rs` is the opt-in real-sshd run.
- **Keys (decision 6).** Public upstream test keys from `ssh-key 0.7.0-rc.11` are copied unchanged under
  `fixtures/ssh-keys/` and labelled test-only in `fixtures/PROVENANCE.md`; no key was generated for commit.
- **Vendored russh (decision 7).** Production links the same `vendor/russh`; `scripts/check.sh` runs its client suite
  (29 tests with patch 3).
- **Runtime.** russh needs a Tokio context: every client future and task is spawned on the vendor runtime, never on
  core (R2-wonder-2). Reply timeouts (sshj's 30 s) and the keep-alive go through `VendorClock`.
- **Keep-alive.** russh's own keep-alive is disabled (any received data resets it, which contradicts R7/T25);
  `keep_alive::KeepAliveRunner` ports sshj's runner as an owned task.

## Real-host measurements (macOS OpenSSH 10.3p1)

Run 2026-10-24 with the user's approval, against the remote Mac's own sshd (macOS 27.0.1, build 26A434, arm64;
`OpenSSH_10.3p1, LibreSSL 3.3.6`, zsh login shell, `LANG=C.UTF-8`), never its port 22 (Tailscale SSH). It was reached

- **P1:** only default-visible sshj lines are reproduced, exactly: `TransportImpl - Dying because - <msg>`,
  `Promise - <<name>> woke to: <toString>` (kex done, channel open, exec request), `OpenSSHKnownHosts` unparseable-line
  errors and `Host key for … has changed!`, and `KeyExchanger - Disconnecting because none of the configured Host key

  `ssh.debug`. Under `ssh.debug`, russh's own records (no trace) go to DEBUG under their crate targets.
- **P2:** deterministic `Cancelled` for an await still running when close finishes.
- **P3:** A15 not reproduced.
- **P4:** not needed (see markers above); the SSH-1 `bits e n` form is skipped as unparseable.
- **P5:** a second close after a failed first skips the backend but cancels and joins the scope.
- **P6:** `SshTest` `n/a`; memoised random factories not ported.
- **P7:** saturating interval and loss-message arithmetic.
- **P8:** first resolved address only.

## Known Kotlin bugs

A2, A11, A12, A14, A17 reproduced with named tests; A13 not kept (D7), with the Linux and macOS measurements added; A15 not
reproduced (P3); A16 moved to 4.3 (4.2 delivers its `UNKNOWN`). **New A33:** a rejected `exec` never closes its
session channel, which holds a `MaxSessions` slot until the connection ends (Kotlin evidence `reject` transcript),
reproduced under D5. **New A32** (review round 2): an unread stream overflows sshj's 16 MiB buffer while the other
stream's reads keep refilling the shared window, and the reader thread's death takes the whole connection. The second candidate, `Error disconnecting <addr><port>` without a colon, is ported verbatim
(`executor.rs`) but has no row: sshj's `disconnect` throws only when closing the socket fails, which neither the fake
nor a real sshd can provoke, and the Rust close never fails, so the line is unreachable in tests.

## Changes to merged code

- `crates/marathon-apple/src/cmd/mod.rs` (4.1): `safe_execute` matches sshj subclasses through `is_instance`;
  new `CommandExecutor::log_error_with(message, cause)` (default delegates to `log_error`) so the SSH executor logs the
  throwable as Kotlin's `logger.error(e) { … }` does. Regression: `command_helpers.rs`.
- `crates/marathon-apple/src/cmd/base_command.rs` (4.1): a failed close releases only its own retained task
  (R2-wonder-4). Regression: `failed_session_close_is_shared_then_retried_without_overlap`.
- `crates/marathon-apple/src/cmd/channel.rs` (4.1): `LineChannel::cancel` keeps the first close cause (4.1 nit).
- `crates/jcompat/src/logging.rs`: `MarathonLogging::slf4j_logger(name)`, a plain slf4j lookup that sets no level,
  for sshj's `LoggerFactory.DEFAULT` loggers (`OpenSSHKnownHosts`).
- **`crates/marathon-core/src/executor/mod.rs` (3.1), review round 1:** the vendor runtime is built with
  `enable_io()` as well as `enable_time()`. Without the I/O driver every vendor socket and `tokio::process` child
  panicked ("IO is disabled"): the SSH connect, and also 4.1's local executor (pipes and SIGCHLD), which no test ran
  on the production wiring. Regression: `crates/marathon-apple/tests/production_runtime.rs` (both executors through
  `CoreExecutor::run`, `core.vendor()`, `core.vendor_clock()`). No other change to the runtime.
- `vendor/russh` (0.3a/0.4a): patch 3, manual window adjustment (default off).
- `scripts/check.sh`: runs the vendored russh client tests.
- `crates/marathon-apple/Cargo.toml`: russh, log, base64, hmac, sha1, md5; tokio `net`/`fs`; dev: fake-worker, rand,
  serde_json.

## Merge prep: Linux gate failure

`scripts/remote-check.sh` failed `reading_only_stderr_overflows_unread_stdout_and_kills_the_connection` ("the
overflow must kill the whole connection"); macOS passed. The cause is the test's timing, not a Linux difference
in the product. A stderr read grants window credit only if the window is at or below sshj's adjust threshold
(512 KiB) at that moment, as `ChannelInputStream.checkWindow` does. If a read lands while granted stdout is still
in flight, it grants nothing; the fake's next stderr byte sits behind a megabyte of stdout it may not send, so the
read waits forever. The oracle probe's 100 ms sleep only makes this unlikely, and sshj stalls the same way. On the
box, 1 run in 5 hit it: the read timed out after 9 stderr bytes with the window at 0, no stderr pending and
10223608 bytes of stdout unread.

Fix (`6f2e05e`): before each read the test waits until the window has drained to the threshold
(`ExecChannel::local_win_size`, sshj's `Channel.getLocalWinSize()`). It waits up to 30 s for the drain and for
the death, and a stalled read fails the test instead of ending the loop quietly. The assertions are unchanged. A
port that stops refilling from stderr reads still fails (the read stalls), and so does one that never overflows
(no death). With 4 copies of the suite running at once, two other tests failed. In
`executor_close_disconnects_and_fails_live_channels` (2 runs in 12), `connection_end` was read before the fake's
handler had recorded it. That read, and the same `connection_end` reads in the bad-extended-data test and in
`ssh_task_lifetime.rs`, now poll through `Fake::events_at_least`. It did not fail again in the next 12 runs under
load. `ignored_term_on_timeout_still_gives_null` failed
once more (1 run in 12); it was subsequently fixed as 4.2-U5 (see below).
The sleep-paced reads of `slow_consumer_receive_window_stays_within_the_buffer_cap` cannot stall (stdout always
has bytes buffered), so it is left as is. Linux: 20 of 20 sequential runs and 12 of 12 under 4x load passed this
test.

## Post-merge test hardening

`slow_consumer_receive_window_stays_within_the_buffer_cap` could sample only 5472240 unread bytes under CPU
load: its fixed sleeps measured worker throughput, not exhausted receive credit. It now waits for
`local_win_size() == 0` before the first single-byte read and after each of the sixteen reads, checks that the
connection survives and the buffer stays below 16 MiB, and requires exactly 16777215 unread bytes at the end.
This proves refill beyond the initial 2 MiB window as well as the cap. The fake's queued-part `sent` bound is
replaced by that fully received byte count. The stderr overflow companion keeps its state-based threshold/death
waits through a shared 30 s helper; the stalled-channel test waits for initial output events instead of 300 ms.
The two vendored window tests now wait for their expected byte counts before checking for excess output during
the existing quiet period; `russh-manual-window.patch` records the same test-only change.

Validation (macOS): each of these five tests passed 30/30 runs with 18 `yes` processes (one per CPU), 150/150
total; all load processes were terminated and reaped. Temporary mutations disabling refill or restoring uncapped
refill both failed the slow-consumer test; the unchanged production code was restored and the test passed again.

## Fake-worker signal ordering (4.2-U5)

The channel reader and post-EOF control reader now poll queued wire messages before channel cancellation, and
the channel actor polls that reader before the action. The output action polls queued signals before cancellation
and completed work. This preserves TERM-before-CLOSE ordering even when the close handler has already cancelled
the actor's token before it resumes. Ignored signals are recorded before the actor ends; the 4.2 assertion uses
`events_at_least` because russh can reply to CLOSE before the actor's asynchronous transcript append finishes.

The added contract test sends two ignored TERMs immediately followed by CLOSE, with and without preceding EOF,
then joins worker shutdown and checks that all four ignored-signal events survived. The 0.4a wire, script and
transcript formats are unchanged.

Validation (macOS): `ignored_term_on_timeout_still_gives_null`, the new immediate-CLOSE contract test, and
`ignored_term_custom_signal_exec_rejection_and_extended_data` each passed 50/50 runs with 18 `yes` processes
(one per CPU), 150/150 total with zero failures. All 18 load processes were terminated and reaped. The new
contract test failed against the original worker (2 ignored-signal events instead of 4); the fixed source was
restored before the repeated runs. `cargo test -p fake-worker --test contracts`: 14 passed.
