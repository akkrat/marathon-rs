## Consumer API

- `XcodebuildSession::new(runtime, logging)` returns `Arc<Self>`.
  `produce(context, open, consume)` starts a retained vendor task and returns
  `EventReceiver`; the callbacks receive the session's cancellation context.
  `consume` receives `Arc<CommandSession>` and `EventSender`. Receivers have no
  Drop cleanup: every consumer explicitly calls `cancel()` and/or session `stop()`;
  both runner and parser cancel then stop in their explicit finally paths.
  `stop(timeout, context)` explicitly cancels and joins without inheriting caller
  cancellation; it returns an optional close failure. `await_closed` only waits,
  observes caller cancellation and returns the closed flag. `check_closed(serial)`
  preserves the DeviceLostException / IllegalStateException / close-failure chain.
  `closed()`, `abandoned()` and `CLOSE_TIMEOUT` (60 s) are public.
- A producer is never abandoned by dropping its task handle. After a stop timeout,
  the session retains the handle and the task keeps closing. A later successful
  close makes `closed()` true while `abandoned()` stays true. Device disposal in
  5.2/5.5b chooses whether/when to await `join_producer()`; no extra shutdown wait is
  imposed here. Drop does not close a command. Open acquisition receives the
  cancellation context and is always awaited, including its transport cleanup.
- `AppleDevice::execute_test_request(request, session, &context)` is the new trait
  seam. Its default rejects unsupported calls, leaving existing non-running test
  devices source-compatible. Concrete 5.2/5.6 devices override it, check their
  previous session first, record the new session second, then call
  `execute_test_request::execute_test_request` with an owned device Arc and
  `TestOutput { label, args, timer, listeners, logging }`.
  Simulator args use the merged `simulator_test_args`; macOS uses raw user args.
  Pass the device's `Arc<dyn Timer>` as `timer`; the shared body constructs the
  merged XctestEventProducer from `request.test_target_name.unwrap_or_default()`
  and that timer, using the supplied logging. Devices must not build a separate
  producer or choose a target independently of the request. The device's LogProducer delegates add/remove to
  its shared `LineListeners`; one async gate serializes stdout/stderr callbacks.
  Events are sent before line listeners (A20); trimmed-empty stderr is discarded,
  other stderr uses the existing WARN Xcodebuild logger even with debug disabled.
- `AppleDeviceTestRunner::new(device, runtime, logging)` uses a 60 s close timeout;
  `session_close_timeout` can be overridden. `execute(configuration, bundle, batch,
  listener, context)` builds the unchanged request and guarantees explicit finally
  cleanup. `RunError` preserves `error`, optional Apple device-failure `reason` and
  an Apple-local suppressed list. Consumers classify the reason before
  `into_vendor()`, which flattens suppressed throwables into the existing Failure
  representation without changing marathon-core. `process_events` is public for
  the one-to-one listener mapping. `execute_request` is the unit lifecycle seam.
- `NmTestParser::new(vendor_configuration, registry, identifier, class_regexes,
  runtime, logging)` and `XCTestParser::new(vendor_configuration, registry,
  identifier, installer, runtime, logging)` implement RemoteTestParser.
  Registry lookup stays inside all three attempts. Nm awaits both initial scans
  before rescanning, checks Swift before ObjC, registers every test before class
  filtering and preserves duplicates and the empty ObjC package. XCTest uses
  the concrete merged installer with `use_xctest_parser=true`, `push_file`, and
  an insertion-ordered collection. It ignores non-start events and class regexes.
  `collect_tests` is the unit-level collection seam used by upstream-style tests.
- `AppleTestBundleIdentifier::{put,bundle,identify}` is a mutex-protected map keyed
  by core Test equality (metadata ignored). Later puts overwrite; identify misses
  return ConfigurationException, never `Ok(None)`. All tests in an attempt share
  the same Arc<AppleTestBundle>, preserving batching identity.

## Review round 2

- **R2-sonnet-1:** Extended the producer-close latch from runner-failed-after
  to runner-close-failure and runner-close-timeout, ordering close after the
  failure and after-run callbacks. The timeout mode then blocks on release
  until the runner returns. Audited runner-cancel: producer cancellation only
  reaches the reader after close completes (its release wait expires first),
  so latching it on after-run would deadlock. XCTest parser modes register
  the listener before producing and stop/join before removing it; the separate
  late-close session probe already uses explicit closing/release latches.
  Other modes have no competing close callback recorded in the transcript.
