## Audit and contract boundary

An independent audit loaded every normalized view at `a830d106` and in the new
generation. For each changed command it compared selector Counters (including
multiplicity), verified the order differs, and verified all command text outside
the selector operands is byte-identical. Each of the six views changes exactly
one command. For the four Apple views it also verified the selected-test arrays
have identical multisets and that restoring only their old order makes the
whole `state.json` value equal. Restoring only selector order similarly makes
every whole transcript equal; no stream bytes, exit status, command count,
non-test argument, mode or other field changed. All per-view paths/key orders
and every other entry were compared unchanged. No normalizer was modified.

In these native goldens, **batch membership never changes**: every changed batch
contains the same multiset of tests. With unchanged priorities in general,
FIFO can change membership where ties cross a batch boundary and can change
the number of resulting batches: the listed-APK integration regression now
fills 20/100 batches where the heap needed 21/101. The integration tests pin
this distinction. RandomOrder's changed key assignments and newer
observations on re-add can independently move tests across boundaries, as D60
states. No batching rule, rejection bound or duration limit changed.

Every report file, progress line and summary is unchanged in all 18 native
views. Scripted devices emit fixed result order even when selectors move;
real-device report order follows execution order. The only command differences
here are the adb class-list and xcodebuild selector permutations above.

Unchanged views: `local`, `parse`, `ios-media`, `ios-screenshot`,
`android-smoke`, `android-remote`, `android-instrumentation-eof`, `ios-parse`,
`macos-parse`, `android-parse`, `ios-pass`, `macos-pass`.

The generated `provenance.json` changes only `native_sha` to the implementation
commit; driver, platform, Python and release-source provenance are unchanged.
The configuration corpus is unchanged and was not re-blessed.
