## Scope decisions and review notes

- The CLI input is the two-device fixture plus run-local `debug: false` and `bootWaitingThreads: 1`. This makes console
  repeatability meaningful without pretending to control every live vendor thread. The original fixture is unchanged.
- Core clocks/scheduling are virtual. The CLI uses frozen wall/monotonic clocks, real socket/scheduler time and completion
  barriers. Arbitrary Apple/SSH/media/process workloads are inventoried but are not certified by this Android replay.
- Check (b) normalizes **nothing**. Check (c) uses the explicit field-by-field rules in `nondeterminism.md`, including JVM
  frame differences from instrumentation, live device roles and timeline tie ordering. Its console check preserves message
  multiplicities rather than live inter-thread ordering. Source case assignments and times in core transcripts stay exact.
- The `scripted` reference pair enters `runAsync`; only the patched side can intercept synchronous `run`. Both execute the
  same core. Its injected bridge marker is the only event-log entry removed in check (c).
- Kotlin C19 (array annotations rendered as identity strings) was observed and added to the known-bug ledger; only the
  nondeterministic suffix is taped. Existing C16/C17/C18 behavior remains in the reports/logs.
- The orchestrator still owns reviewer assignment, Linux `remote-check.sh`, and merge. Review should explicitly confirm the
  CLI input variant and reference normalization scope before these hooks become a basis for WP 3.10 goldens.
