## Decisions taken

1. **Placement (orchestrator decision 5).** `marathon_config::loader` holds
   the only implementations of the 0.6 traits: `MarathonConfigurationLoader`
   (`ConfigurationLoader`), `MarathonVendorHooks`
   (`VendorConfigurationHooks`) and `LogicalConfigurationValidator`
   (`ConfigurationValidator`). Each also has a `*_sync` method returning
   `Result<_, Box<ConfigurationError>>`, the shape of 2.3a's free functions
   (clippy's `result_large_err` rejects the unboxed 328-byte error). The
   trait futures do the blocking work on their first poll, hold nothing
   across an await and unbox at the trait edge; callers dispatch them off the
   core executor (`lifecycle.md`). The parity tests call the trait methods
   (`tests/support/load.rs::ready` polls once with a no-op waker), so the
   frozen boundary is what is tested.
2. **Stage (a)** = `bind_bytes(bind_configuration(_, bind_vendor_configuration))`
   → the hooks' post-processing → the tracking merge, in that order and once.
   `post_process` runs 2.3a's free functions with the real
   `bundle.validate()` at factory step 2 (before every `canonicalFile`);
   `Empty` → unwrapped `ConfigurationException("No vendor configuration
   specified")`. Tracking: `context && bound`, per flag, after the vendor
   branch (`true` in `BindingContext` = the CLI has no opinion).
3. **`devices()` context (decision 2).** `devices` rebuilds the context
   field by field with `Profile::Marathondevices`, whatever the caller
   passed (`devices_binds_with_p2_whatever_the_callers_profile`).
4. **`LoadError` → `ConfigurationError` (decision 3),** all at stage `Parse`:
   - `NullDocument` → `java.lang.NullPointerException`, unwrapped, with the
     JDK's helpful message, which the JVM witness `a-null-document` shows is
     not null: `Cannot invoke
     "com.malinskiy.marathon.config.Configuration.getVendorConfiguration()"
     because "configuration" is null`.
   - `Substitution` → its Java class and message, unwrapped (witness
     `a-substitution-cycle`: `IllegalStateException`, "Infinite loop in
     property interpolation of …").
   - `Worker` (no Kotlin counterpart: the binding thread could not be
     created) → `java.lang.IllegalStateException` with the OS error text.
   - Binding failures keep `bind_bytes`'s P1 wrapper; `devices` keeps 2.3b's
     stage `Provider` and original class.
5. **One converter (deliverable 2):** `validation_error_to_configuration_error(error, stage)`
   — FQCN class, verbatim message, no causes, empty path/span (P4) — used
   for the bundle callback at `Parse` and every `validate()` at `Logical`;
   `tests/bundle.rs` now calls it instead of its local copy. F18's
   `FileNotFoundException` keeps its class (corpus `b-ios-ssh-key-missing`,
   `b-ios-known-hosts-missing`).
6. **Stage (b)** is `LogicalConfigurationValidator.kt:12-89` in file order;
   iOS/Android dispatch through the hooks' `validate`, macOS compares the
   queue and `provisioningConcurrency` with fresh defaults and never calls
   `MacosConfiguration::validate` (F6). The iOS bundle is validated on a
   clone, so extraction runs again (P2 rejected; `stage_b_re_extracts_the_bundle`).
7. **`to_map(&self, process_dir)` (deliverable 4, P3).** `render.rs`
   projects every configuration type into `KotlinValue` by hand: data
   classes in constructor order with Kotlin property names, the two
   analytics masking overrides and `PasswordAuthentication(username='…')`,
   enums by constant name, `Regex` as pattern, `File` as stored, doubles via
   `jnum`, ISO time. `outputDir` is `File.absolutePath` against `process_dir`
   (the JVM's `user.dir`; a no-op for the CLI's canonical paths). The return
   is an ordered `Vec<(JavaString, JavaString)>` of 23 entries. No `Debug`
   shortcut.
8. **`serialize` (deliverable 5, P1 approved).** `render.rs` also projects
   into `WriterValue` for 1.5's `JacksonYamlWriter`, following what the JVM
   witnesses showed Jackson does: `type` first, constructor order,
   `@JsonProperty` names, iOS written as `iOS` (the first of its four
   names), singletons as `{type: …}`, nulls omitted, derived timeouts written
   as plain fields, `@JsonIgnore`d bundle paths and `effectiveWorkerCapacity()`
   not written. P1 only asks for a round trip, but the output turned out
   byte-identical to Kotlin's `serialize()` on all 16 witness rows, except
   one D6 difference: Kotlin writes the default nm `testClassRegexes`
   pattern, whose lookahead the regex crate cannot compile (WP 2.3a decision
   7), so we leave the key out and the re-parse rebinds the same default.
   The projection works per section (`WriterProjection` for
   `XcresultConfiguration`, used by the queue round-trip row).
9. **Deliverable 6:** the `TestPackageFilter` `subpackages` caveat is in
   PLAN D9, F10 and `list_drop_nulls` (`dffa74b`).
10. **Carried 2.2 item:** the validator half of `observedDurationMinTests is
    parsed for every backend` is `tests/validation.rs` under the same name
    (whole file plus validator), next to the below-one row. The 2.2 row keeps
    pointing at its section-level test in `tests/schema.rs`, whose comment
    now names the completion.

## Approved differences that show here

- **D9 (narrowed S4):** a null filter `values` element is dropped at bind, so
  `toMap()` shows `values=[a, b]` where Kotlin shows `[a, null, b]` (corpus
  row `m-filter-null-value`, asserted as exactly that difference).
- **D6:** the nm default pattern above.
- **F29 (new):** the identity hash in `Object.toString()` renderings.
- Set-valued fields keep first-seen order (2.3a P7). Kotlin's are
  `HashSet`s with run-specific order, so the witness rows give sets one
  element; comparisons against Kotlin (2.6) stay order-insensitive.
- **D9 (carried from 2.3a):** the keys of maps that `toMap()` renders are
  the binder's `String`s, not `JavaString`s. A key carrying a lone
  surrogate is already rejected at bind, so `toMap()` loses nothing that
  Kotlin could print.

## Changes to merged code

- **`crates/marathon-config/src/paths.rs` (WP 2.1/2.3a): behaviour change.**
  `canonical_file` now keeps the unresolved suffix on `ELOOP` as the JDK
  does (incidental bug U-a below): anywhere on macOS, only at the last
  component on Linux. Before, a Marathonfile path through a symlink loop
  failed the whole parse with a `JsonMappingException` on both.
- **`crates/marathon-config/src/schema.rs` (WP 2.2/0.6): behaviour change.**
  The four types with `f64` fields (`Defaults`, `SortingStrategyConfiguration`,
  `BatchingStrategyConfiguration`, `FlakinessStrategyConfiguration`) have
  hand-written `PartialEq` comparing those fields as `Double.equals`
  (new `pub fn java_double_eq`), so every schema type is now also `Eq`
  (`Configuration`, the analytics configurations). Before, NaN was unequal
  to itself and 0.0 equal to -0.0.
- `crates/marathon-config/src/bind.rs`: doc comment only (`list_drop_nulls`
  caveat). `lib.rs`: the `loader` and `render` modules.
- `crates/marathon-config/tests/bundle.rs`: uses the production converter;
  `tests/schema.rs`: one comment.
- `PLAN.md` D9 and `known-kotlin-bugs.md` F10: the caveat wording.
- `tools/oracle`: the new generator, its wrapper and `Main.kt` entry.
- No change to `jcompat` or `snakeyaml`; no new dependencies.

## Open questions

1. F29: is the class-name hash an acceptable stand-in for the JVM's
   run-specific identity hash, or should `toMap()` print something else
   (e.g. the bare class name)? Kotlin's value is never reproducible.

   permission on the path), where the JDK's canonicaliser may fall back as
