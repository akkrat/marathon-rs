## Implementation and shared crates

**Changed merged crate: marathon-apple only.** The existing SSH error hierarchy
adds NoRouteToHostException, BindException and PortUnreachableException as
SocketException subclasses, so the classifier sees the inherited Java types.
The existing cmd/lib/remote module exports expose the new modules, and
`tests/production_runtime.rs` adds a factory/transfer case through the real
`CoreExecutor` → `call_vendor` bridge. Existing core, config and jcompat APIs
are unchanged. Apple's existing nix dependency enables socket/net/poll in
addition to signal/fs; Cargo.lock adds its memoffset 0.9.1 dependency. No russh
or fake-worker production code changed.

`device::connection_factory` provides run-owned constructors, create,
create_or_throw, connect_worker, direct unregistered create_local, dispose and
join_pending. It consumes shared config types and the production local/SSH
executors. The connector and address probe are explicit test seams; the default
connector preserves preparation errors outside the handshake catch boundary.
A Tokio fair semaphore defaults to eight permits, with resolution, reachability,
auth and verifier preparation outside it. The pending/shared/identity-lease maps
use short synchronous locks; checks, connect, close and pending waits happen
outside them. Connectivity checks run on the vendor blocking pool. Lost executor
leases survive independently of their replacements. Bridge construction happens
outside the separate endpoint cache lock, and first publication wins.

Acquires and closes belong to retained vendor tasks. A delivery acknowledgement
covers abandonment between sending a result and the caller receiving it; a
cancelled/dropped awaiter cannot leave a user counted indefinitely. Cancelled
waiters leave the shared attempt running. An abandoned owner releases an
undelivered lease after setup finishes; a racing waiter may re-lookup after that
release and reconnect, exactly as when a successful owner's last dispose races
a waiting caller. Consumers must await join_pending during provider teardown,
in addition to disposing delivered executors. There is no cleanup in Drop.
Cleanup joins all retained tasks and bridges before returning the first join
error; a failing close cannot short-circuit later owned cleanup.

The typed DeviceFailureException/Reason and classifier retain SshFailure causes
and reasons until classification, then project into the frozen core Failure.
Only Unknown/FailedRunner are batch failures. The cause bound is sixteen;
owned Rust chains cannot represent JVM self-links. Generic I/O, auth, host-key
and explicit KEX reasons remain permanent; A16's actual UNKNOWN KEX is transient.

The rsync bridge implements Apple's existing FileBridge. Sends serialize;
receives overlap. Both directions use the actual rsync4j argv order and process
environment overrides, plus source/destination directory trailing separators.
A repeated links setter emits one host flag (measured library behavior).
The rsync4j executable bootstrap is also preserved: /usr/bin defaults,
RSYNC4J overrides, per-process discovery caching, required-binary failure and
one-time optional sshpass warning. Discovery I/O runs on the vendor blocking pool.
Debug alone performs the version probe; -vvv requires both debug switches.
Password command argv uses sshpass -p for nonempty passwords; an empty password
retains sshpass but omits -p and its operand. Missing auth fails only on transfer.
Send is unbounded; receive sends TERM at its 30-second monitor expiry and still
waits for child exit, as processoutput4j does. Reader tasks are owned and joined;
a timeout can stop their reads after the child exits. Output line endings follow
BufferedReader/CollectingProcessReader, including the final newline. Transfer
await abandonment retains the process and send mutex until completion.

WriteFile reproduces the size/path guard, exact padded-base64 shell script,
neighboring temporary name, owner-only installation and exception/cancellation
boundary. The thin iOS routing test supplies the caller's ssh.debug, transport,
size and helper-success guards; production routing remains WP 5.2. SharedTransfers
serializes by worker/destination, keeps absolute noncanonical source paths, and
retains only a successful transfer. Exists true/false/null and thrown callbacks
keep the Kotlin short-circuit/cache behavior. Provider-owned instances remain
5.4/5.6 wiring; no second RemoteFileManager was added.

## Review round 2

The cross-family Claude R1 review raised four low-severity findings; Sol's R1
fixes were verified. The orchestrator chose to fix all four, in Claude's round 2
(commits on top of `26ea4e8`, without rebasing, because WP 4.4 is stacked):

- R1-claude-1 (`2856aac`): `tcp_echo` now follows the JDK's `tcp_ping4` and
  `NET_Wait`. An immediate connect of 0 or ECONNREFUSED means reachable.
  ENETUNREACH, EAFNOSUPPORT and EADDRNOTAVAIL mean false, as do EINVAL and
  EHOSTUNREACH on Linux. Any other immediate errno, including EHOSTUNREACH on
  macOS, becomes the text
  `java.net.ConnectException: <strerror> (connect failed)`. The wait polls
  POLLOUT and retries failed or early polls until less than 1 ms is left; then
  SO_ERROR 0 or ECONNREFUSED means reachable, anything else false. Socket
  creation errors become `java.net.SocketException: <strerror> (Can't create
  socket)`. The exception texts follow `JNU_ThrowByNameWithMessageAndLastError`
  from the JDK sources; no oracle triggers them. `Reachability.java`, and
  Probe.kt's equivalent mode, add broadcast 255.255.255.255 and multicast
  224.0.0.1. Both platforms report false (connect fails immediately with
  EAFNOSUPPORT on macOS and ENETUNREACH on Linux). Both `reachability-*.jsonl`
  files were regenerated with the runner, and the Linux scratch directory was
  deleted. Before this fix, the macOS EAFNOSUPPORT case produced the exception
  text instead of "not reachable". The optional resolution-cause message is
  done: the UnknownHostException cause is `<host>: <gai_strerror>`, matching
  the JDK's `no-such-host.invalid: nodename nor servname provided, or not
  known` on macOS. The test pins only the `<host>: ` prefix, because the
  getaddrinfo text differs by platform.
- R1-claude-2 (`4298b85`): updated the ConnectionCounter n/a note (both reviewers
  agreed) and the ConnectionFactory/ConnectionFailures note. Regenerated
  `docs/source-inventory.csv` with the script; 505 files, three rows changed.
- R1-claude-3 (`cc50f39`): took the byte-for-byte option. The new
  `tools/oracle/connection-probes/normalize-argv` rewrites only the scratch root
  and recorder path, and keeps argv-rsync's own serialization.
  `rsync-argv.jsonl` now keeps the four debug-bridge `--version /tmp /tmp`
  rows in invocation order; the sixteen transfer argvs are unchanged. The Rust
  test checks each version row before its bridge's transfers and checks that
  every row is consumed. A fresh `run argv`, and also a fresh `run
  empty-options`, piped through `normalize-argv` is `cmp`-identical to the
  committed file. Documented in the corpus README and PROVENANCE.
- R1-claude-4 (`e0bc710`): the new `cmd::retained_tasks::RetainedTasks` backs both
  `ConnectionFactory.tasks` and `RsyncFileBridge.tasks`. It is needed because
  the frozen core `VendorTask` has no completion query. Each spawn drops tasks
  whose body already succeeded. Failed tasks stay until joined, so
  `join_pending` still returns their error; the existing 4.3-U2 regression
  exercises this, since a failed close is followed by another retained task.
  `RsyncFileBridge::process` now holds every error (child wait, monitor delay,
  diagnostic write) until it has reaped the child and joined both readers. A
  wait error triggers one more wait, and the readers are cancelled only after
  the child exits. A failed diagnostic write no longer skips the TERM.
  A monitor-delay error waits for the child without TERM, because the 30-second
  limit was never reached. New tests:
  `succeeded_tasks_are_pruned_when_new_ones_are_retained` (200 create/dispose
  cycles keep at most 2 handles, and 0 after join) and
  `finished_transfers_are_pruned_and_an_early_error_still_reaps_the_child`
  (3 sequential sends keep 1 handle; a failing clock's receive returns its
  error only after the 0.3 s child has exited).

No new known Kotlin bug, incidental bug, deviation or parity-matrix row. The
changed code stays in **marathon-apple**.
