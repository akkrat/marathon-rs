## Behaviours to reproduce (exact Kotlin locations)

- **Negotiation/framing:** `A/request/sync/compat/Compat{Stat,List,Pull,Push}FileRequest.kt:30–37,30–37,41–58,38–54` select STAT_V2, LS_V2 and SENDRECV_V2 independently. No compression even when advertised (`v2/PullFileRequest.kt:41–48`, `v2/PushFileRequest.kt:42–54`). `extension/Socket.kt:162–195` writes ASCII tag + little-endian UTF-8 path length + path; v2 then repeats the tag with optional mode and flags. v1 push appends **decimal** masked mode (`0777` → `511`), v2 sends binary mode; dry-run is `0x80000000` with its own feature check (`v1/PushFileRequest.kt:36–53`, `v2/PushFileRequest.kt:47–71`). Pull/list/stat path validation counts UTF-16 units; push counts UTF-8 bytes (1024 limit; base pull :126–131, base push :107–121). Preserve validation order/text via merged helpers.
- **Stat/list:** `A/request/sync/v1/StatFileRequest.kt:36–51`, `v1/ListFileRequest.kt:41–73`, `v2/StatFileRequest.kt:39–60`, `v2/ListFileRequest.kt:53–101`: v1 unsigned mode/size but signed timestamp seconds; v2 keeps error/dev/ino/nlink/uid/gid/size/three times. **N18 applies**: use merged `bytes::{to_long,to_ulong}` for v2, not correct native 64-bit decoding. `model/FileEntry.kt:27–35,47,64` uses bit-inclusion type predicates and all-zero mode/size/mtime for absence, even in v2 with a nonzero error. A non-DENT tag ends a list with accumulated entries, whereas wrong stat tags throw `UnsupportedSyncProtocolException`.
- **Transfer:** `A/request/sync/base/BasePullFileRequest.kt:47–58,60–122` uses **v1 STAT on the same sync connection** if size is absent, even before RCV2. Start writer only for positive size; DATA ≤65536, progress = bytes/expected size, DONE closes/drains writer, FAIL → `PullFailedException("Failed to pull file <path>: <text>")`, other tags → UnsupportedSyncProtocol. Do not clamp progress or invent a final 1.0. `BasePushFileRequest.kt:41–51,58–103` sends ≤65528 data bytes, progress per DATA then another 1.0 only after acknowledgement. DONE's mtime is **big-endian** truncated epoch seconds (:65–68), unlike DATA lengths. Keep that bug; do not follow the ADB spec instead. `io/AsyncFileReader.kt:45–80` eagerly opens input, queues two chunks; writer :35–65 lazily creates parents/truncates and joins at close. Probe zero-size and failure timing; do not silently turn early EOF/failed writes into success.
- **Directory push/shell list:** `A/request/sync/PushRequest.kt:58–120,126–163,170–213`, `BFFSearch.kt:30–43`: stat target, file-to-directory basename, breadth-first order ignoring `.`/`..`, create directories before files, stop when a file's final progress is not 1.0. Keep `mkdir -p '<root>'`, subsequent `mkdir` batches at 4096 UTF-16 units, even the final bare `mkdir`; `extension/List.kt:19–21` supplies quote escaping. `request/file/ListFilesRequest.kt:23–81` sends unquoted `ls -l <directory>`, fixed Java-pattern semantics, skips nonmatches/unknown leading types, invalid size → 0, symlink requires exactly one `->`. Reuse JavaRegex/hardcoded-pattern conventions; no user regex or new shell parser.
- **Install/uninstall:** `A/request/pkg/StreamingPackageInstallRequest.kt:52–110,113–124`: validate file/features/extension in order; prefer ABB_EXEC, then CMD; extra args before `-r -S <bytes> [--apex]`, NUL-separated ABB args versus individually shell-escaped extra args on `exec:cmd package`. Write APK bytes then read trimmed output; only `startsWith("Success")` succeeds. `InstallRemotePackageRequest.kt:27–50` uses unquoted remote path and raw joined options, including repeated `-r`; `UninstallRemotePackageRequest.kt:27–39` emits `pm uninstall [-k ]<package>` through the frozen v1 shell exit trick. ## Proposed simplifications (for the orchestrator, not decided)

The user's pragmatic-parity direction allows proposals, not silent exceptions. Until approved, the baseline above and all 105 rows apply. Preserve rejected/superseded oracle witnesses and record decisions in findings/deviations.

- **P1 — unused APIs:** omit recovery sideload (8 rows), parsed `PmListRequest` (2), atomic parent create/add-session (20), reverse list/remove-all (3): **33 rows** could become `n/a` with explicit reviewer agreement. Marathon calls none of these; its installed-package check uses a plain shell command. - **P2 — malformed/oversized data:** fail explicitly on short sync/framebuffer records, negative/oversized lengths and inconsistent image geometry instead of stale-buffer contents, panic-equivalent indexing or hanging. - **P3 — file-worker machinery:** sequential async reads/writes with the same packet sizes, progress and awaited completion instead of two-slot reader/writer coroutines, pooling and exact open/start races. This can shift local-I/O failure timing and cancellation partial-file contents; propose explicit propagation and complete resource shutdown. Preserve network ordering; never accept a successful transfer before its writes complete.
- **P4 — color-model cache identity:** fresh Rust image values and profile-aware conversion without AWT object reuse or the cache's profile-only/type-confusion bug. Pixel/profile fidelity (including P3) stays required; no proposal to treat all color spaces as sRGB. This drops only allocation identity and mixed-adapter cache poisoning, not the assigned repeat-capture assertions.
