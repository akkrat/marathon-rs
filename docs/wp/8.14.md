# WP 8.14: Runtime cleanup: dead coroutine surface, bridge payload, defect fixes

Effort **M**. Branch `wp/8.14-runtime-cleanup`, based on `main` after WP 8.13 (commit `a85639dd`).
WP 8.12 (Apple async reads) may still be in flight; whichever merges second rebases.

## Why

WP 8.13 designed the move away from the Kotlin coroutine emulation (`docs/design/tokio-tasks.md`), and
two independent reviews settled the first steps (§7 of that document). This WP does the small, safe part:
delete what nothing uses, simplify the bridge payload, route lost failures to the log, and fix four
defects the reviews found. **Scheduling, cancellation and timeout semantics do not change** except
where a fix below says so.

## Scope

Each item is its own commit with its own tests.

1. **Delete the unused timeout overloads** (`crates/marathon-core/src/executor/timeout.rs`, about 55
   lines, no callers; the design's step A). Update the source inventory or parity rows if the module is a
   recorded port.
2. **Bridge payload** (`executor/bridge.rs`, step B): replace the shared mutex slot with a `oneshot`, read
   with **`try_recv` after the protected join** succeeds (the producer has already sent; do not add an
   `.await`). Keep failure, cancellation and missing-payload behaviour; add tests for the first-poll window
   and a missing payload.
3. **Delete dead surface:** `Actor::safe_send` and `Job::cancel_and_join` (no production callers; their
   tests go, parity rows `n/a` with reason `8.14: dead coroutine surface` if any exist).
4. **`completion_logging`:** loggerless unhandled failures are collected into a vector nothing drains in
   production (`executor/completion_logging.rs`, `executor/mod.rs`). Route them to the log queue as an
   ERROR line (a diagnostic line, so §3.12 point 5 allows it) and delete the unread accumulation; keep a
   test-only way to observe them if tests need it.
5. **Defect fixes**, each with a witness test that fails before the fix:
   - a vendor future that panics on its **first poll** leaves its cancellation gate unarmed, so a child
     holding the gate waits for ever (`bridge.rs`, the arming after `body.poll`);
   - `Tracked` (`executor/tracking.rs`) releases its replay ticket only in `poll`; add a `Drop` release so
     an aborted or dropped tracked future cannot leak the busy count;
   - iOS `apple_simulator_device::LinkedSignal::cancelled()` uses an unbiased `select!` while `reason()`
     prefers the parent; make `cancelled()` `biased` toward the parent so both agree when both sources
     are ready (the provider's linked signal already does this);
   - `timeout_panics_surface_as_failures_without_leaving_children_live` spawns no child: add a witness
     that a panicking timeout body cancels and cleans up a live descendant (fix the code if it does not).
   Keep and document the existing precedence where a cancelled vendor task that panics reports
   cancellation (`IoRuntime`); do not change it.

**Out of scope:** the concrete-handle refactor (8.15), timeout consolidation, the actor mailbox, any
retirement of Kotlin coroutine quirks.
