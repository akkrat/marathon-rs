# WP 2.3a findings

## Vendor-binder seam (decision 3)

WP 2.2 in `.claude/worktrees/wp-2.2` defines the seam in `crates/marathon-config/src/bind.rs`:

```rust
pub fn bind_configuration(
    value: Value<'_>,
    mut vendor: impl FnMut(Value<'_>) -> Result<Option<VendorConfiguration>>,
) -> Result<Option<Configuration>>
```

with a test stub `bind_empty_vendor_configuration` (`fn(Value) -> Result<Option<VendorConfiguration>>`)
handling only `empty`. This WP supplies the real binder with exactly that
shape: `marathon_config::bind_vendor::bind_vendor_configuration`. It handles
`Android`, `iOS`/`watchOS`/`tvOS`/`visionOS`, `macOS`, `stub` and `empty`
(case-sensitive; `iPadOS` is not registered). An absent `vendorConfiguration`
keeps 2.2's Builder default `Empty`; rejecting `Empty` at parse
(`No vendor configuration specified`) stays WP 2.4's loader staging. In the
2.2 integration step, 2.2's stub was deleted and its tests pass
`bind_vendor_configuration`; 2.2's top-level binder needed no other change
from this WP. The schema slots
conflict is mechanical: 2.2 fills the top-level types in `schema.rs` and keeps
`AndroidConfiguration`/`IosConfiguration`/`MacosConfiguration`/`MarathonDevices`
as slots; this WP removes the three vendor slots and defines the real types in
`crates/marathon-config/src/vendor.rs` (re-exported from the crate root). One
real collision to reconcile at merge: 2.2 adds `ConfigurationException`
(message only) in `schema.rs`; this WP's `validate()` definitions return
`vendor::ValidationError` (class + message) because
`SshConfiguration.validate()` throws `FileNotFoundException` (decision 8).
WP 2.4 converts either into `ConfigurationError` at stage (b). (Round 1:
the error type is now `vendor::ValidationError { class, message }` with
`configuration(..)`/`file_not_found(..)` constructors and an FQCN accessor;
2.2's `ConfigurationException` was migrated onto it at the 2.2
integration step (its `validate()`s return `ValidationError` with
`ExceptionClass::Configuration`, messages byte-identical).)

## Factory within-branch order (for WP 2.4)

`ConfigurationFactory.kt:71-131` (iOS) and `:132-188` (macOS): within one
branch the factory (1) re-resolves the bundle paths with plain
`marathonfileDir.resolve(...)`, (2) builds a fresh
`AppleTestBundleConfiguration` and calls `validate()` on it (extraction side
effects; WP 2.3b), (3) re-resolves iOS `mediaFiles` the same way, (4) computes
`devices` (`resolveAgainst` = resolve + `canonicalFile`, else
`marathonfileDir.resolve("Marathondevices")`), (5) rewrites
`ssh.knownHostsPath` and a public-key `key` via `resolveAgainst` (password
and absent authentication pass through), (6) rewrites `xcresult.pull` into
`pullingPolicy`, and only then (7) copies everything into the configuration.
`post_process_ios`/`post_process_macos` here do steps 1, 3–6 and mutate in
place instead of copying; WP 2.4/2.3b must call bundle validation at step 2's
position — observably, a bundle-validation failure precedes any
`canonicalFile` failure from steps 4–5. The Android branch consults the
environment only when the bound `androidSdk` is null (`fill_android_sdk`).

## Other notes and open questions

- Map keys are binder `String`s, not `JavaString`s (2.1 `Value::map`). A
  surrogate-carrying key is already rejected by the binder's key check under
  D9, so no information is lost at bind; WP 2.4's `toMap()` should note it.
- `WorkerConnectionConfiguration::pause_after`: approved simplification —
  saturates on `Duration` overflow (returns the capped `retryInterval`)
  where Kotlin's doubling throws `ArithmeticException`, since an
  overflowing pause is past any cap and the signature has no error channel.
  Flagged for WP 5.5b, the consumer. `pause_after` uses `wrapping_sub` so
  `attempt = Int.MIN_VALUE` does not panic.
- `XcresultQueueConfiguration::default_worker_capacity(…, 0)` returns 1
  where Kotlin throws on division by zero (approved simplification; note
  for WP 4.9, whose `ArtifactProcessor` passes caller values); `validate()`
  rejects concurrency 0 first, matching every Kotlin call path found.
  Division uses `wrapping_div`, so `MIN / -1` returns 1 as Kotlin does.
- Note for WP 2.3b: the resolved `app`/`testApp`/`xctest` fields it adds
  must stay out of `PartialEq`, as Kotlin's do.
- `AndroidConfiguration::validate` and `SshConfiguration::validate` build
  `File.absolutePath` messages against the process directory at call time
  (`std::env::current_dir`), as Kotlin's `File` does against `user.dir`; the
  stage-(b) hooks signature has no context parameter. If `current_dir` fails,
  the path as given is used in the message.
- SDK lookup with a repeated environment name takes the FIRST occurrence,
  as JVM `System.getenv` does (round 1; both `read_environment` and the
  pipeline substitution lookup); if that occurrence is empty it counts as
  unset under P2 rather than falling back to a later occurrence.
- `bind_vendor::bind_object` and the `polymorphic` flatten use
  `MismatchedInputException` for the unreachable null-subtype arm; WP 2.2's
  subtype binders return non-optional results instead. Cosmetic; the arm
  cannot fire because `polymorphic` only dispatches on maps. Worth aligning
  at merge if reviewers prefer 2.2's shape.

## Incidental bugs

1. WP 2.1's `Value::regex` rejects the Kotlin object form
   `{pattern, options}`. Orchestrator decision: NOT supported, folded into
   D9 as exotic syntax. The rejection now names the field and states only
   string patterns are supported; corpus row `nm-obj-options` pins the
   divergence (see Oracle evidence).
2. Duplicate environment names resolved to the last occurrence in both
   `read_environment` and WP 2.1's pipeline substitution lookup; JVM
   `System.getenv` takes the first. Both fixed with regressions in round 1
   (P2 still treats an empty first occurrence as unset).
