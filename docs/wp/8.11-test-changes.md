# WP 8.11 implementation and test changes

The design at `8d5cc887` was approved with group-1 and group-2 text unchanged,
no D62, and changes limited to group-3 diagnostic text. The implementation
deletes the recursive writer, the entire `jcompat::writers` module and its
export. It does not replace that tree with another generic value enum.

## Renderer owners

- `marathon-core/src/filter/annotation.rs`: `annotation_text` and `decoded_text`,
  re-exported by `filter/mod.rs`. Their doc comments define the `annotationData`
  grammar. The existing `AnnotationRenderer` adapter and matching/extraction
  control flow stay. Both float formatters remain in `jcompat::jnum`.
- `marathon-config/src/render.rs`: the private `ResultText` trait and local
  record/list/map joins produce the same 23 ordered `Configuration::to_map`
  entries. Existing field order, scalar/time/regex formatters, nulls, enum and
  class names, omissions, path handling and secret overrides stay.
- `marathon-core/src/report/projection.rs`: `metadata_text` delegates to the
  annotation grammar. `RawJsonReporter` keeps its separate top-level unboxed
  null → empty string rule; decoded null remains the string `null`.
- Android `runner.rs` and Apple `apple_device_test_runner.rs`: result-bearing
  messages retain explicit unquoted `join(", ")` lists. They do not use Debug.
- Historical Apple Test/event strings live only in
  `marathon-apple/tests/support/rendering.rs`. The ADB parser's historical
  adapter stays inside its existing test module. Both format explicit fields
  into strings and keep the copied witnesses unchanged.

commands retain their existing contracts.

as well as formatting, clippy, workspace/vendor tests and the plan, source and
parity inventories. No re-bless or normalizer change is part of this WP.
