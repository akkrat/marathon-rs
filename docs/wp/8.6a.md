# WP 8.6a: Typed error kinds instead of Java class strings

Effort **H** (wide, mostly mechanical, with about 40 behaviour points). Branch `wp/8.6a-typed-errors`,
based on `main` after WP 8.5 (commit `90f60aa2`). The first of two WPs; 8.6b changes the rendered text.

## Why

Phase 8 removes Java emulation while keeping the contract in PLAN.md §3.12. Errors are still modelled as
Java exceptions: `marathon_core::error::Failure` carries `class: String` (`"java.io.IOException"`,
`"kotlinx.coroutines.TimeoutCancellationException"`, ...), and several other types do the same
(`marathon-adb`'s `JavaThrowable`, the Apple SSH layer's `SshFailure`, `marathon-dex`'s
`DexError::jvm_class`, the class names inside `ConfigurationError`). A survey found 123 distinct class
strings in 462 literals across 116 source files, and about 40 places that **decide behaviour** by comparing
a class string or matching message text: retry, cancellation, device lost, swallowing an error, Influx
retries.

This WP replaces the strings with typed kinds and moves every decision onto the types. **What is printed
does not change**: every rendering produces the same bytes as today, through one legacy mapping per kind
type that WP 8.6b will replace with plain wording.

## Scope

### 1. Typed kinds

- `Failure.class: String` becomes a typed kind (`kind: ...`), and the other representations above get
  the same treatment. Kinds are **closed Rust enums** named by meaning (`Io`, `Timeout`, `Cancelled`,
  `IllegalState`, `Ssh(SshKind)`, ...), never by Java class. Sub-enums are fine where a domain has its own
  set (SSH, ADB, config, DEX).
- No `dyn Any`/downcasting, no trait objects in `Failure`; `Failure` stays `Clone + PartialEq + Eq` with
  its cause chain, message and `stacktrace` as today.
- **Layering**: `marathon-adb`, `marathon-dex` and `marathon-config` do not depend on `marathon-core`;
  keep it that way. Choose where each kind lives so the existing crate graph still holds (for example a
  core variant that wraps a small vendor-neutral kind, with the vendor crate converting at its boundary).
  Describe the choice in the milestone-1 design note.
- **Each kind has exactly one legacy rendering**: a `legacy_class(&self) -> &'static str` (or similar)
  per kind type, returning today's Java class name. `to_java_string`, `stack_trace` and every other place
  that prints a class name go through it. After this WP the Java class strings exist in production code
  **only** inside those mapping functions (plus the parse boundary below), so 8.6b can delete them in one
  place.
- **Text from outside the process stays opaque.** Instrumentation stack and `shortMsg`, runner output,
  logcat, XCTest and xcresult text keep their class names as text; do not parse them into kinds. If a
  `Failure` is built from such external text and must carry its class name verbatim, give it one
  explicit variant for that (for example `External(String)`), used only where the class name really
  comes from outside, with a one-line comment at each construction site.
- **Parse boundary**: replay tapes and other recorded inputs that contain class strings are copied
  fixtures and stay as they are. Convert class string → kind once, where the tape is read; an unknown
  string there fails the same way an unknown tape value fails today.

### 2. Every behaviour selector moves onto the types

Every place that compares a class string, checks a class prefix, or matches message text to decide what
to do is rewritten to match on the kind (or, for library errors, on the library's typed API). Same
decisions in every case. The survey's list (line numbers as of `90f60aa2`; grep for more, the list is a
start, not the scope):

- Core: `executor/shared.rs` (the main funnel), `screenshot.rs:383,388`, `event_pipeline.rs:242`,
  `artifact_io.rs:69`.
- Android: `support.rs` (funnel, `:54`), `provider.rs:985`, `runner.rs:513`, `device.rs:513`,
  `installer.rs:200`, `remote_parser.rs:87`, `transfers.rs:107,117,176,565`.
- Apple: `cmd/mod.rs` (funnel, `:161,171`), `nm_test_parser.rs:120`, `test_root_factory.rs:63-65`; SSH:
  `error.rs:65,212,220,238,241,244,248,256`, `executor.rs:152`, `connection_factory.rs:423`,
  `connection_failures.rs:22,40`.
- iOS: `execution.rs:202,221`, `prepare.rs:64`, `boot.rs:123`, `source.rs:54`. macOS:
  `device.rs:507,513,529,558`, `provider.rs:136`.
- `jcompat/src/throwable.rs:6` (JVM `Error` vs `Exception` distinctions) and its consumers: replace with
  a property of the kind; delete what is left without callers.
- Analytics: the message matching in `http.rs:290,336` and `influx.rs:311` (retry decisions), and
  `influx.rs:202`, `influx2.rs:169`. Find out exactly which errors the matched text recognises today and
  decide on the typed source (`reqwest::Error::is_timeout`/`is_connect`, `io::ErrorKind`, a status code)
  with the same outcome for each of those errors. Pin each with a test that fails if the decision changes.
- Config: `bind.rs:231,238`, `binder.rs:122,133,165,533`, `pipeline.rs:82`. DEX: `error.rs:78`.
- CLI: `application.rs` (funnel). Exit-code mapping is already typed; keep it so.
- Test support: the selectors in `marathon-test-support` (for example `stub_device.rs:348`).

Keep the existing distinctions: cancellation scopes (`Cancellation::Timeout { scope }` and friends), the
`VendorError` classification, the SSH, ADB and config subkinds, and cloneable cause chains.

### 3. Nothing else changes

- Every log line, result file, config-dump output (`cli/config_dump.rs:171` writes error JSON) and
  message text is byte-identical to `90f60aa2`. The pinned progress/summary lines, exit codes and goldens
  do not change.
- Out of scope: the rendered wording (8.6b), external text, `KotlinValue`, the YAML writer.

## Rules

- **The gate is the proof.** `scripts/check.sh` passes with the native goldens
  (`fixtures/contract/native-v1`), the config corpus golden and every oracle suite unchanged:
  `git diff 90f60aa2 -- fixtures/` is empty. No D-row; if you find a decision or text you cannot keep
  identical, stop and report it.
- Tests: constructing a `Failure` from a class string becomes constructing it from a kind; asserting on
  `.class` becomes asserting on the kind. Expected **rendered text** in tests does not change. List the
  changed test files (not every function) in `docs/wp/8.6a-test-changes.md`, with any test whose
  assertion changed meaning named individually and explained. No parity row changes.
- Never edit a copied fixture under `fixtures/`; add new files instead.
- Keep `//! Port of ...` headers and comment density. Where a comment explained why a class string was
  compared, keep the why on the typed match.
- No `unwrap()`/`expect()` on I/O, process or network results.
