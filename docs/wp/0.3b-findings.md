## Binding orchestrator decisions

1. Switch to the brief's fallback: port SnakeYAML 2.2's reader, scanner and
   parser in Rust, preserving source attribution and Apache-2.0 terms.
   Keep saphyr only as a comparison baseline; measure port size and recommend
   whether WP 2.1 should reuse it.
2. Store scalar text as UTF-16 units or WTF-8, including lone surrogates;
   move the Java string primitive into jcompat for production.
3. Accept bytes and decode like Kotlin `readText()` with JDK malformed UTF-8
   replacement. Generate oracle rows for the decoding rules.
4. Enforce depth during construction, preserve lazy failure ordering and
   bound or eliminate recursive drop. Regress 50,000-level nesting in a child.
5. Implement Unicode digit, hex-float and Double formatting probes here;
   move the primitives into jcompat in WP 1.2/1.x. Validate the formatter
   against the WP 0.2a table.
6. Compare marks by role and require their presence. Prove missing/swapped
   marks fail, and fix both UTF-8 slicing sites.
7. Turn every reproduction into generated oracle rows. Keep 100% token and
   simple-binding agreement as acceptance, and report saphyr's score.
