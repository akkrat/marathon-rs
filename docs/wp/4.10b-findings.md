## Implementation and consumer handoff

**Changed merged crate: marathon-apple only.** New
`apple_application_installer` module and export; additive
`distributed_derived_data::require_distributed_test_bundle` and private remote
path helper. Existing `require_distributed` behavior is unchanged. No core,
config, jcompat, test-support, fake-worker, dependency or lockfile changes.
The existing factory integration test's narrow device and helpers moved into
`tests/support/test_root_device.rs` for reuse; its nine tests still pass.
No 4.5b commits were rewritten and no factory production code was changed.

`AppleApplicationInstaller::new(configuration, runtime, logging)` defaults to a
no-op hook. `with_after_install(&hook)` accepts an `AfterInstall` owner capturing
its concrete device; its future returns `FactoryResult<()>`. 5.2/5.6 supply
permission hooks without core downcasts. Call
`prepare_installation(device, use_xctest_parser, context).await` on the vendor
runtime through the bridge, and await completion. The factory adapter remains
intact for vendor-local failure-reason classification before `into_vendor`.

Initial upload uses the existing `with_retry_send(3, 1000, ...)` and the supplied
VendorClock. The last vendor error variant is retained through that helper's
OperationError seam. Cancellation propagates without retry; delay failures keep
their own error. Each attempt repeats both mkdir calls. Test-root generation,
after-install, and ordered extra apps follow the original boundaries. The
Kotlin logger name and messages go through the existing jcompat logging layer;
interpolated serial/path strings use JavaString/JavaPath.

`require_distributed_test_bundle(device, bundle, runtime, error_constructor,
context)` returns the remote xctest path. 4.8 supplies TestParsing; the installer
supplies DeviceSetup. It reuses the 4.5b shared check helper and jcompat's general
relative_file implementation, including the non-descendant witness. The runtime
argument keeps cwd lookup off core. Runner binary precedes test binary checks;
both errors name the local runner application. The PlugIns copy rule remains
solely in 4.5b and is witnessed end to end here.

## Decisions, limitations and open review items

P1 needs no prefix-only shortcut because jcompat already supplies the general
relative path behavior. The PLAN row now says this WP witnesses 4.5b's PlugIns
rule. No production behavior deviation is proposed.

The oracle's `no-result` case uses reflection to null Kotlin's nonnullable
xcresult field. Rust's config cannot represent that state, so its defensive
second guard remains but only this reflection-only row is not replayed. The
other two configuration guards and their order are replayed. This is a type-
representation limitation, not a skipped matrix row or an exposed config change.

inputs; the two DerivedData cases additionally run real validation in both
languages. Parser implementation remains with 4.8, permission behavior with
5.2/5.6, and Linux remote-check and independent reviews with the orchestrator.

No implementation-blocking question or disproportionate requirement remains.
