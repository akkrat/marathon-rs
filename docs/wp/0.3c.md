# WP 0.3c: regex spike, the Java regex backend

**Owner:** Opus, medium effort. **Reviewers:** Sol and Muse. **Depends on:** 0.2a (the corpus).

Read first:
- `CLAUDE.md`;
- PLAN.md §4.2 (regex row), §4.3, D6 in §3.11, and WPs 1.4 and 2.1;
- `docs/research/regex.md`: the use sites, the gap table, the translator design and the corpus plan;
- `fixtures/oracle/regex-corpus.jsonl`, about 400 rows of JDK 21 ground truth over families 1–11 plus `flag-scope` and `split`, including watchdog `aborted` rows.

## Goal

Choose the engine behind `JavaRegex`, and fix the list of Java constructs we reject (D6). The engine must reproduce `java.util.regex` as Kotlin marathon uses it: `matches` (full match), find, Kotlin's `split`, and compile errors.

## Deliverables

1. **`spikes/java-regex/`.** A standalone Cargo package, excluded from the workspace, with three candidate backends behind one trait:
   - **(a) `java_regex` 0.1.0** (crates.io, claims byte-for-byte JDK compatibility);
   - **(b) `fancy-regex` 0.19.x plus our own translator.** Its design is in `regex.md` §3: ASCII `\d\s\w\b` by default, inline-flag scoping by walking segments, Java line terminators, `$` before a final terminator, `\Q…\E`, `(?u)`, possessive and atomic constructs;
   - **(c) `pcre2` 0.2.x** (a C dependency).

   Each has an explicit backtracking or step limit that maps to "aborted".
2. **Corpus runner.** Each corpus row is run on each backend. For each row it compares:
   - whether the pattern compiles;
   - the error class for invalid patterns (only the Java exception class has to match; Java's message text doesn't);
   - full-match, find (with group spans if recorded) and split results;
   - add one corpus row for Kotlin `Regex.split(input, limit)` with `limit > 0`, which drops trailing empties. Generate it with the 0.2a regex tool and commit it with the spike.
   - aborted rows: the backend must give up as well, within a bounded time, and not hang.
3. **Audit of `java_regex`:** code size, `unsafe`, panics on hostile input (fuzz briefly with `cargo fuzz` or proptest over the corpus patterns), test suite, licence, maintenance activity, and the Unicode table version against JDK 21's.
4. **`docs/research/regex-spike-results.md`**, with the decision at the top:
   - the chosen backend and its exact pin;
   - pass rates per backend and per family;
   - each divergence, with its cause and whether it's fixable;
   - **the D6 list:** the Java constructs we reject at config load, each with the exact rejection message from `regex.md` §3, a reason, and the corpus rows that show it;
   - the design for WP 1.4's `JavaRegex` API (`matches`, `find`, `split`, compile errors with the Java exception class).

## Acceptance

- **The chosen backend:** 100% agreement on every corpus row except those it rejects under D6. Any other exception must be listed and approved by the orchestrator.
- **No hangs:** every aborted row is bounded on every backend.
- `scripts/check.sh` passes; the spike is outside the workspace. Branch `wp/0.3c-regex-spike`.
- If `pcre2` needs a system library or C toolchain that the Linux box (`scripts/remote-check.sh`) lacks, say so. The chosen backend must build on both targets.
