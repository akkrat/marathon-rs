# WP 8.6b test changes

All copied fixtures and historical JVM captures stay unchanged. No Kotlin test or
parity row is deleted or made `n/a`. Selector behavior, cause order, messages,
retry policy, statuses, paths and progress/summary output stay checked. The
native generated-error golden remains exact.

## Assertion changes beyond literal wording

- Oracle classifications now compare `FailureKind` values decoded through the
  recorded-input whitelist. Serialized observations use the bijective, explicitly
  pinned stable kind identifiers. This changes test representation, not the
  accepted classification set. Influx v1 comparisons that formerly checked only
  the class compare `dedup_key()` (category without retry metadata); the separate
  retry-disposition assertions remain.
- `config_dump_matches_the_jvm_goldens` checks the approved `class` to `kind`
  schema change and ordered cause descriptions in the generated error slot;
  every byte outside that slot remains compared. `cli_matrix_matches_the_reference_build`
  maps only that slot or the generated uncaught envelope. The Python config
  replay preserves its original configuration/filesystem comparisons and message
  allowances; `native_error_self_test` rejects changed kinds, cause counts and
  external-message text, as well as unknown classes.
- `debug_embedded_in_clock_failure_messages_keeps_legacy_fields_and_causes` is
  replaced by `debug_uses_typed_fields_and_display_uses_the_description`: the
  obsolete Debug `class` field becomes a typed `kind` field. The actual SSH
  fallback is covered by the new
  `a_clock_failure_message_uses_display_and_keeps_external_message_text`.
- `every_recordable_legacy_kind_round_trips_through_the_whitelist` becomes
  `every_recordable_kind_has_a_whitelisted_name`, retaining exhaustive enum
  coverage without requiring a production name renderer. The new
  `every_whitelisted_name_parses_and_identifiers_and_descriptions_are_unique`
  covers the other direction and uniqueness. Existing v1 category/retry and
  invalid-recording assertions stay typed and exact.
- `io_funnel_kinds_preserve_each_legacy_class_and_message` is renamed
  `io_funnel_kinds_preserve_each_description_and_message`;
  `file_open_and_clock_funnels_keep_their_distinct_legacy_names` becomes
  `file_open_and_clock_funnels_keep_their_distinct_descriptions`.
  Their I/O categories, messages and distinct replay kinds remain checked.
- New boundary regressions
  `generated_class_is_mapped_but_external_class_inside_its_message_is_not` and
  `generated_error_object_keeps_external_class_text_inside_the_message` keep
  external class names verbatim.
  `cli_error_comparison_keeps_external_class_names_in_message_lines` pins both
  a root message and a generated cause message containing a class-looking continuation.
  The CLI matrix declares its six cause-bearing rows explicitly; the adapter maps
  one known generated header and copies the remaining message whole.
  `class_looking_continuation_lines_in_messages_are_not_cause_headers` additionally
  checks that a message continuation beginning with `Caused by:` stays opaque.
  The milestone-1 test
  `test_native_only_scenario_rejects_a_historical_jvm_capture` remains.
- `a_malformed_test_duration_escapes_as_a_typed_error` additionally pins the parser
  error's Display; its typed failure assertion remains. The parser error delegates
  to its projected Failure instead of formatting Debug.
- `every_concrete_kind_displays_its_approved_description` pins all 208 literal
  descriptions and identifiers independently of production tables;
  `validation_aliases_display_the_projected_kind` pins delegation and External
  text is checked verbatim.

The named-test inventory below includes all tests in files that use the typed
oracle adapters, including helper-driven cases. It is a conservative inventory;
not every assertion in those files changed beyond wording. No assertions on
unrelated values, order, messages or output structure are removed.
