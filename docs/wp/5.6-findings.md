## Shared crate changes — integration handoff

- **marathon-core:** `VendorDependencies` now carries `logs: LogSender` and
  `wall: WallSource`. `construction.rs` supplies the run's existing sender and
  wall source. These are required by TestResultsListener and the Apple logging
  sink; no separate console or clock is created. Other vendor constructors must
  populate these two fields if they construct dependencies themselves.
- **marathon-apple:** `AfterInstall::after_install_on(device, bundle, context)`
  is a provided hook that defaults to the original `after_install`. The shared
  installer calls it at the same point. Existing hooks remain compatible; the
  macOS hook resolves the concrete allocation by pointer identity through weak
  registrations, including when XCTestParser shares one installer across hosts.
  `bin::kt` is public so macOS uses the existing Kotlin whitespace semantics.
- **jcompat:** `KotlinValue::object` centralizes D12/F29's stable class-name hash
  rendering for Local transport and replacement-device log messages.
- **marathon-cli:** the macOS production vendor slot calls `marathon_macos::construct`.
  Other vendor slots retain their previous behavior. Construction selects both
  nm and xctest parsers, shares the registry/identifier/installer, and does no
  connection or discovery work. No dependency on the iOS vendor was added.

The core lifecycle interfaces otherwise remain unchanged. Vendor futures run on
I/O via the existing bridge; no core-side filesystem/process operations were
introduced. Per-device tasks and sessions have explicit owners. Preparation
continues if its awaiter is cancelled. Disposal shares one retained completion;
a dropped waiter cannot abandon it. Caller-cancel join and later disposal each
have a full independent budget. `join_pending` is an explicit test/final-owner
drain, never part of bounded disposal. Provider initialization cancels sibling
work after its first failure and waits for settlement. A89 leases remain owned
without extra factory-release calls; termination releases only current devices.

## Behavior and decisions

- Defaults are 60 seconds for shared session close and 70 seconds for cancelled
  batch join (the former plus 10 seconds), with both injectable.
- Result completion and execute completion remain independent. Listener order
  is results, log adapter, debug, diagnostic, session, no-op recorder, then the
  shared ResultBundleRunListener with processor `None`. Pull/rename/remote clean
  remain inline. Diagnostic/session/debug are the extra line listeners.
- Every non-incompatible DeviceFailure drops the device; there is no iOS
  BatchFailurePolicy, retry counter, dynamic discovery or reconnect feature.
- Provider parsing uses P2, whole-Transport overwrite, filtering after overwrite,
  provisioning-UDID fallback, the shared consuming event queue and replay borrow
  hook. Setup order and command options are compared against the JVM transcript.
- Permission tests keep A18 (exact-line SIP detection), A85 and A86. Commands use
  the existing sqlite wrapper, including ignored sudo. SQL clock reads occur once
  per client; negative millis truncate toward zero. Empty grants skip SIP.
- P1 omits dead scaffolding; P2 returns the typed Kotlin NotImplementedError from
  all six unsupported operations; P3 uses the shared vendor runtime and replay
  selection, preserving per-device order without JVM dispatcher/hash scheduling.
- **A87 not reproduced (P4):** Kotlin interpolates `com.example."broken` directly
  into SQL; the `bad-client` JVM row witnesses malformed SQL. Rust rejects double
  quotes and control characters before sending SQL. No host TCC/SIP/settings
  were read or modified. All permission operations were recording fakes.
