## Deliverables and boundary

In `crates/marathon-ios`, plus the policy in `crates/marathon-apple`:

1. **`AppleSimulatorDevice`** (`D`, 1,209 lines): one `Arc` allocation implementing frozen `Device` + `AppleDevice` + `Screenshottable` + `LogProducer`, and 5.4's `SimulatorSetup`. Explicitly constructed (deliverable 5); constructing runs no setup and no I/O. Internal state under one short lock (Kotlin `executionLock`, `D:157–165`): disposal cell, running-batch handle, `lost`/`retired` flags, `previous_batch_finished_at`, `last_xcodebuild_session`. No lock held across an await, command, callback or log call; no blocking call on core; the device dispatcher is the vendor runtime (`deviceThreads`, `D:193–199`), and `Drop` performs no observable cleanup (lifecycle.md).

Public `boot()`/`monitor_status()`/`shutdown(udid)` (`D:938–962`) stay as the internal surface 5.5a/b call; audit their Kotlin callers and keep exactly those.

## Behaviours to reproduce (`D` unless stated)

- **Identity and info** (`:166–201`): serial `"<udid>@<host.id>"`; `DeviceInfo` snapshot is fresh per `info()` call (model-contract), with setup-filled model/manufacturer `"Apple"`/OS/features/abi; `healthy` is the constant `true`, so `network_state` is always CONNECTED (candidate A72). `workerId` is the transport id (4.10a `apple_worker_id`); `arch` recomputes per 4.10a/A45 after setup changes the ABI.
- **Setup** (`:222–290`): facts first, once per cycle through the context. `home` = worker `env["HOME"]`, else `getenv SIMULATOR_HOST_HOME`, else `""` — blank throws `DeviceSetupException("simulator <udid>: invalid value  for environment variable HOME")` (note the empty interpolation). If `getenv HOME` (simulator) returns null the record is re-looked-up **fresh** (`:237–241`, the deleted-simulator guard the context rows pin); `rootPath` strips a trailing `/data` via `substringBefore("/data")` — the *first* occurrence, anywhere (candidate A70). `deviceType` falls back inventory → device.plist `deviceType` (trimmed) → `DeviceSetupException(… unable to detect deviceType)`. Order of the `getenv`s (`SIMULATOR_MODEL_IDENTIFIER` defaulting to deviceType, runtime build/version, version info) is command-visible; keep it.
- **Worker facts** (`:270–290`, the 5.4 contract): `env`, Xcode version, `uname -m`, `/usr/sbin/system_profiler -detailLevel mini -xml SPDisplaysDataType`, and, only when transcoding is enabled, `<transcoder> -version` — sequentially, in that order. `shareable` iff every probe *completed with an exit code* (nonzero is shareable; null result/exit is not). `arch` is the trimmed stdout of a *successful* `uname` else `"Unknown"`; features per `detectFeatures` (`:984–997`: VIDEO iff a displays line contains `spdisplays_metalfeatureset` or `spdisplays_metalfamily`, and only on success; SCREENSHOT unconditionally — enum order preserved); transcoding iff enabled **and** the probe succeeded. `fetchEnvvars` (`:1057–1078`) throws `DeviceSetupException(… unable to detect environment variables)` on a non-success `env`, trims each line, splits on the first `=` (a line without one maps to itself as key *and* value — candidate A71).
- **Prepare** (`:335–400`): `artifactProcessor.await(serial)` **before** anything removes the storage directory, `keptSources` become `removeRemoteDirectory(keep)` (insertion order; A46 glob semantics stay in 4.10a), then, inside `track.trackDevicePreparing`, create device + shared dirs and run `pkill -f 'simctl io <udid> recordVideo'` (argv exactly as at `:351`, result ignored). Installation (`prepareInstallation`, then build `AppleTestBundle` or `IllegalArgumentException("No test bundle provided")`) and simulator steps (`handleLifecycle(onPrepare)` → `disableHardwareKeyboard` → `bootForPreparation` → media import) run **in parallel** under a supervisor scope; both are awaited, and `Timings` logs `Simulator <serial> prepared in <T> ms: cleanup <C> ms, installation <I> ms, boot <S> ms` with `measure` (`:402–406`) wall-`Timer` reads — three separate elapsed reads, not one. A `BootFailure` marks the device lost and leaves as `NotBooted("Simulator <udid> on worker <host> is taken out of its pool: <msg>")`; caller cancellation cancels the detached preparation and rethrows **without joining it** (a boot wait stops at its next poll — retain the task handle, U55). The `admission` check runs last, is cleared before it runs, and a reason retires the device and throws `NotAdmitted("<serial> is not admitted to the run: <reason>")`.
- **Boot** (`:858–916`): exactly `BOOT_ATTEMPTS = 2`. Per attempt: deadline = start + `bootWait` (monotonic, through the nondeterminism labels); BOOTED ⇒ done; CREATING/BOOTING ⇒ poll; SHUTDOWN ⇒ `simctl boot` — a `CommandException` there is survivable iff a re-check finds BOOTING/BOOTED, else the failure text is `simctl boot failed (<e.message lines trimmed, joined with " ">), its state is <STATE>`; UNKNOWN ⇒ `its state is UNKNOWN` at once, no boot command. Polls check *immediately*, then delay `min(1 s, ceil(remaining_ms))` (the `(left + 999_999)/1_000_000` rounding at `:909`); a check landing on BOOTED at/past the deadline still succeeds; in-flight commands keep their own timeouts past the deadline. Timeout text: `it has not booted within <bootWait as Java Duration>, its state is <STATE>`. Between attempts: WARN `Simulator <udid> on worker <host> failed to boot: <failure> after <ms> ms, attempt <n> of 2`, `shutdownAfterFailedBoot` (skipped when device.plist state is 1; budget `shutdown + shell`; timeouts/exceptions only WARN, cancellation rethrows), 10 s pause (injectable in tests); after attempt 2, `BootFailure("it failed to boot: <reason>")`. State comes from device.plist `state` re-read **uncached** per check (`:963–982`: 0 CREATING, 1 SHUTDOWN, 3 ⇒ BOOTED iff `isRunning` (SpringBoard probe, A41) else BOOTING, anything else/missing/wrong-typed UNKNOWN — candidate A73). `waitForState` (`:999–1020`) keeps its fixed 30 × 1 s defaults regardless of configured timeouts (candidate A74).
- **Lifecycle** (`:408–427`): TERMINATE (ps/pkill pipeline, `:1125–1148`), then SHUTDOWN-before-ERASE sharing one `shutdown()` call when both are set; failures are WARN `Exception shutting down/erasing simulator <udid>`, successes INFO. `shutdown()` (`:822–838`) is true when already SHUTDOWN, false on UNKNOWN without a command. `erase()` (`:839–856`) proceeds on SHUTDOWN/UNKNOWN without shutting down. Keyboard (`:1150–1163`): PlistBuddy `Add` then `Set` of `:DevicePreferences:<udid>:ConnectHardwareKeyboard` = false, both always, results ignored, then the DEBUG line.
- **Execute** (`:428–516`): the batch runs as a **lazy** job on the device scope. Under the lock, a disposed device cancels the unstarted job and throws `DeviceLostException(IllegalStateException("Device <serial> has been disposed"))`; otherwise the job is registered (completion clears the registration only if it is still that job). Idle-gap DEBUG uses `previousBatchFinishedAt` (set in `finally` on **every** exit, including the disposed rejection). Classification, in source order: `DeviceLostException` from the runner ⇒ retired, rethrown; idle `TimeoutException` ⇒ policy `onBatchCompleted(progress)` may lose it (the timeout is *suppressed* onto the policy's exception — vendor-local suppressed list, flattened at the boundary as in 4.8 decision 4 / 5.4), else rethrown; normal completion ⇒ same policy check; `CancellationException` ⇒ `joinCancelled`, then `DeviceLostException(e)` if the *caller* is still active (e.g. disposal cancelled the batch) else the cancellation itself; sshj `ConnectionException`/`TransportException`/`OpenFailException` and any other `IllegalStateException` ⇒ lost + `DeviceLostException(e)` (map from 4.2/4.3's `Failure` classes, P5); `DeviceFailureException` ⇒ policy `onBatchFailed` (retired if the reason is in `failuresNotFixedBySetup` = {SystemAppUnavailable, IncompatibleDevice}, `:115`, else lost); kept ⇒ WARN `Test batch <id> failed on <serial>, keeping the device` — but with **no completed results** it is `TestBatchExecutionException(e.message ?: e.reason)` instead. Progress = any *finished or failed* test in the completed deferred (`hasFinishedTests`, `:562–567`; an exceptionally completed deferred is no progress). Permissions with `BEFORE_EACH_BATCH` are granted inside the job, after listener registration, before the runner (`:445–449`).
- **`BatchFailurePolicy`** (`B/device/BatchFailurePolicy.kt`): non-batch failure ⇒ lost immediately; batch failures count to **3** in a row with no passed test (a passed test resets; any completed batch resets); `maxBatchesWithoutProgress` (default 0 = off) loses after that many consecutive progress-less batches, however they ended, with cause `IllegalStateException("No test has passed or failed in <n> batches in a row")`, and is checked *before* the passed-test reset in `onBatchFailed` (the failure is suppressed onto it). Not thread-safe in Kotlin (plain `var`s) and only ever touched from `execute` — keep it behind the device lock or the execute job, do not add atomics that change interleavings.
- **Session gating and lost/retired** (`:291–333, 526–567`): `markLost` upgrades to retired when the last session exists and is not `closed`; `retired` also reads true when that session is `abandoned`, even if the flag was never set. `lost` is false once retired or disposing. The anonymous first listener in the composite retires the device **at `testRunFailed` time** for the two not-fixed-by-setup reasons (`:649–655`), before the batch unwinds — this is what the "even if its run is cancelled" row pins. `awaitSessionClosed` with no session is true.
- **`joinCancelled`** (`:517–525`): cancel, then join NonCancellable for `cancelledBatchTimeout` = session-close (1 min) + 10 s grace; still running ⇒ WARN `Cancelled batch on <serial> has not finished within <timeout>, taking the device out of the run` and retire — the batch itself is **not** joined further (retain its handle; lifecycle.md:241).
- **Dispose** (`:568–608`): synchronous Kotlin `dispose()` blocks and only DEBUG-logs failures; the frozen async adapter awaits at the same call sites. First caller creates the disposal cell under the lock and captures the running batch; later concurrent callers await the same cell. The batch is `joinCancelled` *before* `onDispose` lifecycle, which runs only when `commandExecutor.connected`; lifecycle failures are DEBUG `Error closing command executor` (yes, that text). The device dispatcher is closed even when lifecycle failed; the cell completes in `finally` whatever happens. Disposal does **not** close the shared executor or touch the artifact processor (the artifact row pins in-flight transfers surviving).
- **Listener assembly** (`:609–677`), composite order is observable: retire-on-dead-system-app marker, `TestResultsListener` (4.7; gets `xcodeVersion` from setup), log listener (`XCODEBUILDLOG` attachment), `DeviceLogListener` (5.3), `DebugTestRunListener`, the diagnostic/session path finders, recorder listener (5.3; `RecorderTypeSelector` over setup's features, `supportsTranscoding` passed through), `DataContainerClearListener` (5.3), `ResultBundleRunListener` (4.9, always with the run's processor here). Attachment providers accumulate in construction order (recorder, then log — note the source adds the recorder first). Line listeners are exactly {diagnostics finder, session finder, debug printer}, added before permissions and removed in `finally`.
- **Transfers and worker commands** (`:711–771`): shell/shellIdle timeouts; `measureFileTransfer`/`measureFolderTransfer` wrapping (3.9a's merged helpers); `pushGeneratedFile` takes the `WriteFile` shortcut only for SSH transports with `ssh.debug` off and `len ≤ MAX_WRITTEN_FILE_SIZE`, falling back to the bridge on a false write; `pushShared` keys on `transport.id()` (A37). `install`/`importMedia` are the simctl wrappers' `successful`.
- **Media, screenshot, permissions** (`:773–821, 1165–1197`): video start passes config codec/display/mask + pidfile; stop is the `kill -s INT $(cat …) && lsof …` shell string, WARN + false on failure, pidfile removed only on success. `getScreenshot(timeout, dst)` never uses `timeout` (candidate A75); the image overload stages through a temp file with the config-type suffix (jpeg ⇒ `.jpeg`) and deletes it in `finally` — in Rust this is `Screenshottable::screenshot` returning the decoded frame (frozen). `grant`: UserTracking/Pasteboard go through a sqlite3 `replace into access …` against the TCC db under **`env["HOME"]`** (not the validated `home`) and return **true unconditionally** (candidate A69); everything else is `simctl privacy grant`. `clearAppContainer` terminates, then removes the *trimmed combined stdout* of `get_app_container data`, WARN with raw stdout/stderr on failure.
- **Logs**: logger `com.malinskiy.marathon.apple.ios.AppleSimulatorDevice` via the jcompat registry; `Timings` at INFO with the ` (+N ms since start)` suffix from a separate Timer read (as 5.4 does).
