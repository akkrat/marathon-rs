# YAML spike results (WP 0.3b)

**Historical report. WP 2.1 promoted the parser to `crates/snakeyaml`, replaced the prototype binder with `crates/marathon-config`, and deleted `spikes/yaml-node` (including the saphyr baseline). Current commands, D9 policies and scores are in [2.1-findings](../wp/2.1-findings.md).**

**Decision: use the Rust port of SnakeYAML 2.2's `StreamReader`, `ScannerImpl`
and `ParserImpl`, in `spikes/yaml-node/src/snakeyaml/`, for WP 2.1.** The
round-1 reviews showed scanner differences that saphyr adapters could not
reliably close. This is the brief's fallback, selected by the orchestrator.
The default loader now uses the port. Vendored **saphyr-parser 0.2.1** remains
only as the comparison baseline; it is not the recommended parser.

**Parser and token parity is this spike's deliverable.** Its binding layer is
**a prototype for corpus comparison only**. The known binding gaps are listed
for WP 2.1 in [the round-3 findings](../wp/0.3b-findings.md#round-3-carried-to-wp-21);
they must become required tests for the real Jackson-compatible binder. Under
PLAN §8.2, the orchestrator explicitly carried R3-sol-2 through R3-sol-8 there.
The prototype does not satisfy general Jackson binding parity.

Measured agreement before the round-3 additions: **2,824/2,824 token streams** (including
exception classes and required marks by role), and **1,694/1,694 simple
binding rows**, each with 13 targets. These are corpus measurements, not a
claim of equivalence for every possible input. The previous claims that
saphyr accepts a strict superset of Jackson's language and that formatted
patch application reproduces the vendor tree byte-for-byte are withdrawn.
Unicode line breaks disprove the former; scanner comment wrapping differed
in the latter investigation.

## Implementation and source

The port follows SnakeYAML 2.2's reader operations, simple-key bookkeeping,
fetchers, scalar/tag scanners and parser productions. Java production objects
become explicit Rust states; tail transitions use a dispatch loop. As on the
Jackson default path, `processComments=false`: comments are read and checked,
but comment tokens/events and comment-only productions are omitted. Trivial
sequence/mapping and literal/folded wrappers share their parameterized
fetcher. `Composer` and constructors are deliberately absent: Jackson bypasses
them, so neither alias expansion nor SnakeYAML's composer depth limit applies.

Source: Maven Central `org.yaml:snakeyaml:2.2:sources`, SHA-256
`8f7cf911cf63db55fd980a926d155bd846317737351a2f48ef1c1088c414538a`.
Every ported module names its source and version. The Apache-2.0 attribution
is retained in `src/snakeyaml/LICENSE` and module headers.

The three original Java files have 3,607 lines, including their extensive
comments. **WP 2.1 should take the reader/scanner/parser implementation as
is for the default path**, keep its oracle tests, and integrate the Node and
error interfaces below. The minimal binder is a corpus-comparison prototype, not
the full Configuration binder. Move the Java primitives to jcompat rather
than making YAML own them permanently.

`float_roundtrip`, and `sha2 =0.10.9`. `float_roundtrip` matters in this runner:
otherwise decoding the oracle's JSON numbers can introduce one-ULP differences
before any YAML comparison. The original saphyr vendor tree and its patch are
retained unchanged as evidence.

## Final Node and token contract for WP 2.1

```rust
struct JavaString(Vec<u16>); // authoritative text; lone surrogates are valid
struct Mark { index: usize, line: usize, column: usize }
struct Span { start: Mark, end: Mark }
struct Node {
    kind: NodeKind,
    anchor: Option<String>, tag: Option<String>,
    span: Span,                 // whole node
    opening: Span,              // actual scalar/alias/start event
    closing: Option<Span>,      // actual collection end event, if read
}
enum NodeKind {
    Scalar { text: JavaString, style: Style },
    Seq { items: Vec<Node>, complete: bool },
    Map { entries: Vec<(Node, Node)>, complete: bool },
    Alias { name: String },
    Cut,
}
struct Document { explicit_start: bool, root: Node }
struct Stream { documents: Vec<Document>, error: Option<YamlError> }
```

These types and invariants are implemented:

- Mapping entries preserve source order and duplicates. Tags retain resolved
  handle plus suffix; anchors and aliases retain names. Aliases never expand.
  Empty explicit documents contain the empty plain scalar; empty input has
  no document. The binder consumes the first document only.
- Mark indices count code points including a leading BOM; line/column are
  one-based. A BOM advances the index but not the displayed column. YAML 1.1
  NEL, LS and PS breaks, CRLF and an EOF without a newline follow the reader.
- `Token` keeps its **event span**, anchor, tag and lossless `java_text`.
  A start token does not use the collection's whole-node range. An incomplete
  collection ends at the last consumed event, contains its parsed children,
  and has `closing: None`. Scalar/field variants also carry a UTF-8 projection
  for the simple binder;
  `java_text` is authoritative for text output and surrogate comparisons.
  WP 2.1 should use JavaString directly in its production string tokens and
  map keys, removing this prototype convenience projection.
- `JavaString::as_utf8` is fallible; conversion to Unicode is never the
  storage boundary. The binding comparator uses the target type to distinguish
  user maps from string transport objects. `json()` uses a `{"$utf16":[...]}` object only for strings
  with unpaired surrogates. This is a corpus transport convention, not a
  Marathon output format. Long strings are hashed using JDK UTF-8 encoding
  replacement (`?` for an unpaired UTF-16 unit), not lossy Rust replacement.
- `load_bytes` first decodes UTF-8 like Kotlin `readText()`/JDK
  `InputStreamReader`. For example, `ED A0 80` becomes **one** U+FFFD;
  `C0 AF` becomes two. Corpus byte rows pin malformed-prefix consumption and
  truncated, overlong, surrogate and out-of-range sequences.
- Reader checks happen when the scanner reads a 1,024-UTF-16-unit chunk,
  including the extra read for a final high surrogate. The code-point limit
  is tested in `fetch_more_tokens`, with document-index resets at the parser's
  explicit document transition. Oversized root scalars can therefore emit a
  token before the limit error; a huge leading comment can fail before any
  document event. No whole-input limit approximation remains.
- Construction stops before opening depth 1,001. Incomplete collections and
  `Cut` preserve the stream prefix; an earlier key/coercion failure still wins
  during binding. Node drop and token walking are iterative. A subprocess
  regression sends both closed and unclosed 50,000-level flow inputs and
  requires 1,000 start tokens followed by `StreamConstraintsException`.

Java integer digit parsing, correctly rounded hexadecimal floating parsing
(including subnormals and ties), and Java Double formatting are implemented
in the spike sufficiently for the grown corpus and formatter table. These
belong in **jcompat, WP 1.2/1.x**, together with JavaString, before production
reuse. This spike's digit table is not a replacement for a fully specified
JDK Character database, and its formatter validation is finite evidence.

## Error and binding contract

`YamlError` records the stage, cause message, context mark, problem mark and
Jackson location. `TokenError` retains the stage and all three role-bearing
marks; depth exceptions have no location. Messages use our own wording under
PLAN §3.10, not Jackson's full message text.

For new oracle rows, marks are read directly from `MarkedYAMLException` and
`JsonProcessingException`, including explicit absence. The comparator requires
**each expected role** and its line/column; a problem mark cannot satisfy the
location check. Legacy rows use separate SnakeYAML and Jackson message formats.
Self-tests reject missing marks and swapped problem/location marks. UTF-8
message scanning uses character boundaries, and diagnostic truncation cannot
slice inside a multibyte character.

`BindingError` is now structured: `class`, `stage`, `path: Vec<PathPart>`,
`cause: BindingCause` and an optional source span. `PathPart` distinguishes
keys and list indices. A stream cause keeps its original `TokenError` even
when the binder wraps it as `JsonMappingException`; a coercion cause keeps
our own explanation. The prototype delays nullability validation until bean completion. This
differs from Jackson creator timing and exception precedence (R3-sol-2),
which WP 2.1 must implement. Deferred
errors retain the parameter's own `k` path and null-token span. Java trim
precedes target-specific empty/null/Boolean coercion; File text validation
rejects NULs and unpaired surrogates only when constructing an actual path.

**Implemented:** token spans; stage/path/cause for the simple targets and
stream failures; lossless scalar binding; required mark comparison; all
measured token prefixes and simple binding outcomes. Binding oracle comparison
checks success values and exception classes. The metadata tests separately
check span and structured-cause retention.

**Planned for WP 2.1/2.6:** Configuration and strategy binding, production
JavaString map keys, target-specific coercion explanations and full property
paths across production schemas, Marathonfile-relative file resolution,
substitution, and the emitter. The spike does not implement these or claim
that its current diagnostics already describe every production binding path.
