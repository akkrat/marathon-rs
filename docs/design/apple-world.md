# Scripted Apple world (WP 0.4b)

This is the small world needed by the four recorded scenarios in
[fake-apple-scenarios.md](fake-apple-scenarios.md). It is test infrastructure;
there is no production Apple port in this WP. It never runs a host Apple tool.
Only the existing 0.4a real-rsync adapter spawns a worker-side executable.

`apple::World` implements `router::Handler`, has no SSH types, and can be used
with `Request` and `VirtualFs` directly. Clone it to share state across
connections. Construct a new world and filesystem for each run:

```rust,ignore
let world = World::new(scenario)?;
let worker = start(config, vec![Arc::new(world.clone())]).await?;
// Drive Kotlin or an in-process client.
let fs = worker.fs.clone();
worker.shutdown().await?;
let state = world.final_state(&fs).await?;
world.validate()?;
```

The standalone interface preserves `--config CONFIG.json` and adds:

```sh
fake-worker --config CONFIG.json --apple WORLD.json --state final-state.json
```

The server prints its ordinary readiness JSON before the CLI starts. After TERM,
it joins the transport/channel/background actors, captures the filesystem and
active-process inventory in `cleanup`, then writes final world state. The Apple
mode exits nonzero for unmatched required counts, a deferred command, an
unfinished xcodebuild, or no batch. The scenario runner additionally validates
the entire evidence set and actual Kotlin reports.

## Scenario schema 1

Complete examples are `fixtures/fake-worker/apple/*/script/world.json`:

```json
{
  "schema": 1,
  "name": "example",
  "platform": "ios",
  "target": "sample_appUnitTests",
  "tests": [{"class":"SampleTests","method":"testFailing","status":"failed"}],
  "media": "none",
  "expectations": [{
    "name":"version", "matcher":{"exact":"xcrun xcodebuild -version"},
    "min":1, "max":1
  }]
}
```

`platform` is `ios` or `macos`; `media` is `none`, `video`, or `screenshot`.
`devices` optionally supplies initial UDIDs; its default is
`AAAAAAAA-BBBB-CCCC-DDDD-EEEEEEEEEEEE`. Initial lifecycle state is Shutdown.
Xcodebuild destinations, keyboard preferences and recording cleanup accept every
initial UDID. The provisioning probe reports the first configured initial UDID,
including a non-baseline single device. Invalid destination/preference/recording
identities fail explicitly.
Tests use the built bundle's module/class/method names and one of `passed`,
`failed`, `skipped`. Media scenarios contain one test and may contain several devices. Capture
barriers and screenshot-seen markers are indexed by UDID; the baseline UDID
retains its original file names so recorded filesystem evidence is unchanged. Invalid combinations fail at
load time. This schema rejects unknown fields.

Matchers are 0.4a's raw exact/prefix/glob matchers, with literal brackets (not
regular expressions). Put a worker/device selector in the raw matcher; each
worker is a separate `World`. `min`/`max` express required invocation counts.
All matching expectations reserve under one short synchronous state lock before
routing. Exhaustion fails explicitly. A dropped/failed routing future rolls its
reservations back; no guard crosses an await. Successful routing commits counts,
while xcodebuild completion is tracked independently by a completion marker.

Baseline effects are the finite commands in `apple.rs`, not an embedded shell or
another general scenario interpreter. 0.4a `Config.script` rules still precede
extensions and supply arbitrary fixture chunks, stream selection, delays,
status, hangs, signal and transport faults when later WPs need them. There is no
new fault engine, global connection ordering, or timing-based event schedule.
A rich effects/guards DSL, delayed/failing simulator transitions, runtime/SDK
profiles and arbitrary selectors are explicitly deferred to their owning WPs.

## State and filesystem

The shared world holds inventory, availability, lifecycle, keyboard preferences,
installed app IDs, captured TCC requests, expectation counts and discovery/batch
sessions. The initial worker profile is arm64, HOME `/Users/worker`, USER
`worker`, macOS 27.0, Xcode 27.1 and iOS 27.1. Boot/shutdown transitions are
immediate; list, getenv, device.plist and SpringBoard probes observe mutations.
Unknown simulator getenv returns the Kotlin fake's stderr/status 148. Lifecycle
state, capture barriers and keyboard configuration are indexed by UDID and
tested with two arbitrary initial devices. No host preferences or TCC database is
opened. The macOS permission scenario explicitly scripts `csrutil` stdout as the
single line `disabled` to pass Kotlin's A18 parser bug.

All uploaded/generated bytes stay in 0.4a's `/tmp/marathon` `VirtualFs`. External
simulator preferences/descriptors and worker facts are explicit response
resources. External SDK runner copying is deferred; the UI scenario reuses the
real uploaded test runner. In-root symlink reads retain 0.4a's resolver; writes
through links remain rejected. `chmod +x` now has a checked filesystem operation
that preserves other permission bits and rejects symlink operands.

Xcodebuild parses the actual uploaded XML/binary plist. It resolves individual
TestHostPath, TestBundlePath and UITargetAppPath fields with
`resolve_xctestrun_path`, then requires products, Info.plists, named nonempty
executables and the discovery dylib to exist. The original plist/environment
bytes and virtual paths are retained, without whole-payload rewriting. Session
state records destination, selected filters, discovery flag, result path and the
consumed plist bytes. A completion file changes final state to finished;
interruption leaves it cancelled. Unsupported user args fail explicitly.

Each batch creates a real directory with `SCRIPTED`, `root.json` and
`tests-0.json`. These are **scripted xcresult bundles, not readable by real
xcresulttool**. The generated Apple scalar/array wrappers, test counts, failure
summary, target name and testsRef agree with the emitted tests. The real Kotlin
xcresult adapter reads root and referenced JSON and replaces the failure trace.
The real rsync adapter pulls the tree; Kotlin renames it and removes the remote
source. Merge is catalogued and deferred because no baseline run produces two
bundles. Existing copied Kotlin fixtures are unchanged; new streams/objects
match these built bundles instead of pretending unrelated fixture names are
present in their Mach-O files.

## Additive transport seams

The existing `start`, Handler signature and Script routing order are unchanged.
The following small additions reuse the same actors, filesystem and process
registry:

* `Chunk.wait_for_file`: an optional virtual file barrier, awaited without a
  filesystem lease. The waiter registers its notification before checking.
  Invalid/escaping paths fail; channel/connection/run cancellation drops it.
* `Action::Publish`: wraps Output and carries `started`, completion `files` and
  an optional `on_signal`. Each file has a contained virtual `path` and base64
  bytes. Foreground publication happens after output completes, before the
  observable command exit, and never after a signal. Background startup files
  appear after PID registration/pidfile creation; completion files appear only
  on the selected signal (INT here). Transport loss does not publish them.
  Every effect uses `VirtualFs.write`, including its per-node containment.
* The complete device-log redirect `sh -c 'xcrun simctl spawn … log stream …
  2>/dev/null > FILE & echo $!'` gets an owned background job and returns its
  virtual PID on stdout. Its exact `sh -c 'kill -s INT PID'` wrapper joins before
  returning, so a subsequent pull sees the final log. The original direct kill
  and nohup/pidfile behavior remains intact.
* Process registration has an owned Drop guard, including the interval before
  spawning its tracked background actor. Registry operations are short
  synchronous map operations; signal delivery/join never holds that lock.
  Final cleanup reports `active_processes: []` and fails if any survived.

RecordVideo starts a hanging Output job; its startup marker releases the
xcodebuild test-end barrier. INT/lsof stop joins it and publishes the MP4.
Ffmpeg validates the completed source bytes and writes the committed transcode.
Screenshot capture writes the PNG. A second capture request proves Kotlin has
pulled/decoded/written the first GIF frame; that request releases the test-end
barrier and waits for cancellation, producing exactly one frame. No arbitrary
sleep is used to coordinate clients. The device-log wrapper has a separate
lifetime and publishes its file on INT. All jobs are connection/run owned.

Media bytes, hashes, metadata and generation commands are documented in
`fixtures/fake-worker/apple/media/README.md`. Host Xcode/ffmpeg are unnecessary
for replay. File hashes and metadata are compared; no frame decoder is used by
the acceptance harness.

## Command inventory and tests

`fixtures/fake-worker/apple/command-catalogue.json` contains 110 form records:
raw example, parsed argv order, matcher/template, Kotlin source, total/idle
timeout selection, expected stream use, status, effects, reachability, contract
and deferred owner/reason. The examples preserve wrapper quirks such as OS X,
quoted nm pipelines, the unused xcresult version parameter and duplicate
`codesign` argv. Families with configurable arguments describe those variants;
this is a catalogue of emitted forms, not their Cartesian product.

Three separate `host_forms` records describe client send/receive/version argv
with portable run/port/identity placeholders, full --rsh quoting and the
hardcoded receive timeout. Original measured argv remains in raw evidence.
The offline verifier checks version/send/receive shapes; per-argv validation
belongs to WP 7.1 (see the replay boundary in `fake-apple-scenarios.md`). The
0.4a shim contracts remain in use. The two iOS non-simctl TCC queries are deferred with
proper SQL bashEscape examples.

Every worker form record is parsed by `catalogue_deferrals_are_explicit`. Deferred records
must select an explicit stderr/status-64 action. Supported forms must route
successfully and match, except an explicit allowlist requiring uploaded
products, booted devices, recordings or result bundles. Baseline execution and
effects are exercised by the real recorded scenarios and nine Rust Apple
contracts. Unknown xcodebuild user arguments return the same recognised but
deferred status-64 action, including switches without an option value. Unknown forms
cannot succeed by falling through to a shell: 0.4a still rejects malformed
quotes, logs unmatched routes and returns a nonzero status.

`recorded_in` in the inventory records actual scenario reachability. A
supported-but-unreached wrapper is not claimed as executed. Existing 0.4a tests
are retained, including real rsync, containment and cancellation regressions.

## In-process executor (WP 5.1)

`marathon_test_support::apple::WorldExecutor` implements the production
`CommandExecutor` trait. Supply the same Router, World Handler, Script and
VirtualFs used by `start`; `new_connection` shares the backend and process
registry with an independent connection lifetime. Separate `new` calls create
independent backends. The world retains its measured Xcode 27.1 profile; the
separate Kotlin `FakeSimulatorWorker` uses Xcode 16.4 / iOS 18.6.

Both transports execute non-rsync plans through `fake_worker::execution::Execution`.
Its Sink owns output delivery, events and EOF/exit/CLOSE ordering. SSH keeps
transport faults and real rsync in its channel actor. In process, argv passes
through the production sshj `shell_command`, Request parsing and the unchanged
Router. Script rules still precede World. LineBuffer implements UTF-8 replacement,
chunk boundaries and line decoding; TERM reports 143, other signals no exit code.
The before hook can return a result, propagate a Failure class or change the
connection flag. SSH transport faults remain SSH tests.

Session drop cancels its foreground plan; explicit session close joins it.
Connection close cancels and joins foreground/background tasks. Background
nohup/pidfile and log jobs outlive the launching session and share SignalPid,
Publish and process registration with SSH. A foreground Publish also supports
startup files and publication on a selected signal, for live recording tests.
All filesystem work uses VirtualFs's blocking pool and existing containment.
WorldFileBridge imports/exports local file trees directly, preserving bytes,
modes and links; raw rsync commands fail explicitly. No second wire protocol or
host Apple command is introduced.

`marathon-test-support/tests/world_executor.rs` generates 46 reachable command
comparisons from the catalogue, using the merged Apple wrappers where those
finite forms have a wrapper. The 12 excluded forms require uploaded products,
executables, generated result bundles, or rsync.
The real xcodebuild wrapper additionally runs discovery/batches on two arbitrary
UDIDs. Existing SSH tests and four full Kotlin CLI replays cover the transport.
