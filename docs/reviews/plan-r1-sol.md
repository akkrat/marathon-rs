# Plan review, round 1: Sol (gpt-6.1-sol, high)

Reviewed the checked-out fork at `e47352f25cbc50333900d5d040a5544ff1224501`, which matches the plan. No files were modified. This review used source inspection; I did not build or run Marathon.

1. **Blocking — §§6.6, 7.5: shadow runs are not isolated.**  
   Separate `outputDir`s do not prevent Kotlin and Rust from overwriting worker state. Apple uses `/tmp/marathon`, shared application bundles, and fixed `marathon.xctestrun` filenames. Transfers also use deletion flags. Evidence: [AppleDevice.kt:84]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/AppleDevice.kt:84), [RemoteFileManager.kt:17–77]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/RemoteFileManager.kt:17), [RsyncFileBridge.kt:166–176]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/cmd/remote/rsync/RsyncFileBridge.kt:166).  
   **Fix:** use separate workers and simulators for concurrent shadow runs, or run sequentially with restored device state. Explicitly isolate shared storage, installed applications, simulator lifecycle, and Android tracing files.

2. **Blocking — §§3.1, 4.2–4.3, 0.4c: `fancy-regex` is not a Java-regex compatibility layer.**  
   The interface accepts user-supplied patterns, so testing patterns found in Kotlin source is insufficient. Java defaults `\d`, `\s`, and `\w` to ASCII classes; Rust’s underlying regex engine defaults to Unicode. Java quoting, flags, Unicode properties, line terminators, and replacement semantics also need treatment. Evidence: [FilteringConfiguration.kt:41–45]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/FilteringConfiguration.kt:41), [Scheduler.kt:130–138]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/Scheduler.kt:130), [Java Pattern documentation](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html), [fancy-regex documentation](https://docs.rs/fancy-regex/latest/fancy_regex/).  
   **Fix:** make the spike test arbitrary Java constructs against representative inputs, including Unicode and runtime backtracking failures. Specify a translator/emulation layer; evaluate PCRE2 as another backend without assuming it is Java-compatible. Any unsupported syntax requires an explicit compatibility deviation.

3. **Blocking — §5, WP3.1: the proposed Job tree is not the actual Kotlin lifecycle graph.**  
   `Scheduler.job` is a detached `Job()`. Its device subscription launches in the surrounding coroutine context, while pool jobs belong to the detached job. `execute()` joins the detached job’s children; provider termination happens afterward. Attaching the subscription to a conventional Scheduler parent and joining all children could make completion wait forever. Evidence: [Scheduler.kt:45–85]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/Scheduler.kt:45), [DevicePoolActor.kt:61–74]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/DevicePoolActor.kt:61), [Marathon.kt:209–218]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/Marathon.kt:209).  
   **Fix:** document the actual parentage, detached jobs, completion conditions, and shutdown order before freezing interfaces. Model cancellation request separately from completed cancellation; a `CancellationToken` alone does not provide Kotlin’s join or completion-handler semantics.

4. **Major — §§5, 6.4, 10: single-thread execution does not guarantee deterministic scheduling.**  
   The core inherits `runBlocking`’s thread, but vendor completion and connection events arrive concurrently. Random sorting and random device borrowing add nondeterminism. Tokio’s task scheduling also need not reproduce Kotlin’s cooperative scheduling. Evidence: [Marathon.kt:71–90]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/Marathon.kt:71), [RandomOrderSortingStrategy.kt:8–14]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/strategy/impl/sorting/RandomOrderSortingStrategy.kt:8), [AppleMacosProvider.kt:118–122]($MARATHON_KT/vendor/vendor-apple/macos/src/main/kotlin/com/malinskiy/marathon/apple/macos/AppleMacosProvider.kt:118).  
   **Fix:** retain the single-thread core for serialization, but remove the determinism claim. Add controlled event replay with injected clocks, IDs, randomness, and completion barriers. Compare exact batch assignments only under controlled inputs; test live runs through invariants and outcome distributions.

5. **Major — §6.4, WP7.1: the PATH-only fake Apple toolchain cannot intercept all commands.**  
   `PlistBuddy` is invoked as `/usr/libexec/PlistBuddy`; simulator discovery invokes `/usr/sbin/system_profiler`. Local transport also uses direct filesystem copying rather than rsync, so it cannot validate SSH/rsync behavior. Evidence: [PlistBuddy.kt:22–23]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/bin/plistbuddy/PlistBuddy.kt:22), [AppleSimulatorDevice.kt:274]($MARATHON_KT/vendor/vendor-apple/ios/src/main/kotlin/com/malinskiy/marathon/apple/ios/AppleSimulatorDevice.kt:274), [JvmFileBridge.kt:7–21]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/cmd/local/JvmFileBridge.kt:7).  
   **Fix:** build an oracle harness that injects `CommandExecutor`/`FileBridge`, or use an isolated worker filesystem. Add a separate real-sshd transcript suite. Move the harness prototype into Phase 0.

6. **Major — §6.1, WP0.1: an `@Test` scanner misses substantial specification coverage.**  
   Configuration serialization, timeout defaults, Xcode-version branches, annotation parsing, and connection behavior use `@ParameterizedTest` with several argument sources. Core also has a separate integration-test source set. Evidence: [TimeoutConfigurationTest.kt:33–95]($MARATHON_KT/configuration/src/test/kotlin/com/malinskiy/marathon/config/vendor/apple/TimeoutConfigurationTest.kt:33), [ConfigurationSerializationTest.kt:43–65]($MARATHON_KT/configuration/src/test/kotlin/com/malinskiy/marathon/config/serialization/ConfigurationSerializationTest.kt:43), [core/build.gradle.kts:12–24]($MARATHON_KT/core/build.gradle.kts:12).  
   **Fix:** inventory test methods and parameterized invocations across every source set. Include dependency-library tests needed to replace adam and DEX parsing. Record disabled/unexecuted tests separately from justified exclusions.

7. **Major — §§3.1, 6.3, WP2.4: validation parity includes timing and side effects, not only messages.**  
   Parsing validates Apple bundles and may extract archives. Logical validation runs later inside `Marathon.run`; importantly, its macOS branch does **not** call `MacosConfiguration.validate()`. Moving all available validators into parsing would reject configurations Kotlin accepts and change exit behavior. Evidence: [ConfigurationFactory.kt:71–86, 132–147]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/ConfigurationFactory.kt:71), [LogicalConfigurationValidator.kt:40–60]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/LogicalConfigurationValidator.kt:40), [AppleTestBundleConfiguration.kt:121–148]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/vendor/apple/AppleTestBundleConfiguration.kt:121).  
   **Fix:** specify staged validation explicitly. Extend the oracle to distinguish parse rejection, logical-validation rejection, provider failure, and resulting filesystem effects.

8. **Major — §§3.1, 4.1, WP2.3: Marathondevices uses a different deserialization profile.**  
   Its mapper registers Kotlin support but not Marathonfile’s custom `FileDeserializer`, `SerializeModule`, or Java-time module. Reusing the Marathonfile deserializer would change relative SSH-key paths and coercions in transport authentication. Evidence: [IosVendor.kt:31–41]($MARATHON_KT/vendor/vendor-apple/ios/src/main/kotlin/com/malinskiy/marathon/apple/ios/IosVendor.kt:31), [MacosVendor.kt:30–40]($MARATHON_KT/vendor/vendor-apple/macos/src/main/kotlin/com/malinskiy/marathon/apple/macos/MacosVendor.kt:30), [Transport.kt:20–24]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/configuration/Transport.kt:20).  
   **Fix:** define separate Marathonfile, Marathondevices/update, and parse-output profiles. Add differential cases for authentication paths in each profile.

9. **Major — §§3.1, 4.2, WP2.1: “YAML 1.1” and “merge keys rejected” are too broad.**  
   Jackson consumes SnakeYAML events; it is not a normal YAML object loader. A `<<` key can be ignored by a handwritten deserializer or accepted as an ordinary map key. The mapper also disables native type IDs only for **generation**, leaving parsing behavior to Jackson defaults. Duplicate keys, tags, multiple documents, mapping-key spelling, null/default distinctions, and limits are missing from the contract. Evidence: [ConfigurationFactory.kt:30–48]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/ConfigurationFactory.kt:30), [InfluxDbConfigurationDeserializer.kt:14–29]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/yaml/InfluxDbConfigurationDeserializer.kt:14), [VendorConfiguration.kt:65]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/vendor/VendorConfiguration.kt:65).  
   **Fix:** specify Jackson’s token and binding behavior rather than blanket YAML rules. Preserve raw spelling, tags, and duplicate entries in `Node`. The [saphyr-parser documentation](https://docs.rs/saphyr-parser/latest/saphyr_parser/) identifies it as a YAML 1.2 parser; expand its spike to syntax acceptance/rejection against SnakeYAML.

10. **Major — §§3.1, 6.3, WP2.2: the `timeLimit` fallback is field-specific and exception-specific.**  
    The three handwritten deserializers catch only `InvalidFormatException`, not every failed Instant conversion. Fixed-size batching can produce a null limit when both conversions fail; execution-time sorting throws `"bbb"`; probability-based flakiness throws another message. Success-rate sorting is not one of these handwritten deserializers. Evidence: [ExecutionTimeSortingStrategyConfigurationDeserializer.kt:25–45]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/yaml/ExecutionTimeSortingStrategyConfigurationDeserializer.kt:25), [FixedSizeBatchingStrategyConfigurationDeserializer.kt:32–54]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/yaml/FixedSizeBatchingStrategyConfigurationDeserializer.kt:32), [SortingStrategyConfiguration.kt:29–32]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/strategy/SortingStrategyConfiguration.kt:29).  
    **Fix:** document each field’s behavior. Cover numeric Instants, numeric Durations, quoted numbers, nulls, arrays, overflow, and conversion exceptions. Inject reference time into both oracle implementations.

11. **Major — §3.1, WP2.3/5.5a: the dynamic-provider contract is incomplete and its length type is wrong.**  
    `readInt()` reads a signed 32-bit value, not `u32`; payloads are capped at `2^20` bytes. Negative lengths fail through buffer-limit handling. An existing devices file selects the static provider even when configuration says dynamic. Connection refusal retries every five seconds; other errors end the producer. Evidence: [AppleSimulatorProvider.kt:159–181, 191–262]($MARATHON_KT/vendor/vendor-apple/ios/src/main/kotlin/com/malinskiy/marathon/apple/ios/device/AppleSimulatorProvider.kt:159).  
    **Fix:** specify signed framing, ignored reserved bytes, limits, malformed-frame behavior, file precedence, substitution, and connection-error behavior. Test split/coalesced frames, zero/negative/oversized lengths, partial EOF, invalid YAML, and static-file precedence.

12. **Major — §§3.1, 6.3, WP1.3: environment substitution needs an explicit failure contract.**  
    The plan lists syntax but omits unresolved-variable behavior, empty versus absent variables, substitution in variable names versus values, and cycle/error handling. Marathonfile substitution occurs outside the `JsonProcessingException` wrapper; device-file/update substitution occurs outside its mapping wrapper. Android SDK discovery also has independent `ANDROID_HOME` precedence over `ANDROID_SDK_ROOT`. Evidence: [ConfigurationFactory.kt:50–56, 200–201]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/ConfigurationFactory.kt:50), [AppleSimulatorProvider.kt:255–260]($MARATHON_KT/vendor/vendor-apple/ios/src/main/kotlin/com/malinskiy/marathon/apple/ios/device/AppleSimulatorProvider.kt:255), [SystemEnvironmentReader.kt:12–13]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/environment/SystemEnvironmentReader.kt:12).  
    **Fix:** add a substitution truth table and subprocess oracle with controlled environment variables, including failures and their exception boundaries.

13. **Major — §§3.1, 3.2, WP2.5/3.10: the CLI contract needs an executable argument-and-exit matrix.**  
    Long options are missing from the written surface. Root options are separate from `run` options and are not forwarded to a subcommand. Errors during configuration loading occur outside the catch that emits “crashed”; meanwhile `Marathon.run` catches `Throwable` and can return `ignoreFailures`. `version` also emits a startup log before printing its version. Evidence: [CliCommands.kt:13–44, 62–76, 90–102]($MARATHON_KT/cli/src/main/kotlin/com/malinskiy/marathon/cli/args/CliCommands.kt:13), [ApplicationView.kt:38–95]($MARATHON_KT/cli/src/main/kotlin/com/malinskiy/marathon/cli/ApplicationView.kt:38), [Marathon.kt:92–101]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/Marathon.kt:92).  
    **Fix:** cover help, invalid/missing arguments, option placement, repeated options, configuration errors, no devices/tests, parse mode, and `ignoreFailures`, recording stdout, stderr, and status separately. Do not inherit clap defaults unquestioned.

14. **Major — §3.1, WP1.6: logging has startup and runtime phases.**  
    Before vendor configuration, CLI logs use `%d … %-5level %logger{36} - …`, not the pattern stated in §3.1. `debug=false` changes levels when `MarathonLogging.logger()` is called; it does not globally reconfigure every previously created logger. Evidence: [cli/logback.xml:2–10]($MARATHON_KT/cli/src/main/resources/logback.xml:2), [MarathonLogging.kt:30–49]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/log/MarathonLogging.kt:30), [AppleLogConfigurator.kt:18–46]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/AppleLogConfigurator.kt:18).  
    **Fix:** specify startup/runtime formatter switching, logger creation/retrieval behavior, stdout routing, and ANSI behavior for terminals and redirected output. Add startup-failure and version goldens.

15. **Major — §§4.3, 0.3, WP1.1: heap compatibility also requires model equality and comparator behavior.**  
    `Test.equals` ignores metadata. That affects duplicate suppression, bundle lookup, retry accounting, and `removeAll`. Comparators can consult mutable observed-duration estimates or assign random priorities lazily, making comparator-call order relevant. Evidence: [Test.kt:11–21]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/test/Test.kt:11), [FixedSizeBatchingStrategy.kt:24–55]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/strategy/impl/batching/FixedSizeBatchingStrategy.kt:24), [QueueActor.kt:276–286]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/queue/QueueActor.kt:276).  
    **Fix:** freeze equality separately from identity and serialized representation. Pin the reference JDK and its actual heap implementation, including bulk removal. Test duplicate logical tests with different metadata, iterator removal, equal priorities, changing comparator values, and comparator-call traces.

16. **Major — §7: several shared components have no explicit owner.**  
    WP3.9 names reporter endpoints but not the event-to-report pipeline: `Track`, `MappingTracker`, `DelegatingTrackerInternal`, `ExecutionReportGenerator`, and summary/retry construction. Shared `LogListener`/`LogWriter` and attachment collection are also only implicit. These components carry observable ordering and data-selection rules. Evidence: [TrackerFactory.kt:59–103]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/TrackerFactory.kt:59), [ExecutionReportGenerator.kt:6–33]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/internal/sub/ExecutionReportGenerator.kt:6), [ExecutionReport.kt:26–96]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/internal/sub/ExecutionReport.kt:26), [LogListener.kt:28–50]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/execution/listener/LogListener.kt:28).  
    **Fix:** add a source-file-to-WP inventory across every module, including files with no tests. Split event aggregation and shared attachment/log infrastructure into explicit packages.

17. **Major — §§3.3/D4, 4.2, WP3.4: analytics parity exceeds queries and line protocol.**  
    Influx v1 checks/creates databases and retention policies and enables batching. Influx v2 resolves organizations and creates buckets. Client buffering, retry, flush/close behavior, and 60-second network timeouts affect external behavior. Evidence: [InfluxDbProvider.kt:19–52]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/external/influx/InfluxDbProvider.kt:19), [InfluxDb2Provider.kt:24–65]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/external/influx2/InfluxDb2Provider.kt:24).  
    **Fix:** add backend lifecycle operations and client-library behavior to the contract. Run the existing integration tests’ equivalents against real Influx v1/v2 and Graphite services; add request transcripts and close/flush tests.

18. **Major — §§4.2, 0.4a, WP4.2: the russh spike is too narrow.**  
    sshj truncates keepalive intervals to whole seconds; connection attempts retry connect failures using fresh clients, while authentication happens afterward. Command execution ignores `env` and `workdir`, and TERM-derived exit code is distinct from timeout returning null. The patched channel also suppresses a particular late-data-after-EOF error. Evidence: [SshjCommandExecutorFactory.kt:48–64, 85–88]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/cmd/remote/ssh/sshj/SshjCommandExecutorFactory.kt:48), [SshjCommandExecutor.kt:37–64, 104–133]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/com/malinskiy/marathon/apple/cmd/remote/ssh/sshj/SshjCommandExecutor.kt:37), [PatchedExecChannel.kt:40–51]($MARATHON_KT/vendor/vendor-apple/base/src/main/kotlin/sshj/connection/channel/direct/PatchedExecChannel.kt:40).  
    **Fix:** test transport loss, exhausted MaxSessions, output around EOF/close, simultaneous streams, ignored TERM, host-key formats, key formats, and authentication failures. Verify keepalive semantics rather than copying similarly named [russh settings](https://docs.rs/russh/latest/russh/client/struct.Config.html). Retain an alternative channel-capable SSH backend if the spike fails.

19. **Major — §3.1, WP6.1–6.7: the Android worker interface needs explicit dependency contracts.**  
    `ArgumentsFactory` emits adam’s externally consumed test-runner argument names, including ADB reverse access, emulator console authentication, and gRPC addressing. Implementing reverse forwarding and instrumentation parsing does not automatically reproduce this contract. Evidence: [ArgumentsFactory.kt:15–83]($MARATHON_KT/vendor/vendor-android/src/main/kotlin/com/malinskiy/marathon/android/adam/execution/ArgumentsFactory.kt:15), [Versions.kt:63–66]($MARATHON_KT/buildSrc/src/main/kotlin/Versions.kt:63).  
    **Fix:** explicitly assign `ArgumentsFactory`, `TestRunnerContract` constants, feature negotiation, instrumentation request generation, and exception translation. Pin adam/DEX/AXML dependency sources and compare their behavior, not merely protocol documents.

20. **Major — §6.4: output comparison omits much of the promised contract.**  
    Diffing raw JSON, JUnit, and HTML data does not validate device/billing/test JSON, Allure, parse YAML, timeline, attachment references, worker cleanup, or media. Allure is written by its own lifecycle/model library, not the Gson formatter. Evidence: [TrackerFactory.kt:90–101]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/analytics/TrackerFactory.kt:90), [AllureReporter.kt:50–68, 116–160]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/report/allure/AllureReporter.kt:50).  
    **Fix:** compare a complete directory manifest and every artifact family. Define field-specific normalization with referential integrity for IDs and paths. Use byte comparisons for controlled text serialization and decoded-content comparisons for media.

21. **Major — §§6.3–6.6: the oracle needs controlled time, filesystem, and backend state.**  
    Relative `timeLimit`s use real `Instant.now()`. Bundle parsing can delete/recreate extraction directories. Reports use wall-clock timestamps, and test batches use random UUIDs. Running both binaries sequentially over the same files can change the second run’s inputs. Evidence: [InstantTimeProviderImpl.kt:5–6]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/serialization/time/InstantTimeProviderImpl.kt:5), [AppleTestBundleConfiguration.kt:21–23]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/vendor/apple/AppleTestBundleConfiguration.kt:21), [TestBatch.kt:5]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/test/TestBatch.kt:5).  
    **Fix:** give each run an equivalent isolated filesystem and backend snapshot. Inject time/IDs for component comparisons. Define canonical config dumps explicitly, including derived bundle paths currently hidden by `@JsonIgnore`.

22. **Major — §§6.5, 7.2, 7.5: macOS has no real acceptance run.**  
    The plan promises three vendors, but real E2E covers only iOS and Android. macOS has distinct initialization, host targeting, TCC updates, installation layout, and cancellation/disposal behavior. Evidence: [AppleMacosProvider.kt:80–114]($MARATHON_KT/vendor/vendor-apple/macos/src/main/kotlin/com/malinskiy/marathon/apple/macos/AppleMacosProvider.kt:80), [MacosDevice.kt:378–410, 507–515]($MARATHON_KT/vendor/vendor-apple/macos/src/main/kotlin/com/malinskiy/marathon/apple/macos/MacosDevice.kt:378).  
    **Fix:** require macOS local and SSH E2E, including cancelled batches, disposal, both parsers, permissions, and result enrichment. Make unavailable prerequisites explicit release blockers rather than silently skipping the vendor.

23. **Major — §7: dependencies and package sizing understate the integration work.**  
    WP0.3 freezes interfaces before the spikes resolve YAML, regex, SSH, and concurrency constraints. WP7.1 is deferred until after the behavior it must constrain. WP3.9 combines all reporting formats; WP2.3 combines three vendors, bundle extraction, devices parsing, and protocol framing; WP6.7 combines execution and numerous artifact systems. The listed critical path omits essential oracle, Apple command-layer, Android, macOS, packaging, and hardware gates.  
    **Fix:** write an explicit dependency DAG and move executable contracts/harnesses earlier. Split these WPs by independently reviewable behavior. Make 5.5a precede 5.5b unless their shared provider changes are separated architecturally; create fake-worker support before device/provider ports.

24. **Major — §§8.2–8.3, 10: review closure and release closure are underspecified.**  
    The loop ends when Sol has no blocking findings, leaving major compatibility findings or Muse objections potentially unresolved. Reviews are not tied to an exact commit, `n/a` decisions have no approval policy, and three rounds can become an implicit escape hatch. The moving-source queue has no required drain/revalidation gate before releasing “latest fork state.”  
    **Fix:** track both reviewers’ findings by severity and commit; require all blocking/major findings resolved or explicitly waived. Re-audit affected completeness rows after fixes and merge. Three rounds should trigger escalation, not acceptance. Require a recorded release source SHA, a drained port queue, and renewed differential gates.

25. **Minor — §§3.3/D3, 4.2: two artifact details are misstated or incomplete.**  
    The lazy `safeSerialNumber$delegate` field can also occur inside per-test JSON because `TestJsonReporter` serializes `TestResult.device`; D3 only mentions devices/bills. Screenshot dimensions are configurable, not fixed at 720×1280, and GIF timing/loop/disposal metadata are observable. Evidence: [TestJsonReporter.kt:14–16]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/report/test/TestJsonReporter.kt:14), [ScreenshotConfiguration.kt:5–9]($MARATHON_KT/configuration/src/main/kotlin/com/malinskiy/marathon/config/vendor/android/ScreenshotConfiguration.kt:5), [GifSequenceWriter.kt:71–104]($MARATHON_KT/core/src/main/kotlin/com/malinskiy/marathon/device/screenshot/GifSequenceWriter.kt:71).  
    **Fix:** enumerate every affected JSON location in D3. Specify configured screenshot sizing and GIF metadata, with decoded-frame and timing tests.

**Overall verdict:** do not approve the plan as an implementation baseline yet. Correct the compatibility profiles and lifecycle graph, make the oracle/harness executable early, and establish isolated three-vendor release gates before parallel porting begins.
